# Spec: 類別樹不留空葉——刪三片 0 框的葉,並由測試擋下新的空葉

Status: ready-for-agent
Date: 2026-10-30

起因是站主發現搜尋頁選 にする→裏側表示 永遠沒有結果。查證後這片葉從開葉起就是 0 框,而且全樹還有兩片同樣的空葉。

## 需要你決定的

### にする→裏側表示 怎麼處理?

決定(2026-10-30):刪除。

- (a)刪除(建議):表示形式剩五葉;代價是將來若有效果寫「裏側表示にする」,會落 にする 預設葉,要等站主發現後再開葉。
- (b)放寬成「變成任何裏側表示」:與 →守備表示 的處理對稱,但收到的框架和 →裏側守備表示 完全相同,樹上多一個重複節點。
- (c)保持空葉:照舊規格「每種表示形式一葉」,但搜尋頁一直有選了必定零結果的節點。

### 其他兩片空的預設葉要一併刪嗎?

決定(2026-10-30):一併刪除。

- (a)一併刪除(建議):樹上不再有必定零結果的節點;代價是將來不符合現有子葉的框架進未歸清單,而不是預設葉。
- (b)保留當兜底:網頁上照樣有兩個零結果節點。
- (c)樹不動、匯出時隱藏:樹檔與網頁不再一一對應,匯出器多一條規則。

### 要怎麼防止之後再出現空葉?

決定(2026-10-30):加到真樹回歸測試。

- (a)真樹回歸測試(建議):空葉在測試階段被擋下;代價是卡文更新可能讓它變紅,要站主裁定才會綠。
- (b)建置檢查:比測試更硬,但空葉會擋住整條資料更新。
- (c)不加防線:下一片空葉要靠人工發現。

### 測試接縫?

決定(2026-10-30):既有 classify 加一條全語料檢查,框架檔不存在時略過。

- (a)兩個接縫,缺檔時略過並印原因(建議):乾淨 clone 也跑得了其他測試;代價是沒有框架檔的環境防線不生效。
- (b)兩個接縫,缺檔時失敗:防線不會默默失效,但沒先跑分詞鏈就過不了全套測試。
- (c)放進分詞鏈的最後一步:等同建置檢查,空葉會擋住資料更新。

## Problem Statement

站主在搜尋頁的動作類別軸選節點找卡。類別樹上有三個可以選、但選了必定零結果的節點:

- **にする→裏側表示**:全語料 にする 框架目的欄是「裏側表示」的只有 8 框,全部在條件位(…モンスターが裏側表示になった時),而類別只歸效果位與代價位。把怪獸翻成裏側的效果一律寫「裏側守備表示にする」(效果位肯定 100 框、可能 9 框);魔法、陷阱寫 セットする。
- **指定 › 指定**(預設葉):12 框全部進 指定@フィールド。
- **無効にする(耐性) › 無効にする(耐性)**(預設葉):框架全部進 :効果/:発動/:召喚 三葉。

選到這些節點的站主看到零結果,無從判斷是卡真的不存在、還是網站壞了。這片葉當初開的時候就知道是 0 框(「照規格開」),沒有任何機制會提醒它一直是空的。

## Solution

從類別樹刪掉這三片葉,葉數 236 → 233。選父節點 指定、無効にする(耐性) 的結果不變。

同時立一條規則:每片葉在全語料的效果位或代價位至少要有一框,預設葉也一樣。真樹回歸測試檢查這條規則;日後卡文更新或規則調整讓某片葉變成 0 框時,測試失敗並列出葉名,由站主決定刪葉或改規則。

## User Stories

1. 身為站主,我想在搜尋頁只看到選了可能有結果的類別節點,以便零結果真的代表「沒有這種卡」。
2. 身為站主,我想讓表示形式只留語料實際出現的五葉(→裏側守備表示、→表側守備表示、→表側攻撃表示、→守備表示、→攻撃表示),以便不必猜 →裏側表示 和 →裏側守備表示 差在哪。
3. 身為站主,我想選 →裏側守備表示 時照樣收到全部把怪獸翻成裏側的效果,以便刪葉不影響找卡。
4. 身為站主,我想選 指定 時照樣拿到現有 12 框,以便刪預設葉不影響父節點。
5. 身為站主,我想選 無効にする(耐性) 時照樣拿到它三片子葉的全部框架,以便刪預設葉不影響父節點。
6. 身為站主,我想讓「裏側表示になった時」這類條件句維持不進動作類別,以便它們留給另開的觸發事件軸。
7. 身為站主,我想讓刪葉前後每一框的歸類除了這三片葉之外逐框相同,以便不必為這次改動重新抽樣覆核。
8. 身為站主,我想讓已歸、未歸、不適用三個數字刪葉前後都不變,以便確認刪掉的真的是空葉。
9. 身為站主,我想在卡文更新後某片葉變成 0 框時收到測試失敗並看到葉名,以便決定刪葉或改規則,而不是等有人搜不到才發現。
10. 身為站主,我想讓這道檢查把預設葉也算進去,以便它們同樣不會變成必定零結果的節點。
11. 身為站主,我想讓只在條件位出現的葉算空葉,以便檢查的口徑和搜尋實際用到的框架一致。
12. 身為開發者,我想在沒跑過分詞鏈的環境照樣跑完其他測試,以便乾淨 clone 不被產物檔卡住;跳過時要印原因,以便知道防線沒生效。
13. 身為開發者,我想讓將來效果寫「裏側表示にする」時落 にする 預設葉,以便不會憑空遺失,且在檢驗時看得到。
14. 身為開發者,我想讓將來不符合 指定、無効にする(耐性) 子葉的框架進未歸清單,以便與「規則表沒覆蓋的不貼」一致。
15. 身為使用者,我想讓帶著已刪節點的舊連結照常打開、只是那個條件不生效,以便舊連結不會出錯。
16. 身為站主,我想在拆解頁、類別樹草案與檢驗摘要看到新的葉數與這次決定,以便所有文件和網站一致。

## Implementation Decisions

- **類別樹來源檔**:刪掉 にする 節點的 →裏側表示 葉,刪掉 指定、無効にする(耐性) 節點的預設葉 `{}`。樹檔「說明」補一段 2026-10-30 的紀錄;舊段落的「表示形式六葉」是當時的紀錄,不改寫。
- **機制不動**:歸類、匹配、樹完整性檢查都不改。已先以記憶體中改過的樹試載,樹完整性檢查通過、葉數 233;得る 也是沒有預設葉的詞元節點。
- **空葉查詢**:類別模組新增一個函式,輸入類別樹與全語料框架,回傳沒有任何已歸框的葉名清單(依樹序)。只數狀態為已歸的框,條件位的框不是已歸,自然不算。這個函式不進建置流程、不擋匯出,只給測試用。
- **網頁**:不改程式。節點由匯出的樹展開,預設葉子節點會隨樹消失;舊連結裡找不到的節點路徑已是「不當條件」,結果會變寬、不報錯。
- **文件**:GLOSSARY「動作類別」詞條的新規則已於 grill 時補上。類別樹草案提到「表示形式六葉、→裏側表示 0 框」的段落改成五葉,並新增已決事項記本規格決定。檢驗摘要補本線一節與儀表板葉數 236 → 233。舊規格與舊票是歷史紀錄,不改。
- **交件**:重跑分詞鏈與網站建置,拆解頁、草案、檢驗摘要、本規格的鏡像照原網址發布。

## Testing Decisions

- 好的測試只驗外部行為:一句卡文歸到哪些葉、一棵樹對一批框架報哪些空葉;不驗樹檔內部結構或函式實作。
- **既有 classify 接縫**(仿現有真樹回歸類):
  - 效果位「裏側表示にする」的句子落 にする 預設葉;
  - 「裏側守備表示にする」照舊帶 →裏側守備表示 與 →守備表示;
  - 條件位「裏側表示になった時」不帶動作類別葉;
  - 所在不是場上的 指定 框進未歸;
  - 不含 効果/発動/召喚 字面的 無効にする 耐性框進未歸。
  - 實作時優先找真卡句造例;後兩條語料目前沒有真例(所以才是空葉),用造句,並在測試註明。
- **空葉查詢,小樹**(仿樹完整性與小樹測試):小樹與少量造句框架證明函式會回報空葉,包含預設葉空、以及只在條件位命中的葉算空;全部有框時回傳空清單。這條確保防線會紅,不只是現在剛好綠。
- **空葉查詢,全語料**:真樹對框架檔重新歸類,回傳清單要是空的;失敗訊息列出葉名。重新歸類而不是讀舊的類別產物,改樹後不必重跑分詞鏈就驗得到。實測約 1.6 秒。框架檔不存在時略過並印原因。
- **交件驗證**:與刪葉前的框架類別檔逐框比對,差異必須為零框;已歸、未歸、不適用不變;類別與匯出決定性重跑逐位元組相同(除建置時間戳);真瀏覽器確認三個節點不見、選 指定 與 無効にする(耐性) 有結果、帶舊節點路徑的連結不出錯。

## Out of Scope

- 「裏側表示になった時」這 8 框的搜尋:屬於另開的觸發事件軸。
- 放寬 →裏側表示、新開 →表側表示。
- 葉數很少但不是 0 的葉(半分にする、S素材とする、取り除く 的預設葉各 1 框):不是空葉,照現狀。
- 舊連結把已刪節點轉成其他節點,或提示使用者條件已失效。
- 把空葉檢查放進建置流程。

## Further Notes

- 之前的查證說「裏側表示になった」詞元是 なる,這是錯的:框架線已把 なる 統一成 にする,那 8 框詞元就是 にする,只因為在條件位才不進類別。
- 葉編號會因刪葉位移,但網址存的是節點路徑,不受影響;編號只在同一次建置內有效。
