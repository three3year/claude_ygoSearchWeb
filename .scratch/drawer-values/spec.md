# Spec: 抽屜只列選得出結果的值

Status: ready-for-agent
Date: 2026-11-02

站主回報:抽屜裡大部分按鈕沒有作用,用單詞標籤搜尋時按了右側按鈕就沒有結果。2026-11-02 診斷:按鈕都有反應、查詢也正確,問題是抽屜列出整個值域,不管這個動作在語料裡有沒有這個值(數字見 [Further Notes](<#Further Notes>))。同日 /grill-with-docs 訪談定案,下面各題都已決定,正文依決定寫。上游規格是 `.scratch/predicate-ui/spec.md`(抽屜、條件模型、網址),本規格改它的三條:位置全關、極性沒寫、中心詞自由輸入。

## 需要你決定的

### 抽屜裡選了會沒結果的值怎麼處理?

決定(2026-11-02):分兩層,排版不跟著選擇跳動。這個動作在語料裡根本沒有的值隱藏;要配合目前其他欄才沒結果的值灰掉。不在鈕上標張數。

- (a)標張數,0 張灰掉不能按(建議):一眼看出能按什麼。代價:鈕變寬、抽屜變長。
- (b)不標張數,0 張直接隱藏:抽屜最短。代價:換標籤或改條件時鈕會出現、消失。
- (c)標張數,0 張仍可按:只給資訊不擋操作。代價:還是按得出空結果。
- (d)不標張數,只灰掉 0 張:畫面最乾淨。代價:看不出按下去剩多少。

### 判斷有沒有結果,只看這張標籤還是整個查詢?

決定(2026-11-02):(a)只看這張標籤。

- (a)只看這張標籤(建議):和抽屜現有的「N 張」同一口徑,OR 區不必另想算法。代價:多條件並用時還是可能按出 0 張。
- (b)看整個查詢:按得出的就一定有結果(在 AND 區)。代價:OR 區的語意難懂;每按一下要多算很多次查詢。

### 隱藏名單依據什麼?

決定(2026-11-02):(a)只看動作。

照字面用新增時的預設條件判斷,否定形四顆在預設極性下會永遠隱藏,就算之後按了極性否定也不會出現。

- (a)只看動作,三個位置與三種極性都算(建議):同一動作的所有標籤排版相同,讀網址也一樣。代價:帶條件的具名查詢(如 特殊召喚←墓地)多一些灰鈕,而不是隱藏。
- (b)用新增時的預設條件:字面照做。代價:否定形在預設極性標籤上永遠按不到;改過欄位後重整網址找不回原本的預設。
- (c)預設條件,改位置或極性時重算:按了極性否定後否定形才冒出來。代價:按這兩欄時排版還是會跳。

### 灰色怎麼判定、能不能按?

決定(2026-11-02):(a)值本身沒命中就灰,不能按。

同一欄多值是「或」,所以不能看按下去的結果:已選「自分」時,加上任何值結果都不會是 0。

- (a)值本身沒命中就灰,不能按(建議):其他欄照目前選的,這一欄只留這個值,沒有命中就灰;不會留下按了張數不變的鈕。
- (b)按下結果是 0 才灰,不能按:完全照字面。代價:會有按下去張數不變的鈕。
- (c)值本身沒命中就灰,但仍可按:灰只是提醒。代價:還是按得出空結果。

### 亮著的鈕關掉會變 0 張時,能不能關?

決定(2026-11-02):(b)可以關。

例:位置 代價+效果、施事者=相手,而相手只出現在代價,此時關掉「代價」就是 0 張。

- (a)按不掉,樣式同最後一顆(建議):抽屜裡按不出空結果。代價:要想一下為什麼按不掉。
- (b)可以關,結果變 0 張:規則最少,鈕還在,按回去就好。

### 按否定形時要不要連動極性?

決定(2026-11-02):(c)不連動。極性不含「否定」時否定形的值是灰的(配合[隱藏名單](#隱藏名單依據什麼?)的決定)。

否定形只出現在極性為否定的框上(見 [Further Notes](<#Further Notes>))。

- (a)自動換成只有否定(建議):語意最精確。
- (b)自動加入否定,保留肯定與可能:查到的卡相同。代價:畫面暗示肯定也算。
- (c)不連動,先手動按極性否定:行為最單純。代價:要懂這層關係才知道怎麼用。

### 位置能不能全部關掉?

決定(2026-11-02):(a)最後一顆按不掉。

現在只選「效果」時按它會變成三顆全亮、張數變多,再按又變成只剩代價和條件,按不回去。

- (a)最後一顆按不掉(建議):每顆鈕都是單純的開關。代價:只亮一顆時按它沒反應,要做出不可按的樣子。
- (b)全亮時按一顆只留那一顆。代價:同一顆鈕在不同狀態下行為不同。
- (c)另加「全部」鈕,一般鈕變單選。代價:不能選兩個位置的組合,網址與規格要改。
- (d)維持現狀:全關等於三個都看。代價:這個誤會還在。

### 極性能不能全部關掉?

決定(2026-11-02):(a)比照位置,最後一顆按不掉。

- (a)比照位置(建議):要不限就三顆都按亮;舊網址沒寫極性讀進來視為三顆全亮,查到的卡相同。
- (b)維持全關等於不限。代價:沒有鈕亮時張數反而變多的誤會還在。

### 區域選單與中心詞候選要不要過濾?

決定(2026-11-02):(a)都只列有命中的;中心詞框是快捷選取,不是自由輸入。

- (a)都只列有命中的(建議)。
- (b)只過濾區域與玩家,中心詞候選不動。代價:從候選挑一個仍常常 0 張。
- (c)都不過濾,只處理點選鈕。代價:0 張問題留在這幾欄。

### 中心詞框怎麼收字?

決定(2026-11-02):(a)只能挑清單,清單內全列。

- (a)只能挑清單,清單內全列(建議):打字只縮小清單;清單外的字被清掉。代價:不能自造詞尾查詢,清單可能上百項。
- (b)只能挑清單,最多 300 個。代價:常見詞以外的命中詞選不到。
- (c)清單為主,仍收自打的字。代價:打錯或沒命中是 0 張。

### 一欄的值全被隱藏時怎麼顯示?

決定(2026-11-02):(b)整欄隱藏,沒有例外。

- (a)整欄隱藏,否定形留一行提示「先按極性 否定」(建議)。
- (b)整欄隱藏,沒有例外:抽屜最短、規則一致。
- (c)欄名都留著,寫「目前沒有可選的值」。代價:抽屜仍然長。

### 測試接縫就這三個嗎?

決定(2026-11-02):(a)三個。

- (a)三個(建議):條件模型(既有,新增抽屜選項函式與按鈕規則)、`Hash`(既有,極性往返)、條件列事件(既有,中心詞收字);畫面互動由交件票在真 Chrome 走一輪。代價:灰鈕、隱藏後排版這類 DOM 呈現沒有自動測試。
- (b)再把 CDP 腳本變成自動測試。代價:要本機裝 Chrome,比其他 node 測試慢很多。

## Problem Statement

站主點一張單詞標籤(如「破壊」)開抽屜,按大部分的值鈕都得到「沒有符合條件的卡片」,事前看不出哪顆會這樣,以為按鈕壞了。原因是抽屜列出 `VOCAB.frame.domains` 的全部值,不看這個動作有沒有:單詞標籤每 10 次加值有 6 次以上是這個動作根本沒有的值。另有兩種情況:值要配合其他欄才有,但被預設的位置或極性擋掉;還有否定形四顆在預設極性下永遠 0 張。

位置與極性還有一個誤會:全部關掉等於三個都看(或不限),所以只亮「效果」時按它,三顆反而全亮、張數變多,再按就按不回去。

## Solution

1. **隱藏**:這張標籤的動作(詞元)在語料裡從沒出現過的值,不論位置、極性,抽屜不列。名單只看動作,整個標籤期間不變。一欄全被隱藏時整欄不列;進階欄全部不列時「進階」小標也不列。
2. **灰色**:其他欄照目前選的,這一欄只留這個值仍沒有命中,這顆就灰掉、不能按。其他欄一改,灰色跟著更新,但鈕的位置不動。
3. **亮著的鈕**:一律列出、都能關,網址帶進來的值也一樣;關掉可能變 0 張。
4. **位置與極性**:最後一顆亮著的按不掉;要全部就三顆都按亮。舊網址沒寫極性時視為三顆全亮。
5. **否定形**:不連動極性。極性不含否定時,否定形的值是灰的;動作完全沒有否定形時整欄不列。
6. **區域**:玩家選單只列這個動作在這一欄出現過的玩家;區域選單不列動作沒有的區域,對目前選的玩家與其他欄沒有命中的區域灰掉。
7. **中心詞**:打字只是縮小清單,只能從清單挑。清單是目前條件下有命中的全部中心詞,清單外的字不收。

驗收:真 Chrome 桌面與手機寬各走一輪;單詞標籤上按任何可按的鈕都有結果;全語料檢查隱藏、灰色、可按三種判定和引擎實際張數一致。

## Implementation Decisions

**判定(條件模型,經引擎掃框)**

- 判定在框層:一個值「有命中」等於有一個框同時滿足述詞其他欄、且這一欄有這個值。全部框都掛在卡上(見 [Further Notes](<#Further Notes>)),所以框層有命中就是卡層有命中,和標籤單獨張數同一口徑。包含、排除不影響判定。
- 其他欄:述詞除了這一欄以外的全部欄,含位置與極性。判位置的鈕時,其他欄含極性;判極性的鈕時,其他欄含位置。
- 隱藏:只看詞元。詞元的框裡(三個位置、三種極性都算)這一欄從沒出現過這個值,就隱藏。詞元有多個值時,任一個的框都算。
- 灰色:沒隱藏、沒亮、而且依上面規則沒有命中。
- 亮著的值不判隱藏與灰色,一律列出、可關;但位置與極性只剩一個亮著時,那一顆鎖住。
- 引擎提供一個純函式:給述詞與一欄,回傳「其他欄成立的框上,這一欄出現過的值」;隱藏名單用只帶詞元的述詞呼叫同一個函式。條件模型在呼叫時才讀引擎(同它讀 `Query.FIELDS` 的做法)。一次只掃詞元自己的框;框數最多的詞元是 特殊召喚 1,524 個。
- 區域三欄的值是 (玩家, 區域) 項:區域隱藏看詞元的框在這一欄有沒有這個區域(任何玩家);玩家隱藏看有沒有這個玩家(不限玩家一律列出)。灰色看 (選單上目前選的玩家或不限, 區域) 在其他欄成立的框上有沒有;玩家在其他欄下沒有任何區域命中時也灰。
- 中心詞兩欄:清單是其他欄成立的框上,這一欄出現過的中心詞,依中心詞表的順序(次數遞減),已加入的不重複列;沒有 300 個的上限。選一個詞仍照尾綴比對,所以結果至少含這個詞本身。

**條件模型的介面**

- 新增「抽屜選項」:輸入一張標籤,回傳分組(常用、進階)→ 欄 → 值與狀態。狀態四種:亮、亮且鎖住、可按、灰;隱藏的值不列,沒有值可列的欄不列,沒有欄的組不列。區域欄另回玩家清單(含狀態),以及每個玩家對應的區域清單(含狀態);中心詞欄另回候選清單。
- 切換規則:位置、極性只剩一個亮著時,關掉它不改標籤。其餘欄照舊可以關到空(空欄等於沒寫)。
- 加值不在模型擋灰色:灰色鈕在介面上不能按,模型的狀態是唯一依據。
- 極性:述詞沒有極性視同三種全亮。由網址讀入時明寫三個值;寫網址時三個全亮就不寫極性(和舊網址同義,`canon` 穩定);短句三個全亮寫「極性 不限」,預設的肯定+可能照舊不寫。
- 位置:全關不再出現;網址沒寫位置照舊是效果。上游規格「位置全關視同三個位置都看」一條作廢。

**條件列與抽屜(DOM)**

- 抽屜照「抽屜選項」畫:可按是一般鈕;灰是不能按的鈕,提示「目前條件下沒有結果」;亮且鎖住是亮著但不能按,提示「至少要留一個」。
- 區域:玩家選單列出選項清單,灰的選項不能選;區域選單依目前選的玩家列出,灰的不能選。
- 中心詞:候選清單用選項清單;Enter、離開框或點抽屜別的鈕時,字等於清單裡的某一項才加入,否則清空框、不改標籤。票 09 的「框裡有字時按下不搶焦點」保留。
- 抽屜頭、「N 張」、還原、刪除、包含/排除不變。
- 手機底部面板只差 CSS。

**文件**

- 上游規格 `.scratch/predicate-ui/spec.md` 是已交件的審核關卡,不回頭改;本規格開頭記明改掉的三條。

## Testing Decisions

- 好的測試只看接縫輸出:抽屜選項的值與狀態、切換後的標籤、hash 字串與解析結果、事件送出的標籤。不斷言 DOM 結構。
- 條件模型(先例 `conditions.test.js`,經 harness 載入真前端程式,手寫小框表):
  - 詞元沒有的值不列,欄全空不列,進階全空不列組。
  - 其他欄擋掉的值是灰;改其他欄後變可按;同欄已選一值時,本身沒命中的另一值是灰。
