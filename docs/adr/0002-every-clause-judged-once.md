# 每一條待判效果句都必須經 LLM 判定一次,規則只做影子驗證

判定[[效果類型]]時,[[官方明示]]覆蓋約 62% 的[[效果句]],其餘約 8,300 條需要 LLM 逐條判定。判定過程中會不斷歸納出新的分類規則,而這些規則理論上可以直接覆蓋尚未判定的效果句、省下將近一半的工作量。我們**不這麼做**:新規則只寫入 `rule_predicted` 影子欄位,不寫 `kind`;該行仍照常送 LLM 判定,判完當場與影子預測比對,一致則 `source` 升為 `llm_then_rule`,不一致則進衝突清單。

## Considered Options

- **規則覆蓋即跳過判定**(約 12–15 張判定票):工作量少近一半,但歸納出的規則從未被獨立驗證過——一條寫得太寬的規則會靜靜地誤標數十到數百行,而且因為那些行從未被人看過,誤標只能等使用者事後逐卡回報才會浮現。前一世代正是這個失效模式。
- **所有效果句都判定一次**(20 張判定票,採用):每條規則都有一次獨立判定作對照,規則寫錯會在下一票就炸出衝突,而不是等全部跑完。

注意本決定的對象是**歸納出的規則**,不含[[官方明示]]——官方權威資料直接採用、不送判定,這是判定量從 21,947 降到 8,335 的原因。

## Consequences

- 判定票數固定為 20,不隨規則歸納而遞減;規則的價值全部轉為「驗證既有判定」與「未來新卡的[[差值更新]]」。
- 規則層因此必須可稽核:每條規則登記於 `docs/effect_kind_rules.md`,記錄判別條件、覆蓋條數、新增票號,以及變更(過寬、衝突、合併)的理由與票號。
- 收斂條件是可機器檢查的:全表跑完一輪後規則清單無異動、每條規則覆蓋 ≥ 8 條、衝突清單為空。
