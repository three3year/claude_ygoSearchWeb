# 01: 網址不帶參數,查詢存在瀏覽紀錄

**What to build:** 搜尋後網址維持不變、不帶任何參數;上一頁、下一頁、重新整理照樣回到對應的查詢。範圍是整個查卡網站現有的條件,動作條件由票 08 接上。

- 查詢狀態(卡片條件、排序)不再寫進網址。每次搜尋在瀏覽紀錄新增一筆,狀態存在那一筆裡;上一頁、下一頁、重新整理時從那一筆還原條件並重查。
- 存在瀏覽紀錄裡的狀態可能是舊版網站寫的:認不得的欄位或值忽略,其餘照常還原。
- 網址帶著舊格式的參數時不解讀,顯示首頁,並把網址上的參數清掉。
- 把條件寫成網址、從網址讀回條件的程式與它的測試一併移除,包括修復被轉傳弄壞的連結那一段。
- 狀態的形狀要留得下之後的動作條件(票 08 會加),這張票不必先定它的內容。
- 雙擊開啟與經伺服器開啟行為相同。

- 規格:需要你決定的「Q27」;實作決策「網址與瀏覽紀錄」;使用者故事 42–46;測試決策「接縫三」與人工驗收。
- 背景:「不改網址、把狀態存在瀏覽紀錄裡」在雙擊開啟的頁面上實測可行(規格「補充說明」)。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

### 實作者(as/01)

**做了什麼**
- `web/js/hash.js` 換成 `web/js/saved.js`(`Saved.snapshot`、`Saved.restore`):存進瀏覽紀錄的是 `{ q, sort }` 的正規形;還原時認不得的欄位或值忽略(合法碼跟著按鈕走,與舊的網址解析同一套規則:兩態軸丟排除、被建置期拿掉按鈕的效果類型值視同未知碼),那一筆不是物件時還原成空條件。網址的編解碼、`canon`、修復被轉傳弄壞的連結(`MANGLED_SEP`、裸 `%` 補救)整段刪掉,測試一併換掉。
- `web/js/main.js`:搜尋與改排序時 `history.pushState(狀態, '')`(不給網址,網址不變);`popstate` 與載入時從 `history.state` 還原並重查。網址帶 `?…` 或 `#…` 時用 `replaceState` 清掉、保留那一筆的狀態。
- 狀態的形狀留給票 08:動作條件是 `{ q, sort }` 旁邊多一個鍵,舊的一筆沒有它就是沒有動作條件。

**沿用舊行為、請站主知悉的兩點**
- 改排序也新增一筆瀏覽紀錄(舊版改排序會改 `#hash`,同樣新增一筆)。上一頁會先回到改排序前。
- 條件與排序都和目前這一筆相同時再按搜尋,不新增一筆(舊版 hash 相同時也不新增)。

**自動測試**:`node --test` 113 項全過(接縫三:存進瀏覽紀錄再還原相等、舊版狀態的認不得欄位與值被忽略、空的或不是本站寫的那一筆還原成空條件、被拿掉按鈕的效果類型值被忽略、還原後引擎得到同一批卡、條件數不變);`python -X utf8 -m unittest discover -s script/web` 全過。
另用無頭 Chrome 在雙擊開啟(file://)的頁面走過一次:`#name=…&attr=dark` 打開是首頁、網址參數被清掉;兩次搜尋加一次改排序,網址不變;重新整理後條件與排序還在;上一頁、下一頁依序還原。經伺服器開啟沒有自動驗。

**站主人工驗收步驟**(雙擊 `web/index.html` 一次、經本機伺服器開一次,各走一遍)
1. 開頁,填卡名「青眼」按搜尋:網址列與搜尋前相同、沒有 `#` 或 `?`。
2. 再改條件(例如屬性選闇)按搜尋,再把排序改成攻擊力。
3. 按重新整理:條件、排序、結果都還在。
4. 按上一頁:回到第 2 步改排序前;再按上一頁回到「青眼」的條件與結果;再按一次回到空白首頁。按下一頁依序回來。
5. 在網址後面加 `#name=%E9%9D%92&attr=dark` 開啟(或打開以前存的舊連結):看到的是首頁、條件全空、網址上的參數被清掉、沒有錯誤訊息(開發者工具的 Console 沒有紅字)。
6. 沒有條件時的畫面與改版前相同。
