# Spec: 舊卡文全庫翻新(text-rewrite)

Status: ready-for-agent

2026-08-23 盤問定案機制與試點批(#01–#05 已收工、試點 49 筆已進站);2026-08-24 盤問擴充為全庫翻新(本版由票 06 寫入)。路線索引:同目錄 [map.md](map.md)(wayfinder map)。

## Problem Statement

[[文本改寫表]]進站機制與試點批已全線驗證:改寫→審查→進站→驗證→kind 補判的完整管線跑通,49 張反轉怪獸已上站。但庫裡仍有 3,756 段/3,756 張[[舊式卡文]](2026-08-24 快照),而試點版 spec 明文把「試點批以外任何群的改寫」排除在外——工程停在 49 張,沒有一份長期規格讓後續批次照表推進。

網站使用者面對的仍是:九成以上的舊卡卡文無圈號分層、句型過時,不查裁定讀不懂。

## Solution

以試點批驗證過的管線**原樣重複**,不動任何程式與機制,把改寫佇列依句型分批清到歸零:

- **分母**:三級分類報表「舊文本」級全部(清到歸零即本 feature 終點)。
- **分批**:依[[句型群]](§4.x 偵測標籤 × 卡片大類)分批,張數最多的群先;首群為「僅基礎條目(§4.1)× 怪獸」964 段。
- **進站**:句型群內依卡片密碼升冪切[[子批]],每子批 50 筆、一票、獨立 commit;流程照試點(逐行審查、全線驗證、kind 補判收尾)。

## User Stories

機制面(#01–#05 已交付,行為持續成立):

1. 作為站主,我想要文本改寫表作為審核過改寫的正式落點,新全文為本站正式卡文,讓改寫成果真正上站。
2. 作為站主,我想要每筆帶舊全文校驗、對不上即建置吵鬧失敗,讓改寫永遠不會默默套錯卡。
3. 作為站主,我想要勘誤表與改寫表同卡互斥、違反即建置失敗,讓「勘誤=內容、改寫=形式」的分工不被混淆。
4. 作為站主,我想要改寫卡獨立成「本站已改寫」級並在報表獨立成區,讓翻新進度直接可視化。
5. 作為網站使用者,我想要改寫卡有「顯示原文」整段切換,讓我查得到舊寫法。
6. 作為站主,我想要改寫進站後新①段自動切句、新句進既有判定佇列,讓效果判定管線同一套接手。

批次工作流(本次擴充):

7. 作為站主,我想要以全庫「舊文本」級為分母、清到歸零,讓翻新工程有明確終點而不是無限期的挑卡。
8. 作為站主,我想要依句型群(§4.x 標籤 × 大類)分批,讓同批共用同一組改寫規範、規範查一次套整批。
9. 作為站主,我想要張數最多的句型群先改,讓最常用的規範最早確定、後面批次越改越快。
10. 作為站主,我想要首群選「僅基礎條目(§4.1)× 怪獸」(964 段),讓最大群先動工。
11. 作為站主,我想要怪獸/魔法/陷阱大類分開成群,讓召喚條件句與發動條件句的規範差異不在同批裡互相干擾。
12. 作為站主,我想要複合標籤(一卡命中多個 §4.x)的卡自成獨立群、不併入單一標籤群,讓每群的規則集合乾淨。
13. 作為站主,我想要句型群內依卡片密碼升冪切子批、每子批 50 筆,讓每張票的範圍可預測、不重不漏。
14. 作為站主,我想要每子批一票、審查+進站合一(不再拆審查票/進站票),讓票數與交接成本減半。
15. 作為站主,我想要每子批獨立進站、獨立 commit,讓出錯時回滾範圍只有一批。
16. 作為站主,我想要子批票逐張開(前批 resolved 才開下一張),讓 tracker 不被幾十張預切票淹沒、每張票都反映當下報表現況。
17. 作為站主,我想要審查檔沿用試點完整格式(日文原文/查牌網舊譯/新文本三欄+依據條目+判斷點),讓我逐行審查的習慣與依據不變。
18. 作為站主,我想要全程逐行審查不抽樣,讓每一筆進站文本都經過人眼。
19. 作為站主,我想要首子批同時確立該句型群的規範細節、審查中長出的規範追記進[[文本格式規範]],讓同群後續子批直接沿用、越審越快。
20. 作為站主,我想要審查批改以「審查批改」commit 落檔,讓規範的成長軌跡可回溯。
21. 作為站主,我想要改寫遇到誤譯直接寫對在新文本、reason 註明,讓改寫批不必為誤譯另開勘誤票。
22. 作為站主,我想要判斷點(取對象、區域指涉、強制/任意)查得到官方佐證才改句面、查不到保守照日文原句型照譯,讓猜測永遠不進正式卡文。
23. 作為站主,我想要每子批進站後全線驗證(照試點 checklist)、kind 補判為固定收尾,讓前端索引的吵鬧失敗閘門保證沒有缺類型的效果句上站。
24. 作為站主,我想要依慣例只在我明說 commit 才提交,讓正式卡文的變更永遠經過人審。
25. 作為站主,我想要 map.md 記錄路線與決策索引,讓跨 session 的推進不必重新盤問。
26. 作為未來的改寫 agent,我想要每張子批票純照本 spec 與試點範本填表執行,讓後續批次零架構討論。
27. 作為網站使用者,我(間接)想要舊卡文逐批現代化,讓我不查裁定也能讀懂全庫任何一張卡。

## Implementation Decisions

### 機制沿用,零程式變更

進站機制(改寫表套用、兩表互斥、「本站已改寫」級、前端顯示原文、tagcard 銜接)全部沿用試點批交付的現狀,本 spec 不動任何程式、schema、前端。批次推進純粹是**資料工作**:往改寫表填經審核的筆。

### 分批策略

- 句型群與子批的定義以 `CONTEXT.md` 詞條(「句型群」「子批」)為準,不在此重述。
- 句型地圖=三級分類報表的改寫佇列分群(§4.x 標籤 × 大類),不另做掃描;每批開工前重跑報表,以當下群成員為準(map 與本 spec 的張數是 2026-08-24 快照)。
- 順序:張數最多的句型群先;群內子批依卡片密碼升冪、每子批 50 筆。
- 首群:「僅基礎條目(§4.1)× 怪獸」964 段,約 20 個子批;之後依報表當時排序接續(快照參考:§4.1×陷阱 429、§4.1×魔法 403、§4.5×怪獸 260、§4.8×怪獸 233、§4.4×怪獸 187、其餘中小群與複合標籤群)。

### 每子批一票的固定流程

改寫(faq_info 日文基底,依 §4.x→§3.x 譯寫,對照查牌網舊譯互查語意缺漏)→ 完整三欄審查檔 → 站主逐行審查、退回的迭代到放行 → 放行後寫入改寫表(`ticket` 填 `text-rewrite#NN`)→ 重建全站全線驗證 → kind 補判(新句待判清零)→ 站主明說 commit 才提交。單票走完全程,不拆審查票/進站票。

### 票務

- 票號自 #06 續編,同 feature 目錄;子批票逐張開(前批 resolved 後 create-then-wire)。
- map.md 為路線索引:已結票的 gist 進 Decisions so far,霧區(後續群)留在 Not yet specified。

### 規範成長

- 審查中長出的規範追記 `docs/text_format_guide.md`,以「審查批改」commit;首子批對其句型群負確立規範之責。
- 規範爭議走 /grilling + /domain-modeling;詞彙變動同步 `CONTEXT.md`。

### 勘誤卡遷移

既有勘誤卡日後被改寫時,勘誤筆遷出勘誤表併入改寫筆(試點 spec 已定的規則,遇到時執行,維持兩表互斥)。

## Testing Decisions

- **零新接縫**。三條既有接縫(建置套用純函式、三級分類器、前端索引建置)已由試點批的測試覆蓋,批次推進不新增測試面。
- 每子批的驗收即全線驗證 checklist(範本:試點票 05):重建逐位元組冪等、報表「本站已改寫」增量正確、pending_split 等式兩側同步縮減、前端 ow/tx 欄位抽查、五套測試全綠——把既有測試當回歸網,只測外部行為。
- 例外:若某批的規範追記動到偵測樣式(OLD_PATTERNS)或分類器,擴充對應的既有測試(prior art:`test_classify` 的同尺迴歸錨點隨佇列縮減更新)。

## Out of Scope

- 純通常怪獸 684 張與無段可判 5 張(掃描基準排除,無效果文可改)。
- 「官方已改寫」與「新格式新卡」級的譯文稽核(非舊文本翻新,另一條線)。
- 卡文勘誤表的擴充(誤譯修正另一機制;改寫卡的語意錯誤在新文本內直接修正)。
- 效果類型判定線的日常重判(每子批的 kind 補判收尾除外)。
- 前端任何變更;官方效果 Errata(效果內容修訂)議題。

## Further Notes

- 進度推估(試點比例):每 50 卡約產 50–60 條效果句,其中約 6 條需人工判 kind;審查檔約 55 KB/50 卡。
- 審查檔範本:`review-flip-monsters.md`(每卡一節、放行/退回/改判批註、退回卡同檔迭代)。
- 964 段清完後「舊文本」約剩 2,792 段;各群實際張數以屆時重跑的報表為準。
- 收尾驗收(歸零後的終局檢核、OLD_PATTERNS 與報表機制去留)在 map 霧區,接近終點再議,不屬本版 spec。
