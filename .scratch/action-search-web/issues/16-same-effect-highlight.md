# 16: 同一個效果、標出命中的效果

Status: resolved

**What to build:** 動作條件和效果類型、效果文、必發/選發一起用時,要落在同一個效果;結果裡命中的那個效果整個加底色。

- 現有的句層條件(效果文、效果類型、必發/選發)和動作條件要落在同一個效果句。這取代票 08 的「同一張卡即可」。
- 動作命中的段沒有對回效果時,在這個判斷裡當作符合。
- 引擎輸出每張卡命中的效果句;結果畫面用現有標出命中效果句的方式加底色。動作條件不標到字。
- 命中的段對不回效果的卡照樣列出,只是不標。
- 經引用的命中算在引用節點所在的效果上(票 14 做完後才有;兩張票後做的那張把這個接上)。
- 無法確認的卡不做同一效果的判斷。

- 規格:需要你決定的「Q25」「Q26」;實作決策「效果對應」「前端查詢引擎」「玩家介面」;使用者故事 3、4、5、34;測試決策「接縫三」。
- 參考:原型只做到同一張卡、不標命中的效果,這兩點都與原型不同。

## Comments

### 實作者(as/16)

**做了什麼**
- `web/js/action.js`:`Action.prepare` 多讀卡那一行的第 6 格「效果」(票 07),每段多一個 `clause`(效果句序號;對不回或舊產物沒有這格是 null)。`Action.match` 不變,回的段帶著 `clause`。
- `web/js/engine.js`(`runQuery`):
  - 有句層條件(效果文、效果類型、必發/選發)又有動作條件時,`clauseRows` 命中的效果句再和動作命中的段的 `clause` 取交集(`sameClause`);交集是空的就不命中。動作命中的段裡有一段對不回效果(null)時當作符合:卡照樣命中,但那一段不標,`rows` 只留真的對得上的句(可能是 `[]`)。句層條件本身一句都沒命中時照樣不命中。
  - 只有動作條件時,`rows` 是動作命中的段對回的效果句(`hitClauses`,去重、照序號排;對不回的段不算,所以可能是 `[]`)。
  - 有動作條件時 `marks` 多一個 `{ type: 'action' }`。沒有動作條件時 `marks`、`rows` 與票 08 相同(`rows` 只在有句層條件時才有)。
- `web/js/render.js`:`MARK_ZH` 多 `action: () => ''`。命中的效果句沿用現有的 `.eff.hit` 底色;動作條件不加標籤、不標到字。和效果文一起用時,效果文的字照舊標(`<mark>`),效果類型/必發選發的標籤照舊。
- 接縫三夾具 `script/web/action_fixture.js`:段的描述多 `clause`(省略是 null),寫進卡那一行的第 6 格。

**實作者自己定的小事(請站主知悉)**
- 卡同時有對得上的段與對不回的段:句層條件命中的句裡,只標「動作也對得上」的那幾句;對不回的段不讓別的句被標。例:效果文「對手」命中 ① ②,動作只對回 ②、另有一段對不回 → 卡命中,只標 ②。
- 只靠對不回的段命中的卡,一句都不標(故事 34 的「照樣列出,只是不標」),即使效果文本身命中了某幾句。若站主想讓這種卡至少標出效果文命中的句,改 `sameClause` 一行即可。

**經引用(票 14)**:合併整合分支時票 14 還沒進來,這張票沒有接。接法:經引用的命中由 `Action.match` 回進同一個 `Map(卡號 → 段)` 時,把引用列的第 5 格(引用節點所在的效果句,`decode_action_index` 的 `clause`)放進那筆的 `clause`;`sameClause`/`hitClauses` 只看 `clause`,不用再改。

**「兩邊答案一致」**:這張票不改「只有動作條件」時命中的卡,只在同時有句層條件時收窄,並多輸出命中的效果句。`test_web_parity.py` 的查詢都只有動作條件、沒有句層條件(Python 的 `run_query` 沒有效果文、效果類型、必發/選發這些條件),所以同一個效果的判斷不在那組測試的範圍內,由接縫三的 `same_effect.test.js` 守。

**無法確認的卡(票 15)**:這張票只動動作命中的卡;票 15 把未解析組放進結果時不要走 `sameClause`(句層條件照現有的 `clauseRows` 判)。
