# cdb 位元 → 值域的轉換只住在建置期,按鈕由值域生成

[[卡片總表]]存的是 cdb 的原始位元與整數:`type: 65538`、`race: 0`、`attribute: 0`、
`link_marker`、`setcode`。要做搜尋介面,就得有東西把它翻成「速攻魔法」「暗」「龍族」,
而這份對照表要住在哪裡,決定了一個特定的失效模式會不會發生。

## 失效模式長什麼樣

**值域漏一個碼,某批卡就從搜尋結果無聲消失。** 不報錯、不白屏、不進任何 log——只是
結果少了幾百張,而使用者不知道自己少看到了什麼。這不是假想:oldProject 的 ADR-0015
記著一個病歷,漏抄一個碼讓 **29 個效果無聲消失**。

同一份專案的 `CONTEXT.md` 還記了另一個同族的錯:「分類的定型句一度同時住在擷取層與
分類層,註記『兩處同步維護』」。**手抄兩份、註記同步維護,就是漂移的預定路線。**

## 三種擺法

**執行期 JS 解位元。** [[前端索引]]存原始位元,前端自持解碼表與中文表。索引更小一點,
改中文名不必重生。代價是前端得懂 cdb,而且值域是**手寫**的——它與資料的實際內容之間
沒有任何東西在對帳,漏一個碼不會有東西發現。這正是上面那個病歷的形狀。

**兩邊各一份。** Python 管建置、JS 管顯示。明確不採用,理由見上:專案自己的前身已經
記下這種錯一次。

**建置期 Python 正典(採用)。** 單一來源產出兩樣東西:cdb 位元/整數 → 短碼的解碼表,
與短碼 → 中文 + 宣告序的對照表。建置時把卡片解成短碼寫進索引,同時把值域與中文表輸出成
`window.VOCAB`。**HTML 不寫死任何選項,按鈕由 JS 依 VOCAB 生成。**

## 為什麼「按鈕由值域生成」是這個決定的一半,而不是額外的講究

如果值域住在建置期、按鈕卻寫死在 HTML,那還是兩份。新增一個種族時 VOCAB 有、HTML 沒有,
那個種族的卡就搜不到——**失效模式一模一樣,只是換了個地方發生**。所以「正典住建置期」與
「按鈕由正典生成」必須一起成立,少一半就不成立。

同一份宣告序還有第二個用途:**領域序排序的比較序**。大類序、[[卡片子類型]]序、屬性序、
種族序,四層比較用的都是 VOCAB 的宣告順序。oldProject 的 `RACES = VOCAB.race.map(e => e.zh)`
旁邊註著「與宣告序同一份」,就是這個做法。第三抄(排序表)因此也不存在。

## Consequences

- **建置期擋得住漏碼。** 索引裡出現任何 VOCAB 沒有的值即建置失敗(不是警告)。這是本 ADR
  的整個重點——把一個沉默的失效模式換成一個吵鬧的失效模式。
- **值域正典需要自己的測試接縫。** `build_index` 吃的永遠是 repo 裡那一份正典,所以它測
  不到「換一份壞的進來會怎樣」:重複短碼、缺中文、宣告序有空洞、位元對應重疊。正典因此
  自成一個接縫(`vocab.problems()` / `vocab.digest()`)。這與 `tag_card` 把 `rules` 自檢
  獨立出來是同構的,理由也是同一句話。
- **效果句層級的值也存短碼。** [[效果類型]]、`role`、[[必發/選發]]同樣走 VOCAB。32,637 個
  效果句各存一次中文字串是無謂的重複,而且短碼讓漏碼撞得到建置期的檢查。
- **改中文名要重生索引。** 這是採用建置期方案的實際代價。可接受:值域的中文名幾乎不動,
  而重生索引本來就是一個指令。
- **[[卡片子類型]]與[[卡片種類]]是兩套值域,不可互用。** 前者 23 個 cdb 位元(含融合/同調/
  超量/連結/調整/反轉這些怪獸細分),服務搜尋;後者十值、怪獸不細分,服務[[效果類型]]的
  判定([[魔陷卡效果]]的值就是它的名字)。兩個詞長得幾乎一樣,拿錯的後果是怪獸只剩一顆
  按鈕。辨析寫在 `CONTEXT.md`。
- **cdb 有值不代表卡片有那個參數,而這件事該在來源層解決。** 79 張魔陷卡(罠モンスター)
  在 cdb 裡帶著完整的種族/屬性/等級/攻守,但那是**它變成怪獸之後**的數值,寫在效果文的
  括號裡(「此卡變成通常怪獸(水族、水、等級2、攻1200/守0)」),不是印在卡面上的欄位。
  **正典的職責是把位元翻成值域,不是判斷哪個欄位算不算卡片參數**——解碼與語意是兩件事,
  這一條是它們的分界。語意那一側歸[[卡片總表]](card-list 票 07:大類非怪獸即清空這些
  欄位,與既有的「連結怪獸沒有守備欄」同一條原則),索引這一側只留一道不變式斷言:
  「大類是怪獸 ⟺ 有種族與屬性」雙向成立,否則建置失敗。
  過濾若放在消費層,每個消費者都得各自記得過濾一次,而漏掉的後果是無聲的錯誤結果。
