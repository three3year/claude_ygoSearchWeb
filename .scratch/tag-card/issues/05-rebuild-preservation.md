# 05 — 重跑保留語意

**What to build:** [[效果標記表]]變成真正可以手工維護的來源檔(見 ADR-0001)。使用者可以直接打開檔案改一行判定、標成 `manual`,之後任何一次重跑都不會把它改回去;而當卡文勘誤或拆句法變動導致某一行的身分改變時,系統會標記待複查而不是靜靜覆蓋掉使用者的修正。

**Blocked by:** 02 — 拆句骨架

**Status:** ready-for-agent

- [ ] 接縫的 `既有標記表` 參數生效:重跑時以 `(卡片密碼, section, index)` 為鍵對應既有行
- [ ] `source: "manual"` 的行永不被覆蓋,需有測試
- [ ] `source: "official"` 的行永不被覆蓋,需有測試
- [ ] `text_hash` 相同時沿用既有行的全部判定與來源標記,不重算
- [ ] `text_hash` 變動時**不覆蓋**,標記為待複查並列進報告
- [ ] `source: "llm"` 且雜湊未變者不重算;只有雜湊變動或本來就是 `null` 的才會被重新處理
- [ ] **遲到的官方明示**:既有行為 `source: "llm"` 或 `"llm_then_rule"`,而來源資料新增了該行的[[官方明示]]時,不沿用而是比對——一致則 `source` 升為 `"official"`;不一致則**保留原判定**並列進衝突清單。此情境會在補足情報更新時發生(官方會替舊卡補寫、新卡的 Q&A 頁面也會陸續出現),需有測試
- [ ] 首次建置(無既有標記表)與重跑(有既有標記表)走同一條路徑,不是兩套邏輯
- [ ] 端到端可驗證場景:手動把一行改成別的類型並標 `manual` → 重跑 → 該行不變;修改來源卡文使雜湊改變 → 重跑 → 該行標記待複查且原判定保留
- [ ] 報告列出待複查清單與各 `source` 值的筆數
