# 14 — 自動展開連動與網址還原

**What to build:** 摺疊區塊在三個時機**自動展開**,讓連動出現或還原出來的條件不躲在
收起的標題後面:

1. [[大類]]點選 → 對應子類組出現**且自動展開**(點了怪獸就是要篩子類,省一次點擊)
2. 效果類型的承載使[[必發/選發]]軸出現 → 該軸自動展開;承載消失照舊隱藏並清空
3. 開啟帶條件的分享網址 → 所有**有已選條件的軸**自動展開(含連動出現者),
   收到連結的人一眼看到這個查詢設了什麼

「還原網址時哪些軸該展開」抽成 Query 純規則(`查詢條件 → 該展開的軸集合`),與
`optionalAvailable` 同一個模式:規則是純的所以沙箱測得到,DOM 那層只照答案開。

## Comments

2026-08-17 實作完成(與票12、13 同一輪)。「還原展開判定」為純函式
`Query.expandedAxes(q)`:已選條件的軸(逐軸已選數 > 0)+ 大類選取帶出的子類組
+ 承載的效果類型帶出的必發/選發。承載判斷與 `optionalAvailable` 共用同一份
`VOCAB.optional.carriers` 宣告,但兩者答的問題不同(出不出得來 vs 要不要展開):
一顆效果類型都沒選時必發/選發**出得來但不自動展開**——預設可見不代表連動出現。

互動側的自動展開走 `showAxis` 的**轉換判定**:只在 hidden↔visible 轉換時動作,
連動出現才展開;點另一顆大類鈕重跑 syncSubs 時,已可見的子類組不會把使用者剛
手動收起的又彈開。`write()`(網址還原)最後照 `expandedAxes(read())` 統一開合——
吃 read() 而不是傳入的 q,因為過期的段(有子類型沒大類)已在寫回時被丟掉。
接縫 3 測試 +3 條。展開的 DOM 動作走人工驗收。
