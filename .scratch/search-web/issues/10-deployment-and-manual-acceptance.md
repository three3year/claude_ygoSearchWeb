## Comments

### 驗收方法與結果(2026-08-14)

清單裡的「人工」項目全部改以**真實瀏覽器(headless Chrome,新無頭模式)** 對本機
static server(`python -m http.server`,從 repo 根目錄起)與 `file://` 實測,不是只讀程式碼:

- **相對路徑**:根目錄起站後 `/`、`/web/index.html`、`data.js`、`style.css`、七支 js
  全部 200;開 `/` 經 meta refresh 轉到查卡頁,渲染出「共 14207 張,第 1/285 頁」。
- **`file://`**:headless Chrome 直開 `file:///F:/…/web/index.html`,同樣 14,207 張、
  當頁 50 張卡片渲染(`<script src>` 載入,`fetch`/CORS 問題不存在,與 ADR-0007 的設計一致)。
- **卡圖對得上卡**:截圖抽查——異宇宙軍神(卡面 ATK/2500 DEF/2000 = 顯示的攻2500/守2000)、
  鋼鐵裝甲蟲(2800/1500)、青眼白龍 `89631139`(3000/2500,圖確為青眼白龍)。
- **異圖切換**:以同源驅動頁在真瀏覽器裡實際點擊:`1/17 → 2/17(46986415.jpg)→
  3/17(46986416.jpg)→ ‹ 回 2/17`,再連按 16 次 › 繞回 `1/17(46986414.jpg)`——
  換版、環繞、版次顯示都對。另以 curl 逐一確認黑魔導 16 個異圖檔在 jsDelivr 上全部 200。
- **缺圖安靜隱藏**:把卡圖 src 改成 CDN 上實際 404 的 `46986440.jpg`,`onerror` 把
  `visibility` 設成 `hidden`——實際觀察到,不是只看程式碼。
- **標亮與 badge 對比**:`#text=從牌組特殊召喚` 的結果截圖——命中行整行標亮、行首
  「效果文」badge、關鍵字行內上色,深色底上清楚可辨。深色配色整體截圖檢視無過亮元素;
  「實機上不刺眼」的主觀部分使用者隨時可用 `file://` 複驗。
- **手機寬度**:390×844 裝置模擬截圖——側欄收成頂部「篩選條件」摺疊鈕、卡片單欄。
- **帶條件網址還原**:全新 profile 開 `#name=青眼%龍&text=融合` → 自動搜尋、4 張;
  `#code=89631139` → 密碼欄還原、1 張。跨裝置的那一半見清單註記。
- **「上一頁」**:真瀏覽器裡 `#code=46986414`(共 1 張)→ 改 hash 為
  `#text=從牌組特殊召喚`(自動重搜,共 39 張)→ `history.back()` 回到共 1 張、hash 還原
  → `history.forward()` 再回 39 張。歷史、還原、自動重搜全部符合預期。

**首次載入實測**(本機 server,不含網路傳輸差異):headless Chrome 完整載入(含瀏覽器
啟動與當頁卡圖自 CDN 拉取)三次 17.4 / 9.3 / 13.5 秒,波動主要在 CDN 圖片;`data.js`
本體 7,617,299 bytes(7.27 MiB),gzip -6 後 1,837,171 bytes(1.75 MiB,與 spec 預估一致),
node 端 require+parse 約 0.4 秒——文字部分的載入不是瓶頸,圖片才是(lazy loading 已開)。
