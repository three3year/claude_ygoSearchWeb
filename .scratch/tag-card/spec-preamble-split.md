# Spec: 前言段以日文換行拆句(引用跨行合併)

Status: ready-for-agent
Parent: ADR-0009、票64(本 spec 由票64 的 grilling 共識展開)

## Problem Statement

使用者回報 70488851:中文前言「此卡不能通常召喚。只能…特殊召喚。這個卡名的①怪獸效果1回合只能使用1次。」在[[效果標記表]]裡合成單一 `"0"` 效果句、role 只記「召喚條件」,但日文官方卡文是三行、官方 Q&A 也把次數限制與召喚條件分開裁定——它們不是同一個句子。

全表掃描確認這不是個案:7,968 段有日文的前言中,1,525 段日文是多行的,今天**全部**被合成一句、只帶一個 role;其中 262 段中文行數少於日文(中文來源 salix5 cdb 缺換行),約百張卡的使用次數限制被記在別的 role 底下。role 是搜尋條件的依據——「哪些卡有召喚條件」「哪些卡有使用次數限制」目前對這批卡給出錯資料。

## Solution

前言段(第一個效果編號之前)以**日文官方換行**為拆點拆成多個[[效果外文本]]效果句;[[補足情報]]的 `『…』` 引用跨行時,被括住的那幾行合為一句(官方視為一體的單位不切開)。中文側以「自身換行 + 句號」切成單位後按日文各行的單位數依序分組。拆分是建置期機械規則、每次重跑現場重算,不新增來源檔;對不上的段落維持現狀不拆、列入報告。決策取捨全文見 ADR-0009。

## User Stories

1. As a 使用者, I want 前言段依日文官方換行拆成多個效果外文本效果句, so that 召喚條件與使用次數限制不再被合成同一句。
2. As a 網站查詢層, I want 拆出的每個前言句各自帶 role(素材指定/召喚條件/使用次數限制), so that 以 role 為條件的查詢對這 1,525 張卡給出正確結果。
3. As a 使用者, I want 補足情報『…』引用跨行時合併被括住的那幾行, so that 官方逐項裁定視為一體的單位(如 70488851 的兩行召喚條件)不會被切成官方沒有認可的兩句。
4. As a 使用者, I want 無補足情報的卡退回純換行拆分, so that 沒有引用可驗的卡仍享有拆分,不因缺資料而整批擱置。
5. As a 使用者, I want 中文側以自身換行與句號切成單位、按日文各行單位數依序分組, so that 中文缺換行的 262 段也能找到對應拆點。
6. As a 使用者, I want 無句號的素材行(名詞片語)算一個對位單位, so that 素材指定行不會讓兩側單位數對不上。
7. As a 使用者, I want 單位數對不上、或任何引用會被拆點切開時,整段維持現狀不拆並列入報告, so that 機械規則絕不猜測,錯誤配對不會靜靜寫進資料。
8. As a 使用者, I want 拆出的段以 `0-1`、`0-2`…照日文行序編鍵、沒拆的維持 `"0"`, so that 6,443 段單行前言的鍵與 diff 完全不動。
9. As a 使用者, I want 每段都是中文原文的連續子字串、兩側串接可無遺漏蓋回原文, so that 拆句不可能悄悄改寫或漏掉卡文。
10. As a 使用者, I want 前言各段 kind 固定為效果外文本、source 為 rule, so that 與既有前言判定慣例一致,官方明示照常在其後覆蓋升級。
11. As a 使用者, I want 效果外文本的官方明示落到引用命中的那個細段, so that 歸屬因拆句變準;引用合併保證引用永不橫跨段界。
12. As a 判定執行者, I want 遮蔽測試樣本的 preamble 欄位收齊該卡同 section 的全部前言列, so that 拆過的卡不會拿到空前言而重演票62 的誤判。
13. As a 使用者, I want 無日文的前言(14 段)維持現狀, so that 繁中單側卡(ADR-0006)不受影響。
14. As a 使用者, I want 編號句(①②…)內部的 130 句換行差異只列一次性資訊清單、不動資料, so that 純排版差異不會變成資料變動,也不會悄悄消失於視野。
15. As a 使用者, I want 全表重跑後報告拆分段數、退回筆數與 role 分布變化, so that 驗收有數字可對(預期 ~1,500 段拆出 ~3,000+ 列、使用次數限制列數明顯上升)。
16. As a 使用者, I want 「效果外明示不在前言段」報告筆數不因本次變動上升, so that 拆句沒有讓官方明示歸屬變差。
17. As a 使用者, I want 前端索引隨拆分重建, so that 網站查詢層讀到細分後的前言句。
18. As a 使用者, I want 新卡在差值更新時自動適用同一套拆分, so that 不需要為新卡補任何人工紀錄。
19. As a 使用者, I want 從中文行數少於日文的 262 段抽查 10 段人工核對分組, so that 句序調換造成的沉默錯配有人工防線(ADR-0009 已知限制)。
20. As a 使用者, I want 拆分規則對 1,525 段全體適用而非只限行數不一致那批, so that 譯者有沒有換行這個排版差異不決定一張卡的前言是幾句。
21. As a 使用者, I want 拆不了而退回的段落清單帶兩側原文, so that 人工兜底(必要時動用拆句表)有完整素材可判。

## Implementation Decisions

- **拆點權威**:日文換行為預設拆點;補足情報 `『…』` 引用(含 `【『…』について】` 標頭引用,經既有的正規化比對)跨行時合併。與拆句表的「引用交叉驗證」同一原則。「先判 role 再合併同 role」方案被否決——那是拿推論蓋官方訊號(ADR-0009)。
- **機制**:建置期機械規則,住在拆句骨架的前言處理裡;**不是**拆句表來源檔。ADR-0003 的「無法由卡文重算」立論不適用——本拆點可重算,存檔反而製造會過期的複本。拆句表保留為人工兜底容器,本 spec 不擴充它。
- **中文對位演算法**:中文以自身換行與句號切成單位(無句號的行塊算一單位);日文每行的單位數 = 句號數(無句號行算 1);兩側總數相等時依序分組,否則整段退回不拆。分組假設中日句序一致——句序調換且句數恰好相等時會錯配且不報錯,已接受(拆句表全語料實測重排率 0.75%,票51),防線是抽查。
- **鍵**:拆出的段 `0-1`、`0-2`…照日文行序;沒拆的維持 `"0"`。歸屬模組的 `_is_preamble` 已認得 `0-` 前綴,不需改歸屬邏輯;撞名尾碼不可能落在前言,不相撞。
- **判定欄位**:各段 kind 效果外文本、role 逐段由既有前言 role 規則重算、source rule。已查核前言列現況 source 只有 rule(6,620)與 official(1,418)、零 manual、零 tags、optional 全空——兩者皆每次重跑重算,拆開不丟失任何人工成果,不需要遷移。
- **報告**:新增退回清單(id/section/兩側原文)與拆分統計;編號句換行差異列一次性資訊節。
- **下游**:遮蔽測試樣本建構的 preamble 收集從「index 精確等於 0」改為收集全部前言列依序串接;前端索引照常由建置重生。

## Testing Decisions

- 好測試只斷言**外部行為**:餵合成卡片與補足情報進拆句骨架的頂層純函式,斷言輸出效果句列(index/兩側文字/kind/role/source)與報告鍵;不測內部輔助函式。
- **主接縫(既有)**:拆句骨架頂層純函式。先例:既有測試檔的 TestPreamble(前言)、TestNonEffectAttestation(效果外明示歸屬)。新增場景:純換行拆分、引用跨行合併(70488851 形態)、素材行對位(2133971 形態)、中日行數一致用中文換行、單位數不合退回並報告、明示落到正確細段。
- **次接縫(既有)**:遮蔽測試樣本建構。先例:既有的樣本欄位測試。新增:拆過的卡 preamble 欄位收齊全部前言列。
- **全表層級不寫單元測試**:拆分段數、role 分布、substring 違規 0、明示歸屬報告不升,走建置報告數字 + 人工抽查 10 段,與票09/票10 驗收慣例相同。

## Out of Scope

- 動[[卡片總表]]的卡文本體(中文 desc 不補換行——cards.json 照抄來源的底線不破)。
- 編號句內部換行的顯示對齊(純排版,僅資訊清單)。
- 拆句表擴充到前言段(僅為日後人工兜底的既有容器,本次不動它的結構)。
- 17350692(無日文且多句的唯一一段)的人工處理。
- 前言各段的效果 Tag(分類表定稿後另案)。

## Further Notes

- 有無補足情報會影響拆法(引用合併只在有補足情報時發生),同文卡可能拆法不同——已接受,與既有 confidence 階梯同一種不對稱(ADR-0009)。
- 票64 是本 spec 的父票,其驗收清單由拆票後的子票承接。
