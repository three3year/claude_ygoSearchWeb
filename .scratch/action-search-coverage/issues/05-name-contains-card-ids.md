# 05: 卡名包含先換成卡片編號(中日英名、別名、`%`)

Status: resolved

**What to build:** 動作搜尋給條件的卡名包含,Python 的玩家查詢與網站都先把打的字換成一組卡片編號,被動作的卡在這組裡就命中(滿足條件的卡與這條線的候選卡有交集)。一張卡的名字是中文名、日文名、英文名、別名(中文卡文「※ 別名」,與前端索引同一個抽法)。比法:打的字先去頭尾空白,打的字與名字都做網站現在的折疊(全形英數與全形空白當半形、小寫),以 `%` 切段、去掉空段,各段依序出現在名字裡就算;沒有非空的段時等於沒給。效果:中文「黑魔導」Python 0 → 1,259 張,與網站相同。

- 卡文裡的「カード名に「X」を含む」(卡片結構條件式的卡名包含原子,判候選卡用)照舊只比日文、含位置條件;只有查詢側換。
- 介面不變(沒有語言切換鈕);網站多的是 `%`。
- 這張票不含「〜として扱う」當作的卡名(06)。
- 規格:需要你決定的「卡名包含要比哪些名字」「Q10」「Q12」「Q13」;實作決策「卡名包含換成卡片編號」;使用者故事 22–25、28–32;測試決策「Python 的 `run_query`」「兩邊答案一致」。

實作者(2026-11-24):

**做法**
- Python:新模組 `script/action_structure/query_names.py`。`run_query` 收到查詢時先把只有空白或 `%` 的卡名包含從頂層與「且」拿掉(拿光了等於沒給 condition,`row_match._normalise`);比對前 `resolve_names` 把卡名包含原子換成查詢側專用的「卡號屬於」原子(卡號集合),`eval_condition` 只多一支判「這張卡的卡號在集合裡」。卡文的條件式裡沒有這個原子,卡文的「カード名に「X」を含む」照舊走原來那支,只比日文。
- 別名沿用前端索引同一個函式:`webindex._split_alias` 改名成公開的 `split_alias`(只改名,行為不變)。
- 網站:`web/js/action.js` 的 `fitsCondition` 卡名包含那支改用 `nameParts`(去頭尾空白、折疊、以 `%` 切段去空段)與 `cardNames`(中日英名與別名);`givenOf` 在沒有非空段時不收 name(原本只擋全空白)。
- 票 06 加當作的卡名時,Python 在 `CardNames` 建構時把那類名字併進同一張卡,網站在 `cardNames` 加。

**請站主留意**
1. 全形 `％` 也當萬用字元:規格的順序是先折疊再切段,全形 `％` 折成 `%`。主搜尋的卡名框(`Engine.likeParts`)不折疊,全形 `％` 在那裡是字面。兩個框在這一點不同;要一致的話是改主搜尋,不在這張票。
2. 只有空白或 `%` 的卡名包含只從頂層與「且」拿掉。網站只會送這兩種形狀;直接呼叫 `run_query` 時,放在「或」「非」裡的空卡名包含當作每張卡都符合。
3. Python 每次查詢有卡名包含時重收一次全庫名字,全庫約 0.17 秒;條件遮罩本來就有快取,查詢次數少,沒再加快取。
