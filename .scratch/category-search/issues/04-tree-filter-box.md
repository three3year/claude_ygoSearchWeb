# 04: 過濾框

**What to build:** 牌手在動作類別軸頂端的過濾框輸入日文字面(例:墓地),樹只留名稱含它的節點與其祖先,方便在 235 個葉裡找;清空回原狀,過濾不改已選條件。來源:spec「側欄(query)」。

**Blocked by:** 02

**Status:** resolved

- [x] 過濾框比對節點的日文名稱(子字串),只顯示命中節點與其祖先,祖先自動展開;命中的上層節點底下的子節點照常可展開。
- [x] 清空過濾框時樹回到過濾前的展開狀態;已選節點不因被過濾隱藏而取消,標題已選數不變。
- [x] 手機寬度可用。
- [x] 人工驗收(同現有側欄):輸入 墓地、破壊、→手札 各一次確認結果合理。

## Comments

2026-10-30 實作(/implement):

- 「留哪些節點、展開哪些祖先」是純函式 `Acat.filter(字面)`:名稱含字面的節點連同祖先與子孫留下,祖先強制展開,命中節點與子孫照原展開狀態;空字面回 null。harness 多 `acatFilter`,接縫測試 3 條(祖先展開、命中上層節點的子節點留著、詞元名也命中預設葉/空字面不過濾)。
- 側欄套用(`query.js`):開始過濾前記下各節點展開狀態,每次換字面從那份狀態重套,清空時還原;已選節點被藏起來照樣生效、標題已選數不變;清除條件與網址還原會清空過濾框。手機寬度輸入框 16px(避免 iOS 聚焦放大)。
- 人工驗收(node 經 CDP 驅動 headless Chrome,實際點擊與輸入):過濾「墓地」可見 33 個節點(召喚 › 特殊召喚 › 特殊召喚←墓地、區域移動 › ←デッキ › 送る:デッキ→墓地、←墓地 底下五葉…),「破壊」16 個(破壊 底下全部,含預設葉),「→手札」15 個(各來源的 加える:X→手札);清空後回到 13 個頂層節點、展開狀態還原、已選數仍 2。手機寬度(390px)scrollWidth = 390,樹可展開、可點選。
