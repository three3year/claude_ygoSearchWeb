# Spec: 動作類別搜尋——類別樹上網站搜尋

Status: ready-for-agent
Date: 2026-10-30

上游是動作類別線(`.scratch/action-categories/`,票 01〜09)與它之後的框架線修正:類別樹 235 葉、13 個頂層節點,全語料 46,732 個動作框架已歸 30,112。類別線規格把「網站搜尋介面、前端索引、值域正典的任何改動」列為 Out of Scope,卡層彙總只先為搜尋設計格式;站主驗收翻卡時覺得要修的還很多,決定先把類別接上網站、看到搜尋的樣子再回頭修類別。本規格是 2026-10-30 /grill-with-docs 的定案;GLOSSARY.md「軸」(動作類別軸內 AND 的例外)與「動作類別」(搜尋語意)兩個詞條已於 grill 時更新,資料流另立 ADR-0017(網站搜尋讀分詞鏈匯出的類別檔,分詞程式仍留在試點目錄)。

- (a)網站內可搜的預覽版:改網站本體但先不 push。
- (b)拋棄式原型 artifact:只試介面形狀,不和現有條件軸一起用。
- (c)直接做上線版。

### 沒有類別的卡怎麼處理?

決定(2026-10-30):(a)不命中,軸標題寫明涵蓋範圍。

- (a)不命中+寫明涵蓋範圍(建議):選了類別條件時舊式卡文的卡一律不中,軸標題寫「涵蓋 N / 全部 張」。
- (b)不命中、不提示。
- (c)先把舊卡補上類別再做。

### 類別條件命中的單位?

決定(2026-10-30):(b)句層——與效果類型、必發/選發、效果文同屬句層條件,逐標記句比對。

- (a)卡層:卡上任一句有這個葉就算。
- (b)句層(與效果類型、效果文同句)。
- (c)兩種都做、可切換。

### 條件區的形狀?

決定(2026-10-30):(a)可展開樹+三態鈕+過濾框;節點顯示日文原名、不標卡數,放在效果類型、必發/選發旁、預設摺疊。

- (a)可展開樹+三態鈕+過濾框(建議)。
- (b)只有過濾框+選中的葉列成標籤。
- (c)只開放大類與詞元兩層。

### 代價位算不算命中?

決定(2026-10-30):(a)預設只看效果位,軸內「含代價」勾選打開時代價位也算。

- (a)預設只效果位+「含代價」勾選(建議)。
- (b)只效果位,不給勾選。
- (c)代價與效果分兩組三態。

### 類別軸內多選怎麼組合?

決定(2026-10-30):(b)軸內 AND——每個選中的節點各自要有一句帶它,可以是不同句,每一句命中句都要符合句層條件;排除是卡層。這是 GLOSSARY「軸」的例外。

- (a)軸內 OR,照既有軸語意。
- (b)軸內 AND。
- (c)加一個 OR/AND 切換。

### 結果清單怎麼顯示類別?

決定(2026-10-30):(b)每句標記句尾都列它全部的葉(不論有沒有搜類別),代價位的葉另色、命中的葉強調。

- (a)只在命中句掛命中的葉。
- (b)每句都列出全部的葉。
- (c)不顯示類別,只高亮句子。

### 卡片資料更新後類別檔過時怎麼辦?

決定(2026-10-30):(a)匯出檔每句記原文雜湊,索引建置對不上就失敗;差值更新流程加一步重跑分詞鏈。

- (a)記雜湊,對不上就報錯+更新流程加重跑(建議)。
- (b)記雜湊,對不上的句子當沒類別、只警告。
- (c)不檢查。

## Problem Statement

查卡網站目前只能用卡名、效果文字面與卡面參數(屬性、種族、等級、效果類型、必發/選發…)找卡。牌手真正想找的是「做什麼」——從墓地特殊召喚、從牌組加入手牌、破壞對手場上的卡——只能靠在效果文框裡猜字面,而卡文寫法變化多,猜不全。

動作類別線已經把新格式新卡的每個動作框架歸到一棵類別樹的葉上,但它只活在試點目錄與檢視 artifact 裡:網站搜不到它,站主也就看不到「拿類別找卡」實際是什麼手感、哪些葉在真實搜尋裡讀起來不對。上一次的效果 Tag 搜尋(2026-10-01 撤出)的教訓是指標全綠卻沒用;這一次站主要先在網站上真的用類別搜過,再決定類別要怎麼修。

## Solution

網站側欄在效果類型、必發/選發旁多一個條件軸「動作類別」:一棵可展開的類別樹(大類 › 中類 › 詞元 › 葉),每個節點是三態鈕(包含/排除),頂端有「含代價」勾選與過濾框。選中的節點都要命中(AND),每個節點各自在卡上找一句帶它的標記句,而那一句要同時符合使用者選的效果類型、必發/選發與效果文;排除則是卡上任何一句帶它就整張不要。軸標題寫明只涵蓋新格式新卡(張數)與已選數。

結果清單裡每一句標記句尾列出它全部的葉:代價位的葉另色,這次搜尋命中的葉強調。選的節點寫進網址,分享網址就能重現搜尋。

資料面,分詞鏈多匯出一份入版控的類別檔(每句標記句的效果位葉、代價位葉、原文雜湊與類別樹),網站索引建置讀它;原文雜湊對不上或葉不在樹裡就建置失敗,不讓過時或對不上的類別靜默上線(ADR-0017)。

## User Stories

1. 身為牌手,我想在側欄找到「動作類別」條件,以便用「這張卡做什麼」找卡,而不是猜效果文字面。
2. 身為牌手,我想把類別樹依大類 › 中類 › 詞元 › 葉一層層展開,以便從粗到細找到我要的動作。
3. 身為牌手,我想點選一個上層節點(例:區域移動 › ←墓地),以便一次找出底下任一葉的卡,不必逐葉點。
4. 身為牌手,我想點選一個葉(例:特殊召喚←墓地),以便只找從墓地特殊召喚的卡。
5. 身為牌手,我想再點一下同一個節點變成排除、第三下取消,以便和其他三態軸一樣操作。
6. 身為牌手,我想同時選兩個節點(例:破壊 與 特殊召喚←墓地)時找出兩個都做的卡,以便縮小到「既破壞又蘇生」的卡。
7. 身為牌手,我想讓兩個選中的節點可以落在同一張卡的不同效果(①破壞、②蘇生),以便找到分在不同效果裡做這兩件事的卡。
8. 身為牌手,我想在選了效果類型(例:誘發效果)時,類別的命中句也必須是誘發效果,以便找到「誘發效果破壞」而不是「啟動效果破壞、另有誘發效果」的卡。
9. 身為牌手,我想在選了必發/選發時,類別的命中句也必須符合,以便類別與必發/選發是同一句的事。
10. 身為牌手,我想在效果文框也有字時,類別的命中句也必須含那段字,以便用字面再過濾同一句。
11. 身為牌手,我想排除一個節點(例:破壊)時,卡上任何一句帶它就整張不出現,以便「不要會破壞的卡」真的看不到會破壞的卡。
12. 身為牌手,我想預設只比效果位的動作,以便「丟一張手牌當費用」的卡不會出現在「丟牌」的搜尋裡。
13. 身為牌手,我想勾「含代價」時代價位的動作也算命中,以便找「有丟牌費用」或「要解放當費用」的卡。
14. 身為牌手,我想勾了「含代價」時排除也一併看代價位,以便排除的範圍和包含一致。
15. 身為牌手,我想在軸標題看到「涵蓋 N / 全部 張」,以便知道舊式卡文的卡不在類別搜尋範圍裡、不會以為搜全了。
16. 身為牌手,我想在軸標題看到已選幾個節點,以便摺疊時也知道類別條件仍在生效。
17. 身為牌手,我想讓類別軸預設摺疊,以便不用類別的人側欄不會被一大棵樹撐長。
18. 身為牌手,我想在過濾框輸入日文字面(例:墓地)時樹只留名稱含它的節點與其祖先,以便在 235 個葉裡快速找到要的那幾個。
19. 身為牌手,我想清空過濾框時樹回到原狀,而且已選的節點不因過濾而被取消,以便過濾只是找、不是改條件。
20. 身為牌手,我想在結果清單每句標記句尾看到它全部的葉,以便一眼讀出每個效果在做什麼。
21. 身為牌手,我想讓代價位的葉和效果位的葉看得出不同,以便分辨「這是費用」還是「這是效果」。
22. 身為牌手,我想讓這次搜尋命中的葉被強調,以便看出是哪個葉讓這句中的。
23. 身為牌手,我想讓命中類別條件的句子照現有方式高亮,以便和效果類型/效果文的命中句一致。
24. 身為牌手,我想讓沒有類別的句子(條件位、未歸、舊式卡文)句尾不多出任何東西,以便清單不出現空標籤。
25. 身為牌手,我想把選好的類別條件寫進網址,以便分享或重新整理後條件還在。
26. 身為牌手,我想讓網址裡已經不存在的節點(類別樹改名或刪除後)被安靜忽略,以便舊網址還能開、只少了那個條件。
27. 身為牌手,我想讓類別條件和屬性、種族、卡名等其他軸照常 AND,以便類別只是多一個縮小範圍的條件。
28. 身為牌手,我想在只選類別排除、沒選包含時,舊式卡文的卡也不出現,以便「選了類別條件,結果就只在涵蓋範圍內」這件事沒有例外。
29. 身為牌手,我想讓同一個框架帶多個葉時(複合區域、多關鍵詞、兩軸並收)每個葉都搜得到它,以便「手札・墓地から特殊召喚」同時出現在 ←手札 與 ←墓地 的搜尋裡。
30. 身為牌手,我想讓詞元節點的預設葉(例:破壊 底下沒有條件的那一葉)也能單獨選,以便找「沒有更細分類」的那一群。
31. 身為牌手,我想讓同一個詞元出現在幾個大類下時(にする 在 數值、規則改寫…)各自只代表掛在那裡的葉,以便選 數值 › にする 不會連 規則改寫 的 にする 一起中。
32. 身為牌手,我想在手機寬度也能展開樹與點選,以便手機上一樣能用類別找卡。
33. 身為站主,我想讓類別資料以入版控的匯出檔進網站,以便網站建置不必跑分詞鏈、clean checkout 也能重建索引。
34. 身為站主,我想讓匯出檔每句記原文雜湊、索引建置比對不上就失敗並列出過時句數,以便卡文勘誤或新卡進來後不會靜默沿用過時的類別。
35. 身為站主,我想讓匯出檔裡出現類別樹沒有的葉時建置失敗,以便類別樹與匯出檔不一致會吵鬧地失效,而不是某批卡默默搜不到(值域正典)。
36. 身為站主,我想讓類別樹本身進值域正典、由它生成側欄的樹,以便側欄與類別資料只有一個來源。
37. 身為站主,我想讓類別規則一改,依序重跑分詞鏈、更新匯出檔、重建索引就能讓網站反映,以便我修類別後能馬上在網站上驗。
38. 身為站主,我想讓差值更新流程多一步「重跑分詞鏈」,以便更新卡片資料時不會忘了更新類別。
39. 身為站主,我想讓匯出與索引同一份輸入兩次建置逐位元組相同,以便版控裡的差異讀得出改了什麼。
40. 身為站主,我想讓匯出檔的筆數、涵蓋卡數、各葉句數在建置報告裡看得到,以便知道這次重建類別資料有沒有大變動。
41. 身為站主,我想讓索引加了類別後的大小與 gzip 大小仍在建置報告裡,以便看出載入成本漲了多少。
42. 身為維護者,我想讓框架對到標記句的規則(含 ● 子效果句與選項)有回歸例子,以便分詞鏈改動後對應錯了會在匯出端就失敗。
43. 身為維護者,我想讓查詢引擎的類別語意(AND、同句耦合、上層節點、含代價、卡層排除、舊卡不中)都有合成資料的測試,以便日後改引擎不會把語意改壞。
44. 身為維護者,我想讓呈現的句尾葉名、代價葉、命中葉有字面斷言的測試,以便改樣式不會讓使用者看不到這些區分。
45. 身為維護者,我想讓網址往返(條件 → hash → 條件)涵蓋類別節點與「含代價」,以便分享網址不會掉條件。

## Implementation Decisions

**分詞鏈匯出(新)**

- 分詞鏈在框架類別之後多一步匯出:輸入是動作框架、框架類別與效果標記表的標記句,輸出一份類別匯出檔,寫進資料目錄、入版控(ADR-0017)。分詞程式本身留在試點目錄。
- 匯出的單位是**標記句**,鍵與效果標記表一致(卡片密碼、段落 main/pendulum、index;● 子效果句是自己的 index)。只有新格式新卡(分詞鏈的涵蓋範圍)有紀錄。
- 框架對標記句:效果句只有一段時,框架全屬那一句;拆開的效果句(領起句+子效果句),框架帶選項 n 時屬 index-●n 那一句、沒有選項時屬領起句。全語料實測每個動作框架都剛好對到一句,沒有對不上、也沒有跨句。效果句只有一段但框架帶選項(官方沒拆的 ●)時,仍整個屬那一句。
- 每句記:效果位框架的葉集合、代價位框架的葉集合(各自去重、依樹序)、原文雜湊(那一句標記句的日文原文)。條件位(不適用)與未歸的框架不帶葉;約束框架不在本線。
- 匯出檔另帶類別樹(節點路徑、大類/中類/詞元/葉、樹序、預設葉),作為網站值域的類別部分;葉以樹裡的位置識別,同名詞元在不同大類下是不同節點。
- 涵蓋卡數(有紀錄的卡)由匯出檔決定,不寫死。

**索引管線(接縫 1)**

- 索引建置多讀類別匯出檔。每句標記句在既有的平行陣列旁多兩個對齊欄位:效果位葉、代價位葉(葉以短碼/編號表示,沒有葉的句省略,沿用「空值省略不寫 null」)。
- 建置時以效果標記表的日文原文重算每句的雜湊,與匯出檔比對;有任何一句對不上(或匯出檔有、標記表沒有的句)就**建置失敗**,報告列出過時句數與前幾筆。索引本身不帶雜湊與日文原文(前端索引既有規則)。
- 匯出檔裡出現類別樹沒有的葉也建置失敗(值域正典,ADR-0008)。
- 類別樹進 VOCAB,由前端據以生成側欄的樹;VOCAB 也帶涵蓋卡數(軸標題用)。
- 建置報告加:涵蓋卡數、帶葉的句數、各大類句數、索引大小與 gzip 大小的變化。
- 同一份輸入兩次建置逐位元組相同。

**查詢引擎(接縫 3)**

- 查詢條件多兩項:類別節點的三態選擇(包含集合、排除集合,以節點路徑識別)與「含代價」旗標。
- 節點展開成葉集合:葉是它自己,上層節點(大類、中類、詞元)是掛在它底下的所有葉(詞元節點含預設葉);同一詞元在不同大類下各自只含掛在那裡的葉。
- 可用的句:符合既有句層條件(效果類型、必發/選發、效果文)的標記句。每句的「有效葉」是效果位葉,加上「含代價」時的代價位葉。
- 包含:每個選中的包含節點,都要有至少一句可用的句,其有效葉與該節點的葉集合有交集;不同節點可以由不同句滿足(AND)。
- 排除(卡層):卡上任何一句(不受句層條件限制)的有效葉與任一排除節點的葉集合有交集,整張卡不中;同軸包含與排除衝突時排除優先(既有規則)。
- 有任何類別條件(包含或排除)時,沒有類別紀錄的卡(舊式卡文、不在涵蓋範圍)一律不中。
- 命中句(用於高亮與回傳):符合句層條件、且有效葉與任一包含節點有交集的句;只有排除沒有包含時,命中句照既有句層條件的規則。
- 其他軸與類別軸之間照常 AND。

**網址 hash**

- 類別的包含/排除節點以節點路徑寫進 hash,「含代價」另一個參數。解析時樹裡找不到的路徑安靜忽略(同現有 hash 對已拆參數的行為)。條件 → hash → 條件往返相等。

**呈現**

- 每句標記句尾列它全部的葉(效果位與代價位),不論有沒有搜類別;葉名用類別樹的日文原名。
- 代價位的葉與效果位的葉在字面上可辨(例如前綴或另一種 badge);本次搜尋包含節點命中的葉在字面上可辨(強調)。
- 沒有葉的句子句尾不多出任何東西。

**側欄(query)**

- 新軸「動作類別」放在效果類型、必發/選發旁,預設摺疊;標題列寫「涵蓋 N / 全部 張」與已選數(摺疊的既有語意:收起只是視覺,已選條件保留生效)。
- 軸內頂端:「含代價」勾選、過濾框。過濾框比對節點的日文名稱(子字串),只留命中節點與其祖先;過濾不改已選條件。
- 樹由 VOCAB 的類別樹生成:大類 › (中類) › 詞元 › 葉,節點可展開/收合,每個節點是三態鈕(未選 → 包含 → 排除);詞元節點的預設葉以與詞元同名、標示「預設葉」的方式列在子節點最後(同類別總覽頁)。不標卡數。
- 手機寬度可用(沿用側欄既有的響應式規則)。

**資料更新**

- 差值更新流程在重建網站資料之前多一步:重跑分詞鏈(分詞 → 框架 → 類別 → 匯出)。不重跑時,卡文有變的句子會讓索引建置失敗。

## Testing Decisions

- 好的測試只斷言接縫的外部行為:輸入資料或查詢條件進去,匯出紀錄、索引欄位、命中卡與命中句、HTML 字面出來;不斷言 DOM 結構、CSS class、內部資料結構。
- **分詞鏈匯出(新接縫)**:`(動作框架、框架類別、標記句) → 類別匯出紀錄`。用合成的小資料(幾張卡、含 ● 子效果句、帶選項但沒拆的 ●、效果外文本、靈擺段落、條件位與未歸框架、多葉框架、代價位框架)斷言每個框架落在哪一句、效果位/代價位分組、條件位與未歸不帶葉、雜湊是那一句的原文。先例:`test_categories.py`、`test_assemble.py`(同目錄、unittest、真的分詞器)。另加一個全語料不變式檢查(每個動作框架剛好對到一句)放在匯出步驟本身,對不上就失敗。
- **接縫 1(索引管線)**:`test_webindex.py` 的寫法——合成卡片總表條目、標記表條目與類別匯出紀錄,斷言每句對齊的葉欄位、空值省略、VOCAB 帶類別樹與涵蓋卡數;雜湊對不上、匯出有標記表沒有的句、葉不在樹裡,三種都建置失敗(先例:`test_unknown_ban_value_fails_the_build`、`test_optional_outside_the_canon_fails_the_build`)。
- **接縫 3(查詢引擎)**:`engine.test.js` 的合成資料集加幾張帶葉的卡與一張沒有類別的卡,斷言:單葉包含、上層節點=任一葉、同詞元不同大類各自獨立、兩節點 AND 可不同句、AND 時每句都要符合效果類型/必發選發/效果文、預設不看代價位、含代價時代價位算、卡層排除(含代價時排除也看代價位)、只有排除時舊卡也不中、命中句索引正確、與其他軸 AND。hash 往返用既有 harness 的 hash 解析(先例:engine.test.js 末段的往返測試),含未知節點路徑被忽略。
- **呈現縫**:`render.test.js` 的寫法——合成卡片斷言 HTML 字面:每句尾的葉名、代價葉的可辨字面、命中葉的可辨字面、沒有葉的句不多出東西。
- **人工驗收**:側欄樹的展開/收合、三態點擊、過濾框、摺疊與標題已選數、手機寬度——同現有側欄走人工驗收;交件時站主在本機開網站實際搜幾組(蘇生、檢索、破壞對手場上、含代價的丟牌)。
- 分詞鏈決定性重跑兩次產物逐位元組相同;索引兩次建置逐位元組相同。

## Out of Scope

- 繁中顯示名(類別節點照日文原名;繁中對照表另開線)。
- 節點旁的卡數(靜態或隨條件變動)。
- 觸發事件軸(條件位框架的歸組,類別線規格已列另開線)。
- 約束框架(限制·次數、時機、素材…)的搜尋。
- 舊式卡文的卡補類別。
- 類別樹本身與框架抽取的修正(驗收後另開票;本線只接資料)。
- 把分詞鏈搬出試點目錄(ADR-0017:類別定版後另開線)。
- push 到 GitHub Pages(等站主開口)。

## Further Notes

- 規模:標記句 34,390 列,其中新格式新卡 24,599 列(7,817 張卡)有分詞與框架;動作框架 46,732 個,已歸 30,112、不適用 16,311、未歸 309;類別樹 235 葉。
- 節點以路徑識別而不是名稱:同一詞元可出現在幾個大類下(にする 在 數值、LP・ダメージ、表示形式、規則改寫),詞元節點的預設葉又和詞元同名,只用名稱會撞。網址裡寫路徑,類別樹改名或搬節點後舊網址的那個條件會失效(安靜忽略)。
- 側欄列整棵樹,包括目前沒有任何框架的葉(類別樹是值域正典,側欄照它生成);點了只是搜不到。若驗收覺得礙眼,另裁是否隱藏。

- 類別的已知未修(檢驗摘要「動作類別已知未修」)會直接反映在搜尋結果裡,這正是本線的目的:讓站主在網站上看到它們。
