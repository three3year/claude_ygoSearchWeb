# 動作詞元變體 LLM 檢驗:子代理工作說明

你會拿到一份批次檔(`batch-<k>.md`):每張卡一節、每句效果句一段,列出**原文**與程式抽出的**框架**。動作框架一列長這樣:

`框架 n:[位置] 動作(極性・態=…)| 主題=… | 主語=… | 對象=… | 來源=… | 所在=… | 目的=… | 內容 | 子句=…`

態沒有值時不列「・態=」;主題/主語/所在沒有值時不列;格後的「(回填)」表示值是規則從前面的述語接過來的,「(推得)」表示值是規則依動作補的、原文沒寫。約束框架(`[約束 …]`)不是本輪範圍。

你的工作:**看原文,挑出動作框架的錯**,重點是本輪新規則(下面 1〜7),寫成 `findings-<k>.json`。

## 本輪新規則(以此為準,不要用自己的直覺改判)

「動作」欄是**正規化後的動作詞元**,不是原文字面——原文寫法在子句欄。同一個子句展開出的多個框架,子句欄字面相同是正常的。

1. **「〜召喚を行う」記那個召喚**:行う 的對象是召喚時,詞元是那個召喚(S召喚を行う → S召喚;アドバンス→A、リンク→L 照寫法歸一),「の」前的名詞片語是**對象**(魚族Sモンスター１体のS召喚を行う → S召喚、對象=魚族Sモンスター1体);沒有「の」時對象空。講次數或條件的也一樣(通常召喚を３回まで行う事ができる → 通常召喚 可能,「3回まで」只留子句;儀式召喚を行う場合 → 儀式召喚 條件位)。主題形「このカードの融合召喚は…でしか行えない」→ 融合召喚 否定,「このカードの」只留子句、不進任何欄。法鏈「融合・S・X・リンク召喚」**一法一框**(融合召喚、S召喚、X召喚、L召喚 四框);「AのS召喚またはBのX召喚を行う」出兩框、各帶自己的對象。召喚框架和直接寫「〜をS召喚する」一樣補 目的=フィールド(推得)、對象片語裡的區域切成來源(手札の…モンスター１体の召喚を行う → 來源=手札)。對象不是召喚的 行う(戦闘、コイントス、バトルフェイズ…)照舊是 行う。
2. **「法(・法)*召喚の素材に/と + する/なる/できる/できない」展開成各法的素材詞元,一法一框**:融合→融合素材、S→S素材、X→X素材、リンク/L→L素材,原文助詞 に/と **照留不歸一**(融合・S・X召喚の素材にできない → 融合素材にする、S素材にする、X素材にする 三框 否定;融合召喚の素材となって → 融合素材とする)。不論極性與位置都展開;法前的所有格(このカードの、相手の、光属性Xモンスターの)只留子句、不進任何欄;受事者(を 對象、が 主語、は 主題)每框相同。沒有「召喚の」的素材句(〜として素材にできる、〜を融合素材として)不屬此型。
3. **素材詞元的態**:融合/S/X/L素材にする/とする 原文是 する 形(含 として、にできない、とする場合)記 他動,なる 形(となって、になり、になった)記 自動,被動句記 受身。所以「S素材として墓地へ送られた」的 S素材とする 是 他動(受身 在後面的 送る 上),這不是錯。
4. **「攻撃対象に選択」是 攻撃対象にする**:〜を攻撃対象に選択できない → 攻撃対象にする 他動 否定、對象=那張卡;攻撃対象に選択された → 攻撃対象にする 受身;**目的欄空**(攻撃対象 已在詞元裡),「相手モンスターの攻撃対象に選択された」的「相手モンスターの」只留子句、不進任何欄——這是規格決定,不是錯。「攻撃対象は相手が選択する」(講誰來選)與選效果的 選択 照舊是 選択。
5. **補語與 なる/する 之間夾 も 不擋併入**:相手の効果の対象にもならない → 対象にする 自動 否定(與「対象にならない」同一詞元);「相手の効果の」只留子句。
6. **補語以 効果 收尾時不併**:その効果は以下の効果となる → とする 自動、目的=以下の効果;…自分のLPを回復する効果になる → にする 自動、目的=自分のLPを回復する効果;同じ効果になる → にする、目的=同じ効果。「効果を無効にする」的補語是 無効,照舊 無効にする。
7. **「〜の素材として扱う」的述語是 扱う**:記一個 扱う 框架,「素材として」不成框架。

### 既有規則(上一輪定案,照此判)

- 態:被動句一律 受身;なる 形併出的詞元(対象にする、にする、倍にする…)なる 記自動、する 記他動;不在統一組的詞元(破壊、送る、特殊召喚、S召喚、選ぶ…)主動句態空著是對的——空是「沒判」,不是錯。
- 補語是封閉值域字面或屬性名詞(闇属性、守備表示、レベル、攻撃力…)時不併,詞元 にする/とする、補語在目的。
- 態不改變受事者落在哪一欄:自動與受身的受事者在主語/主題、他動的在對象。

## 錯誤類型(type 欄只能填這些字)

本輪新增(請優先檢查):
- `展開錯`:法鏈展開少框、多框或法對錯(融合・S・X 只出兩框、出了不該出的法、S 寫成 X…),或「または」並列的召喚沒拆對。

沿用(新規則相關也請檢查):
- `詞元錯`:動作欄不是上面規則該給的正規詞元(該記召喚法卻留 行う、攻撃対象に選択 留 選択、素材詞元的 に/と 被改了…)。
- `態錯`:態的值不對(素材詞元 する/なる 的 他動/自動 反了、該 受身 沒記…)。
- `補語錯欄`:不併的補語沒進目的、進錯欄、目的字面多吃或少吃;或 行う:召喚 的「の」前名詞片語沒進對象、進錯欄、切錯位置。

既有類型(新規則以外看到明確的錯也可回報):`漏抽動作`、`論元抽錯`、`位置判錯`、`極性判錯`、`多抽(不是動作)`。

## 回報格式

寫 `findings-<k>.json`(UTF-8,k 與批次檔相同):一個 JSON 陣列,每筆
`{"card": 卡號(整數), "index": "①"/"②"/"效果外文本 0"…(句的標籤,照批次檔「### 句」後的寫法), "frame": 框架序(整數)或 null, "type": 上列之一, "reason": "一句話,引原文片段說明哪裡錯、應該是什麼"}`。

- 沒有錯就寫 `[]`。一個框架有多個問題各寫一筆。
- reason 用繁體中文,引原文照抄日文。
- 只回報有把握的錯;判準寫在上面,和判準不同的地方照判準,不要改判準。拿不準的在 reason 開頭寫「(待確認)」。
- 不要改動批次檔或其他檔案。
