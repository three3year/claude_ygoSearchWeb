# 51 — 拆句表容納兩側語序不一致的卡

**What to build:** 讓[[拆句表]]記得下「繁中與日文把同一批句子排成不同順序」的卡。目前這種卡只能整團留空(§8 判準11),而留空的卡每一票都會原封不動再出現一次,永遠拿不到[[效果類型]]。

**Blocked by:** 13 — 拆句試點票、18 — 要拆+判 split-02

**Status:** done

## 為什麼現在做

判準11 是票13 立的:兩側語序不一致就整團留空,理由是「拆句表存的是**兩側**的原文子字串,配錯就是永久的錯誤資料」。那個理由到今天仍然成立——**但它是資料結構的限制,不是領域上的限制**。段落的兩側其實配得起來,只是拆句表的一筆把「第 i 段」同時當成「繁中的第 i 塊」與「日文的第 i 塊」,兩者不同時就寫不進去。

已經累積 3 張(52140003 爆弾ウニ、3129635 カース・オブ・スタチュー、296499 一族の掟),票18 另用句級數字指紋掃出至少 1 張還沒判到的(95920682 英豪贈禮)。實判率 3/400 = 0.75%,推到剩下的 3,410 段約 25–30 張。

**不能靠「參考之前同類型的排序」繞過**:拆句表照定義只收得下位置對位成功的紀錄,所以現有 395 筆裡一筆重排的例子都沒有,沒有語料可歸納。

## 設計

一筆拆句紀錄多一個**選用**欄位 `ja_order`:`segments` 位置的排列,給出**日文的閱讀順序**。

- **`segments` 照繁中順序列。** 網站給人看的是繁中卡文,段落順序照繁中排,讀起來才對得上卡面。
- **`index` 照日文的序號給。** 官方用①②③稱呼舊式卡文,`official._seq_target()` 是拿 `index` **字串**對位、不看列表位置,所以 index 必須跟著日文那一側。§8 判準15 早就說過 `index` 與段落在卡文裡的位置無關,這裡是同一條規矩再用一次。
- **沒有 `ja_order` 就是恆等排列。** 既有 395 筆一個字都不用改。

三道驗證怎麼跟著改:

| 驗證 | 改動 |
|---|---|
| 無遺漏覆蓋 | 繁中照 `segments` 順序串接、日文照 `ja_order` 順序串接,各自等於該側原文 |
| 引用交叉驗證 | 不變(只問「引用有沒有完整落在某一段裡」,與順序無關) |
| 卡文變動即失效 | 不變 |
| (新)結構檢查 | `ja_order` 必須是 `0..n-1` 的排列,否則 `split_malformed` |

### 結果

- `ja_order` 上線,既有 395 筆一個字都沒動(缺欄位 = 恆等排列,補了一條測試釘住)。
- 回頭補判的 3 張全部拆完、三道關卡 0 個問題:

  | 卡 | 日文順序 → 繁中順序 | `ja_order` |
  |---|---|---|
  | 一族の掟 296499 | ①②③ → ③①② | `[1, 2, 0]` |
  | カース・オブ・スタチュー 3129635 | ①②③ → ①③② | `[0, 2, 1]` |
  | 爆弾ウニ 52140003 | ①②③ → ③①② | `[1, 2, 0]` |

  拆句表 395 → 398 筆,拆出效果句 541 → 549 條,因拆句新取得[[官方明示]] 346 → 348 條(3129635 的 index=2 由官方接手,判定的必發保留)。**待判集合裡不再有已知的語序不一致卡**,只剩還沒判到的 ヒロイック・ギフト 95920682。

### 為什麼繁中是列表順序、日文是 `index`

拆的時候兩件事會打架:**人要照繁中讀**,**官方的①②③照日文數**。硬要統一就得犧牲一邊。分開之後兩邊都對得上,而且不必新增欄位——`index` 本來就與段落位置脫鉤(判準15)。`official._seq_target()` 是拿 index 字串對位、不看列表位置,所以這個分法不需要改抽取器,補了一條測試釘住這個前提。

### 兩個 CLI 旗標

`--only`(只放指名的卡)是硬需求:合併程序的**集合一致性自檢**要求結果檔涵蓋批次檔的全部,所以補判 3 張就得有一個只含那 3 張的批次。`--name`(自訂檔名)同樣是硬需求而不是方便:`--only` 篩完只剩一組,批號還是從 `--start` 起算,預設檔名會是 `split-01.json`——那是票13 的稽核軌跡,會被蓋掉。

兩個旗標都加了護欄:`--only` 只吃逗號分隔的數字、指名的卡不在待判集合(或不屬於 `--series`)就退出 1;`--name` 只在**剛好寫出一個檔案**時放行,否則同一個名字會自己蓋掉自己。旗標的說明裡也寫明 `--only` 不是拿來挑卡的——正式排票要的仍然是無遺漏地判完全部。

票13 當時是寫一次性抽樣器再刪掉,這次做成旗標,因為「回頭補判特定幾張」會反覆出現(留空的卡每票都會再回來)。

### 沒做的事

`【①の効果について】` 標頭對舊式拆句卡仍然對不到(報告的「標頭指名的編號卡文沒有」7 筆)——`_seq_target()` 的序號對位只長在 `『①』` 引用那條路徑上,標頭那條沒有。這是票51 之前就有的行為,與語序無關,沒有一併改。
