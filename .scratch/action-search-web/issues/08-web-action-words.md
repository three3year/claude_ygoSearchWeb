# 08: 網站上用動作詞查卡(第一條貫穿線)

**What to build:** 玩家在側欄打開「動作搜尋」區塊、選動作詞、按搜尋,得到卡文裡有這個動作的卡,和其他卡片條件取且。這是第一張從資料一路做到畫面的票;之後的票各加一種篩選。

- 側欄多一個可摺疊區塊「動作搜尋」,預設收起。
- 動作索引在兩種時候載入,載過就不再載:第一次展開這個區塊;或從瀏覽紀錄還原的查詢帶著動作條件。其餘時候不載入。雙擊開啟也要能載。
- 動作詞的選項由索引帶的表生成,HTML 不手抄;依列數排,前面一批直接顯示,其餘收在「更多」。可多選,全部都要在同一段裡。
- 這張票還沒有其他選項,比對用玩家介面的預設值:段類別 效果、召喚手續、限制、代價;極性 做、可以、必須;推得的值不算;泛用引用關;不看代替。
- 前端查詢引擎多一組動作條件、多一份動作索引。沒有動作條件時不碰索引,結果與現在相同。有動作條件時,卡要同時滿足卡片條件與動作條件(這張票是同一張卡即可;同一個效果由票 16 做)。
- 結果是一份清單,不分組、不帶標記,收特定與泛用兩組(經引用由票 14 加);排序、分頁、每頁筆數沿用現有的。
- 索引載入中按搜尋:顯示載入中,載完自動查。載入失敗:在區塊裡顯示說明,動作條件不生效,其他條件照常。
- 「清除條件」清掉動作條件。窄螢幕沿用現有側欄的摺疊;摺疊鈕的生效條件數把動作條件算進去。
- 動作條件跟著查詢狀態存進瀏覽紀錄(票 01 的機制)。
- 建立「兩邊答案一致」的測試:一組 Python 測試用測試內建出來的卡片結構攤平成索引,同一批查詢分別交給 `run_query` 和 node 沙箱裡的前端引擎,命中的卡號必須相同。之後每張加篩選的票都往這組測試加查詢。這組測試需要機器上有 node。
- 比對邏輯只比對列,不解讀卡片結構。

- 規格:需要你決定的「Q10」「Q18」「Q20」「Q23」與「測試從哪幾個接縫驗」;實作決策「前端查詢引擎」「玩家介面」;使用者故事 1、2、8、9、32、36–41;測試決策「接縫三」「兩邊答案一致」。
- 參考:原型(分支 `prototype/action-player-ui`)的版面與動作詞的擺法。與原型不同的地方:清單用現有的分頁而不是「再顯示」按鈕;沒有黃色切換列與狀態框。
