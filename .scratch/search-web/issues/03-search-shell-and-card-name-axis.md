# 03 — 搜尋骨架與卡名軸

**What to build:** 左側常駐條件側欄出現,使用者能用卡名找卡——輸入「青眼%龍」得到那一批,
輸入 `46986430` 得到黑魔導。這是第一條端到端的搜尋軸,搜尋引擎的結構在這裡定案,
後面四張票各自往上加一軸。

本票建立**接縫 3**:`查詢條件 -> (命中卡片密碼清單, 每張卡的命中效果句索引)`。
以 `node:vm` 沙箱 + 最小 DOM stub,依 `web/index.html` 的 `<script src>` 順序載入
**真實的前端程式碼**執行。零 npm 依賴、不進 `package.json`,前端檔案不為了可測而加
`module.exports` 之類的東西——production 碼保持乾淨。
**前例:oldProject 的 `scripts/audit/frontend_parity.js`**,同樣的沙箱手法。

回傳值要帶「每張卡的命中效果句索引」而不只是卡片清單,即使本票的卡名軸用不到它:
票 04 的命中標亮與票 06 的句層耦合都靠它,而**那兩個語意只能從命中位置驗證**——
光看命中了哪些卡,分不出引擎是真的做了同句交集還是碰巧兩個條件都在同一張卡上成立。

## Comments

2026-08-13 實作完成。前端多兩支:`web/js/engine.js`(搜尋判定核心,純函式)與
`web/js/query.js`(側欄條件 ⇄ 條件物件);`index.html` 改成「側欄 + 結果區」兩欄版面,
`main.js` 換成「讀側欄 → 跑引擎 → 重畫」的單向流。接縫 3 的沙箱載入器
`script/web/frontend_harness.js` + 測試 `script/web/engine.test.js`(17 條)。
側欄兩個欄位:[[卡片密碼]]在上、卡名關鍵字在下。

**接縫 3 跳過 `data.js`,其餘照 `index.html` 的順序全載。** 那是建置產物(7.5 MB 真實
索引)而不是前端程式碼,接縫測試餵的是合成資料集。跳過的方式是檔名比對——萬一哪天沒
跳成,`window.CARD_DATA` 會被真實索引蓋掉、每一條斷言都會倒,是吵鬧的失效不是沉默的。
載入順序從 HTML 讀,拆檔或插新模組時測試自動跟著走。

**測試檔名是 `engine.test.js` 而不是 `test_engine.py` 那種前綴式。** node 的 test runner
只認 `*.test.js` / `*-test.js` / `test-*.js`,`test_engine.js` 不在其中——跑 `node --test`
會靜靜地一條測試都不跑。各自照各自 runner 的慣例命名,`script/web/` 因此同時有
`test_vocab.py` 與 `engine.test.js`。

**`rows`(每張卡的命中效果句索引)現在一律是 `null`。** 票03 的卡名軸是卡層條件,沒有
人寫得進 rows;但欄位與回傳形狀現在就定了,票04 的標亮與票06 的句層耦合直接掛上去。
有一條測試守著這個欄位存在——不然它會在某次重構裡被當成無用的 null 拿掉。

**`%` 的語意是「這幾段依序出現」而不是嚴格的 SQL LIKE。** 嚴格 LIKE 的話「青眼」要寫成
「%青眼%」才找得到東西,而使用者輸入的九成是光禿禿的關鍵字。實作是 split('%') 後逐段
`indexOf`,順序有意義(「龍%青眼」不命中青眼白龍),頭尾中間與多個 `%` 因此自然都對。
沿用 oldProject `engine.js` 的 `textMatch`。

**[[卡片密碼]]自己一個欄位,排在卡名框上方;卡名框只比對卡名**(2026-08-14 使用者裁示,
**推翻 spec Story 3「卡名框也接受卡片密碼」**,spec 已同步改寫)。一個欄位一件事:密碼軸
只認密碼、不比對卡名,卡名軸只比對卡名、不認密碼。看得出差別的是 `39`——卡名框搜它得到
「No.39 希望皇 霍普」,密碼欄搜它是零結果。兩軸並用是 AND。

密碼比對的三個判準:數值**完全相等**才算(`4698` 是 `46986414` 的前綴但不是任何一張卡的
密碼,當前綴比對只會冒出一堆使用者沒問的卡)、數值比較所以顯示補零的 `00002511` 抄回來
照樣命中、異圖密碼也認(拿到的是異圖卡面時查得到本尊)。非數字的輸入(`4698-6414`)
**不命中任何卡而不是被忽略**:打了條件卻當作沒打,使用者會以為眼前的結果是這個條件篩
出來的。

**關鍵字欄位的空白正規化收斂到 `runQuery` 一處。** 原本 `nameHit` 自己 trim,加上密碼軸
之後就變成兩個地方各修各的——而「只打了空白」到底算不算有設條件,是這一軸的語意問題
不是比對函式的。順帶少掉對 14,207 張卡各 trim 一遍。

**清除條件會直接重搜一次。** 條件清空後的結果就是全部 14,207 張(Story 49);只清表單不
重搜的話畫面停在上一次的結果上,使用者會以為條件還在。

**版面用 `minmax(0, 1fr)` 而不是 `1fr`**:grid 項目的預設最小寬度是內容寬,卡文長的那幾張
會把結果區撐寬、整頁跟著橫向捲。側欄 `position: sticky`,窄螢幕(900px 以下)退回單欄
——收合成頂部可摺疊區是票09。

歷史走人工驗收)。實作過程用較完整的 DOM stub + 真實 `data.js` 跑過一次冒煙:初始列出
