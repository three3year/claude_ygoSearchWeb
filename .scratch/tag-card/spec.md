# Spec: 效果標記表(拆效果句 + 標效果類型)

Status: ready-for-agent

## Problem Statement

網站要做的核心功能是「用效果條件查卡」——例如找出所有具備誘發即時效果的卡、或所有帶永續效果的怪獸。但目前專案手上只有兩份互不相通的資料:[[卡片總表]](14,207 張卡的繁中卡文,整段純文字)與[[官方 Q&A 快取]]抽出的[[補足情報]](13,397 張卡的日文官方裁定)。卡文是一整段文字,沒有任何結構——查詢層無從知道一張卡有幾個效果、每個效果屬於哪一種、是必發還是選發。

前一世代曾用正則表達式做過這件事,失效模式很清楚:同一種句型整族誤標,使用者只能逐卡回報「某某卡的第 N 效果不是某類型」,修正靠外掛的 override 檔,而 override 檔會隨規則演進而失效。根本問題是規則本身從未被獨立驗證過——一條寫得太寬的規則誤標數百行,而那些行從沒被人看過。

同時,官方其實已經替超過半數的效果寫下了答案:補足情報裡有 8,408 張卡直接寫著「誘発即時効果です」「起動効果です」這種句子,只是這份權威資料從來沒有被拿來用。

## Solution

建立[[效果標記表]] `data/tag_cards.json`:把每張卡的卡文拆成[[效果句]],逐句標上[[效果類型]](六種固定值)與[[必發/選發]],作為網站進階查詢的核心依據。

判定分三層權威,由高到低:

1. **[[官方明示]]** —— 補足情報直接寫出類型或必發/選發的句子。實測可覆蓋 21,947 條效果句中的 13,756 條(62.7%),以及 1,164 條必發標記。
2. **規則層** —— 日文卡文的硬性寫作慣例(發動子句以「〜できる」結尾即為選發)、[[效果外文本]]的位置規則(第一個效果編號之前的段落)。
3. **LLM 判定** —— 前兩層判不出的 8,191 條效果句(分佈於 5,868 張卡),由對話 session 逐條判定。

官方明示要能用,前提是**判定它講的是哪一個效果句**。官方用五種寫法標示歸屬(標頭指名、`『①』`序號引用、`『效果原文』`引用、`「卡名」`限定、單效果卡整卡陳述),但補足情報也會為了解說而提及**其他卡**的效果文——例如「深海の戦士」的補足既有指向自己的「『深海の戦士』の効果は永続効果です」,也有引用「海」相關他卡文字的段落。因此歸屬判定的核心原則是:**只有對位證據唯一且明確時才自動套用;任何歧義——引號對不回本卡、命中多個效果段、明示句只提到別張卡、卡名限定卻是多效果卡——一律交由判定者決定歸屬,絕不猜測。**類型值仍取自官方,只有歸屬是判斷。

判定過程中持續歸納新規則,但**新規則不允許讓任何效果句跳過判定**(見 ADR-0002):規則只寫入 `rule_predicted` 影子欄位,該行仍照常判定,判完當場比對。一致則 `source` 升為 `llm_then_rule`,不一致進衝突清單——每條規則因此都有獨立判定作對照,規則寫錯會在下一票就浮現。

效果標記表是**入版控的來源檔而非建置產物**(見 ADR-0001):使用者的逐卡修正直接改檔並標 `manual`,重跑永不覆蓋。

## User Stories

1. As a 網站查詢層, I want 每張卡的效果被拆成獨立的效果句, so that 「這張卡有幾個效果」不再需要在查詢時解析整段卡文。
2. As a 網站查詢層, I want 每個效果句帶有六種固定值之一的效果類型, so that 「找出所有有永續效果的卡」可以直接建索引。
3. As a 網站查詢層, I want 發動型效果句帶有必發/選發標記, so that 使用者能區分「必須發動」與「可以選擇發動」的效果。
4. As a 使用者, I want 效果類型的值域固定為六種且不會擴充, so that 前端的篩選介面是一組固定選項,不需要處理未知值。
5. As a 使用者, I want 「誘發即時效果(2速)」「誘發效果(1速)」的速度標註保留在名稱裡, so that 兩個字面相近的詞在介面上不會被看錯。
6. As a 使用者, I want 必發/選發只在誘發即時與誘發兩類上有值、其餘為空, so that 不會出現「永續效果是必發」這種沒有意義的組合。
7. As a 使用者, I want 效果句同時保留繁中與日文原文, so that 前端能顯示繁中,而判定與人工核對能對照日文官方原文。
8. As a 使用者, I want 判定以日文卡文與補足情報為準而非繁中翻譯, so that 效果類型這個官方裁定概念不會因為經過翻譯而失真。
9. As a 使用者, I want 靈擺卡的靈擺效果與怪獸效果分開標記, so that 兩段各自從①開始的編號不會互相衝突。
10. As a 使用者, I want 靈擺效果的判定只參考靈擺補足情報, so that 怪獸效果的裁定不會污染靈擺效果的判定。
11. As a 使用者, I want 卡文開頭在第一個效果編號之前的段落被獨立抽成一個效果外文本效果句, so that 「這個卡名的①②效果1回合各能使用1次」這種限制文字不會被誤當成某個效果的一部分。
12. As a 使用者, I want 效果外文本再細分為素材指定、召喚條件、使用次數限制, so that 前端能單獨顯示融合素材,而「哪些卡有召喚條件」也變成可查。
13. As a 使用者, I want 拆句只在行首或緊接換行的編號處切割, so that 「這個卡名的①②效果…」裡的編號不會把 2,509 張卡的卡文切爛。
14. As a 使用者, I want 舊式無編號卡文由語意拆成多個效果句, so that 3,802 張沒有①②③的效果卡也能享有同樣的查詢能力。
15. As a 使用者, I want 拆出的每一段都必須是原文的連續子字串、且串起來能無遺漏地蓋回原文, so that 拆句過程不可能悄悄改寫或漏掉卡文內容。
16. As a 使用者, I want 官方在一個編號效果內用「●」分項描述的子效果被拆成獨立效果句, so that 「①是誘發效果、其持續部分是永續效果」這種卡不會被迫塞進單一類型。
17. As a 使用者, I want 每個效果句只有單一效果類型, so that 查詢層與前端不必處理集合語意。
18. As a 使用者, I want 純通常怪獸收進標記表但效果句為空陣列, so that 「已處理且確實沒有效果」與「尚未處理」可以區分。
19. As a 使用者, I want 靈擺通常怪獸只抽靈擺效果、丟棄怪獸敘述段, so that 38 張這類卡的敘述文不會被當成效果去判類型。
20. As a 使用者, I want 補足情報中直接寫出效果類型的句子被優先採用, so that 超過半數的效果句有官方權威依據而非推論。
21. As a 使用者, I want 「起動効果・誘発効果・…のいずれにも分類されない効果です」被正確判為無種類效果, so that 947 張卡不會因為這句話提到了五個類型詞而被判成五類皆是。
22. As a 使用者, I want 「効果ではありません」明確被禁止當作判定依據, so that 「対象を取る効果ではありません」這類限定否定不會誤標數千行。
23. As a 使用者, I want 「〜は効果として扱いません」被視為效果外文本的官方明示, so that 官方認定不構成效果的段落有權威依據。
24. As a 使用者, I want 官方明示指向的段落若不在卡文開頭前言段就列進報告而不自動處理, so that 需要語意對位的高風險判定由我人工決定。(**票16 收窄**:引用**涵蓋整個效果句**時沒有語意對位可言,官方指的就是那一段,自動套用;涵蓋一部分的照舊只報告。)
24a. As a 使用者, I want 官方以『①』純序號引用效果時能直接對位, so that 這 1,584 條最乾淨的官方判定不會因為引號長度過短而被濾掉。
24b. As a 使用者, I want 官方以『效果原文』引用效果時能靠引號比對回卡文的編號區段定位, so that 這 1,480 條原本會被浪費的官方權威判定能被採用。
24c. As a 使用者, I want 官方以「卡名」限定的明示在單效果卡上直接套用, so that 「『深海の戦士』の効果は永続効果です」這類 1,498 條陳述能被採用。
24d. As a 使用者, I want 明示句只提到別張卡名時完全不被採用, so that 補足情報為了解說而引用的他卡效果文不會污染本卡的判定。
24e. As a 使用者, I want 引號對不回本卡卡文、或同時命中多個效果段時不強行猜測, so that 對位歧義變成待判而不是錯誤資料。
24f. As a 使用者, I want 卡名限定但卡文有多個效果時交由判定者決定歸屬, so that 447 張這類卡不會被整卡套用成同一個類型。
24g. As a 使用者, I want 所有對位證據都不成立的多效果卡由判定者決定官方明示的歸屬, so that 這些卡仍能用上官方的類型判定而非退回純推論。
24h. As a 使用者, I want 歸屬由判定決定的條目列成清單, so that 我能抽查那些「類型是官方給的、但歸屬是判斷的」行。
25. As a 使用者, I want 必發/選發優先採用官方明示的「必ず発動する効果です」, so that 1,160 條有官方依據的標記不靠推論。
26. As a 使用者, I want 必發/選發其次採用日文「〜できる」句型規則, so that 這個 OCG 卡文的硬性寫作慣例被利用,而不是交給比它更不可靠的判斷。
27. As a 使用者, I want 每個效果句記錄它的判定來源, so that 我一眼就能看出哪些是官方權威、哪些是規則推導、哪些需要複查。
28. As a 使用者, I want 我的人工修正標記為 manual 且重跑永不覆蓋, so that 逐卡回報的修正不會在下一次建置時消失。
29. As a 使用者, I want 官方明示的判定同樣永不被重跑覆蓋, so that 權威資料不會被後來的規則或判定推翻。
29a. As a 使用者, I want 補足情報更新後新出現的官方明示能對既有的判定行做比對而非被忽略, so that 遲到的權威資料能升級判定,而不一致處能立刻被我看見。
30. As a 使用者, I want 每個效果句記錄其日文原文的雜湊, so that 卡文勘誤或拆法改變時系統知道這一行的身分已經改變。
31. As a 使用者, I want 雜湊變動的效果句被標記為待複查而非直接覆蓋, so that 我的修正不會因為拆句法微調而被靜靜吃掉。
32. As a 使用者, I want 效果標記表一卡一物件、一欄位一行、依卡片密碼穩定排序, so that git diff 可讀,我能逐行審查每次重跑的變動——改一個判定就只動那一行。
33. As a 使用者, I want 每個效果句預留功能 Tag 欄位, so that 之後[[分類表]]定稿時可以原地填入而不需要改結構。
34. As a 判定執行者, I want 一份寫死的效果類型判別規範文件, so that 跨多個 session 的判定有一致的標準而不會隨對話上下文漂移。
35. As a 判定執行者, I want 待判效果句被切成固定大小的批次檔, so that 每一票都能在單一 session 內完成而不會撐爆上下文。
36. As a 判定執行者, I want 每一票完全自足、只依賴規範文件與自己的批次檔, so that 使用者可以手動切換 session 而不需要傳遞前一票的記憶。
37. As a 判定執行者, I want 判定結果先寫進獨立的結果檔而非直接改標記表, so that 半完成或失敗的票不會污染總表。
38. As a 判定執行者, I want 每票自檢輸出的效果句集合與批次檔完全一致, so that 漏判或多判會立刻失敗而不是靜靜寫進資料。
39. As a 判定執行者, I want 任何一票都能單獨重跑, so that 單票失敗不影響其他票的成果。
40. As a 使用者, I want 每票結束後歸納可規則化的判定, so that 規則層持續增強,未來新卡的[[差值更新]]需要人工判定的量越來越少。
41. As a 使用者, I want 新歸納的規則只寫入影子預測欄位而不直接判定, so that 每條規則都有一次獨立判定作為對照。
42. As a 使用者, I want 影子預測與實際判定不一致時列進衝突清單且不動資料, so that 我能自己判斷是規則有洞還是判定出錯。
43. As a 使用者, I want 影子預測與判定一致的行標記為 llm_then_rule 而非 rule, so that 我能分辨「純規則產出」與「規則與判定雙重確認」這兩種可信度。
44. As a 使用者, I want 一份可稽核的規則清單檔, so that 「規則沒有新增或刪除」這個收斂條件是可以驗證的而不是感覺。
45. As a 使用者, I want 每條規則記錄判別條件、覆蓋條數與新增票號, so that 任何一條規則的來歷都可追溯。
46. As a 使用者, I want 覆蓋不足 8 條效果句的規則不進規則層, so that 過擬合的單卡特例不會偽裝成通則。
47. As a 使用者, I want 規則只在過寬、互相衝突、或可合併時才變更且必須記錄理由與票號, so that 規則層不會被隨手改動。
48. As a 使用者, I want 兩條相似的規則可以合併, so that 規則總數收斂而不是無限增生。
49. As a 使用者, I want 規則變更後全表重跑並逐行列出差異, so that 一次規則改動造成的影響是可見的。
50. As a 使用者, I want 一份 300 條的遮蔽測試,遮住官方答案讓判定者判再對答案, so that 判定的準確率有量化證據而不是等我逐卡回報誤標。
51. As a 使用者, I want 遮蔽測試分層抽樣、六類各自看準確率, so that 難分的類別不會被簡單類別的高分稀釋。
52. As a 使用者, I want 必發/選發用官方明示的那批獨立驗證一次, so that 規則層本身的正確性有單獨的證據。
53. As a 使用者, I want 遮蔽測試不通過時的動作是補規範文件或把判定移回規則, so that 失敗會轉化成資產而不是重刷分數。
54. As a 使用者, I want 官方文本本身歧義的條目列入已知歧義清單且不計入分母, so that 準確率反映的是判定品質而非官方的不一致。
55. As a 使用者, I want 五輪仍未達標就停下並回報現況與原因, so that 不會陷入無止境的重跑。
56. As a 使用者, I want 無官方補足依據的卡被標記為低信心並列出清單, so that 我能優先人工審查最沒有依據的那批。
57. As a 使用者, I want 建置後的統計報告涵蓋各判定來源的筆數、殘留未判定數、六類分布與各項待審清單, so that 我能快速判斷這次重跑的健康度。
58. As a 開發者, I want 判定與合併邏輯集中在單一純函式且不碰網路與檔案系統, so that 測試可以餵合成資料快速驗證。
59. As a 開發者, I want 建置管線吃既有標記表作為輸入, so that 保留人工修正這件事是管線的一部分而不是薄殼的臨時處理。
60. As a 使用者, I want 繁中與日文編號數量不一致的卡列進報告, so that 那 2 張對位失敗的卡由我人工處理而不是被靜靜猜測。
61. As a 使用者, I want 舊式卡文的拆句邊界存成獨立的[[拆句表]]來源檔, so that 判定者拆一次的成果不會在下一次重跑蒸發,而卡文勘誤時它會自動失效而不是默默沿用。
62. As a 使用者, I want 官方 `『原文』` 引用被拆點切開時系統會報錯, so that 2,150 張整團的拆句正確性有一道不需要標準答案的自動檢查。
63. As a 使用者, I want 拆句表有紀錄的卡重新走一次官方明示, so that 票11 撤掉的那 1,146 條裡其實正確的那一大半以官方權威回來,而不必花掉判定額度。

## Implementation Decisions

### 領域詞彙

- 本次新增的詞彙已寫入 `CONTEXT.md`:[[效果標記表]]、[[效果類型]]、[[必發/選發]]、[[效果外文本]]、[[官方明示]];既有的[[效果句]]詞條補上邊界定義。全文一律使用這些詞,不使用「tagCard」「effect_kind」等實作名稱描述領域概念。判定開跑後長出來的詞同樣進 `CONTEXT.md`:[[拆句表]]、[[影子預測]]、[[遮蔽測試]]、[[改判]](票52)等。
- 兩份 ADR 記錄了本次最難反轉的兩個決定:ADR-0001(效果標記表是來源檔)、ADR-0002(每條待判效果句都要判定一次)。

### 接縫與模組

- 沿用 card_list / faq_info 的架構模式:**單一純函式管線 + CLI 薄殼**,薄殼不納入自動測試。
- **唯一接縫**:`build_tag_cards(卡片總表條目, 補足情報條目, 既有標記表=None, 判定結果=None, 拆句表=None) -> (entries, report)`。拆句、官方明示抽取、必發/選發規則、影子預測、衝突偵測、拆句表套用、與判定結果合併全部是內部實作,一律透過這一個函式測試。
- 合併判定結果不另開接縫——它是同一次呼叫的一個參數。既有標記表同樣作為參數傳入,讓「保留人工修正」成為管線語意的一部分(ADR-0001 的直接後果)。
- [[拆句表]]是**另一個**參數而不是判定結果的一部分:`拆句表` 決定效果句的**集合**、`判定結果` 決定效果句上的**值**,而且兩者的生效時機不同——拆句表在官方明示抽取**之前**生效(拆完才對得出歸屬),判定結果在**之後**合併。合成一個參數會把這個順序關係藏起來(ADR-0003)。
- 批次檔產生留在 CLI 薄殼:補足情報決定不裁剪、原文照抄,沒有值得測試的邏輯。**[[改判]]票的旗標檢查是薄殼裡唯一帶判斷的地方**(票52):批次與結果檔的旗標兩個方向都要對得上,不對就整批不寫入。它與「集合一致性自檢」同構、同樣是集合差集,照舊不進自動測試;真正會改動資料的那一道(改判碰不到 `official` / `manual`、值相同時是空操作)長在接縫裡,由 `build_tag_cards` 的測試守著。
- 新增資料夾 `script/tag_card/`,與 `script/card_list/`、`script/faq_info/` 並列。CLI 薄殼分為建置(跑規則層產出骨架與批次檔、合併判定結果)與報告輸出。

### 資料結構

輸出 `data/tag_cards.json`,**入版控**,一卡一物件,依卡片密碼升冪,`indent=2`,保留結尾換行。每卡含 `id` 與 `clauses` 陣列;純通常怪獸為空陣列。

每個效果句的欄位:

| 欄位 | 值域 | 說明 |
|---|---|---|
| `index` | 字串 | `"0"`=[[效果外文本]]段(第二段以上為 `"0-2"`、`"0-3"`)、`"①"`~`"⑩"`=原文編號、`"①-●1"`=● 子效果、`"1"`~=無編號舊文本的序位(未拆時整團就是 `"1"`)。**用字串因為值域不是序數**,且原字元讓人工審查能直接對照卡文。`"0"` 標的是「這一段不是效果」而不是「這一段在最前面」——有編號的卡文兩者恰好同義(效果外文本只出現在第一個編號之前),舊式卡文則常把使用次數限制寫在**最後**,那一段的 `index` 仍是 `"0"`(票13 判準15) |
| `section` | `main` \| `pendulum` | 靈擺卡兩段各自從①編號,靠這個欄位區分 |
| `text_zh` / `text_ja` | 字串 | 原文連續子字串,不改寫 |
| `text_hash` | 字串 | `text_ja` 的雜湊,身分變動偵測用 |
| `kind` | 六種中文字串 \| `null` | 值即使用者定義的原字串,含「(2速)」「(1速)」標註 |
| `optional` | `選發` \| `必發` \| `null` | 僅誘發即時、誘發兩類有值 |
| `role` | `null` \| `素材指定` \| `召喚條件` \| `使用次數限制` | 效果外文本的子分類 |
| `source` | `official` \| `rule` \| `llm` \| `llm_then_rule` \| `manual` | 判定來源 |
| `needs_review` | 布林 | 這一行的身分變了但判定被保留,待人工複查。使用者改回 `false` 即結案 |
| `rule_predicted` | 六種字串 \| `null` | 影子預測,不參與 `kind` |
| `confidence` | `high` \| `low` | 無官方補足依據者為 `low` |
| `tags` | 陣列 | 預留給[[分類表]],本次一律為空 |

穩定鍵為 `(卡片密碼, section, index)`。重跑時:雜湊相同則沿用該行(含來源標記);雜湊變動則不覆蓋、標記 `needs_review` 並列入報告。`manual` / `official` / `llm` / `llm_then_rule` 這四種來源都是「判定一次就算數」,永不被重跑覆蓋。

**「永不被重跑覆蓋」不等於「判錯了也不能改」**:規範是逐票長出來的,先判的票用的是舊版規範。定案後回頭修錯判走[[改判]]票——逐條指名標的、結果檔逐行帶 `rejudge` 旗標,而且只碰得到 `llm` / `llm_then_rule`(票52,ADR-0002 的修訂一節)。`manual` 與 `official` 連改判票都動不了。

`rule` 是唯一會被重算的來源——它是當前規則層對當前文本的純函式輸出,沒有人工成果在裡面,不重算則 Story 49 的「規則變更後全表重跑並逐行列出差異」不可能成立。重算後與既有不同的行列進報告。

**例外——遲到的官方明示**:補足情報是會成長的來源(官方替舊卡補寫、新卡的 Q&A 頁面陸續出現)。當某一行既有為 `llm` 或 `llm_then_rule`、而更新後的補足情報對它給出了官方明示時,不沿用而是比對:一致則 `source` 升為 `official`;不一致則保留原判定並列進衝突清單。這與影子預測是同一個機制——比對本身就是一次免費的準確率驗證,而不一致正是最有價值的訊號。

### 拆句

- 繁中與日文的編號數量在 14,093 張可對照的卡中有 14,091 張一致,因此逐句對位安全;不一致的 2 張列進報告。
- 切割點必須是行首或緊接換行的編號字元。文中編號(如「這個卡名的①②效果1回合各能使用1次」,涉及 2,509 張卡)不得作為切割點。
- 第一個切割點之前的非空文字(排除 `【靈擺效果】` 等段落標頭)整段抽成 `index: "0"`、`kind: "效果外文本"` 的效果句,由位置規則產出、標 `source: "rule"`,不送判定。
- 無編號舊文本(3,805 條)由判定者依語意拆分,結果寫進[[拆句表]] `data/clause_splits.json`,一張卡一筆,記下每一段的**繁中與日文原文子字串**、當時的卡文雜湊、與判定票號。兩側都要給——489 張兩側句數不一致,推不出來。骨架讀拆句表把整團切開;沒有紀錄的卡維持整團暫記為 `index: "1"` 的單一效果句。
- 拆句表的三道驗證,任何一道失敗即整筆不寫入、列進待審:
  1. **無遺漏覆蓋** —— 段落按順序串接、忽略空白後必須等於原文。「連續子字串」擋得住竄改但擋不住**漏掉**,而漏掉是判定者唯一的沉默失效模式(2,449 張連換行提示都沒有)。這條同時是卡文勘誤的偵測器。
  2. **引用交叉驗證** —— [[補足情報]]的 `『原文』` 引用不得被拆點切成兩半。2,150 張整團有這種引用,不需要標準答案就能自動檢查,建置報告的違反筆數必須為 0。
  3. **卡文變動即失效** —— 整筆退回未拆狀態,而不是保留舊拆點。保留失效的斷言會讓歸屬階梯在假前提上開火(票11 的錯誤)。
- 拆點**不由[[規則層]]產生**,官方 `『原文』` 引用也只當提示與驗證器、不當拆點(ADR-0003)。實測:「每個句號都是一段」這條最直觀的規則,在 2,184 張有引用可驗的整團裡被打臉 497 張(22.8%)。
- 拆出來的段落 `index`:[[效果外文本]]段為 `"0"` / `"0-2"` / `"0-3"`(59 張同時含召喚條件與使用次數限制,一個 `"0"` 不夠),效果句為 `"1"` / `"2"` / `"3"`。`"1"` 沿用整團現在的 index,所以只有一段效果句的卡拆完後 index 不變,重跑合併天然對得回去、不製造孤兒。段落**順序照原文**(無遺漏覆蓋要求),所以尾端抽出來的效果外文本段會排在效果句後面,index 序列長成 `"1"`、`"0"`。
- 判定者拆不出來的整團**不寫進拆句表**:結果檔給空 `clauses` + `note`,那一張卡維持未拆、下一票會再出現一次(票13 開的出口,200 張裡 3 張走它)。「留空並記理由」在拆句這一側因此與判定那一側同構。
- 靈擺卡以卡文標頭字串區分兩段;`【怪獸敘述】`(通常怪獸)與 `【怪獸效果】`(效果怪獸)是可靠的判別記號,不可只依賴資料庫 type 位元——38 張靈擺通常怪獸同時帶有 Normal 與 Pendulum 位元,只看位元會誤判整張為敘述文。`【怪獸敘述】` 段整段丟棄。
- 官方以 `【●の効果について】`、`【『●』の効果について】`、`【１つ目の●…】` 等標頭描述的子效果,拆成獨立效果句(`index` 形如 `"①-●1"`),各自單一類型。**票16 加開第二種依據**:官方不開標頭、改以行內 `『●…』` 引用逐項給裁定時同樣拆(只對 `〜は以下の効果を得る。●…` 這種賦予型領起句開火),判準與驗證見 ADR-0003 的修訂一節。

### 官方明示抽取

- 抽取對象:補足情報中的「誘発即時効果」「誘発効果」「起動効果」「永続効果」「分類されない効果」與「必ず発動する効果です」。
- **否定句優先判定**:含「いずれにも分類されない」者(947 筆)一律判為無種類效果,不得因該句列舉了其他類型詞而多重比對。
- **禁止使用「効果ではありません」**(4,432 筆)作為任何判定依據——它多為「対象を取る効果ではありません」這類限定否定,語意與效果分類無關。此禁令必須有對應測試。
- 「〜は効果として扱いません」視為效果外文本的官方明示。若它指向的段落不在前言段,列進報告請人工判讀,不自動拆分(**票16 收窄**:引用涵蓋整個效果句時自動套用,見 Story 24)。官方寫過八種等義變體(`効果` 直接接 `扱い`:`として扱いません` / `として扱われません` / `としては扱いません` / `としては扱われません` / `としての扱いではありません` / `としての扱いません` / `の扱いではありません` / `の扱いにはなりません`),全部視為同一種明示、走同一條歸屬路徑(票10 實測 1,712 行)。`効果` 與 `扱い` 之間夾了別的詞的(「効果で破壊された扱いにはなりません」「効果ダメージの扱いではありません」)講的是別件事,不得混入。
- **括弧內的否定不算效果外明示**:官方把「不算哪一種效果」的補述寫在句尾括弧裡(「(モンスター効果として扱われます。罠カードの効果としては扱われません。)」),那是限定否定。實測只在括弧內出現的 7 行全是這一種,其中兩行的括弧外正是一句貨真價實的類型明示,整行改判會把那個類型吃掉。

**歸屬判定(官方明示講的是哪一個效果句)** 是本模組最容易出錯的部分,因為補足情報會為了解說而引用**其他卡**的效果文。統一原則:**證據唯一且明確才自動套用,任何歧義一律交判定者。**

五種對位方式,依序嘗試,可累加(同一張卡的不同效果可能由不同方式對位)。括號內的覆蓋條數是 票03 定案時的估算;票11 之後的實測值為標頭 8,521 / 序號 1,574 / 原文 2,100 / 卡名限定 280 / 一般單效果 103,以 `docs/effect_kind_rules.md` 旁的建置報告為準:

1. **標頭對位** —— `【①の効果について】` 系列標頭直接指名編號(覆蓋 8,193 條)。標頭一律是**新段的開始**,官方偶爾把下一段的標頭黏在前一行的尾巴(實測 15 行),歸屬前先切成獨立的一行;只認**行尾**,行中間的 `【…】` 是強調而不是標頭(實測 1 行,オーディンの眼 88069166「効果の発動を伴わない【カードの発動】だけであれば〜」)。
2. **序號引用對位** —— 明示句以 `『①』` 純序號引用效果(例:「■『①』のモンスター効果は、フィールドで発動する誘発効果です。」)。實測 775 張卡 / 1,591 行,**序號在卡文中不存在的對位失敗為 0 筆**,是最可靠的一種(覆蓋 1,584 條)。注意此形式的引號內容極短,以字元長度過濾引號會整批漏掉。
3. **原文引用對位** —— 明示句以 `『效果原文』` 引用整段效果再敘述其類型。把引號內容比對回日文卡文的編號區段定位(覆蓋 1,480 條)。比對前正規化全形/半形數字;引號可能是原文的截斷,取前綴比對。**命中多個編號區段時視為歧義、不採用**(實測 0 筆,但必須實作防護)。
4. **卡名限定 + 單效果卡** —— 明示句以 `「<本卡日文卡名>」の効果は…` 陳述且該卡只有一個效果句(覆蓋 1,498 條)。
5. **一般單效果整卡套用** —— 明示句無任何歸屬標記且該卡只有一個效果句(覆蓋 1,004 條)。

階梯四、五的「只有一個效果句」必須是**已經成立的事實**。舊式無編號卡文在依語意拆開之前整團只算一個效果句,那是拆句骨架的暫代值而不是證據,兩道階梯因此對它不開火,一律進「歸屬由判定決定」。理由有二:整團套上一個類型會把只描述其中一段的明示放大成整團的判定(機海竜プレシオン 40160226:第一段無種類、第二段啟動,官方講的是第一段);而且整團從此 `kind` 不再是 `null`,再也進不了拆句用的判定批次,**連自癒的機會都沒有**。階梯二的『①』序號引用不受此限——那是官方自己給的歸屬證據。

判別「這一段是不是未拆的整團」看的是**骨架算出來的 `unsplit` 集合**,不是 `index`——拆完只有一段效果句時 index 仍是 `"1"`,光看字串分不出來。骨架在從無編號卡文生出整團時把它放進 `unsplit`,有[[拆句表]]紀錄時就不放,兩道階梯自然開火。同一個集合早就在必發/選發那一層用著(未拆整團的第一句常是素材指定而非發動子句),概念與傳法一致。

因此**拆句表有紀錄本身就是「這張卡有幾個效果句」的斷言**:判定者拆完之後,3,779 張有補足情報的舊式卡會重新走一次官方明示,票11 撤掉的 1,146 條裡「其實是對的」那一大半會以 `source: "official"` 自動回來——權威等級高於判定,也不占 ADR-0002 的判定額度。判定者的類型與重跑出來的官方明示不一致時照票05 的規則走(保留判定 + 進衝突清單),但額外把**整張卡**標 `needs_review`:這條路徑上不一致的最可能成因是拆錯而不是判錯,只標一行會讓人去看錯的東西。

**必須排除、一律交判定者決定歸屬的情況**:

- 明示句以 `「」` 提到的卡名**只有別張卡**、且無序號或原文引用。這是深海の戦士型的陷阱:該卡補足既有指向自己的「『深海の戦士』の効果は永続効果です」(走階梯 4),也有為了解說「海」而引用他卡效果文的段落(必須忽略)。
- `『效果原文』` 引號對不回本卡卡文(22 筆,抽查為官方引用了其他卡)。
- `『效果原文』` 引號同時命中多個編號區段。
- 卡名限定但卡文有多個效果。
- 以上皆不適用的多效果卡。

「只提別卡名」與「卡名限定但多效果」兩項的筆數取決於計數約定(一卡算一次 vs 一行算一次、是否跳過無引號行),不同寫法可差三倍以上。它們是報告項目而非驗收門檻——驗收看的是行為(這些情況不得自動套用),數字只進報告。

這批的類型值仍取自官方,`source` 記為 `official`,並列入報告的「歸屬由判定決定」清單供抽查;判定過程記錄於該票的結果檔。

### 必發/選發

三層:官方明示「必ず発動する効果です」(1,164 筆)→ 必發;日文效果句的發動子句以「できる/できます」結尾 → 選發,否則 → 必發;規則判不出(找不到發動子句)才送判定。僅誘發即時、誘發兩類寫值。

### 判定流程

- 待判量:非通常卡效果句約 21,947 條,官方明示覆蓋 13,756 條(62.7%),剩 8,191 條分佈於 5,868 張卡。
- 每卡輸入實測平均約 600 字元(繁中 111 + 日文 156 + 補足 332),中位 587、p90 949、p99 1299。以 1M 上下文的 50% 為上限、扣除固定開銷後,**每票 300 張卡,共 20 票**。
- 判定票數**固定不遞減**:新規則不從批次中移除任何行(ADR-0002)。
- 批次檔即時產生:每票開始時跑當前規則層、取出下一批未判定的卡,確保吃到最新的影子預測。
- 每票流程:讀規範文件 → 讀批次檔 → 逐卡判定 → 寫入獨立結果檔 → 自檢集合一致 → 合併進標記表 → 歸納規則。
- 補足情報**不裁剪**,全量餵入,以最大化判定準確率為優先。

### 規則歸納

- 規則登記於 `docs/effect_kind_rules.md`:編號、判別條件、對應類型、覆蓋條數、新增票號、變更理由與票號。**定義寫在 `script/tag_card/rules.py`,這份 md 是建置流程的產出物**——覆蓋條數與一致率必須由全表算出來後回寫,不靠人工計數,所以它不能是手寫檔。
- 每條規則須覆蓋 ≥ 8 條效果句;低於門檻視為過擬合特例,不進規則層。
- 規則層的管轄範圍是**效果句**;前言段的類型由位置規則決定(第一個效果編號之前的段落即效果外文本),不歸效果類型規則管。
- 規則變更僅三種情況:同票內出現 2 筆以上影子預測不一致(條件太寬)、與新規則判別條件重疊且結論不同(擇一)、兩條相似規則可合併(記為 `R12 + R15 → R31`,舊條標記合併去向不刪行)。
- 任何變更都觸發全表重跑並逐行列出差異。
- **[[官方明示]]是規則層的驗證集,不是被規則檢查的對象**:規則對官方明示那批效果句的一致率單獨計算(門檻 99%),不一致的另立清單。這與必發/選發的獨立驗證是同一個做法,也讓每條規則在判定票開跑之前就有一次獨立驗證。衝突清單只收「影子預測 vs 判定產出(`llm` / `llm_then_rule` / `manual`)」的不一致——收斂條件看的是判定與規則有沒有互相打臉,官方那邊的例外由使用者逐條裁決。
- 收斂條件(可機器檢查):全表跑完一輪後規則清單無異動(比對規則**定義**的指紋,覆蓋條數變動不算異動) + 每條規則覆蓋 ≥ 8 + 衝突清單為空。

### 判定規範文件

`docs/effect_kind_guide.md`:六類定義、判別流程、官方例句、以及歷史易錯區分(「只要OO在怪獸區域存在」= 永續;裝備方向「裝備此卡的怪獸」vs「此卡裝備的OO」;「…時,可以」完成式事件的發動子句掃描邊界)。此文件是所有判定票的共同 prompt,也是遮蔽測試失敗時的修正對象。

### 範圍邊界

- 無官方補足依據的卡照常收錄,`confidence: low`,獨立清單供優先審查。**有效果句**而無官方依據的僅 41 張(24 張有快取無補足 + 17 張無快取)——無補足的卡雖有 697 張,但其中 673 張是純通常怪獸,`clauses` 本來就是空陣列,沒有效果句需要標記。不重爬——faq-info 票已抽樣確認無補足是官方常態。
- 20 張無官方 Q&A 快取的卡研判為新卡(具象天使、異宇宙等系列),本次不處理。原先的 114 張已於 2026-08-08 補爬 94 張並整合進補足情報來源檔。

## Testing Decisions

- 測試只驗證接縫的外部行為:給定合成的卡片總表條目與補足情報條目,斷言回傳的 `entries` 欄位值與 `report` 內容。不測內部函式、不測拆句器的中間產物。
- 受測模組:`build_tag_cards` 這一個純函式,外加 `rules` 的規則清單自檢(`rules.problems` / `active` / `merged_groups` / `digest`)與[[遮蔽測試]]的兩個接縫(`masked.sample_masked` / `masked.score_masked`)。後者是獨立的量測工具而不是建置管線的一部分——它吃的是**已經產出的**標記表,輸出是一份遮蔽樣本與一份 recall 報告,因此不掛在 `build_tag_cards` 底下,自成一個接縫對。後者測的是**規則清單這份資料本身合不合法**(編號、變更有無票號與正當理由、合併去向)而不是管線的中間產物;它是接縫測不到的——接縫吃的永遠是 repo 裡那一份規則清單,而要測的正是「換一份壞的進來會怎樣」。CLI 薄殼不納入自動測試,與 card_list 的 `build_cards`/`update_cards`、faq_info 的 `build_faq_info`/`recrawl_faq` 同等待遇。
- 先例:`script/card_list/test_cardlist.py` 與 `script/faq_info/test_faqinfo.py` —— unittest、fixture 於測試內程式化建立、不碰網路不碰真實資料檔。
- 應覆蓋的情境:
  - 有編號卡文的拆句與繁中/日文對位
  - **文中編號不切割**(「這個卡名的①②效果…」必須留在前言段內)
  - 前言段抽取與 `role` 三種子分類的判定
  - 無編號舊文本的拆句結果驗證(連續子字串、無遺漏覆蓋、官方引用不得被切開)
  - 拆句表套用後,骨架不再把該卡放進 `unsplit`,階梯四、五因此對它開火
  - 卡文變動使拆句表失效時退回整團,不沿用舊拆點
  - 拆完重跑的官方明示與判定者的類型不一致時,整張卡標 `needs_review`
  - 靈擺卡雙 section、兩段各自從①編號不衝突
  - 靈擺通常怪獸只抽靈擺段、`【怪獸敘述】`丟棄
  - 純通常怪獸為空 `clauses`
  - 官方明示抽取:一般肯定句、`【①の効果について】` 逐效果對位
  - **`『①』` 序號引用對位**(短引號不得被長度過濾掉)
  - **`『效果原文』` 引用對位**:能定位到正確的編號區段
  - 原文引用的正規化(全形/半形數字)與前綴比對(引號為截斷時)
  - 原文引用對不回本卡卡文時**不猜測歸屬**、進報告
  - 原文引用**同時命中多個編號區段**時視為歧義、不採用
  - **明示句只提到別張卡名時不產生任何判定**(深海の戦士型陷阱的回歸測試)
  - 卡名限定 + 單效果卡:套用到該唯一效果句
  - 卡名限定 + 多效果卡:留待判定決定歸屬
  - 無任何歸屬標記的單效果卡:整卡套用
  - 無任何對位證據的多效果卡:留待判定決定歸屬,並進「歸屬由判定決定」清單
  - **階梯四、五對未拆的舊式整團不開火**,一律留待判定決定歸屬(票11)
  - **「いずれにも分類されない」判為無種類效果**(否定句優先)
  - **「効果ではありません」不得產生任何判定**(禁令回歸測試)
  - 「効果として扱いません」的效果外明示(含八種變體),以及不在前言段時只報告不處理
  - **「効果の扱いではありません」認得、「効果ではありません」仍然忽略**(兩者只差三個字)
  - 括弧內的限定否定不當作效果外明示,括弧外的類型明示照常生效
  - 必發/選發:官方明示、「できる」規則、規則判不出時留 `null` 待判
  - 影子預測寫入 `rule_predicted` 而不寫 `kind`
  - 影子預測與判定結果一致時 `source` 升為 `llm_then_rule`
  - 影子預測與判定不一致時不動資料、進衝突清單
  - 既有標記表的 `manual` / `official` 行不被覆蓋
  - `text_hash` 變動時標記待複查而非覆蓋
  - 繁中/日文編號數量不一致時進報告
  - 多卡整合的排序穩定性
