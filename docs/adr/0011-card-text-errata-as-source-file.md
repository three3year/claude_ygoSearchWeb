# 卡文勘誤住在來源檔,建置期套用,失配即建置失敗

繁中卡文來源(salix5 cdb)偶有誤譯。第一例:`84488827` 侵入魔 巨角的「上級召喚成功時,**可以**從以下效果選擇1個效果發動」——日文原文「以下の効果から１つを選択して**発動する**」是必發,[[效果標記表]]也早判必發(official),「可以」是任意語氣的誤植,必發效果的卡文不能有「可」。

修正記在來源檔 `data/text_errata.json`([[卡文勘誤表]]):一筆一個誤譯,記卡片密碼、原文子字串、修正後子字串、理由、票號。建置[[卡片總表]]時套用;原文子字串必須在該卡卡文出現**恰好一次**,比對不到(例如上游自己修好了)或不唯一即**建置失敗吵出來**——與[[值域正典]]同一個「把沉默的失效換成吵鬧的失效」精神,不無聲跳過讓「勘誤還生不生效」變成猜測。

拆句表與效果標記表存著同一句的 `text_zh` 與雜湊,由 `script/tag_card/sync_errata_texts.py` 同票一次性同步(只動文字與雜湊,判定欄位原封不動);未來每筆新勘誤重跑同一支。[[前端索引]]對被勘誤的卡多帶 `og` 欄位——勘誤**前**的來源卡文原樣,由修正後子字串逆推(逆推不唯一同樣建置失敗),前端「顯示原文」鈕讀它。

## Considered Options

- **直接手改 cards.json(加拆句表/標記表)**:改動最小,但總表每次 `update_cards.py` 都由 cdb 整份重建,手改必被蓋回;等於每次更新重做一次,而且沒有任何檔案記得「這裡改過、為什麼改」。
- **只在前端顯示時替換**:資料層照舊是錯的——效果文搜尋比對錯字、下載 `data.js` 的人拿到錯字;替換表藏在呈現層也違反「正典住建置期」(ADR-0008)。
- **勘誤表來源檔、建置期套用**(採用):修正在資料源頭一次生效,搜尋、顯示、下游全部一致;代價是三份檔案的同步紀律,由同步腳本與建置檢查承接。

## Consequences

- 勘誤後文字是本站的正式卡文:效果文搜尋只比對它;原文欄位不進搜尋。
- 「顯示原文」鈕只長在被勘誤的卡上(目前 1 張)——全量帶原文 gzip 要 +340 KB,而未勘誤的卡的原文就是畫面上那份文字。
- 上游修正該誤譯的那天,建置失敗提醒刪掉該筆勘誤,`og` 與鈕隨之消失。
- 勘誤的差值報告會在套用當次列出該卡 `desc` 變動,是預期中的訊號。
