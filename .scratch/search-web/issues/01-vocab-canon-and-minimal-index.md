# 01 — 值域正典與最小索引:網頁列得出卡片

**What to build:** 雙擊 `web/index.html` 就看到 14,207 張卡分頁列出——卡名、[[卡片種類]]大類、
卡文逐[[效果句]]分行。這是整個站的骨架:[[值域正典]]、[[前端索引]]的建置管線、最小的呈現層
與分頁,一次貫通。沒有搜尋、沒有卡圖、沒有怪獸參數,那些是後面的票。

新增 `script/web/`,與 `script/card_list/`、`script/faq_info/`、`script/tag_card/` 並列,
沿用同一個架構模式:**單一純函式管線 + CLI 薄殼,薄殼不納入自動測試**。

本票建立兩個測試接縫,後面每一張票都靠它們:

- **接縫 1**:`build_index(卡片總表條目, 效果標記表條目) -> (index, report)`
- **接縫 2**:[[值域正典]]自檢 `vocab.problems()` / `vocab.digest()`

四道一致性檢查長在 `report` 裡而不是另開接縫;CLI 薄殼因此只是「讀檔 → 呼叫 → 寫
`web/data.js` → 印報告 → 依 problems 決定 exit code」。

前端遵守零建置協定(ADR-0007):無 npm、無 bundler、無框架、無 ES modules,
`<script>` 逐一載入、模組是 IIFE 閉包。索引是 `window.CARD_DATA=…` 的 `.js` 而不是
`.json`,因為 `file://` 下 `fetch` 會被 CORS 擋。

**Blocked by:** card-list 票 07 — 非怪獸卡不得帶怪獸參數(已 resolved)

## Comments

2026-08-13 實作完成。`script/web/` 三支:`vocab.py`(正典 + 自檢)、`webindex.py`(管線)、
`build_index.py`(CLI 薄殼);測試 `test_vocab.py` / `test_webindex.py` 共 48 條。
前端 `web/index.html` + `style.css` + `js/{util,render,main}.js`,索引 `web/data.js`
(6.03 MB、gzip 1.54 MB,比 spec 用中文字串估的 7.82 / 1.75 MB 小,因為值改存短碼)。

**[[卡片子類型]]是 24 種而不是 23。** CONTEXT.md 寫「實際出現 23 種」但它自己列的是 24 個
(怪獸側 15 + 魔法側 6 + 陷阱側 3);spec 的計數表列的則是 20 個**位元**。三個數字數的是
不同東西:cdb 位元只有 20 個(`通常` 只有怪獸側有位元,`儀式` 與 `永續` 跨側共用同一個
位元),而值域成員一側一份、共 24 個,加上登記但 0 張的[[衍生物]]是 25。正典採一側一份
(`sub_m` / `sub_s` / `sub_t` 三個值域),否則 `0x80` 會同時對到儀式怪獸與儀式魔法兩個
成員,位元重疊檢查就得為此開例外。CONTEXT.md 已改寫這一段。

**覆蓋檢查的第三種缺口是真的存在的,但它是故事文而不是漏字。** spec 記的已知缺口是兩種
(靈擺標頭 759 處、`※` 別名 117 處),實測還有第三種:37 張靈擺通常怪獸的
`【怪獸敘述】` + 故事文(其中 4 張連靈擺效果都沒有,整張卡零效果句)。故事文有實際文字,
放它過去等於在檢查上開一個吃掉真文字的洞,所以做法是**把它抽進 `d`**——`d` 因此不只是
「沒有效果句的 689 張」,而是「這張卡的故事文」,靈擺通常怪獸同時有 `tx` 與 `d`。抽完之後
缺口確實只剩兩種:段落標頭 763 處(759 + 4 張零效果句卡的標頭)、`※` 別名 117 處。
spec 說的「5 處標頭碎片」在正規化(忽略空白)之後不存在,不需要第三條規則。

**四道檢查加了兩道同族的**:`type` 出現正典沒解釋的位元(沒登記的位元會被 bitmask 解碼
靜靜忽略,那正是 ADR-0008 要消滅的形狀;`0x100` 罠モンスター位元與 `0x8000` Rush 位元
現在 0 張,哪天冒出來要吵)、卡片沒有[[效果標記表]]條目。另外「索引出現 `VOCAB` 沒有的值」
拆成兩個方向:來源值對不到短碼(可測,餵一個沒登記的[[效果類型]]進去就會倒)、短碼不在
`window.VOCAB` 的按鈕清單裡(值域登記了碼卻沒做成按鈕——ADR-0008 說的「換個地方發生的
同一個失效模式」;這個方向要等票02 帶進 `s` 欄位才會有真的觸發路徑,[[衍生物]]就是它)。

**「總表有卡而索引沒有」不是同義反覆**:大類解不出來(`type` 沒有怪獸/魔法/陷阱位元)的
卡不進索引——它連一顆按鈕都對不到,進去也是搜不到的死資料——由這道檢查報上去讓建置失敗。
測試就是餵一張只有融合位元的卡。密碼重複另有一道(索引以密碼為鍵,重複會被併掉)。

**建置時間與來源檔雜湊由薄殼給進純函式**,管線自己不讀時鐘也不讀檔,「同一份輸入兩次建置
逐位元組相同」因此成立(以真實資料驗過:兩次 `serialize_index` 的 6,323,311 bytes 相同)。

**效果類型的中文標籤直接顯示在每一行卡文前**(`.eff-kind`)。票01 的驗收沒要求,但這是
ADR-0008 的鏈路(建置期短碼 → `window.VOCAB` → 畫面中文)唯一看得見的證據,而且成本是
兩行。票04/06 要在同一位置掛命中 badge 時可以直接換掉。

**子類型的中文名改成跟卡文一致**(使用者裁示):`同調 / 調整 / 同盟` → `同步 / 協調 /
聯合`。CONTEXT.md 原本那三個詞是另一套譯法,站上顯示的繁中卡文(salix5 cdb)寫的是
同步 945 次、協調 774 次、聯合 44 次,而同調 / 同盟 各 0 次、調整 1 次。使用者在同一個
畫面上讀卡文也讀按鈕,兩邊用不同的詞指同一件事會看起來像兩件事。其餘 21 個子類型名稱
本來就一致。改的是正典一處(`vocab.py`)+ CONTEXT.md 的詞彙定義,索引重生;
`vocab_digest` 因此從 `02c8fdab8158e9cb` 變成新值——正典動過,看 META 就知道。
