# Spec: 文本格式規範與三級盤點(text-format)

Status: ready-for-agent

2026-08-22 盤問定案(/grill-with-docs)。研究素材見 [research-sources.md](research-sources.md)。

## Problem Statement

庫內 14,207 張卡的繁中卡文混雜兩個世代:OCG 2014 年 9 期起的①②編號新格式,與其之前的舊式無編號文本。[[拆句表]]與 ADR-0003 已為 3,805 段舊式卡文解決了「怎麼斷句」,但沒有處理「格式本身老舊」——舊文本沒有效果編號、沒有條件/cost/處理的標準句構,讀者無法像新卡一樣從文本直接推出效果分類與時點。

盤問期間查證出一個關鍵事實:這些無①卡的**官方日文源頭也全是舊文本(0 例外)**——Konami 從未再錄改寫它們,查牌網只是忠實翻譯舊日文。所以「等官方改、等查牌網跟」是等不到的;要現代化只能自訂規範、自行改寫,而且**沒有任何一張卡有官方新文本可對照**。

同時,repo 裡沒有任何文本格式規範文件。TCG 的 PSCT(2011,官方七篇)與 OCG 9 期格式(2014,無官方文件、僅社群整理)的知識散落站外,新卡譯文是否符合規範也無從稽核。未來想逐批改寫舊文本、稽核新卡,目前既無規則可依、也無工作佇列。

## Solution

三樣產出,做完即收工:

1. **文本格式規範文件** `docs/text_format_guide.md`:逐條三欄對照(TCG PSCT ↔ OCG 9 期日文 ↔ 查牌網中文句型),擬出本站中文規範句;每條標注來源層級(官方/社群共識/庫內實證);另立「舊→新句型對應」章節——這是未來改寫唯一的憑據。
2. **發售日資料**:從既有來源 YGOPRODeck 取 `ocg_date`,新增來源檔。
3. **三級分類報表**:可重跑的掃庫腳本,把全庫分成三個佇列——舊文本(改寫佇列)、官方已改寫(優先稽核佇列)、新格式新卡(一般稽核佇列);改寫佇列依「所需對應表條目 × 卡種」多標籤分群,未來一批共用同一組對應規則。

未來的改寫管線(本次不執行)寫入本 spec 作為既定架構,見 Implementation Decisions 末節。

## User Stories

1. 作為站主,我想要一份中文文本格式規範,讓未來改寫舊卡文時有據可依,而不是每張卡臨場發明句型。
2. 作為站主,我想要規範的每一條都標注來源層級(官方/社群共識/庫內實證),讓日後對某條規則起疑時知道它可信多少。
3. 作為站主,我想要規範以三欄對照呈現(PSCT ↔ OCG 日文 ↔ 查牌網中文),讓爭議時能回溯到兩套官方脈絡的原意。
4. 作為站主,我想要一章「舊→新句型對應表」,讓改寫工作變成查表套用,而不是自由翻譯。
5. 作為站主,我想要知道庫內哪些卡文是舊文本,讓改寫工程有明確的工作佇列。
6. 作為站主,我想要舊文本判定沿用 [[拆句表]]管線同一把尺(段為單位、排除純通常怪獸與風味文),讓兩邊數字永遠對得上。
7. 作為站主,我想要區分「官方已改寫的舊卡」與「生來就是新格式的新卡」,讓稽核可以優先看前者(官方機械式改寫、譯文品質更可疑)。
8. 作為站主,我想要每張卡帶 OCG 首發日,讓報表能以時間排序、分批。
9. 作為站主,我想要查不到發售日的卡被標成「日期不明」單獨列出,而不是被硬塞進某一級。
10. 作為站主,我想要改寫佇列依所需對應表條目分群,讓同一批改寫共用同一組規則、好審好驗。
11. 作為站主,我想要報表可以在資料更新後重跑,讓清單永不過時。
12. 作為站主,我想要一份「含①卡的舊詞彙訊號命中」附錄(明示不保證準確),讓人工抽查有起點,而不是把偽陽性混進正式佇列。
13. 作為未來的改寫 agent,我想要規範文件裡的中文規範句有實際卡例佐證,讓我照著寫時不會偏離庫內既有新卡風格。
14. 作為未來的改寫 agent,我想要 spec 裡寫明改寫管線(日文基底→翻譯→對照查牌網→檢規範→改寫表進站),讓我開工時不必重新盤問架構。
15. 作為網站使用者,我(間接)想要舊卡文最終被現代化成可判讀的新格式,讓我不用查裁定也能讀懂舊卡——本 feature 是這件事的前置。

## Implementation Decisions

### 判準與分類

- **舊文本判準:①編號有無,單一機檢判準**。沿用 tagcard 管線 `pending_split` 定義:段為單位、排除純通常怪獸(`MONSTER && NORMAL && !PENDULUM`)與【怪獸敘述】風味文段,基準集合 **3,805 段**。
- **放棄句型機檢**:庫內實證顯示詞彙掃描偽陽性為主、真混合案例(有①但帶無編號段)全庫僅 3 張靈擺卡且管線已按段處理。句型訊號只進人工抽查附錄。
- **三級分類**:
  - **舊文本** = 無①段 → 改寫佇列。
  - **官方已改寫** = 有① 且 OCG 首發日在 9 期界日(2014-03-21,ST14 發售日)之前 → 優先稽核佇列。
  - **新格式新卡** = 有① 且 9 期界日(含)之後首發 → 一般稽核佇列。
  - 查無 `ocg_date` → 「日期不明」獨立列出,不猜。
- 發售日只作報表欄位與稽核排序,**不進[[前端索引]]、不做搜尋軸**(search-web spec 明文不做發售日搜尋,不因本 feature 翻案)。

### 資料與模組

- 新來源:YGOPRODeck API `misc_info` 的 `ocg_date`,一次抓齊存 `data/sources/`,納入既有[[資料更新時間]]機制。
- 新模組 `script/text_format/`:核心是**純函式分類器**——輸入一張卡的(desc 段落、`ocg_date`),輸出(三級分類、所需對應表條目標籤)。分段邏輯 import `script/tag_card/tagcard.py` 既有的 `_segments`/`_cut_points`,不重造尺。
- 對應表條目的偵測樣式(regex 清單)作為模組內資料維護;它服務報表分群,不是建置關卡。
- 報表輸出到 `.scratch/text-format/`(markdown),分群 = 對應表條目(多標籤)× 卡種;附錄一頁舊詞彙訊號命中清單。

### 規範文件

- `docs/text_format_guide.md`,命名比照 `effect_kind_guide.md`。
- 結構:逐條三欄對照(TCG PSCT ↔ OCG 9 期日文 ↔ 查牌網中文句型)+ 本站中文規範句;每條標來源層級;「舊→新句型對應」獨立成章。
- 對應章節建法**雙向**:從規則反推對應條目,再抽 3,805 段樣本驗證覆蓋與誤報。
- OCG 側無官方文件:採信遊戯王カードWiki 等社群一級整理,逐條標「社群共識」;能在庫內 10,402 張新格式卡找到實例者升級標「庫內實證」。

### 詞彙與文件配套

- `CONTEXT.md` 新增詞條:「舊式卡文/新式卡文」(以①編號段為界的操作型定義)、「文本格式規範」。與[[卡文勘誤表]]明確區隔:勘誤表=修誤譯,格式規範=管句型。
- 「文本改寫表」機制屬未來 feature,本次只在規範文件與本 spec 定位它,不建 CONTEXT 詞條、不實作。

### 未來管線(既定架構,本次不執行)

以 `faq_info.json` 官方日文卡文為基底 → 依三級分類取出佇列 → 舊文本依規範翻譯成中文新文本 → 對照查牌網譯文互查語意缺漏 → 檢查中文符合文字描述規範 → 成果經新設「文本改寫表」來源檔進站(與[[卡文勘誤表]]並列:勘誤=修誤譯,改寫=格式現代化;前端原文對照機制可沿用)。

## Testing Decisions

- 只測外部行為:餵合成卡片記錄給分類器純函式,斷言(分類、標籤)輸出;不測內部 regex 構造。
- 必測邊界:9 期界日當日/前一日/後一日;無 `ocg_date`;有①但帶無編號段的靈擺卡(11067666 型,段分類不同級);純通常怪獸排除;只剩風味文的靈擺通常怪獸(5 張型)。
- 與管線一致性:分類器對真實 `data/cards.json` 跑出的舊文本段數必須等於 tagcard 報告的 `pending_split`(同一把尺的迴歸檢查)。
- Prior art:`script/tag_card/test_sync_errata.py`(合成記錄、冪等、dry-run 慣例)。
- 報表產生器是薄殼,不立測試。

## Out of Scope

- 任何卡文的實際翻譯與改寫;「文本改寫表」來源檔的實作。
- 對照查牌網找語意缺漏的執行;10,402 張新格式卡的逐卡稽核執行。
- 前端任何變更(不加欄位、不加鈕、不加搜尋軸;發售日不進[[前端索引]])。
- 官方效果 Errata(效果修訂)議題——本 feature 只管格式,不管效果內容變動。

## Further Notes

- 界日 2014-03-21 取自官方 ST14 商品頁,是 OCG 9 期首個新格式產品發售日。
- PSCT 是 TCG 專屬(2011-07 起),OCG 從未採用;「中文規範」實質是以 OCG 9 期格式為骨架、吸收 PSCT 邏輯連接詞精神的自訂規範。
- 庫內統計、七篇 PSCT 逐條、OCG 9 期逐條與全部來源 URL 已落檔於 [research-sources.md](research-sources.md)。
