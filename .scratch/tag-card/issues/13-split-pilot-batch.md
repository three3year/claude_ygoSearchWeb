# 13 — 拆句試點票(第一批 200 張)

**What to build:** 第一張判定票,也是拆句判準的產生器。拿「要拆+判」系列的第 1 批 200 張舊式無編號卡,一次做完拆句與[[效果類型]]判定,把打臉的地方變成 `docs/effect_kind_guide.md` §8 的新判準,並用實際成本定出其餘判定票的張數與票數。

**為什麼要試點而不是直接排 34 張票**:拆句**沒有現成的標準答案集**——[[官方明示]]只寫類型不寫邊界,所以事先歸納的拆句規則驗不了(ADR-0003)。實測佐證:最直觀的「每個句號都是一段」在 2,184 張有官方引用可驗的整團裡被打臉 **497 張(22.8%)**。判準只能像票07 養 `effect_kind_guide.md` 那樣,被實測一輪一輪打出來。

**Blocked by:** 06 — 影子預測與規則登記、07 — 遮蔽準確率測試、08 — 拆句表、判定結果合併與批次檔

**Status:** ready-for-agent

- [ ] 只讀規範(`docs/effect_kind_guide.md`)與批次檔,不回頭查其他來源
- [ ] 逐卡輸出:這團拆成幾段、每段的繁中與日文原文子字串、每段的[[效果類型]]與[[必發/選發]]。拆不出來或判不出來的**留空並記理由**,不猜
- [ ] 判定者寫**一個**結果檔;合併程序把拆點路由進[[拆句表]]、把類型路由進[[效果標記表]]。判定者不維護兩個檔的一致性,那由程式保證
- [ ] 跑完三道驗證(無遺漏覆蓋、官方 `『原文』` 引用交叉驗證、集合一致性自檢),失敗的逐筆列出並修到 0
- [ ] **把打臉的案例變成 §8 的新判準**:每一條新判準都要先拿官方引用交叉驗證掃過全部 2,150 張整團,確認它不會把引用切開,才寫進文件——與票06 歸納規則時「先拿整份官方明示驗證過才寫進去」同一個要求

- [ ] 依實際批次數產生其餘判定票檔案,每張含完整自足的工作契約(讀規範 → 讀批次 → 判定 → 寫結果 → 自檢 → 合併 → 歸納規則)

## Comments

批次的 200 張要從 3,804 張裡怎麼抽,本票執行時決定。建議按日文句數分層(1 句 1,113、2 句 1,405、3 句 853、4 句 276、5 句以上 141),讓單句與長團都有樣本——單句整團看似不用拆,但它同樣要走一遍流程:拆句表裡一筆「1 段」的紀錄本身就是「這張卡是單效果卡」的斷言,階梯四、五要的就是這個。

有官方 `『原文』` 引用可交叉驗證的整團佔 2,150 / 3,805,抽樣時最好讓這一群佔多數——它們是唯一能自動判對錯的樣本,試點的價值大半在這裡。
