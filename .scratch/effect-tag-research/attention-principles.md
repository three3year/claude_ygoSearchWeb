## 1. 論文在講什麼(五分鐘版)

「Attention Is All You Need」(Vaswani et al., 2017)提出 **Transformer** 架構,核心主張是:序列建模不需要循環網路(RNN)或卷積,只靠 **注意力機制(attention)** 就夠了。關鍵構件:

- **Self-attention(自注意力)**:句子裡每個詞對其他所有詞計算「相關度權重」,再按權重加權混合各詞的表徵。一個詞的最終表徵因此帶有整句的脈絡——同一個「發動」在「可以發動」與「不能發動」裡會得到不同的向量。
- **Multi-head attention(多頭注意力)**:同時用多組不同的注意力,各自捕捉不同種類的關聯(語法依存、指代、語意角色……)。
- **Positional encoding(位置編碼)**:attention 本身不知道詞序,位置編碼把「第幾個詞」的資訊加進去——所以「A 破壞 B」與「B 破壞 A」不會混同。
- **Encoder / Decoder**:編碼器把輸入句轉成一疊脈絡化向量;解碼器逐詞生成輸出。後世的 BERT 類模型只用編碼器(適合理解/分類),GPT 類只用解碼器(適合生成)。

## 2. 原理如何對應到「效果文 → 用途」

### 2.1 直覺上的對應

效果文是高度公式化的受控語言(官方同一效果必用同一套句型)。判斷用途時,人會注意:

| 人的判斷依據 | Transformer 裡的對應物 |
|---|---|
| 「破壊する」「墓地へ送る」這類動詞短語決定用途主類 | self-attention 讓動詞的表徵吸收其受詞與修飾語的脈絡 |
| 「デッキから…手札に加える」的框架結構(檢索) | multi-head 各自捕捉「來源區域—動作—目的區域」等關聯 |
| 「相手の効果を無効にする」中否定詞的作用對象 | 位置編碼+attention 區分誰無效化誰 |
| 同義句型歸併(「選んで破壊」≈「対象として…破壊」) | 訓練後語意相近的句子落在向量空間相近位置 |

### 2.2 一個常見誤解:attention 權重不是「哪個詞決定用途」的可靠解釋

直覺上會想:把效果句餵進 Transformer,看 attention 權重最高的詞,那就是「決定用途的詞」。**這條路學術上已被充分檢驗過,結論是不可靠**:

- Jain & Wallace (2019)〈Attention is not Explanation〉:同一預測結果可以由截然不同的 attention 分佈達成;權重與梯度式重要度量測相關性弱。
- Wiegreffe & Pinter (2019)〈Attention is not not Explanation〉:反駁部分論點,但也只主張 attention「可作為一種訊號」,而非逐詞歸因的可靠依據。
- 多層多頭的權重互相糾纏,底層 token 早已混入全句資訊,單看某層某頭的權重無法回答「這個詞決定了分類」。

所以「用 attention 原理分析效果文」的正確打開方式**不是**去讀權重圖,而是下面這條。

### 2.3 真正可用的對應物:句向量(sentence embedding)

Transformer 編碼器把整句壓成一個向量,訓練目標(對比學習等)使**語意相近的句子向量相近**。對效果文而言:

- 「デッキから○○1体を手札に加える」的千百種變體,向量彼此靠近 → 自然聚成「檢索」群;
- 「フィールドのカードを破壊する」聚成「破壞除去」群;
- 分群(clustering)後,每群即是一個候選「用途」,再由人或 LLM 命名。

這正是 CONTEXT.md「分類表」詞條預留的路線:**效果句 embedding 分群 → LLM 命名 → 人工審閱定稿**。attention 是讓這些向量「懂脈絡」的底層機制,但工程上你消費的是向量,不是權重。

### 2.4 本專案語料的先天優勢

- 34,390 條效果句已逐句拆好(效果句是既定的基本單位),不需要再斷句。
- 每條都有官方日文原文(`text_ja`)——受控語言、句型一致性極高,是 embedding 聚類的理想輸入;繁中(`text_zh`)可並行對照。
- 已有 16 值 kind 與效果外文本三形態 role 的既有標註,可作為分群品質的**已知結構對照**(例如「素材指定」句應該自己聚成一群——若沒有,說明方法有問題)。

## 3. 四條路線與成本

| 路線 | 做法 | 成本 | 適用性 |
|---|---|---|---|
| (1) 規則式(現況) | 日文正規式比對句型 | 零依賴;每條規則要人工歸納、驗證(現有 R1–R17 模式) | kind 這種**封閉值域**已驗證可行;「用途」是開放集合,句型組合爆炸,規則難以窮舉 |
| (2) embedding 分群(本實驗 A臂) | 開源多語模型算句向量→分群→命名 | 一次性:venv + 模型下載;CPU 全量分鐘~小時級;**零標註資料** | 適合「不知道有哪些用途」的探索期,湧現分類體系;分群邊界需人工審 |
| (3) LLM 逐句標註(現有判定票模式的延伸) | 給定用途清單,LLM 逐條選標籤 | 每句一次推理;需先有定稿的標籤清單 | 適合**定稿後的增量**(新卡只選 tag 不重跑分群)——正是分類表詞條規劃的收尾形態 |
| (4) 自行訓練/微調分類器 | 按論文架構訓練 | 需上千條人工標註 + GPU + 持續維護 | 本專案規模不划算;(2)+(3) 已覆蓋需求 |

結論:**(2) 探索定體系 → 人工審閱定稿 → (3) 增量維護**,與 CONTEXT.md 既定規劃一致。本實驗驗證 (2) 的實際品質。

## 4. 實驗設計(雙臂)

- **語料**:`data/tag_cards.json` 全量 34,390 條效果句(14,207 張卡),中日兩語並行。
- **A臂(embedding 分群)**:隔離 venv 安裝開源多語 sentence-transformers 模型,全量計算 `text_ja` 與 `text_zh` 句向量,分群;中日兩語各自分群後互相對照穩定性。
- **B臂(LLM 直接語意分群)**:按 kind 分層抽 300 條(比例配額、每 kind 至少 2 條、種子 20260920),由 LLM 直接閱讀並分群命名。
- **對照**:兩臂在同 300 條樣本上比較分群一致性(調整蘭德指數 ARI / NMI + 逐群質性檢視)。
- **已知結構驗證**:效果外文本(9,933 條)已有 role 三形態標註,檢驗其是否自然聚出對應群。
- 實驗程式、venv、模型、全量向量均在 session 暫存區,不入 repo 建置鏈;本目錄只收研究文件與精選結果。

## 5. 實驗結果(2026-09-20)

### 5.1 A臂:embedding 分群

- **模型**:`intfloat/multilingual-e5-small`(118M 參數,多語)。原候選 BGE-M3(568M)在純 CPU 上全量預估需數小時,e5-small 實測**全量 34,390 條×中日兩語共約 12 分鐘**(384 維、CPU),作為可行性驗證已足夠;正式開工時可換更大模型。
- **分群**:KMeans,k 掃描 16→96 的 silhouette 在 0.13–0.17 間緩升(文本 embedding 的典型水準——群有結構但邊界軟),取 k=48 深入檢視。
- **已知結構驗證(通過)**:效果外文本的模板句自成高純度群——「這個卡名的①②效果1回合各能使用1次」2,069 條全落同一群(群內 100% 效果外文本)、「①效果只能使用1次」1,587/1,588、「1回合只能發動1張」849/850。素材指定、召喚條件也各自聚成 top1 佔比 24–41% 的專屬群(素材指定按「等級×2」「族+族」等子模板再分)。
- **語意群樣例**(群內 kind 混合、但用途一致——正是「用途」跨 kind 的預期樣貌):
  - 蘇生群(n=1,362):「以墓地1隻怪獸為對象…那隻怪獸特殊召喚」類,誘發/啟動/陷阱混合;
  - 攻守增減群(n=1,189)、送墓群(n=1,056)、自身特召群(n=869)、魔陷破壞群(n=795)、永續耐性/鎖群(n=807)。
- **中日跨語穩定性**:ARI 0.376 / NMI 0.570——中等。日文模板一致性高、繁中譯文句型較散,兩邊分群結構部分對齊;**驗證了「日文原文為主要輸入」的預設**。

### 5.2 B臂:LLM 直接語意分群

300 條分層樣本(kind 比例配額、種子 20260920)逐條閱讀,底向上湧現 **30 群**(4 個效果外群 N1–N4 + 26 個用途群 E01–E26),每條主群 + 次要標籤。分佈:破壞除去 21、自身特召 21、攻守增減 18、展開 15、檢索 14、鎖 14、蘇生 12⋯⋯完整清單見 `b-arm-clusters.json`。
**19.0%(57/300)的條目帶多重用途**(僅效果句為 26.3%)——「破壞並抽卡」類複合效果證實用途標籤必須是多標籤制。

### 5.3 兩臂對照(同 300 條)

| 指標 | B vs A(日文) | B vs A(繁中) |
|---|---|---|
| ARI | 0.237 | 0.241 |
| NMI | **0.625** | 0.619 |

NMI 0.62 表示兩臂捕捉到大量相同結構;ARI 偏低主因**粒度不匹配**(A臂 48 群 vs B臂 30 群)與 A臂部分按「句型框架」而非「用途」切群。落點模式:

- **高頻用途高度集中**:B臂「破壞除去」21 條有 15 條落在 A臂兩個破壞群;「攻守增減」18 條有 10 條落在兩個攻守群;「行動限制/鎖」14 條有 7 條落同一群;三個效果外 N 群幾乎完美對應 A臂模板群。
- **長尾用途散開**:除外、表示形式變更、效果傷害、放置/裝備化等小群(n≤5)在 A臂被按句型分派到不同群——embedding 分群對**頻率低的用途解析度不足**,k 再大也傾向先按句型切。

### 5.4 追加實驗:舊文本干擾驗證與新式卡文子集重跑(2026-09-20)

**問題**:舊卡文本敘述(無①編號的舊式卡文)會不會把「與新卡相同的效果」拉成不同的群?

**驗證:會。** 以「卡片無任何①編號效果句」操作型判定舊文卡,全庫舊文效果句 5,115 條(佔 34,390 的 14.9%)。在全量 k=48 分群中,舊文句高度集中:群47 舊文比例 95.5%(幾乎是純舊文群)、群23 67.9%、群8 60.8%——舊句型(「選擇…破壞」「可以藉由…」等)確實蓋過了用途語意,把同用途效果按文本世代切開。

**處置:新式卡文子集單獨重跑。** 子集 = 新式卡(有①編號段)的效果句、且排除效果外文本(同時落實 §6 建議),共 **19,342 條**,同模型同 k=48 重分群:

- 群像更純粹地按用途聚合:蘇生、手牌特召、解放特召、回收、攻守增減、魔陷破壞、耐性/鎖各自成群,不再有文本世代混雜;
- 中日跨語 ARI 0.260 / NMI 0.496,兩臂對照(樣本交集 165 條)NMI 0.606——數字比全量略低是**預期現象**:全量指標被「效果外模板群」(跨語言、跨方法都極易對齊的送分題)墊高,子集把送分題全部拿掉之後,剩下的才是真效果句的實際難度;
- 檢視網頁已加入資料集切換(全量 vs 新式效果句),對照表新增「A臂群(新式)」欄。

**對分類表線的含意**:分群餵入的語料應以**新式卡文為界**(有①編號段的卡),舊文卡的效果句不進分群;其 tag 於體系定稿後由 LLM 按清單逐句判定補齊(舊文卡多半有官方改寫紀錄或 faq 現行文可援引)。這與 kind 判定線「以官方現行日文為判準」的精神一致。

## 6. 結論與對分類表線的建議

1. **可行性:成立**。Transformer 句向量分群能以零標註成本把 34,390 條效果句聚成語意連貫的群,已知結構(效果外模板)驗證全數通過,高頻用途(破壞/蘇生/攻守/鎖/檢索)的群清晰可命名。原問題的答案:「Attention Is All You Need」的原理**經由句向量這條路**確實能用於判斷效果用途;attention 權重本身則不是可靠工具(§2.2)。
2. **角色定位:候選分群加速器,不是最終裁決者**。silhouette 偏軟、長尾用途按句型散開、19% 條目多重用途(分群只能單指派)——三者都指向 CONTEXT.md 既定流程的正確性:**分群產生候選 → LLM 命名 → 人工審閱定稿**,定稿後新卡由 LLM 逐條選 tag(多標籤在此階段補足)。
3. **開工時的具體參數建議**:
   - 輸入用**日文原文**(跨語對照證實其一致性優勢),繁中僅作人工檢視輔助;
   - 模型升級到 BGE-M3 或 multilingual-e5-large(需接受小時級 CPU 時間或 GPU);
   - **先把效果外文本(9,933 條,已有 role)排除**再分群——它們佔掉大量群位(k=48 中至少 8 群是模板群),排除後同樣的 k 全部用於真效果句;
   - 對長尾用途不追求分群解析,靠 LLM 命名階段合併/拆分群位,或分兩層:粗分群 → 群內二次分群;
   - 分群只是體系定稿的工具,**逐句貼 tag 應由 LLM 按定稿清單多標籤判定**(對齊現行 kind 判定票的流程與三層權威模式)。
4. **紀律確認**:全部實驗在 session 暫存區完成,repo 零新增依賴;本目錄僅收本文件與兩份結果快照(`a-arm-k48-summary.json`、`b-arm-clusters.json`)。
