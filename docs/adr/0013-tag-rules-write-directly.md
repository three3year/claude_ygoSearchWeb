# 效果 Tag 的規則層直接寫入,以遮蔽測試門檻換判定量

[[效果 Tag]](動作維與觸發時機)沒有[[官方明示]]可用:補足情報寫的是效果類型與必發/選發,從不寫「這一句是牌組→手牌的區域移動」。照 ADR-0002 的做法(規則只寫影子預測、每一條效果句都送 LLM 判定)估算,第一期範圍的新式卡文效果句 19,342 條、多標籤逐句判定,判定量是效果類型線的兩倍以上,而其中大半落在極規律的框架句型上(「デッキから…手札に加える」「墓地から…特殊召喚する」)。我們對 tag 線**偏離 ADR-0002**:高確信句型的規則**直接寫入** `tags`(tag 物件標 `src: "rule"`),LLM 判定票只吃規則未命中的長尾。

這是補充而非取代:**ADR-0002 在效果類型線一字不動**。兩線的差別在有沒有免費的驗證集——效果類型的每條規則都有官方明示對照,規則寫錯下一票就炸出衝突;tag 規則沒有這個對照,所以驗證改由三道人造防線承接,直貼權限以通過防線為前提。

## Considered Options

- **照 ADR-0002 全量逐票判定**:與效果類型線同構、最穩,但 19,342 條 × 多標籤的判定成本是該線兩倍以上,且規律句型上 LLM 只是在重複規則已能斷言的事;體系凍結後新卡增量也永遠背著這個成本。
- **規則直貼 + 遮蔽測試門檻 + 抽驗 + rejudge**(採用):框架句型由規則一次寫對,判定量縮到長尾;代價是錯標風險從「下一票就炸」變成「靠抽驗與回報才浮現」,由下述門檻對沖。
- **規則直貼但不設門檻**:前一世代的失效模式(一條寫太寬的規則靜靜誤標數百行),不考慮。

## 規則敘用門檻(決策)

一條 tag 規則要取得直貼權限,必須先通過**遮蔽測試**(`script/tag_card/masked_tags.py`):從該類別的候選句(粗篩命中)抽固定種子樣本,判定者**看不到規則輸出**、只依判定規範獨立標注,再以判定結果為標準答案對規則計分:

- **錯標 0 筆**(precision 100%):規則寫出的每一個 tag,判定者都給了同一個 tag(全部槽位一致)。直貼的錯標會靜靜進資料,一筆都不容。
- **逐規則 recall ≥ 90%**:標準答案裡屬於該規則管轄框架的 tag,規則要復現九成以上;漏掉的句型記錄於規則變更記錄,殘句歸 LLM 票。
- **分母下限 8 句**:樣本內命中不足 8 句的規則,補抽其命中句至 8 句判定後才算數——1/1 的 100% 不是證據(與效果類型線 `MIN_ATTESTED` 同一個道理)。

門檻之外兩道事後防線:每類別首批直貼**人工抽驗 50 條**(通過才視為該類規則層可信;首期數字,之後每期沿用或由期次票調整),以及 **rejudge 流程對 tag 可用**——錯標浮現時走改判票修正,`src: "llm"` 的 tag 與效果類型的判定同權限,`rule` 的 tag 由規則修正後重跑自然更新(規則 tag 不是被保留的判定,是當前規則對當前文本的純函式輸出,見 ADR-0002 對 `source: "rule"` 的同一分界)。

## Consequences

- `tags` 陣列裡 `src: "rule"` 的 tag 每次重跑都重算,規則一改全表跟著變(有逐行差異報告);`src: "llm"` / `"manual"` 的 tag 走「判定一次就算數」的保留與改判規則。同一內容的 tag 兩邊都到達時記 `src: "llm_then_rule"`(雙重確認,與效果類型線同名同義)。
- tag 規則登記於 `script/tag_card/tag_rules.py`、清單回寫 `docs/effect_tag_rules.md`,含判別條件、覆蓋條數、遮蔽測試成績與變更記錄——可稽核性要求與效果類型規則相同。
- 適用邊界:**僅 tag 線**(動作 tag 與觸發時機)。效果類型與必發/選發維持 ADR-0002/ADR-0004,不因本 ADR 取得任何直貼權限。
- 判定票的量從「全量」變成「長尾」,tag seal 的「零空缺」因此定義為:類別粗篩命中的每一條效果句,要嘛帶該類 tag、要嘛有判定紀錄(含「判過、無此類 tag」);粗篩本身的漏網是已接受的殘餘風險,記錄於判定規範。
