# 約束框架 LLM 檢驗:子代理工作說明

你會拿到一份批次檔(`batch-<k>.md`):每張卡一節、每句效果句一段,列出**原文**與程式抽出的**框架**。框架有兩種:

- 動作框架:`框架 n:[位置] 動作(極性)| 對象=… | 來源=… | 目的=…(| 次數/窗口)| 子句=…`
- 約束框架:`框架 n:[約束 類別·子類] 欄位 值・欄位 值 | 子句=…`

你的工作:**只檢查約束框架與「取代規則」**,看原文挑錯,寫成 `findings-<k>.json`。動作框架自己的論元/位置錯誤(對象少吸了定語、位置該是條件卻標效果)不是本輪的範圍,**不要回報**,除非它和取代規則有關(見錯誤類型 5)。

## 約束框架的判準(以此為準,不要用自己的直覺改判)

約束框架記的是效果或卡片「能怎麼用、什麼時候用、怎麼出場」,由句型認出,被認成約束的句子/子句**不再出動作框架**。六種:

1. **限制·次數**(欄位:期間 回合/決鬥/同一連鎖、次數、對象、共用 それぞれ/いずれか１つ)
   - 句首或子句首的「１ターンに１度、」——不論是不是發動句(P 區「…無効にできる」、代破「…代わりに…事ができる」、場地魔法也算);對象記 この効果。寫在 ● 選項裡的屬於那個選項。
   - 註記句「このカード名の①②の効果はそれぞれ１ターンに１度しか使用できない」「このカード名のカードは１ターンに１枚しか発動できない」「この効果は１ターンに１度しか使用できない/まで使用できる」「「名」の①の効果はデュエル中に１度しか…」:對象=は 前的主題原文(含 ①②);「自分は「名」を１ターンに１度しか特殊召喚できない」對象記「「名」の特殊召喚」;「①の方法による特殊召喚は１ターンに１度しかできない」對象記整個主題。一句多個註記(できず、相連)各出一個;「同一チェーン上では発動できない」記同一連鎖 1 次。
   - 括弧註記「（同一チェーン上では１度まで）」「（１ターンに１度のみ）」:對象 この効果。
   - 召喚條件句的「「名」は１ターンに１度、…特殊召喚できる」:次數框架的對象記「「名」の特殊召喚」,另有一個召喚條件框架。
   - **不是**次數框架的:句中的「１度だけ」「もう１度だけ」「１ターンに１度だけ戦闘では破壊されない」——那是效果內容,記在那個動作框架自己的「次數」欄(批次檔動作框架列會多出 `| 次數 1(回合)`)。「自分フィールドに１枚しか表側表示で存在できない」(期間不是回合/決鬥/連鎖)也不是。「S召喚にしか使用できない」是素材用途限制,不是次數。
2. **限制·事件回合禁用**(欄位:事件、禁止):「この効果はこのカードが特殊召喚したターンには発動できない」「…墓地へ送られたターンには使用できない」→ 事件=「このカードが墓地へ送られたターン」(は 後到 ターン 的原文)、禁止=発動/使用。
3. **限制·誓約**(欄位:觸發、動作、形式 只能/不能、範圍、來源):「この効果を発動するターン、自分は機械族モンスターしか特殊召喚できない」「このカードを発動するターン、自分は…」「この方法で特殊召喚したターン、自分は…」「このターン、自分は…しか/を…できない」「この効果の発動後、ターン終了時まで自分は…」——每個否定述語一個框架;しか → 只能、沒有 しか → 不能;範圍=しか 前的片語(定語整段保留)或 を 的對象;「SモンスターしかEXデッキから特殊召喚できない」來源=EXデッキ;「裏側守備表示でしかモンスターを特殊召喚できない」範圍記「モンスター(裏側守備表示で)」。寫在發動句括弧裡的一樣要認。誓約句裡的 特殊召喚/発動/攻撃 否定動作框架**不應再出現**。「このターン、自分は１枚ドローする」沒有否定述語,不是誓約。
4. **限制·召喚條件**(欄位:形式、方式、手續、來源;**只在效果外文本**,編號效果 ①② 裡的同形句照舊是動作框架):「このカードは通常召喚できない」→ 形式 不能通常召喚;「カードの効果でのみ特殊召喚できる」「融合召喚でしか特殊召喚できない」→ 只能以某方式特殊召喚、方式=でのみ/でしか 前的片語;「〜を除外した場合のみ特殊召喚できる」→ 只能以某方式特殊召喚、手續=除外 〜(動作與論元);「〜した場合に特殊召喚できる」(沒寫 のみ)→ 可以某方式特殊召喚;「〜をリリースしてアドバンス召喚できる」「〜の上に重ねてX召喚する事もできる」→ 可以某方式アドバンス召喚/X召喚、手續=リリース/重ねる;「融合召喚及び以下の方法でのみ特殊召喚できる。●…した場合にEXデッキから特殊召喚できる」→ 領起句一個(方式=融合召喚及び以下の方法)、● 各一個(手續)。一句裡「通常召喚できず、…でのみ特殊召喚できる」是兩個框架。召喚手續與 特殊召喚 本身**不應再出動作框架**。不是召喚條件的:「このカードをS召喚する場合、〜もS素材にできる」「L召喚されたターンにはL素材にできない」(素材規則,照舊是動作框架)。
5. **時機**(欄位:回合 自分/相手/雙方、窗口、型態 限定/追加、極性):
   - 發動句(以 発動できる/発動する 收尾)裡括弧外的窗口片語:「自分メインフェイズに発動できる」→ 自分・メインフェイズ・限定;「自分・相手のメインフェイズに」「お互いのメインフェイズに」→ 雙方;「相手ターンに発動できる」→ 相手・ターン・限定;「自分・相手のバトルフェイズ開始時に」→ 雙方・バトルフェイズ開始時;「自分スタンバイフェイズに発動する」也算;「次の自分スタンバイフェイズに」窗口記「次のスタンバイフェイズ」;「相手のメインフェイズ及びバトルフェイズに」窗口記「メインフェイズ及びバトルフェイズ」。窗口可以不帶玩家(「エンドフェイズに発動できる」→ 回合 無)。
   - 註記句「この効果は相手ターンでも発動できる」→ 相手・ターン・**追加**;「この効果はお互いのメインフェイズにのみ発動できる」→ 雙方・限定;「この効果はダメージステップでは発動できず、相手ターンでも発動できる」→ 兩個(ダメージステップ 限定 否定;相手ターン 追加)。
   - **不是**時機的:以事件界定的回合「このカードが特殊召喚したターン」「モンスターが戦闘で破壊された自分・相手ターンに発動できる」「〜したターンのエンドフェイズに」(事件界定,不出時機;前者是事件回合禁用);觸發事件「〜した場合/時に発動できる」(照舊是條件動作框架);選項標籤「●相手ターン：」;效果內容裡的窗口「〜はエンドフェイズに破壊される」「通常召喚に加えて１度だけ、自分メインフェイズに…召喚できる」(記在那個動作框架的「窗口」欄,不是時機框架);「このターンに」「発動ターンによって」。
6. **素材**(欄位:召喚法 融合/同調/超量/連結/儀式、素材清單 每項「字面×數量」;只在效果外文本):素材行「「アマゾネス女王」＋「アマゾネス」モンスター」→ 兩項各 ×1;「「双天」モンスター×２」→ ×2;「チューナー＋チューナー以外のモンスター１体以上」→ チューナー×1、チューナー以外のモンスター×1以上;「効果モンスター２体以上」→ ×2以上;「「名」モンスターを含むモンスター２体」(定語保留)→ ×2;召喚法由卡片子類型帶入(融合怪獸=融合…),降臨句「「光の黄金櫃」により降臨」→ 儀式、清單是那張儀式魔法 ×1。**不是**素材框架的:儀式魔法卡上的「「名」の降臨に必要」、裝備卡的「〜にのみ装備可能」(這些沒框架是對的)。

**取代規則**:被認成約束的句子/子句不再出動作框架——註記句的 使用/発動 否定、誓約句的 特殊召喚 否定、召喚條件的 除外/リリース/特殊召喚、「この効果は…発動できない」整句。但**發動句其餘的代價/條件/效果動作框架必須保留**(「１ターンに１度、手札を１枚捨てて発動できる」的 捨てる 代價、「〜を対象として発動できる」的 対象とする 條件都要在)。

## 錯誤類型(六種,type 欄只能填這些字)

1. `漏認約束`:原文有約束句型,卻沒有對應的約束框架(例:「自分メインフェイズに発動できる」沒出時機;素材行沒出素材;「この効果を発動するターン、自分は…」沒出誓約)。
2. `誤認約束`:出了不該出的約束框架(例:效果內容的窗口被當時機;「このターン、自分は１枚ドローする」被當誓約;編號效果裡的「このカードは特殊召喚できない」被當召喚條件)。
3. `類別/子類判錯`:框架有,但類別或子類錯(例:事件回合禁用被記成時機;誓約被記成召喚條件)。
4. `欄位抽錯`:類別對,欄位值錯或缺(次數的對象/期間/共用、時機的回合/窗口/型態/極性、誓約的動作/形式/範圍/來源、召喚條件的形式/方式/手續/來源、素材的清單/數量/召喚法)。
5. `取代錯誤`:該消失的動作框架還在(誓約句還出 特殊召喚(否定)、註記句還出 使用(否定)、召喚手續還出 除外 動作),或不該消失的動作框架消失了(發動句的代價/條件/效果框架被連帶吃掉)。
6. `次數歸屬判錯`:句首「…度、」被記在動作框架的次數欄,或句中「１度だけ」被記成限制·次數框架。

## 回報格式

寫 `findings-<k>.json`(UTF-8,k 與批次檔相同):一個 JSON 陣列,每筆
`{"card": 卡號(整數), "index": "①"/"②"/"0"/"0-1"…(句的標籤,效果外文本寫它的 index,如 "0"), "frame": 框架序(整數)或 null(漏認時 null), "type": 六種之一, "reason": "一句話,引原文片段說明哪裡錯、應該是什麼"}`。

- 沒有錯就寫 `[]`。
- 一個框架有多個問題各寫一筆;同一句多個框架有錯各寫一筆。
- reason 用繁體中文,引原文請照抄原文(日文)。
- 只回報有把握的錯;判準寫在上面,和判準不同的地方照判準,不要憑直覺改判準。拿不準的可以回報但在 reason 開頭寫「(待確認)」。
- 不要改動批次檔或其他檔案。
