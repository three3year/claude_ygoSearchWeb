# Spec: 動作詞元變體——行う:召喚、召喚の素材 展開、攻撃対象に選択、も、効果 補語

Status: ready-for-agent
Date: 2026-10-29

上游是類別線(`.scratch/action-categories/`,2026-10-28 票 07〜09 交件)的 LLM 檢驗與站主裁定:「攻撃対象に選択できない」回框架線(第三批)、「N召喚を行う」回框架線統一成各召喚法詞元(第四批)、「法(・法)*召喚の素材に(できない)」展開成各法 N素材にする(第四批續裁),三項併成同一張框架線票;檢驗摘要「動作類別已知未修」第 5 項列的其他詞元寫法變體一起收。本規格是 2026-10-29 /grill-with-docs 的定案;GLOSSARY.md 的「動作詞元」「態」兩個詞條已於 grill 時更新。本規格延伸 ADR-0016(動作詞元正規化到他動形、態另成框架欄位)的同一條原則,不另立 ADR。

## 需要你決定的

### 這張票的範圍只收詞元變體嗎?

決定(2026-10-29):只收詞元變體;類別線交框架線的論元類問題(已知未修第 1、3、4、9、10 項)另開票。

- (a)只收詞元變體(建議):改動都在詞元對照表、補語併入與並列展開。代價:「〜を対象として」句的區域沒接到後句(類別線最大的一型)要再等一張票。
- (b)詞元變體加第 1 項:代價是回填邏輯與詞元表無關,票變大、驗收面跨兩種改動。
- (c)全部收:代價是跨回填、指代、定語範圍好幾種機制,一張票做不完。

### 行う:召喚 的「の」前面進對象欄嗎?

決定(2026-10-29):進對象欄;「魚族Sモンスター1体のS召喚を行う」→ 詞元 S召喚、對象 魚族Sモンスター1体,與「〜をS召喚する」同一種讀法。

- (a)の 前進對象(建議):代價是框架抽取要多認「N の 召喚法 を 行う」這個句型。
- (b)對象清空:代價是搜「S召喚 某種族」讀不到對象。
- (c)對象整段保留:代價是對象欄裡又帶一次召喚法,和其他 S召喚 框架讀法不一致。

### 講次數或召喚條件的 行う 也照統一嗎?

決定(2026-10-29):一律照統一——行う 的對象是「〜召喚」時詞元就記那個召喚;通常召喚を3回まで行う事ができる → 通常召喚(可能),このカードの融合召喚は上記のカードでしか行えない → 融合召喚(限制),儀式召喚を行う場合 → 儀式召喚(條件位)。

- (a)一律照統一(建議):規則一句話說得完。代價:召喚次數那 3 框讀成「能通常召喚」,「3回まで」只留在對象或子句字面。
- (b)次數句留 行う:代價是多一條例外。

### 行う 的對象是法鏈時怎麼記?

決定(2026-10-29):一法一框,照既有「召喚・特殊召喚」並列展開(このカードを素材とした融合・S・X・リンク召喚しか行えない → 融合召喚、S召喚、X召喚、L召喚 各一個限制框架)。

- (a)一法一框(建議):代價是一句出多框。
- (b)只取最後一法:代價是搜 融合召喚(限制) 漏這張。

### 召喚の素材 展開套用到所有極性和位置嗎?

決定(2026-10-29):句型全收(85 框),不只 41 框的限制句;「融合召喚の素材となって」→ 融合素材とする(態 自動、條件位),「S・X召喚の素材とする場合」→ S素材とする、X素材とする 兩框。

- (a)句型全收(建議):代價是條件位的框架也一句變多框、拆解頁多幾列。
- (b)只收否定 41 框:代價是同一個句型肯定和否定抽法不同。

### 素材 的 に/と 要在這張票歸一嗎?

決定(2026-10-29):不歸一,保留原文助詞(の素材にできない → N素材にする、の素材となって → N素材とする)。

- (a)這張票不歸一(建議):代價是搜「不能當 S 素材」仍要看 S素材にする(限制) 與 S素材とする(限制) 兩個葉。
- (b)素材系歸一到 とする:代價是約 205 框改名、類別樹素材節點要合併。
- (c)に/と 全面歸一:代價是改名上千框(含 対象とする 3,896),對象として発動 與 対象にならない 在卡文裡用法不同。

### 素材詞元加進統一組、既有 する 形補記 他動 嗎?

決定(2026-10-29):照規則加進統一組——融合/S/X/L素材にする/とする 第一次有 なる 形併進來,原文 する 記他動、なる 記自動;既有的 する 形框架(約 640 框,受身除外)態欄補上 他動。

- (a)照規則加進統一組(建議):規則不留例外。代價:約 640 框只多一個態值(類別樹沒拿態當葉條件,葉不動),差異清單變長。
- (b)只記 なる 形的自動:代價是「統一組的 する 記他動」多一個例外,同詞元裡 空 與 他動 意思重疊。

### 「攻撃対象に選択」不分極性與位置一律併成 攻撃対象にする 嗎?

決定(2026-10-29):「に選択」全併(約 119 框):選択できない → 他動(限制),選択された → 受身(條件位);「攻撃対象は相手が選択する」6 框講的是誰來選,仍記 選択。

- (a)「に選択」全併(建議):與既有 攻撃対象にできない/にならない/にされない 33 框同一個詞元。代價:條件位的 55 框也移到 攻撃対象にする 節點。
- (b)只併限制 64 框:代價是「攻撃対象に選択された時」與「攻撃対象になった時」同一件事分兩個詞元。
- (c)連主題句一起併:代價是那 6 框沒有受事者,對象欄是空的。

### 所有格併入詞元後去哪?

決定(2026-10-29):只留在子句字面、不進任何欄,與「相手の効果の対象にならない」的 相手の効果の 一致(相手モンスターの攻撃対象に選択された、このカードのX召喚の素材とする、相手の融合・S・L召喚の素材となり)。

- (a)留子句字面(建議):代價是搜「被對手怪獸選為攻擊對象」從欄位讀不到是誰在選。
- (b)進目的欄:代價是目的欄在這個詞元上變成「選的人/召喚的主人」,與別的詞元的目的(去處、值)意思不同,類別線的目的區域映射也會誤讀。

### 補語與述語之間夾 も 怎麼辦?

決定(2026-10-29):定成通則——「N に/と も なる/する」照「N に/と なる/する」處理;効果の対象にもならない → 対象にする(態 自動、否定)。

- (a)定成通則(建議):語料目前只有 5 框受影響。
- (b)只修 対象にもならない:代價是之後出現同型的新卡還會漏。

### 効果 收尾的補語要不要併入詞元?

決定(2026-10-29):効果 改不併——その効果は以下の効果となる → とする、目的 以下の効果;効果を無効にする 的補語是 無効,不受影響。

- (a)効果 改不併(建議):7 框落到既有的 規則改寫 › とする/にする。代價:補語不併判準多一個「効果 收尾」的條件。
- (b)不動:代價是 7 框永遠未歸,或為 7 框開過不了門檻的節點。

### 兩個 1 框的零星變體怎麼處理?

決定(2026-10-29):(1)「…の素材として扱う事ができる」改抽成 扱う,本票收;(2)「…は選べない」記一般否定不是框架抽取的事——類別線的否定述語形清單只認 できない/行えない,交回類別線。

- (a)(1)收、(2)交回類別線(建議)。
- (b)兩項都不收:代價是「素材として扱う」繼續落 素材 節點。
- (c)兩項都收:代價是框架線的票去改類別線的程式。

### 類別線怎麼跟進?

決定(2026-10-29):本票連類別線重跑一起做——刪變空的節點/葉、全語料重跑、差異逐項說明、草案/檢驗摘要/拆解頁鏡像照原網址重發;不開新葉,需要新葉的寫成提議清單交類別線另裁。

- (a)本票重跑加刪空、不開葉(建議):類別線「等它定版後重跑」在本票內完成。代價:新葉要等下一次類別線裁定。
- (b)照上次只做最小改名、類別線另開票:代價是多一張票、多一次鏡像重發。
- (c)本票連新葉一起裁:代價是本票多一個裁定關卡、跨線。

### 驗收怎麼做?

決定(2026-10-29):差異清單逐框對得上、每型先補回歸例子再修、受影響的卡固定種子抽樣跑一輪 LLM 挑錯(高頻型修掉、長尾記已知未修、不另跑複檢)。

- (a)差異清單加例子加一輪 LLM(建議):代價是多一輪子代理成本。
- (b)不跑 LLM:代價是沒有第三方看過展開後的多框架。

## Problem Statement

站主在類別線的 LLM 檢驗與葉表裁定裡看到,同一件事仍被框架抽取記成不同的動作詞元,類別樹只能分在不同節點,搜尋會漏卡:

1. **「N召喚を行う」記成 行う**:行う:召喚 126 框(含「Sモンスター1体のS召喚を行う」「通常召喚を3回まで行う」「儀式召喚を行う場合」),搜 S召喚 漏掉這些卡。2026-10-27 動作詞元統一時站主裁定不動,2026-10-28 改裁回框架線統一。
2. **「法(・法)*召喚の素材に/と」沒展開**:述語 素材にする/とする 前面隔著 召喚の,抽取只認到裸 素材にする/とする,法鏈留在子句字面(85 框;其中限制句「融合・S・X召喚の素材にできない」41 框全落 素材にする(限制))。「〜を融合素材・S素材として」這種並列已經會展開,這個句型沒有。搜 S素材にする(限制) 漏這些卡。
3. **「攻撃対象に選択」記成 選択**:「〜を攻撃対象に選択できない」64 框落 選択(限制),與 攻撃対象にする(限制) 收的「攻撃対象にできない」13 框是同一件事;「攻撃対象に選択された時」55 框同理。
4. **夾 も 擋住補語併入**:「効果の対象にもならない」抽成裸 なる、落 なる(耐性)(5 框),但「対象にもできない」已正確併成 対象にする。
5. **効果 補語被併入**:「その効果は以下の効果となる」抽成 効果とする、「…効果になる」抽成 効果にする(共 7 框),類別樹沒有這些節點、全落未歸;它們講的是「效果變成什麼」,補語是值。
6. **「素材として扱う」抽成 素材とする**:述語是 扱う(視同),丟了述語(1 框)。

## Solution

框架線在動作詞元對照、補語併入與並列展開三處補規則:

1. **行う 的對象是召喚**時,詞元記那個召喚法(寫法歸一照舊:アドバンス→A、リンク→L),「の」前的名詞片語進對象;對象是法鏈時一法一框。對象不是召喚的 行う(戦闘、コイントス、ダメージ計算、バトルフェイズ)不動。
2. **「法(・法)*召喚の素材に/と + する/なる」**展開成各法 N素材にする/とする 多框架,不論極性與位置;原文助詞 に/と 照留。所有格(このカードの、相手の)只留子句字面。
3. **「攻撃対象に選択」**是 攻撃対象にする:選択できない → 他動、選択された → 受身;主題句「攻撃対象は相手が選択する」仍是 選択。所有格(相手モンスターの)只留子句字面。
4. **補語與述語之間的 も** 不擋併入。
5. **効果 收尾的補語不併**,詞元 にする/とする、補語進目的欄。
6. **「素材として扱う」**的詞元是 扱う。
7. 融合/S/X/L素材にする/とする 因第 2 條第一次有 なる 形併入,加進態的**統一組**:原文 する 記他動、なる 記自動(受身照舊)。

類別線在本票內跟進:刪除變空的節點與葉、全語料重跑、差異逐項說明;不開新葉,需要新葉的寫成提議清單。拆解頁、類別樹草案、檢驗摘要三個鏡像照原網址重發。

## User Stories

1. 作為站主,我要「S召喚を行う」的詞元是 S召喚,這樣搜 S召喚 收得到用 行う 寫的卡。
2. 作為站主,我要「魚族Sモンスター1体のS召喚を行う」的詞元是 S召喚、對象 魚族Sモンスター1体,這樣它與「魚族Sモンスター1体をS召喚する」讀法一樣。
3. 作為站主,我要「「真竜」モンスター1体のA召喚を表側表示で行う」的詞元是 A召喚、對象 「真竜」モンスター1体,這樣 A召喚 的寫法歸一照舊生效。
4. 作為站主,我要「「ヴァルモニカ」Lモンスター1体のL召喚を行う」的詞元是 L召喚,這樣 L召喚 與 リンク召喚 的歸一也套在 行う 句上。
5. 作為站主,我要「このカードの召喚を行う」「モンスター1体の召喚を行う」的詞元是 召喚、對象分別是 このカード 與 モンスター1体,這樣通常召喚的「行う」寫法也收齊。
6. 作為站主,我要「Sモンスター1体のS召喚を行う事ができる」的詞元是 S召喚、極性 可能,這樣極性照原句。
7. 作為站主,我要「このターン自分は通常召喚を3回まで行う事ができる」的詞元是 通常召喚、極性 可能,這樣規則一句話說得完、不留例外。
8. 作為站主,我要「このカードの融合召喚は上記のカードでしか行えない」的詞元是 融合召喚、極性 否定,這樣它落 融合召喚 的限制節點。
9. 作為站主,我要「自分が儀式召喚を行う場合」的詞元是 儀式召喚、位置 條件,這樣條件位的召喚也是同一個詞元。
10. 作為站主,我要「このカードを素材とした融合・S・X・リンク召喚しか行えない」出 融合召喚、S召喚、X召喚、L召喚 四個框架,這樣法鏈與既有的「召喚・特殊召喚」並列同一種讀法。
11. 作為站主,我要「戦闘を行う」「ダメージ計算を行う」「コイントスを行う」「バトルフェイズを行えない」照舊是 行う,這樣對象不是召喚的 行う 不被吃掉。
12. 作為站主,我要「このカードは融合・S・X召喚の素材にできない」出 融合素材にする、S素材にする、X素材にする 三個否定框架,這樣搜 S素材にする(限制) 收得到這張卡。
13. 作為站主,我要「このカードはX召喚の素材にできない」出 X素材にする 一個否定框架,這樣單法的句子也不再是裸 素材にする。
14. 作為站主,我要「融合・S・X・L召喚の素材にもできない」照樣展開成四框,這樣夾 も 的限制句與沒夾的一致。
15. 作為站主,我要「このカードが融合召喚の素材となって」出 融合素材とする、態 自動、位置 條件,這樣條件位的素材句也展開、助詞 と 照留。
16. 作為站主,我要「このカードをS・X召喚の素材とする場合」出 S素材とする、X素材とする 兩框、態 他動,這樣肯定句一法一框。
17. 作為站主,我要「装備モンスターが融合・S・X・リンク召喚の素材になった事」出 融合素材にする、S素材にする、X素材にする、L素材にする 四框、態 自動,這樣 リンク 照寫法歸一成 L。
18. 作為站主,我要「そのXモンスターは…X召喚の素材にできる」出 X素材にする、極性 可能,這樣可能形也展開。
19. 作為站主,我要「元々の持ち主が相手となるモンスターをこのカードのX召喚の素材とする場合」的詞元是 X素材とする、對象 元々の持ち主が相手となるモンスター,「このカードの」只留子句字面,這樣所有格不混進任何欄。
20. 作為站主,我要「相手の融合・S・L召喚の素材となり」出 融合素材とする、S素材とする、L素材とする 三框,「相手の」只留子句字面。
21. 作為站主,我要「自分フィールドのランク4モンスターをレベル4モンスターとして素材にできる」(沒有 召喚の)照舊是 素材にする,這樣不屬這個句型的素材句不動。
22. 作為站主,我要「このカードを融合素材とする」的態是 他動、「融合召喚の素材となって」的態是 自動,這樣素材詞元照統一組的規則記態。
23. 作為站主,我要「このカードはS素材として墓地へ送られた場合」這類受身的素材框架態照舊是 受身,這樣補記 他動 不蓋過受身。
24. 作為站主,我要「相手は「ジェネレイド」効果モンスターを攻撃対象に選択できない」的詞元是 攻撃対象にする、態 他動、極性 否定、對象 「ジェネレイド」効果モンスター,這樣它與「攻撃対象にできない」同一個詞元、同一個限制節點。

## Implementation Decisions

**行う 的對象是召喚(框架抽取)**

- 判定:行う 框架的對象片語以「召喚」收尾(含 召喚法+召喚 與裸 召喚;前面可帶「N の」)。符合時詞元改記該召喚的原詞元,再過詞元對照表(アドバンス召喚→A召喚、リンク召喚→L召喚);對象改成「の」前的名詞片語,沒有「の」時對象空。
- 對象片語是 主題 而不是 を 對象時(このカードの融合召喚は…でしか行えない)同一條規則:詞元 融合召喚,「このカードの」是所有格、只留子句字面。
- 對象片語是「法・法…召喚」並列(含前面有定語)時,沿用既有召喚並列的展開機制,一法一框;各框架共用極性、位置與其他欄。
- 數量、次數、表示形式等跟在召喚後面的字面(3回まで、表側表示で)不另抽,原文仍在子句。
- 行う 的其他對象(戦闘、ダメージ計算、コイントス、バトルフェイズ…)不動。
- 統一後的召喚框架沿用該召喚法既有的推得值規則(目的 フィールド 等),與直接寫「〜をS召喚する」的框架一樣補。

**召喚の素材 展開(並列展開)**

- 句型:「法(・法)* 召喚 の 素材 に/と(+ も)+ する/なる/できる/できない…」。法鏈逐法成詞(分詞器既有),每法出一框,詞元 = 法的素材前綴 + 素材 + 原文助詞形(融合→融合素材、S→S素材、X→X素材、リンク/L→L素材;に → にする、と → とする),再過 なる→する 規則與態。
- 原本抽出的裸 素材にする/とする 框架被展開的各法框架取代,不另留。
- 法前面的所有格(このカードの、相手の)不進任何欄;受事者(を 對象、が/は 主語/主題)照既有規則、每框相同。
- 不屬這個句型的素材句(〜として素材にできる、〜を素材として)不動。

**態的統一組**

- 融合素材にする/とする、S素材とする、X素材にする/とする、L素材にする/とする 加進 する 形統一組(S素材にする、素材にする/とする 已在):原文 する 記他動、なる 記自動,受身照舊由述語錨點判。
- 這會讓既有的 する 形素材框架(約 640 框)態欄從空變 他動;只改態欄,其他欄不動。

**攻撃対象に選択(詞元對照)**

- 選択 框架的目的是以「攻撃対象」收尾的片語(攻撃対象に選択)時,詞元改記 攻撃対象にする;態照原句:能動 → 他動、被動 → 受身。目的欄清空(攻撃対象 已在詞元裡),片語裡 攻撃対象 前的所有格(相手モンスターの)只留子句字面。
- 攻撃対象 在主題位(攻撃対象は相手が選択する)、或目的不是 攻撃対象 的 選択 不動。

**補語併入的兩條補充(補語不併判準)**

- 補語與 なる/する(含可能形)之間夾 も 時,照沒有 も 處理。
- 補語最後一個詞是 効果 時整段不併:詞元 にする/とする(なる 形態 自動),補語原文字面進目的欄。狀態/角色詞清單拿掉 効果;同じ効果にする、効果にする、効果とする 這幾個詞元從此不再產出。

**素材として扱う**

- 「〜の素材として扱う」的述語是 扱う:框架詞元記 扱う,「素材として」不成框架。
