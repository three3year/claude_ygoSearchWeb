# 召喚手續另出動作框架

站主想查「黑魔導從場上到除外」,毀滅的黑魔術師(滅びの黒魔術師)不在結果裡:它的除外寫在召喚條件「自分フィールドのレベル６以上の魔法使い族・闇属性モンスター１体を除外した場合のみ特殊召喚できる」,這句被認成[[約束框架]],手續只存成字串,不出[[動作框架]],[[框架述詞]]看不到。全語料 304 張卡的召喚條件帶手續(解放、除外、疊放、送墓、回牌組…),全部查不到。站主裁定(2026-11-03 /grill-with-docs,地圖 procedure-target-zh 票 01 甲段;規格 `.scratch/summon-procedure/spec.md`):**召喚條件的手續步驟,動作在白名單內的,各出一個動作框架,位置是新的第四個值「召喚手續」;約束框架照舊記手續,逐位元組不變**。這推翻了約束框架原本的「被認成約束的句子或子句不再另出動作框架」在召喚手續上的適用(GLOSSARY 約束框架條同日改);召喚條件本身的「特殊召喚できる」仍不出。

## Considered Options

- **約束框架直接進索引**(述詞對約束框架的手續欄評估):不用新框,但搜尋的單位是對單一動作框架的欄位評估(ADR-0018),手續欄是字串,沒有片語、結構化區域、施事者、[[動作對象]]。要嘛另寫一套評估器(欄位對不上,「除外←墓地」這類[[具名查詢]]不能直接用),要嘛替手續另做一次結構化——等於重做一條分詞鏈。
- **手續步驟出成效果位的動作框架**(不加位置值):不動位置值域,但召喚條件不是效果;新標籤預設只看效果,既有查詢的結果會突然多出一堆召喚條件。
- **每個手續步驟都出框**(同效果位,不過白名單):手續步驟共 17 種動作(337 步),其中 存在、になる、となる、合わせる、異なる 是前提,P召喚可能 是召喚法本身的前提,都不是卡片做的動作;発動 唯一一步是「相手が…発動していた場合」(做的人是對手,施事者一律 自分 會錯),選ぶ 唯一一步是效果文被誤認成召喚條件。全出會把雜訊與錯框一起送進索引。
- **約束框架的手續欄改成指向動作框架**:兩邊不重複,但動到已驗收的既有欄;手續欄還記著被白名單擋掉的步驟(前提、P召喚可能),改成指標會丟掉它們。
- **另出動作框架、位置是第四個值、過白名單、約束框架不動**(採用):召喚手續走效果位的同一條分詞鏈與結構化(片語、區域、施事者、方式、否定形、回指、動作對象),具名查詢、中心詞欄、數量欄自動適用;位置分開,要不要看召喚條件由使用者自己按亮。

## Consequences

- **白名單**是封閉表,9 種:リリース、除外、重ねる、送る、戻す、捨てる、取り除く、見せる、払う(283 框、271 張;規格 Further Notes)。效果位不過白名單——它的述語錨點都是效果做的事;召喚條件的手續是約束框架的句型認法寬鬆收進來的步驟,前提、對手的動作、誤認的效果文都在裡面,所以只放行白名單內的動作。白名單外的步驟只留在約束框架的手續欄;LLM 抽驗也看被擋掉的步驟裡有沒有真動作(漏收),要加值隨抽驗裁定。
- **約束框架的手續欄保留不改**:字面欄逐位元組不變是框架線的驗收條件(ADR-0018「結構化是加欄不是換值」);手續欄是召喚條件的全貌(連同形式、方式、來源),拆解頁與抽驗照舊讀它;它也是白名單外步驟唯一的落腳處。
- **同一段卡文有兩種框架表示**:約束框架記「這張卡怎麼出場」(手續是字串),召喚手續動作框架記「出場要做哪些可查的動作」。代價是兩處可能不一致——抽取錯修了一邊,另一邊不跟著動;手續欄的步驟與動作框架之間沒有連結。取捨是保住既有欄與查詢語意,不合併;之後要合回去,得先回答上面兩個被否決的選項各自的問題。
- 位置值「召喚手續」排在 代價、效果、條件 之後:索引的位置碼照值域序,1〜3 不變,召喚手續是 4。匯出檔格式版本 2 → 3,目錄每列多一格召喚手續張數與雜湊,「全語料至少命中一張」改看四個位置;目錄樹畫面照舊只顯示效果位張數,新標籤預設只看效果。
- 召喚手續框兩條專門規則:施事者一律 自分(不看主題與主語);動作對象把此卡當成在召喚來源(沒寫時主牌組怪獸算手牌、額外牌組怪獸算額外牌組),召喚手續的 重ねる 一律此卡。
- **驗收的守門剝框重編**(summon-procedure 票 01):召喚手續框依原文順序和既有框混排,會把後面的框序往後推。剝鍵比對(`baseline_diff.py`)與下游基準(`downstream_baseline.py`,動作對象、回指)比之前先剝掉位置是召喚手續的框、框序照剩下的重編(`baseline_diff.strip_procedure`,動作對象整句判完才剝);匯出檔另由 `export_diff.py` 剝掉召喚手續框列、目錄與統計位置的召喚手續格、值域的召喚手續,與加之前逐句相同(入版控的 `export-digest.json`)。既有 digest 不重凍——重凍就失去「沒碰到既有欄」這道守門。
