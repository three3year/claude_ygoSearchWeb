# 08 — 拆句表、判定結果合併與批次檔

**What to build:** 判定工作變得可執行的**機制**。建置流程能讀[[拆句表]]把舊式無編號整團切開、能把判定票寫回的結果檔合併進[[效果標記表]]、能吐出批次檔。本票**完全不需要任何判定**——三道驗證與兩個新參數都可以用合成 fixture 純 TDD 做完。

關鍵契約:判定結果**可以改變效果句的集合**,不只是填 `kind`。但改變集合這件事不由判定結果檔做,而是由獨立的[[拆句表]] `data/clause_splits.json` 做(ADR-0003)——`splits` 決定效果句的**集合**、`judgments` 決定效果句上的**值**,兩者生效時機不同:拆句表在[[官方明示]]抽取**之前**,判定結果在**之後**。

**Blocked by:** 03 — 官方明示:五階梯歸屬與類型抽取、04 — 必發/選發規則層、05 — 重跑保留語意

**Status:** ready-for-agent

## 拆句表

- [ ] 接縫加參數:`build_tag_cards(cards, faq_entries, existing=None, judgments=None, splits=None)`
- [ ] 拆句表格式:一張卡一筆,鍵為 `(卡片密碼, section)`,內含每一段的 `index` 與**繁中、日文兩側的原文子字串**,外加拆句當時的卡文雜湊與判定票號。兩側都要給——實測 489 張兩側句數不一致,推不出來
- [ ] 骨架依拆句表把整團切開,`index` 規則:[[效果外文本]]段 `"0"` / `"0-2"` / `"0-3"`,效果句 `"1"` / `"2"` / `"3"`。`"1"` 沿用整團現在的 index,只有一段效果句的卡拆完後 index 不變、不製造孤兒,需有測試
- [ ] **驗證一・無遺漏覆蓋**:段落按順序串接、忽略空白後必須等於原文。不成立則整筆不寫入、退回整團並列進待審,需有測試
- [ ] **驗證二・引用交叉驗證**:補足情報的 `『原文』` 引用不得被拆點切成兩半。違反則整筆不寫入並列進待審;建置報告列出違反筆數(全表必須為 0),需有測試
- [ ] **驗證三・卡文變動即失效**:雜湊或覆蓋等式對不上時**退回整團**(`unsplit` 重新成立),不保留舊拆點。保留失效的斷言會讓歸屬階梯在假前提上開火,那是票11 的錯誤,需有測試
- [ ] 骨架把 `unsplit` 集合傳進 `official.attest()`,票11 的階梯四、五排除條件改看它而不是看 `index`——拆完只剩一段時 index 仍是 `"1"`,光看字串分不出來。有拆句表紀錄的卡不進 `unsplit`,兩道階梯自然開火,需有測試
- [ ] 報告列出:套用的拆句表筆數、拆出的效果句條數、三道驗證各自的失敗筆數、以及因拆句而**新取得官方明示**的條數(票11 撤掉的 1,146 條會從這裡回來)

## 判定結果合併

- [ ] `judgments` 參數生效:能填入 `kind` / `optional` / `role`,需有測試
- [ ] 合併後的行 `source` 為 `"llm"`,`confidence` 依該卡是否有官方補足依據決定(3,779 / 3,805 有補足,絕大多數為 `high`)
- [ ] 拆完重跑的官方明示與判定者的類型不一致時,照票05 的規則走(保留判定 + 進 `late_official_conflicts`),但額外把**整張卡**標 `needs_review`——這條路徑上不一致的最可能成因是拆錯而不是判錯,需有測試
- [ ] 合併時的集合一致性自檢:結果檔涵蓋的效果句集合必須與對應批次檔完全相同,少一筆或多一筆即失敗

## 批次檔

- [ ] 從[[效果標記表]]取出仍為 `kind: null` 的卡,附繁中與日文卡文與**完整**補足情報(不裁剪),批次檔含判定所需的全部上下文,判定票不需要回頭查其他來源
- [ ] **分成兩個系列**:「只判類型」(4,143 張,每批 300)與「要拆+判」(3,804 張,每批 200)。兩種工作的輸出格式與成本差約兩倍,混在一起排票會讓每票的實際負擔不可預測
- [ ] 「要拆+判」的批次檔額外附上該卡補足情報裡命中整團的 `『原文』` 引用,當作拆點提示(**只是提示**,不自動拆——理由同 `_split_bullets`:官方沒有明確分項的引用可能只是一句話的片段)
- [ ] 報告列出兩個系列各自的批次總數、每批卡數、待判效果句總條數
- [ ] **只生「要拆+判」系列的第 1 批**當試點的輸入,其餘批次檔等試點跑完再生

## 判定票的產生

- [ ] 本票只產生**試點票**一張(即票13),不預先生出其餘判定票——每票要放幾張卡取決於試點跑出來的實際成本
- [ ] **判定票的編號在執行時才決定**:掃 `.scratch/tag-card/issues/` 取目前最大編號 + 1 起連續配號,不得預先寫死。骨架票進行期間會為途中發現的缺陷開新票(票10、票11、票12 就是這樣佔掉原本預留給判定票的號碼),任何寫死的起始號都會過期
- [ ] 其餘判定票的產生與配號移到票13 的驗收項目

## Comments

原票面把「判定結果可以替換某卡的整組效果句」寫成 `judgments` 參數的能力。grilling 後改為獨立的拆句表,理由寫在 ADR-0003:責任分離(骨架永遠負責「卡文 → 效果句」、判定永遠負責「效果句 → 類型」),以及「拆完之後重跑官方明示」在單一參數之下每次都得先重算一遍拆句才跑得動。

拆句表記卡文雜湊這件事,對「偵測變動」其實是**冗餘的**——無遺漏覆蓋等式已經涵蓋任何一個字元的變動。留著是為了**診斷**:出事時能一眼看出這筆拆點是對著哪一版卡文切的。
