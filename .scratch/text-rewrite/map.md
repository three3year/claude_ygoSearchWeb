# Wayfinder Map — 翻新舊卡文(全庫)

Label: wayfinder:map

## Destination

三級分類報表的「舊文本」級歸零:全庫 3,756 段/3,756 張舊式卡文,全部依
`docs/text_format_guide.md` 改寫、經站主逐行審查放行、寫入文本改寫表進站並
通過全線驗證。終點是**改完的庫**,不是規格文件。

## Notes

- **本圖攜帶執行**:子批進站票(Type: task)就是路線本體,不只決策——此為
  對 wayfinder「plan, don't do」預設的明示覆寫。
- 分批策略已於 2026-08-24 盤問定案,細節由 [06 — spec 擴充](issues/06-spec-update-full-corpus.md)
  寫入 `spec.md`:全庫為分母、依句型群(§4.x 標籤×大類)分批、張數最多先、
  子批 50 筆依卡片密碼升冪、每子批一票(審查+進站合一)。
- 詞彙:見 `CONTEXT.md` 的「句型群」「子批」詞條。
- 每張子批票的固定流程:改寫 → 完整三欄審查檔(日文原文/查牌網舊譯/新文本
  +依據+判斷點)→ **擬稿過卡文詞彙表**(`script/text_glossary/check_draft.py`,
  2026-08-25 站主定案)→ 站主逐行放行 → 寫入 `data/text_rewrites.json` → 重建
  全站全線驗證 → kind 補判(固定收尾)→ 站主明說 commit 才提交。範本:試點批
  `issues/04`、`issues/05` 與 `review-flip-monsters.md`;詞彙表那一關的判準與
  兩種系統性誤報見 `spec.md`「擬稿過卡文詞彙表」。
- 審查中長出的規範,照試點慣例追記 `docs/text_format_guide.md`,以「審查批改」
  commit;規範爭議走 /grilling + /domain-modeling。
- **子批票逐張開**:前一子批 resolved 後才開下一張(create-then-wire),
  不一次預切整群 ~20 張票。
- 佇列與張數以當下重跑的 `.scratch/text-format/report.md` 為準,map 裡的
  數字是 2026-08-25 快照(舊文本 3,628 段,票08 排除後)。
