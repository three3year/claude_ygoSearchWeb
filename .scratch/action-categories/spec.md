# Spec: 動作類別第二版——動作框架歸組成類別樹

Status: ready-for-agent
Date: 2026-10-16

上游是效果文分詞線的動作框架(票 04〜17)、約束框架線(票 01〜11)與第二版論元(一)(票 01〜06),三線於 2026-10-15 合併驗收結案、框架抽取定版。本規格是 CONTEXT.md「動作類別」詞條的第二版定義(2026-10-16 /grill-with-docs 定案)。

## Problem Statement

站主手上有試點層(新格式新卡 7,818 張)每張卡的效果拆解:46,796 個動作框架(動作詞元 193 種)與 12,582 個約束框架,拆解頁一卡一頁翻得出「這張卡在做什麼」。但框架是逐句的描述,不是可以橫向比較的單位——要回答「哪些卡會從墓地特殊召喚」「哪些卡以捨手牌為代價」,現在只能逐卡讀,沒有一層把 46,796 個框架收攏成有限的類別。

舊 21 類分類表(2026-09-20 凍結、2026-10-01 停工)的教訓有三:類別貼在標記句上、丟掉誰對誰做什麼與代價/效果的分界;蘇生/檢索這些牌手真正會搜的概念被降成「槽位組合的顯示層對照」,搜尋鈕與直覺脫節;指標全綠卻沒用。CONTEXT.md 從 2026-10-01 起就寫「動作類別將以效果文分詞線重新推導」,票 04 把歸組留給「另開票」,票 11 結案時再次寫明「類別歸組另開線」。這條線就是它。

## Solution

把每個代價位或效果位的動作框架貼到一棵**類別樹**的葉上。樹的葉是「動作詞元+論元條件」的組合、名字就是那個組合(特殊召喚←墓地、加える:デッキ→手札、破壊:魔法・罠),葉之上是詞元層(特殊召喚、送る、破壊),詞元之上是少數大類(區域移動這類沒有詞元可組名的節點,名字由站主在裁定關卡取);分支可以不等深。歸組是一張決定性規則表:以動作詞元為主鍵,依來源/目的(字面映到區域封閉值)、極性、對象欄關鍵詞細分;複合來源的框架帶多個葉、仍屬同一大類;否定極性另成類(耐性、限制),可能極性與肯定同類。規則表沒覆蓋的框架不貼、列未歸類清單;條件位的框架不歸本樹,留給另開線的「觸發事件」軸。

產物三份,都在試點目錄、決定性建置、不入版控:**類別樹**(來源檔,站主裁定)、**框架類別檔**(每個動作框架的葉清單、大類、來源玩家/目的玩家、狀態)、**卡層彙總檔**(每張卡的葉集合分效果組與代價組,為日後搜尋設計的格式)。拆解頁的框架表多一欄類別,新分頁「類別總覽」展開樹、列每類的框架數、卡數與例句。

站主先在裁定關卡看樹的草案(附每葉的條件、框架數、卡數與例句)封頂,貼完後 LLM 子代理依葉分層抽樣挑「這個框架歸錯葉」,修規則、同批複檢,最後站主翻拆解頁與類別總覽做質性驗收:「這組類別讀不讀得出卡在做什麼、搜起來像不像牌手的語言」。

## User Stories

1. 身為站主,我想打開類別總覽看到一棵樹,大類下掛詞元、詞元下掛葉,以便一眼看完整個分類的形狀。
2. 身為站主,我想看到每個葉的名字就是詞元加論元條件(特殊召喚←墓地、加える:デッキ→手札),以便不必查定義就知道葉收什麼。
3. 身為站主,我想看到每個葉附它的條件(詞元、來源區域、目的區域、極性、對象關鍵詞)、框架數、卡數與隨機例句,以便裁定時判斷葉切得對不對。
4. 身為站主,我想在裁定關卡為大類取名、把詞元搬到別的大類、把葉拆開或合併,以便樹封頂前是我的裁定而不是 agent 的草案。
5. 身為站主,我想讓樹的分支可以不等深——區域移動※特殊召喚※特殊召喚←墓地 三層、破壊 一層就是葉——以便不為整齊補無意義的節點。
6. 身為站主,我想看到「墓地から特殊召喚」的框架貼在 特殊召喚←墓地,以便搜蘇生時命中。
7. 身為站主,我想看到「デッキから手札に加える」貼在 加える:デッキ→手札、「墓地から手札に加える」貼在 加える:墓地→手札,以便檢索與回收分開。
8. 身為站主,我想看到「手札・墓地から特殊召喚」同時帶 特殊召喚←手札 與 特殊召喚←墓地 兩個葉、大類仍是一個,以便複合來源的卡在兩邊都命中。
9. 身為站主,我想讓「自分の墓地」「相手の墓地」「墓地」都映到區域值 墓地,以便葉不因玩家前綴分裂。
10. 身為站主,我想讓框架類別檔另記來源玩家與目的玩家(自分/相手/雙方/無),以便總覽頁與卡層彙總能按玩家過濾,哪天要開成葉只改樹。
11. 身為站主,我想看到「破壊されない」「対象にならない」歸耐性這組類別、「できない」歸限制這組,以便承受方的耐性與行為方的限制不混進「卡做了什麼」。
12. 身為站主,我想讓「破壊できる」與「破壊する」歸同一葉,以便可能極性只是選發的文體差異、不另成類。
13. 身為站主,我想讓「魔法・罠カードを破壊する」與「モンスターを破壊する」依對象關鍵詞分到不同葉,以便破壞魔陷與破壞怪獸分得開。
14. 身為站主,我想讓「発動を無効にする」與「効果を無効にする」依對象關鍵詞分葉,以便無效發動與無效效果分得開。
15. 身為站主,我想讓對象關鍵詞只在某個葉需要時才看、對不上的落到該詞元的預設葉,以便不做對象欄的通用正規化。
16. 身為站主,我想讓條件位的框架(存在、成功、対象とする、「…が破壊された場合」的 破壊)不貼本樹、狀態記「不適用」,以便「什麼時候」不混進「做什麼」。
17. 身為站主,我想讓代價位的框架(リリース、捨てる、払う)照貼葉,以便分析時看得到代價的分佈。
18. 身為站主,我想看到卡層彙總把每張卡的葉集合分成效果組與代價組,以便日後搜「除外」不撈到自家代價除外的卡,搜「以捨手牌為代價」時能開代價組。
19. 身為站主,我想讓規則表沒覆蓋的框架狀態記「未歸類」、類別欄留空,以便沒有「其他」這種垃圾桶。
20. 身為站主,我想在類別總覽看到未歸類框架依詞元聚合的清單與數量,以便知道規則的盲區在哪些詞元。
21. 身為站主,我想看到已歸/未歸/不適用三個數字與已歸比例當儀表板,以便追蹤進度,但不拿它當通過門檻。
22. 身為站主,我想讓約束框架不貼本樹,以便它們自己的 類別·子類 就是歸組、不出現兩套值。
23. 身為站主,我想讓出自選項(●)的框架照貼葉,以便「●自分ターン：」底下的動作也被歸組。
24. 身為站主,我想讓同一個框架帶多個葉時只算一個大類,以便大類層的計數不重複。
25. 身為站主,我想在拆解頁的框架表多一欄類別,顯示從大類到葉的路徑,以便逐卡核對歸組。
26. 身為站主,我想在類別總覽點一個葉就看到它的框架清單(卡號、卡名、子句字面),點一條跳到那張卡的拆解,以便從類別走到卡。
27. 身為站主,我想讓類別總覽與拆解頁在同一個檢視 artifact、照原網址重新發布,以便驗收入口不變。
28. 身為站主,我想讓歸組與分詞鏈一起決定性重跑、同輸入逐位元組相同,以便規則改動的影響可以逐框架比對。
29. 身為站主,我想讓歸組只讀框架抽取的輸出、不改框架抽取,以便框架線定版的結果不被本線動到。
30. 身為站主,我想在貼完後讓 LLM 子代理依葉分層抽樣挑錯,每葉固定抽幾個框架、未歸類另抽一批,以便小葉也被看到、錯誤直接對到規則條。
31. 身為站主,我想讓 LLM 回報的錯誤附理由並分類(歸錯葉、該歸未歸、葉定義本身有問題),以便知道該修規則還是該改樹。
32. 身為站主,我想讓規則修正後用同一批樣本複檢,以便確認修正有效且沒有改壞別處。
33. 身為站主,我想在交件時拿到「已知未修」清單,以便知道剩下的長尾是什麼、為什麼沒修。
34. 身為站主,我想讓每次規則修正都附一句回歸例子進測試,以便之後的修改不會把已修好的歸組改壞。
35. 身為站主,我想讓類別樹草案與舊 21 類對照一次(哪些舊類被合併、拆開、新增),以便知道差在哪,但新樹不以舊表為起點。
36. 身為維護者,我想讓類別樹是一份可讀的來源檔,改名或搬節點只改這份檔、重跑即生效,以便樹的演進不碰程式。
37. 身為維護者,我想讓框架類別檔與卡層彙總檔有清楚的欄位定義,以便日後搜尋線直接接。
38. 身為維護者,我想讓本線完全不碰舊效果 Tag 的資料與規則層,以便新歸組不被舊線帶偏。

## Implementation Decisions

### 類別樹(來源檔)

- 一份來源檔,內容是一棵樹。節點三種:**大類**(名字由站主取,無規則條件)、**詞元節點**(名字就是動作詞元;當它底下沒有再細分時自己就是葉)、**葉**(名字是詞元+論元條件的組合,帶規則條件)。
- 葉的條件欄:動作詞元(必填)、來源區域、目的區域、極性、對象關鍵詞(可選)。沒有條件欄的詞元節點是該詞元的預設葉。
- 葉名的組合寫法固定:來源用「詞元←區域」、目的用「詞元→區域」、來源加目的用「詞元:來源→目的」、對象關鍵詞用「詞元:關鍵詞」、否定用「詞元(否定)」。名字由條件機械組出,不另取慣用名。
- 大類是少數(估十幾個);草案階段由 agent 依詞元分佈給建議名與成員,裁定關卡由站主改名、重分。
- 否定極性的詞元節點掛在獨立的大類底下(耐性、限制兩組,大類名仍由站主定),不掛在肯定詞元的大類下。
- 樹的完整性在建置期檢查:葉名全樹唯一、每個葉至少有詞元條件、每個大類至少一個葉、同一詞元的葉條件不重疊(重疊時以較具體者優先的順序寫在樹裡)。

### 規則表語意

- 主鍵是動作詞元。一個框架先找到它詞元的節點,再依條件匹配葉;匹配只看框架欄位(動作、來源、目的、極性、位置、對象),不看子句字面。
- 複合來源或目的(字面含「・」)拆成多個區域,逐區域各匹配一葉;一個框架因此可帶多個葉,大類取葉的共同祖先(樹的設計保證同詞元的葉同大類)。
- 來源/目的字面 → (玩家, 區域) 的映射表住在歸組模組:玩家是 自分/相手/雙方(自分か相手の、自分・相手の)/無;區域沿用值域正典的七值(手牌/牌組/額外牌組/墓地/除外/場上/靈擺區),字面對不上任何區域時該框架對需要區域的葉不匹配。
- 極性:否定走否定詞元的節點;可能視同肯定。耐性/限制以述語形分——框架的動作詞元帶被動否定或「にならない」為耐性,可能否定(できない)為限制;這個判準寫在規則表,不另抽主體。
- 位置:只有代價與效果位的框架參與匹配;條件位的框架狀態記「不適用」。
- 匹配不到葉(詞元沒有節點,或有節點但條件全不符且沒有預設葉)記「未歸類」。沒有「其他」類。
- 對象關鍵詞是葉條件裡的字面子字串清單(魔法・罠、モンスター、発動、効果、ダメージ…),只在該葉宣告時比對;不做對象欄的通用正規化。

### 產物

- **框架類別檔**:每個動作框架一列——卡號、段落、句序、框架序(與 frames.json 對齊)、狀態(已歸/未歸/不適用)、葉清單(有序)、大類、來源玩家、目的玩家。
- **卡層彙總檔**:每張卡一列——效果組的葉集合、代價組的葉集合(各自去重、依樹序排);大類與詞元層由樹展開,不另存。
- 兩份都是決定性建置產物、不入版控,與 frames.json 同待遇;分詞鏈重跑時在框架抽取之後、檢視資料之前重算。
- 類別樹來源檔入版控;改樹不改程式。

### 檢視

- 拆解頁框架表加「類別」欄:顯示大類到葉的路徑,多葉時並列;不適用與未歸類各以淡色標示區分。
- 新分頁「類別總覽」:樹狀展開,每節點顯示框架數與卡數(大類與詞元層由葉彙總,多葉框架在大類只算一次);點葉列該葉的框架(卡號、卡名、子句字面),點一條跳到該卡的拆解;未歸類依詞元聚合另列;儀表板顯示已歸/未歸/不適用三個數與已歸比例。
- 沿用既有檢視 artifact,照原網址重新發布;資料與分片的產生沿用既有檢視資料腳本,多讀框架類別檔與卡層彙總檔。

### 裁定關卡與 LLM 檢驗

- **裁定關卡**:樹的草案是一份審核關卡 md(走 review-mirror 鏡像),內容是整棵樹、每葉的條件/框架數/卡數/三條例句、未歸類詞元清單、與舊 21 類的對照表;站主在鏡像上裁定後才貼。大類名在這裡取。
- **LLM 檢驗**:依葉分層固定種子抽樣——每葉抽 5 個框架(不足全取)、未歸類另抽 50 個;子代理拿原文子句、框架欄位與葉定義,回報錯誤分三類(歸錯葉/該歸未歸/葉定義有問題)附理由;依類型修規則或改樹,同批複檢到只剩個別長尾;樣本與每輪歸納存檔。
- **交件**:檢驗摘要(與框架線同一份摘要檔加本線章節)、已知未修清單、儀表板數字、拆解頁重新發布;站主翻類別總覽與拆解頁做質性驗收。

### 用詞與邊界

- 本規格的產物就是 CONTEXT.md「動作類別」詞條的第二版;舊 21 類是第一版,只在草案對照表出現一次,不當起點、不解凍、資料不用。
- 試點範圍同框架線(新格式新卡層);目錄與分詞鏈並列、自成一個 feature 目錄。
- 觸發事件軸(條件框架的歸組)另開線,本線不定義它的形狀。

| 未歸類 | 不貼、列清單、覆蓋率當儀表板,無「其他」類 |
| 正規化 | 住在歸組模組,frames.json 不動 |
| 產物 | 框架類別檔、卡層彙總檔(效果組/代價組)在試點目錄,不進 web/ |
| 檢視 | 併進拆解頁:框架表加類別欄、新分頁類別總覽,照原網址重發 |
| 驗收 | 樹草案先站主裁定 → LLM 依葉分層抽樣挑錯、修、複檢 → 站主翻頁 |
| 詞彙 | 沿用「動作類別」,詞條已改寫 |
| 接縫 | 一個:效果句原文 → 每個動作框架的類別紀錄 |

## Testing Decisions

- **唯一接縫**:「一句效果句原文(帶同卡同段上文)→ 每個動作框架的類別紀錄」。包住既有的框架抽取接縫再接歸組,用真的分詞器、詞典、類別樹與規則表;只斷言每個框架的(動作、狀態、葉清單、大類、來源玩家、目的玩家),不測規則內部、不測樹怎麼存。
- **好的測試**是句型層的回歸例子:一句原文、預期每個框架的葉。修規則或改樹前先補一條會失敗的例子。
- **第一批例子**涵蓋:蘇生(墓地から特殊召喚)、檢索與回收(デッキ/墓地から手札に加える)、複合來源帶兩葉、玩家前綴不分葉但玩家欄有值、否定歸耐性/限制、可能視同肯定、對象關鍵詞分葉(破壊 魔法・罠/モンスター、無効にする 発動/効果)、對象對不上落預設葉、代價位照貼、條件位不適用、未歸類詞元、選項內的框架照貼。
- **卡層彙總**經同一接縫餘多句組裝驗:一張卡的幾句原文 → 效果組與代價組的葉集合。
- **樹的完整性檢查**是建置期檢查,測試用真的樹跑一次(葉名唯一、條件合法、大類非空、同詞元條件不重疊)。
- **全語料**:分詞鏈決定性重跑,比對前後的已歸/未歸/不適用數;總覽頁與拆解頁不另設接縫,靠重跑與站主翻頁。
- **前例**:動作框架與約束框架的行為測試檔(同一接縫、真的分詞器、brief tuple 比對)就是寫法前例;測試檔放在模組旁,沿用專案的 unittest。
- 詞典或框架規則改動連帶影響本線測試屬預期;失敗時判斷是框架線該改還是樹該改。

## Out of Scope

- 觸發事件軸:條件位框架的歸組,另開線、另走 /grill-with-docs。
- 約束框架的歸組(它們的 類別·子類 已是歸組)。
- 網站搜尋介面、前端索引、值域正典的任何改動;卡層彙總檔只是格式先為搜尋設計。
- 舊效果 Tag 的資料、規則層、遮蔽測試、分類表(不用、不對照、不解凍;草案的對照表只是一次性說明)。
- 慣用名(蘇生、檢索、回收)當正式值或顯示對照;葉名就是詞元+論元組合。
- 對象欄的通用正規化、主體欄、期間/範圍欄(第二版論元(二)的候選),以及玩家前綴開成葉。
- 試點層以外的語料;中文側卡文。
- 把類別複製回 frames.json 或改框架抽取。
