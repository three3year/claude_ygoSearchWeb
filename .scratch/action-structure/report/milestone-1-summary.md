### 本票修的一個讀回漏洞

第一次在全庫產物上逐張核對時,滅びの黒魔術師 不通過(「被改的屬性無模板:視為」),同一張卡在測試的記憶體建置裡卻通過。原因是產物省略空格後,`card_structure.load_structures` 沒把修飾段(「〜として扱う」)被改屬性裡的區域、prefix、also、尾綴,以及階段前提的方、字段原子的 setcode 列、分歧前提的區域補回來;反向檢查拿讀回的區域與重新解析的區域比,不相等就判無模板。全庫有 170 張讀回後與建置結果不等,反向檢查報告因此多報 130 段(128 張的「視為」段等)。

修法只在讀回時補格,產物位元組不變;修後全庫 build → serialize → load 讀回不等 0 張,建置版與讀回版的反向檢查不通過數相同。新增一條往返測試(`test_card_structure.test_treat_as_and_phase_premise_survive_the_round_trip`)。反向檢查通過段數因此由 17,091 變 17,220。

## 未解析優先順序

依「補了能解掉多少」排,數字來自 `coverage.md`「段解析不出的原因」與實跑 `stats/milestone_stats.py`(後者的寫法分類是字面粗篩,一段可落在多類)。

1. **述語解析不出**(26,188 段 / 12,219 張;只差這一種就整張通過的 3,511 張):量最大,而且很多段的動作詞其實認得,是子句規則沒收某種寫法。這一類裡含下列寫法的段(段 / 張):
   - 抗性/限制「されない・できない・受けない」2,934 / 2,661(破壊されない 701、召喚できない 605、攻撃できない 183…)
   - 「〜表示で」2,097 / 1,912(表側表示で存在する、守備表示で特殊召喚する)
   - 傷害「ダメージ」1,935 / 1,631
   - 攻撃力・守備力的增減「アップ/ダウン」1,774 / 1,694
   - 「選んで」+ 述語 1,117 / 993(「〜から選んで特殊召喚する」)
   - ドロー 938 / 840;超量素材「取り除いて」547 / 488
   - 依段類別:效果 17,450、條件 7,038(存在する場合 580、に成功した時 541、成功した場合 498…)、召喚手續 868、代價 780。
2. **物件修飾解析不出**(物件 8,375 / 6,125 張;只差這一種的 478 張):修飾語認不得的那截;各票 Comments 提過的例子有「フィールド上に表側表示で存在する」(票 11,850 張)、「EXデッキから特殊召喚された〜が存在する」(票 05)。
3. **物件解析不出 / 子句解析不出**(3,623 / 3,202 張、3,379 / 3,005 張)。
4. **述語語尾不明**(2,192 / 2,012 張)、**發動句解析不出**(1,445 / 1,356 張)。
5. **段樹**:分歧方式判不出 565 張(「以下の効果を適用する」等引導句不在閉集)、分歧前提解析不出 133 張。

建議的第一批:抗性/限制句型(極性「不能」與「不會」已有,補句型即可)、「選んで」與「〜表示で」(只是子句裡多一截,動作詞已認得)、攻守增減(性質變更已有格)、ドロー 與 傷害(新動作詞)。這幾類合計觸及的段數最多,且多半不必改形狀。
