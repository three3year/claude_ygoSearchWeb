### 投影了什麼

- 46,732 個動作框架、23,775 列標記句、7,817 張涵蓋卡(索引 14,207 張)。每框 10 欄:詞元(118 值)、位置(3)、極性(3)、態(4,含空)、來源/目的/所在各是 [玩家×區域] 多值(places.parse_zones;實際出現 34 種對)、動作對象(patient.judge_sentence 現行判定,此卡/非此卡/皆非)、受事者中心詞(對象→主語→主題第一個有值的欄,categories.head_nouns 切;52,246 個、3,172 種字面,其中 1,413 種只出現一次)、目的中心詞(目的字面不是區域也不是純玩家時;3,199 個)。
- 外推:每框再加 5 個小整數(值域 5/4/7/5/9,代表中心詞類、施事者、方式類、數量類、修飾語類),兩種分布——均勻(gzip 幾乎壓不動,是上界)、偏態(七成是 0,接近真實欄位多數為空)。
- 每張涵蓋卡的框數:平均 6、中位 6、p95 9、最多 17。
- 誤差來源:句以 frames.json 的列為單位(領起句與 ● 子句合一列),448 張卡的列數少於 tx 句數(23,775 列對 24,603 句),拆到每句只動巢狀括號、不動欄位數;中心詞用現行關鍵詞中心詞規則,不是未來的論元片語;修飾語、數量、方式的**字面**沒估,只估了類(小整數)。

### 速度(Node 22,14,207 張卡一次搜尋,30 次取中位數,ms)

| 查詢 | C | A |
|---|---|---|
| 1 述詞(特殊召喚、效果位、來源∈{墓地,除外}×{無,自分})→ 703 卡 | 3.2 | 8.7 |
| 3 述詞(上者 + 破壊@相手場上 中心詞含 モンスター + 送る/除外→墓地/除外 肯定) | 3.4 | 9.5 |
| 5 述詞(上者 + 加える:牌組/墓地→手牌 非此卡 + 排除 対象とする) | 3.6 | 8.2 |
| 條件位 1 述詞(存在、條件位、目的 自分:場上)→ 1,067 卡 | 3.8 | 9.7 |
| 只比中心詞 2 個子字串、沒有詞元(最差分支)→ 7,720 卡 | 10.2 | 17.1 |
| 3 述詞 + 只比中心詞 + 排除 | 4.1 | 8.1 |

評估器是純函式:述詞內同欄多值 OR、述詞間卡層 AND、排除卡層優先、回命中句與命中框。C 的中心詞子字串在查詢期先解成對照表碼集合(3,172 種掃一遍 0.35 ms),每框只比整數;A 每框對字面做 includes。fr 部分單獨 JSON.parse:C 1.9 MB 40 ms、A 4.9 MB 53 ms(data.js 是 JS 字面量,量級相當)。

### 結論(給規格 3 的事實與建議,格式仍由規格 3 定)

1. **編碼選 C**(定序元組 + 列舉小整數 + 中心詞對照表 + 尾端空值截掉):gzip 增量是 B 的 2/3、A 的 1/2;評估器也最快(整數集合比對)。VOCAB 多兩張表(詞元、中心詞)與各封閉類值域。
2. **不拆檔**:C 加 5 欄也只 +337 KB gz(+17%),一個 2.3 MB gz 的 data.js 還是一次載完;拆成第二個檔多一個請求與版本對齊問題,沒有換到什麼。若日後要延遲載入,fr 單獨是 1.4〜2.0 MB raw / 185〜296 KB gz。
3. **進索引的字面欄一律走對照表**:B 到 C 只差中心詞字面換碼,就省 90 KB gz(5.5 萬個字面)。未來修飾語、數量、方式若帶字面進索引,同樣要對照表,否則每個字面欄都是這個量級。
4. **評估器不需要倒排索引**:逐卡逐框掃 46,732 框,1〜5 個述詞 3〜4 ms,最差(沒有詞元、只比中心詞)10 ms,都在一次按鍵的預算內。
5. **再加封閉類欄便宜,高熵欄貴**:5 個偏態欄 +153 KB gz,同樣 5 欄均勻分布 +224 KB gz;每框別放雜湊、序號這類高熵值。
