# 07 — 遮蔽測試

**What to build:** 在投入 20 張判定票之前,先量化判定的準確率。從[[官方明示]]已填好的效果句裡分層抽 300 條、遮掉官方答案,只憑卡文與判定規範文件判一次,再對答案。這是判定鏈開跑的關卡,也是規範文件的回饋迴圈——測試失敗時修的是規範文件,不是重刷分數。

樣本檔自建,不依賴批次機制,所以這張票可以與合併/批次那條線平行進行。

**Blocked by:** 01 — 效果類型判別規範文件、03 — 官方明示:五階梯歸屬與類型抽取

**Status:** ready-for-agent

- [ ] 從 `source: "official"` 的效果句分層抽 300 條,六種類型各至少 40 條,不足的類別全取
- [ ] 樣本檔遮蔽官方答案,只保留卡名、繁中與日文效果句原文、以及不含類型結論的補足情報
- [ ] 判定只依據 `docs/effect_kind_guide.md`,不得回頭查看官方答案
- [ ] 產出**逐類別** recall 報告,總體準確率另報但不作為門檻
- [ ] 門檻為逐類別 100%;未達標時報告列出每一條錯判及其類型與句型
- [ ] 未達標時的動作依錯判性質分流並記錄:規範文件不清楚 → 補判別流程與例句;規則層本來就能判 → 移回規則;官方文本本身歧義 → 進「已知歧義清單」且不計入分母
- [ ] 已知歧義超過 300 條中的 5 條時停下回報,不繼續重跑(代表六類邊界定義本身有問題,需回頭改 `CONTEXT.md`)
- [ ] 執行五輪仍未達標即停下,報告當前準確率、各類別分布、以及未達標的原因分析
- [ ] 每一輪的準確率與修正動作記錄在本票內,形成收斂曲線
