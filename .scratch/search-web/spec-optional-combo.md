# Spec: 必發/選發軸的怪獸側組合鈕

Status: ready-for-agent

(2026-08-22 grill-with-docs 定案。母 spec:`spec.md`;本 spec 是其[[必發/選發]]軸的增量。)

## Problem Statement

[[必發/選發]]的使用情境大多落在怪獸效果上——現在的「必發」鈕 1,830 張卡裡有 1,481 張
(81%)是怪獸側([[效果類型]]為誘發即時(2速)/誘發(1速)的效果句)。但使用者想問
「怪獸的必發效果」時,得先在效果類型軸點開「怪獸側」組、點齊誘發即時與誘發兩顆,再回到
必發/選發軸點必發——三顆鈕、兩個軸,才問得出一個最常見的問題。

想更細地問「誘發效果的必發」(區分 1 速/2 速)也一樣:兩個軸各點一顆,而且兩軸的關聯
(句層耦合)藏在語意裡,畫面上看不出那是一組問題。

## Solution

[[必發/選發]]軸從兩顆鈕擴成**同一軸的兩組六顆**:

- **「全部」組**:既有的必發/選發二值,語意原樣——命中任何承載句(十二個承載類型)。
- **「怪獸側」組**:四顆**效果類型×必發/選發的組合條件**——鈕面「誘發即時(必發)」
  「誘發即時(選發)」「誘發(必發)」「誘發(選發)」。一顆鈕就是「同一[[效果句]]是該類型
  **且**帶該值」的單一條件。

全表卡數(2026-08-22 由 `web/data.js` 現場數得):

| 鈕 | 句 | 卡 |
|---|---|---|
| 必發(全部) | 2,061 | 1,830 |
| 選發(全部) | 7,634 | 5,833 |
| 誘發即時(必發) | 16 | 16 |
| 誘發即時(選發) | 1,526 | 1,421 |
| 誘發(必發) | 1,664 | 1,467 |
| 誘發(選發) | 5,034 | 4,132 |

誘發即時(必發)全庫只有 16 張——官方裁定裡 2 速必發本來就極稀有。這顆鈕很小但不是零,
照建置慣例保留。

**魔陷側不設組合鈕**:軸內排除優先的既有語意已經表達得出來——「必發(全部)包含 +
誘發(必發)排除 + 誘發即時(必發)排除」= 魔陷側必發(360 張)。

## User Stories

1. As a 使用者, I want 一顆「誘發(必發)」鈕, so that 「怪獸的必發誘發效果」這個最常見的
   問題從跨兩軸三顆鈕變成一顆。
2. As a 使用者, I want 組合鈕區分誘發即時(2速)與誘發(1速), so that 我查「對方回合也能
   連鎖的必發」時不被 1 速的結果淹掉。
3. As a 使用者, I want 原本的必發/選發保持原樣(「全部」組), so that 既有的「找所有必須
   發動的效果」問題(含魔陷側)一顆鈕照舊問得出來。
4. As a 使用者, I want 組合鈕與效果文關鍵字同句耦合, so that 「效果文=特殊召喚 +
   誘發(必發)」找到的是「一個必發的誘發效果做特招」,而不是兩件無關的事湊在同一張卡。
5. As a 使用者, I want 組合鈕的排除態是「這一句不是『該類型且該值』」, so that 排除
   誘發(必發)時,誘發但選發的句子、非誘發的句子都不被擋——與句層三態的既有語意一致。
6. As a 使用者, I want 「必發(全部)包含 + 怪獸側兩顆必發排除」問得出魔陷側必發,
   so that 不補魔陷側組合鈕也能問到那 360 張卡。
7. As a 使用者, I want 命中的效果句照舊標亮並掛 badge, so that 我看得出這張卡是因為
   哪一句被選中。
8. As a 使用者, I want badge 寫那一行自己的值(「必發」), so that 與既有 badge 語意一致
   ——這是什麼類型由旁邊既有的效果類型 badge 回答,不重複寫。
9. As a 使用者, I want 兩組鈕在同一軸內是 OR、同軸包含與排除並存時排除優先, so that
   組合鈕不引入第二套條件語意。
10. As a 使用者, I want 效果類型軸的包含選取全都不是誘發即時/誘發時「怪獸側」組隱藏並
    清空, so that 「啟動效果 + 誘發(必發)」這種同句不可能成立的條件設不出來。
11. As a 使用者, I want 「全部」組照既有規則隱藏(包含的效果類型全都不承載時), so that
    「永續效果是必發」照舊設不出來——連動隱藏的粒度從軸下放到組,兩組各自判。
12. As a 使用者, I want 一顆效果類型都沒選時兩組都顯示, so that 「誘發(必發)」單獨就是
    一個有結果的條件,不必先去效果類型軸點任何鈕。
13. As a 使用者, I want 怪獸側組因效果類型的承載而出現時自動展開(沿用既有的自動展開
    時機), so that 連動帶出來的條件看得見。
14. As a 使用者, I want 組合鈕的選取進網址 hash, so that 查詢照舊可以分享、重載後還原。
15. As a 使用者, I want 不承載必發/選發的效果句(22,942 句)不被組合鈕命中也不被其排除態
    排掉, so that 「不承載不是一個值」的既有原則對組合鈕同樣成立。
16. As a 使用者, I want 組合鈕與效果類型軸並用時句層 AND 自然運作(不設防), so that
    組還在時設出的細粒度矛盾(效果類型只含誘發即時 + 誘發(必發))得到誠實的零結果,
    而不是某顆鈕被魔法般鎖住。
17. As a 維護者, I want 四顆組合鈕的成員宣告住[[值域正典]]、按鈕由 VOCAB 生成, so that
    不在前端手抄第二份清單(ADR-0008 的失效模式:抄了就漂移,漂移的形狀是一組條件
    安靜地不出現)。
18. As a 維護者, I want 正典自檢驗證組合成員的效果類型是承載者、分組蓋滿全部可篩選成員,
    so that 宣告寫壞在建置期就撞到,而不是某顆鈕安靜地消失。
19. As a 維護者, I want `web/data.js` 完全不動(組合由既有的效果類型與必發/選發兩個逐句
    欄位現場推導), so that 7.6 MB 的版控產物不必為這個 UI 增量重生。
20. As a 維護者, I want CONTEXT.md 的[[必發/選發]]與[[連動隱藏]]詞條已更新(本次 grilling
    已寫入), so that 詞彙表與實作一致。

## Implementation Decisions

- **同一軸、分兩組**:組合鈕不是新軸。拆成獨立軸的話「必發(全部) AND 誘發(選發)」這種
  永遠零結果的軸間組合會設得出來——正是母 spec Story 25 要擋的失效模式。分組呈現與
  效果類型軸的「怪獸側/跨類型魔陷效果」同一個手法。
- **組名「全部」「怪獸側」**;怪獸側鈕面省略「效果」與速度標注:「誘發即時(必發)」
  「誘發(選發)」等——與效果類型軸的全名「誘發即時效果(2速)」對得起來,但不佔滿一列。
- **組合是[[值域正典]]的宣告**:必發/選發值域多四個組合成員,各自宣告「哪個效果類型 ×
  哪個值」;值本身仍只有必發/選發二值(組合成員不是第三種值,是條件的形狀)。正典自檢
  多兩條:組合指到的效果類型必須是承載者(carriers 的成員)、必須是怪獸側六類。
- **前端由逐句的效果類型碼與必發/選發碼現場推導組合命中**:一句對組合軸的值集合是
  「自己的必發/選發碼 + 符合的組合碼」,既有的三態比對函式直接吃——包含、排除、
  軸內 OR、排除優先全部不另寫規則。
- **逐卡索引零改動**:`o`/`k` 欄位原樣,無新欄位;`web/data.js` 的 VOCAB/META
  尾段隨正典重生(`window.VOCAB` 住在 data.js 裡),14,207 行卡片資料逐位元組不變。
- **ADR-0010 的本類排除與組合無交集**:組合只指怪獸側的誘發即時/誘發,而本類語意只
  作用於魔陷十值,兩者天然不相撞;組合的命中不因此需要特例。
- **連動隱藏粒度下放到組**:全部組收於「包含的效果類型全都不承載」(既有規則原樣),
  怪獸側組收於「包含的效果類型全都不是誘發即時/誘發」。排除不算已選,照舊。隱藏即
  清空,照舊。可用性判斷的介面從單一布林改為兩組各自的答案。
- **細粒度矛盾不設防**:組可見時,效果類型軸與組合鈕仍可能設出同句不可能滿足的條件,
  句層 AND 給零結果,不加反向鎖定。
- **hash**:必發/選發那一段多四個組合碼,編解碼與非法碼丟棄沿用既有規則。
- **badge**:命中行照舊寫該行自己的必發/選發值;效果類型另有既有 badge,不合併。
- **不做的對稱**:魔陷側組合鈕不補(用排除態表達);「怪獸必發/怪獸選發」聚合鈕不做
  (使用者裁示:要的是逐類型的組合,不是怪獸側總和)。

## Testing Decisions

- 只測外部行為:條件物件進、命中卡與命中效果句索引出;不測 DOM、不測內部函式。
- 五個既有接縫,零新接縫,建置管線側無新測試(零改動):
  1. **接縫 3(引擎)**:vm 沙箱載真實前端碼(`frontend_harness.js`),合成資料集。
     測組合鈕的同句命中/排除、與效果文關鍵字及效果類型軸的句層交集、與全部組的
     軸內 OR 與排除優先、不承載句不被命中也不被排除。先例:母 spec 票06 的接縫 3 測試。
  2. **可用性規則**:兩組各自的連動隱藏答案(全部組沿用既有案例、怪獸側組新案例:
     只含啟動效果 → 收;含誘發即時 → 開;排除不算已選;空選擇 → 兩組都開)。
     先例:既有 `optionalAvailable` 測試群——注意介面改為兩組,既有測試跟著改形狀。
  3. **軸生成**:必發/選發軸由 VOCAB 長出兩組六顆(組名、順序、鈕面)。先例:既有
     `axes()` 測試。
  4. **hash roundtrip**:四個組合碼進出網址、非法碼丟棄。先例:既有 parseHash/hashOf
     roundtrip 測試群。
  5. **正典自檢**(Python 側):組合成員宣告合法性、指到非承載者/非怪獸側即不合法、
     匯出形狀。先例:`test_vocab.py` 的 carriers 測試。
- DOM 渲染(分組標題、隱藏清空、自動展開的實際畫面)照母 spec 慣例走人工驗收。
