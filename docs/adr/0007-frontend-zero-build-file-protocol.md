# 查卡網站不引入建置工具:原始碼就是上線碼

`web/` 底下的東西**沒有建置步驟**。沒有 npm、沒有 bundler、沒有框架、沒有 TypeScript、
沒有 ES modules。HTML 一個、CSS 一個、幾支 `<script src>` 逐一載入的 JS,模組是掛在全域的
IIFE 閉包。瀏覽器載進去的每一個位元組,都與 repo 裡那個檔案逐字相同。

這條約束的代價很具體——沒有型別檢查、沒有真正的模組邊界、沒有熱更新——所以要寫下它換到
了什麼。

## 考慮過的三種

**Vite + 框架。** 換到 TypeScript、元件化與熱更新。代價有四層,前兩層是這個 repo 特有的:

1. **CI 那條路走不通。** GitHub Pages 只吃 repo 裡的靜態檔,它不會幫忙跑 build。正常做法
   是接 GitHub Actions,但專案規則是**永不 push**、目前也沒有 remote,Actions 需要 push 才
   觸發。所以只剩「把 `dist/` commit 進版控」這一條路。
2. **雙軌維護。** 原始碼與產物並存,每改一行前端都要記得重跑 build 再 commit,忘了就是
   上線舊版。而產物是壓縮過的單檔、hash 檔名每次都變,`git diff` 完全不可讀——這個 repo
   的每一份資料都刻意做成 diff 可讀([[效果標記表]]一卡一物件、[[卡片總表]]一卡一行),
   前端產物會是唯一的例外。
3. **零安裝破功。** 專案至今是「僅需 Python 3 標準庫,無安裝依賴」。上了 node 工具鏈之後,
   任何人(包括未來的自己、或新 session 的 agent)要改一行 CSS 都得先 `npm install`。
4. **`base` 路徑。** GitHub Pages 專案站的網址是 `/<repo>/`,Vite 要設 `base`,設錯就是
   全站資源 404。相對路徑的零建置方案沒有這個問題。

換到的東西相對薄:這個站沒有路由、沒有後端、沒有共享狀態管理,前端總量是六個檔案的量級。
打包後的 JS/CSS 只有幾十 KB,跟 7.8 MB 的[[前端索引]]比根本不算什麼——**體積從來不是
這個決定的變數,雙軌與依賴才是**。

**零建置但用 ES modules。** 一樣不需要 npm,但有真正的模組邊界。**致命傷是 `file://`**:
ES modules 受 CORS 管轄,雙擊開啟 `index.html` 會白屏,本機驗證一律得先起 server。
這條約束會傳染——[[前端索引]]也就不能用 `.js`(`fetch` 同樣被擋),整套零安裝的驗證方式
跟著陪葬。模組邊界值不了這個價。

**零建置、純 `<script>`(採用)。** 原始碼即上線碼。

## 這條約束保護的是什麼

不是「簡單」,而是**驗證與修改的門檻**。具體有三件事因此成立:

- 雙擊 `web/index.html` 就能看到真實的站,不需要任何前置步驟。
- clone 下來的人不裝任何東西就能改、就能驗。
- 上線與本機是同一份檔案,所以「本機好好的、線上壞了」這個類別的 bug 從結構上不存在。

同一個理由已經寫在專案的 Python 側:三個模組都只用標準庫。前端與後端的門檻一致,不是
巧合而是同一個決定的兩面。

## Consequences

- **[[前端索引]]必須是 `.js` 而不是 `.json`**(`window.CARD_DATA=…`)。`file://` 下 `fetch`
  會被 CORS 擋,`<script src>` 不會。這不是風格偏好,是本 ADR 的直接後果。
- **沒有型別檢查,所以介面靠測試守。** 前端查詢引擎因此需要自己的測試接縫
  (`查詢條件 → 命中卡片與命中效果句`),而不是只靠人工點一點。
- **測試也必須零安裝。** 用 node 內建能力(`node:test` / `node:vm`)、零 npm 依賴、
  不進 `package.json`。前例是 oldProject 的 `scripts/audit/frontend_parity.js`:以 `vm`
  沙箱依 `index.html` 的 `<script src>` 順序載入**真實的前端程式碼**——這也意味著前端
  檔案不必為了可測而加 `module.exports` 之類的東西,production 碼保持乾淨。
- **瀏覽器自動化測試(Playwright 等)被排除。** 它會拖進 npm 依賴與瀏覽器下載,
  推翻本 ADR。DOM 渲染、CSS、卡圖載入這些走人工驗收清單。
- **要推翻這條,先推翻它。** 若將來真的需要建置工具(例如站長成有路由的多頁應用),
  正式的動作是新開一份 ADR 說明為什麼,並保留這一份註明被取代——而不是默默加一個
  `package.json`。
