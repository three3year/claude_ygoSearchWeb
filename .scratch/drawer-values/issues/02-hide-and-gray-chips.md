- 做法:引擎 `Engine.fieldValues(述詞, 欄)` 回「述詞其他欄成立的框上這一欄出現過的值」,只掃詞元自己的框(詞元碼 → 框號第一次呼叫才建,載入時沒有框表的頁面與測試不受影響)。為了解碼,`FRAME_CHECKS` 改成 `FRAME_FIELDS`:每欄一個 `{check, codes, value}`,欄的 slot 與編碼只寫一處;`predHitTable` 照舊用 check。條件模型 `Cond.drawerOptions(標籤)` → `[{group, fields: [{field, kind, …}]}]`,點選鈕的欄帶 `values: [{value, state}]`,state 是 亮、鎖住、可按、灰;隱藏 = `fieldValues({詞元}, 欄)` 沒有,灰 = `fieldValues(述詞, 欄)` 沒有;亮著的一律列出。`Cond.locked` 不再匯出,鎖住由抽屜選項給。抽屜照它畫:灰與鎖住都是 `disabled` 加 title(「目前條件下沒有結果」「至少要留一個」),灰的 CSS 是 `.drawer-chip:disabled:not(.on)` 淡掉;組沒有欄就不畫,「進階」小標跟著不畫。
- 給票 03、04 的接點:`cond.js` 的 `FIELD_OPTIONS = { values: chipOptions, region: regionOptions, text: textOptions }`,票 03 只改 `regionOptions`、票 04 只改 `textOptions`(回 null 就是整欄不列);`strip.js` 的 `FIELD_BODY = { values: chipsHtml, region: regionHtml, text: textHtml }`,畫法各改 `regionHtml(tag, option)`、`textHtml(tag, option)`,option 就是抽屜選項的那一欄。引擎已能解區域對(`[玩家, 區域]`,先排區域)與中心詞(依中心詞表順序):`Engine.fieldValues({詞元}, '來源')`、`Engine.fieldValues(述詞, '受事者中心詞')`。兩張的例子各開自己的測試檔(CODING_STANDARDS 平行票規則),小框表可抄本檔。
