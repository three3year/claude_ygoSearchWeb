# 08 — 判定結果合併、批次檔與判定票產生

**What to build:** 判定工作變得可執行。建置流程能吐出批次檔(每票 300 張卡、補足情報全量不裁剪),能把判定票寫回的結果檔合併進[[效果標記表]],並依**實際**批次數產生後續的判定票檔案。

關鍵契約:判定結果**可以改變效果句的集合**,不只是填 `kind`——無編號舊式卡文的語意拆分是由判定者完成的,骨架票只把它們當單一效果句,合併時必須能用判定結果替換該卡的整組效果句。

**Blocked by:** 03 — 官方明示:五階梯歸屬與類型抽取、04 — 必發/選發規則層、05 — 重跑保留語意

**Status:** ready-for-agent

- [ ] 批次檔產生:從[[效果標記表]]取出仍為 `kind: null` 的卡,每批 300 張,附繁中與日文卡文與**完整**補足情報(不裁剪)
- [ ] 批次檔含判定所需的全部上下文,判定票不需要回頭查其他來源
- [ ] 接縫的 `判定結果` 參數生效:能填入 `kind` / `optional` / `role`,也能**替換某卡的整組效果句**以支援無編號卡的拆句,需有測試
- [ ] 判定結果寫入的效果句,其 `text_zh` / `text_ja` 必須是原卡文的連續子字串,不通過者不寫入、列進待審清單,需有測試
- [ ] 合併時的集合一致性自檢:結果檔涵蓋的效果句集合必須與對應批次檔完全相同,少一筆或多一筆即失敗
- [ ] 合併後的行 `source` 為 `"llm"`,`confidence` 依該卡是否有官方補足依據決定
- [ ] 依實際批次數產生判定票檔案,編號自 `10` 起,每張含完整自足的工作契約(讀規範 → 讀批次 → 判定 → 寫結果 → 自檢 → 合併 → 歸納規則)
- [ ] 第一張判定票的 blocked by 為 06、07、08;後續每張再加上前一張判定票
- [ ] 更新票 09 的 blocked by 為實際的判定票編號範圍
- [ ] 報告列出批次總數、每批卡數、以及待判效果句總數
