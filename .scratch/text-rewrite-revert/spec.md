# Spec:舊卡翻新全數還原(text-rewrite-revert)

Status: ready-for-agent

## Problem Statement

站主推行「舊卡翻新」(將舊式卡文依文本格式規範改寫為新式)已進站 344 筆,但整條路線被判定為不穩定:改寫品質批次間不一致、規範通則反覆追加修訂導致已完成批次不斷回頭重核、每批的審查/交叉檢核/票證流程成本過高、且持續存在改壞官方原文語意的風險。站主對翻新後文本的可信度失去信心,決定止損:將所有已翻新的卡片文本全數還原為上游原文,並清除翻新的過程產物,讓網站回到「只呈現原文(僅套用卡文勘誤表)」的穩定狀態。

## Solution

利用翻新機制「可逆疊加層」的設計:文本改寫表是唯一真值源,上游繁中卡文資料庫從未被覆寫。將文本改寫表清空後重跑建置管線,所有卡片文字自動回到原文。同時拆除只為翻新流程服務的週邊(後端審查工具、三級分類的「本站已改寫」級、過程檔案、規範文件中的純翻新追記),但保留換文機制本身、前端顯示原文功能(休眠)、以及與其他功能綁定或屬於其他功能的一切。完成後以一次性腳本逐筆比對建置產物與上游原文,證明零差異。

## User Stories

1. 作為站主,我想把 344 張已翻新卡的效果文字全數還原為上游原文,讓網站文本回到可信的官方基準。
2. 作為站主,我想保留文本改寫表的檔案(空表)與建置期換文機制,讓未來若以更穩定的流程重啟翻新時管線可直接沿用。
3. 作為站主,我想保留前端「顯示原文」功能的程式碼(還原後因無資料而休眠、使用者不可見),讓未來重啟時不必重做。
4. 作為站主,我想拆除只服務翻新流程的後端工具(反向檢查、網頁審核台、子批擬稿詞彙表機檢殼),讓程式碼庫不殘留無主工具。
5. 作為站主,我想拆除三級分類的「本站已改寫」級,讓分類報表回到還原後不會出現死類別(恆為 0 筆)的四級形態。
6. 作為站主,我想保留分類器的無效果怪獸排除,因為那是分類器本身的正確性修正,與翻新無關。
7. 作為站主,我想從文本格式規範中刪除純翻新追記(來源層級段、翻新產生的五條尾句/通則裁示、分層來源段),讓規範不再引導任何人繼續翻新。
8. 作為站主,我想保留文本格式規範中與翻新無關或與程式碼綁定的內容(全形範圍記號裁示、適用宣告句規範、與分類器偵測邏輯綁定的段落),讓規範與程式行為保持一致。
9. 作為站主,我想讓規範中的文本改寫表章節與 CONTEXT.md 的文本改寫表詞條保留但註明「現為空表、機制休眠」,讓未來讀到換文程式碼的人找得到詞彙定義且不被誤導。
10. 作為站主,我想從 CONTEXT.md 刪除純翻新流程詞條(句型群、子批)與分級清單中的「本站已改寫」,讓詞彙表只反映還原後仍活躍的概念。
11. 作為站主,我想清除整個翻新過程檔案目錄(進度圖、十九張票、審查檔,含工作區未提交的子批7半成品),讓工作區乾淨、翻新僅存於 git 歷史。
12. 作為站主,我想清除翻新期間產生的九個效果種類補判檔,避免還原後留下掛在已不存在文本上的掛空判定。
13. 作為站主,我想確保卡文勘誤表及其整條產生鏈(卡文詞彙表模組、全庫掃描工具、詞彙表文件)完全不被波及,因為修誤譯與翻新是兩回事。
14. 作為站主,我想在動任何資料前先備份上游繁中卡文資料庫,因為它不在版本控制內、是唯一的原文來源。
15. 作為站主,我想在還原後逐筆比對每一張受影響卡片的建置產物與上游原文全等,證明「真的全部還原了、而且沒還原錯」。
16. 作為站主,我想在還原後看到全部既有測試通過(含隨拆級同步修正的測試與硬編碼段數基準),證明週邊拆除沒有破壞其他功能。
17. 作為網站使用者,我想搜尋與閱讀到的卡片文字都是上游原文(僅含勘誤),不再混有本站自行改寫的版本。
18. 作為未來讀 git 歷史的人,我想從還原提交的訊息理解為何歷史上有四十餘個翻新提交但現行資料裡沒有翻新,決策脈絡不失傳。

## Implementation Decisions

- **還原走「清資料+重建」,不走 git revert**:翻新提交與工具/規範變更嚴重混雜(四十餘個提交中至少二十個含非翻新變更),revert 必然誤傷且大檔衝突;而換文機制設計上以文本改寫表為唯一真值源、上游原文從未被覆寫,清空後重建即完成還原。
- **文本改寫表**:清成空表,檔案保留;建置期換文機制(全文相等校驗、與勘誤表互斥校驗)與相關測試全部保留。空表時機制不作用,既有測試已覆蓋此行為。
- **前端顯示原文**:程式碼保留。其資料欄位由建置流程從改寫表餵入,空表時欄位不再產生,功能自然休眠、使用者不可見。
- **後端翻新工具拆除**:反向檢查工具、網頁審核台、子批擬稿詞彙表機檢殼(薄殼)三者刪除。卡文詞彙表模組本體、全庫掃描工具、其測試與詞彙表文件屬 text-glossary/勘誤系統(現行勘誤表約九成五內容的產生工具),不動。
- **三級分類「本站已改寫」級拆除**:分類器回到兩參數純函式與四級形態(舊文本/官方已改寫/新格式新卡/日期不明);分類報表移除該級的區塊、總覽列與對應命令列參數;全庫掃描工具同步去掉該參數。無效果怪獸排除保留。分級拆除與清空改寫表必須同一批完成(只拆級不清表會讓已改寫卡污染優先稽核佇列,反之則留死類別)。
- **文本格式規範精準手工挑**:刪除來源層級段、翻新裁示產生的五條尾句/通則、分層來源段;保留全形「～」範圍記號裁示(獨立格式裁示)、適用宣告句規範(約束對象為既有新卡的合規稽核)、與分類器偵測邏輯綁定的偵測規則段(只退文件會造成規範與程式不一致);文本改寫表章節保留並加註現為空表。已搬遷至詞彙表文件的對照表不搬回(避免兩處重複)。
- **CONTEXT.md 詞條**:刪「句型群」「子批」;「文本改寫表」詞條精簡並加註機制休眠;卡文勘誤表詞條的互斥交叉引用簡化;分級清單去掉「本站已改寫」。「卡文詞彙表」「無效果怪獸」詞條與「舊式段全集等於待拆段扣除無效果怪獸」的敘述必須保留(與現行程式行為綁定)。
- **效果種類規則文件不手動修改**:它是效果標記表建置流程的機器回寫產物(規則定義指紋期間未變,差異全為統計數字漂移),重建後數字自動回寫正確值。
- **過程檔案清除**:翻新過程目錄整個刪除(含工作區未提交的子批7半成品與已修改未提交的進度檔);九個翻新補判檔刪除,對應卡片的效果種類判定回到翻新前狀態。
- **拆句表收尾**:重建後若拆句表存在僅對應已不存在改寫文本的掛空筆,一併移除(與清除掛空補判同一精神);對應原文的拆句筆不動。
- **執行順序**:備份上游資料庫 → 清空改寫表 → 拆工具 → 拆分級 → 改規範與詞彙表 → 清過程檔案 → 重跑完整建置鏈(卡片總表 → 效果標記表 → 前端資料 → 分類報表)→ 全測試 → 逐筆比對驗收。全部完成並經站主驗收後才提交;提交訊息需交代還原決策脈絡(依專案慣例,站主明說才 commit,且永不 push)。
- **硬編碼基準同步**:分類測試中硬編碼的舊文本段數迴歸錨點隨還原改回還原後的實際值(或隨拆級重寫)。

## Testing Decisions

- **不新增任何永久測試接縫**。還原是一次性操作;「空表時建置不套用改寫」的行為既有測試已覆蓋。
- **最高接縫=建置產物對上游來源**:以一次性比對腳本(置於 scratchpad,用完即棄、不進 repo)驗證:(1) 344 張受影響卡片的卡片總表文字與上游繁中資料庫原文逐筆全等;(2) 前端資料檔中改寫前原文欄位歸零(0 個);(3) 分類報表回四級、「本站已改寫」區塊消失、舊文本段數回升至還原後應有值;(4) 效果標記表中受影響卡片的文字雜湊回到原文雜湊。
- **既有測試套件全綠**:分類器、詞彙表、卡片總表建置等既有測試,隨拆級同步修正後全部通過。好測試只驗外部行為(建置產物內容、分類結果),不驗實作細節;先例即本 repo 各建置腳本現有的測試風格。
- 驗收由站主基於比對腳本輸出與測試結果裁定;通過前不提交。

## Out of Scope

- **卡文勘誤表**(修誤譯的子字串替換)及其 163 筆內容:與翻新互斥、性質不同,完全不動。
- **卡文詞彙表系統**(詞彙表文件、核心模組、全庫掃描、其測試):屬勘誤產生鏈,不動。
- **無效果怪獸排除**與其測試:分類器正確性修正,不動。
- **效果標記表系統**(規則定義、判定流程、ADR 既定決策):除補判檔清除與重建自然回寫外,不動。
- **未來是否/如何重啟翻新**:站主明示還原後另行討論,本規格不設計新流程、不寫教訓文件、不立 ADR。
- **git 歷史改寫**:四十餘個翻新提交留在歷史中,不 rebase、不刪。

## Further Notes

- 上游繁中卡文資料庫不在版本控制內(來源目錄被 gitignore),整條還原依賴本機快照,故第一步備份為硬性前置。若快照遺失,備援路徑是用改寫表每筆自帶的改寫前全文回填(344 筆全齊),但本規格以主路徑為準。
- 翻新期間的規範文件變更已逐提交盤點過:哪些屬純翻新追記、哪些與程式碼綁定、哪些屬其他功能,結論已固化在上方實作決策中,執行時不需重新考古。
- 本規格由 /grill-with-docs 訪談收斂而來,所有取捨均為站主逐項裁示;執行中若發現盤點外的牽連,停下回報而非自作主張。
