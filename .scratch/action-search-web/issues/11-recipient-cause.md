# 11: 受方與原因

**What to build:** 可以篩「落在誰身上」與「因為什麼」。Python 的查詢判斷和網站都能用。

- 查詢判斷多兩個鍵:受方(我方或對手)、原因(種類,可以再給是哪一方的)。沒給時行為與現在相同。
- 受方:只比受方是玩家的段。受方是卡的段、沒有受方的段,在查詢給了受方時不命中。
- 原因的種類:寫的和查的相同命中;寫「戰鬥或效果」時查戰鬥、查效果都命中;寫「戰鬥以外」時查效果命中、查戰鬥不命中。其餘種類(作為素材、召喚方式、方法、規則)寫什麼比什麼。
- 原因的哪一方:查詢給了方,段的原因沒寫方時命中(寫得比查詢寬);寫了方就要相同或同時含兩方。
- 沒寫原因:被動句是不限定,用票 10 的同一個開關,開了才命中;主動句不命中。
- 兩者都是段的欄,比的是段。對未解析組不生效。
- 攤平的列多受方、原因兩欄(原因沒寫時分得出是被動句還是主動句),寫進動作索引;原因值的清單與列數進索引的表。
- 網站:區塊多受方、原因(種類與哪一方)的選項。原因的選項由索引的表生成,不列「戰鬥或效果」「戰鬥以外」。

- 規格:需要你決定的「Q4」「Q5」「Q17」;實作決策「比對規則」的受方與原因;使用者故事 20–27、47;測試決策「接縫一」與標準卡表。
- 候選標準卡:受方 毒サソリの罠、溶岩魔神ラヴァ・ゴーレム、バスター・スナイパー;原因 ミラクル・フリッパー、アンクリボー、ラヴァル・ランスロッド、リミット・リバース、神縛りの塚、蛇神降臨、黒魔導強化。

**做了什麼**
- 攤平(`action_rows.py`):列多兩欄,只往後加。`recipient`(`recipient_of`):受方是玩家時的方(我方、對手、雙方各自;玩家字面 `{"side", "text", ...}` 取它的方),受方是卡(物件回指)或沒有受方是 None。`cause`(`cause_of`):(種類, 方或 None);沒寫原因時,被動句是 (不限定, None)、主動句是 None。
- 比對(`row_match.py`):查詢多兩個鍵。`recipient`(我方/對手,其他值 `ValueError`):段的受方相同或是雙方各自命中。`cause`:種類字串,或 `{"kind", "side"}`(比照 `from_zones` 的 `{"zone", "side"}`);種類只收八種(戰鬥、效果、戰鬥或效果、戰鬥以外、作為素材、召喚方式、方法、規則),方只收我方/對手,其他 `ValueError`。判法 `cause_matches`:種類相同,或寫的涵蓋查的(`CAUSE_COVERS`:戰鬥或效果 → 戰鬥、效果;戰鬥以外 → 效果);給了方時段沒寫方、方相同或雙方各自命中;不限定只在 `include_unrestricted` 開時命中;主動句沒寫不命中。兩者是段的條件,和誰排在一起(線比對之前);經引用照著走(被引用卡的命中段也要符合),未解析組不看。`action_query.py` 的查詢鍵說明補上這兩個鍵。
- 動作索引(`action_index.py`):值的清單多 `causes`,帶列數 [值, 列數](值另含 null = 沒寫的主動句、不限定 = 沒寫的被動句;網站生成選項時濾掉)。卡那一行多第 8 格「受方」(每段在 `sides` 的位置,null 的位置是沒有)、第 9 格「原因」(原因碼 = 種類在 `causes` 的位置 × 8 + 方在 `sides` 的位置,同區域碼),只往後加。`decode_action_index` 的段多 `recipient`、`cause`。
- 網站:`Action.condOf` 多 `recipient`(只收我方、對手)、`cause`(`{ kind }` 或 `{ kind, side }`;種類不是字串或是「不限定」整欄不算,方認不得只丟方);`count` 各多算一條;`rowQuery` 換成 `recipient`、`cause`;`prepare` 讀第 8、9 格;`match` 多受方與原因的比對(`causeMatches`);`causeOptions` 由索引的原因表依列數生成,不列戰鬥或效果、戰鬥以外與沒寫的兩種。`ActionPanel` 多「落在誰身上」三選一(不限/我方/對手)與「因為什麼」兩個下拉(種類;不限哪一方/我方的/對手的),跟著瀏覽紀錄存還原、「清除條件」一併清。「含不限定的」勾選移到原因之後(誰與原因共用),提示文字補上沒寫原因的被動句。
