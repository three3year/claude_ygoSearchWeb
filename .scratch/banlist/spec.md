# Spec: 禁限狀態(OCG/TCG/MD 禁限卡表)顯示與搜尋

Status: ready-for-agent

> 詞彙依 CONTEXT.md:[[禁限狀態]]、[[卡片總表]]、[[前端索引]]、[[值域正典]]、[[軸]]、
> [[摺疊]]、[[資料更新時間]]、[[卡片密碼]]、[[同名異圖卡]]。
> 相關 ADR:ADR-0007(零建置協定)、ADR-0008(值域正典/按鈕由 VOCAB 生成)。

## Problem Statement

同一張卡在 OCG、TCG、Master Duel 三個賽制各有自己的禁限卡表狀態(禁止/限制/
準限制),這是組牌與查卡時的關鍵資訊。使用者目前在本站查到一張卡後,得另開
其他網站才知道「這張卡現在能投幾張」,而且三個賽制要查三個地方。

## Solution

把三賽制的禁限狀態接進資料管線,在卡片畫面上以徽章列顯示,並在側欄新增
「禁限」搜尋軸讓使用者能以禁限狀態篩卡(含跨賽制交集,例如「OCG 禁止但
TCG 無限制」)。資料來源不新增第三方依賴:OCG/TCG 取自既有的 ygoprodeck
(禁限端點),MD 取自既有的 masterduelmeta(同一 API 多帶 banStatus 欄位),
皆以[[卡片密碼]]對齊[[卡片總表]]。

實測規模(2026-08-22):OCG 193 張(禁 91/限 90/準 12)、TCG 221 張
(禁 117/限 94/準 10)、MD 230 張(Forbidden 110/Limited 1 94/Limited 2 26)。

## User Stories

1. 身為查卡的玩家,我想在卡片畫面上直接看到這張卡在 OCG/TCG/MD 的禁限狀態,這樣不用另開其他網站查。
2. 身為 OCG 玩家,我想一眼認出「禁止/限制/準限制」這套官方用詞,這樣不用在腦中翻譯 Forbidden/Limited 這類外來詞。
3. 身為 MD 玩家,我想看到 MD 的 Limited 1/Limited 2 以同一套「限制/準限制」用詞呈現,這樣三個賽制讀起來是同一種語言。
4. 身為同時玩多個賽制的玩家,我想在一張卡上並列看到三賽制的狀態,這樣能比較賽制間的差異(例如 OCG 禁止但 TCG 還能用)。
5. 身為讀卡片列表的使用者,我想讓沒上任何榜的卡不多出一列雜訊,這樣常態卡的版面保持乾淨。
6. 身為讀禁限列的使用者,我想在有任一賽制上榜時三個欄位齊列(未上榜的寫「—」、未發行的寫「未發行」),這樣欄位整齊、不用猜缺席的欄位是什麼意思。
7. 身為讀卡片標題列的使用者,我想讓禁限徽章與既有的稀有度/限定徽章同一套視覺語言,這樣畫面不會多出一種風格。
8. 身為搜尋的使用者,我想有一個「禁限」軸能點出「OCG 禁止的卡」,這樣能快速瀏覽某賽制的禁止卡池。
9. 身為搜尋的使用者,我想在同一賽制內多選(例如 OCG 的禁止+限制)得到 OR 語意,這樣「上榜的卡」一次問得出來。
10. 身為搜尋的使用者,我想跨賽制的選取是 AND 語意(例如 OCG 禁止 且 MD 禁止),這樣問得出「兩邊都禁」的卡。
11. 身為搜尋的使用者,我想用三態鈕的排除態(例如排除 TCG 禁止),這樣能把某賽制不能用的卡從結果剔掉。
12. 身為搜尋的使用者,我想把禁限條件跟既有條件(大類、種族、效果文……)並用,這樣能問「OCG 限制的龍族」這類複合問題。
13. 身為搜尋的使用者,我想把含禁限條件的查詢以網址分享,這樣別人打開連結看到同一份結果。
14. 身為側欄的使用者,我想讓「禁限」是一個可摺疊的父層、三賽制各自一個子軸,這樣不用時收起來不佔空間,收起時已選數照樣彙總提示。
15. 身為側欄的使用者,我想在「OCG・TCG 限定」軸旁邊找到禁限軸,這樣賽制相關的條件聚在同一區。
16. 身為訪客,我想知道禁限資料跟著[[資料更新時間]]走(footer 可查),這樣能判斷禁限表改版後站上資料有多新。
17. 身為訪客,我想在 footer 的資料來源行看到禁限資料的出處,這樣知道這份資訊的可信基礎。
18. 身為維護者,我想讓來源多下載兩份檔案也維持原子替換與離線重建(--offline),這樣更新流程的既有性質不被破壞。
19. 身為維護者,我想讓來源出現預期外的禁限值字串時建置失敗而不是靜默略過,這樣不會有一批卡的禁限無聲消失(值域正典原則)。
20. 身為維護者,我想讓同一份輸入兩次建置的索引逐位元組相同,這樣 git diff 讀得出這次禁限表改了哪幾張卡。
21. 身為維護者,我想在建置報告裡看到禁限資料的對齊情形(對不上密碼的筆數等),這樣來源異動時能察覺缺口。
22. 身為查[[同名異圖卡]]的使用者,我想讓禁限狀態掛在本尊上(異圖密碼也對得回來),這樣不會因為來源用了異圖密碼而漏標。

## Implementation Decisions

### 資料來源與下載

- OCG/TCG:ygoprodeck 卡片資訊 API 的 `banlist=ocg` / `banlist=tcg` 端點,各存一份
  來源檔;回傳的 `id` 是卡片密碼,`banlist_info.ban_ocg` / `ban_tcg` 的值域為
  `Forbidden` / `Limited` / `Semi-Limited`。
- MD:masterduelmeta 既有的分頁抓取多帶 `banStatus` 欄位,值域 `Forbidden` /
  `Limited 1` / `Limited 2`;來源檔由 `{密碼: 稀有度}` 擴為同時承載稀有度與禁限。
- 下載沿用既有慣例:.tmp 原子替換、單來源失敗不毀既有檔、`--offline` 沿用既有
  來源檔、User-Agent 照舊。[[資料更新時間]]仍是一次下載執行記一個時間戳
  (CONTEXT.md 該詞條的「五個來源」計數字面同步修正)。

### 正規化與合併(卡片總表)

- 三賽制統一值域:**禁止/限制/準限制** 三值(2026-08-22 使用者裁示);
  MD 的 Limited 1 → 限制、Limited 2 → 準限制。
- 來源出現三值以外的字串 → **建置失敗**(吵鬧的失效,值域正典原則)。
- 每張卡新增三賽制的禁限欄位,只在該賽制上榜時有值;「無限制」「未發行」
  不是值,由呈現層推導(見下)。
- 對齊以卡片密碼為鍵;來源密碼若是異圖密碼,對回本尊。對不上總表的筆數
  進建置報告(如同 MD 稀有度的 coverage 報告),不視為失敗——來源含本站
  不收錄的卡(無正式密碼者)屬正常。
- MD 側只採計已收錄(有 MD 稀有度)的卡的 banStatus;有 banStatus 但無稀有度
  的筆數(來源對未收錄卡的預掛)不採計、進報告。

### 前端索引與值域正典

- [[前端索引]]每張卡新增一個禁限欄位,**只有至少一賽制上榜的卡才帶**
  (欄位的有無由上榜與否決定,約 5xx 張;其餘 1.4 萬張零成本)。
- [[值域正典]]新增三個禁限值域(OCG/TCG/MD 各一,成員同為三值短碼與中文),
  隨 `window.VOCAB` 輸出;索引出現 VOCAB 沒有的值即建置失敗。
- 「無限制」與「未發行」由既有欄位推導,不進索引:OCG/TCG 的未發行看 `ot`
  (TCG 限定 → OCG 未發行,反之亦然),MD 的未發行(未收錄)看 MD 稀有度
  欄位的有無。

### 呈現(卡片畫面)

- 位置:日/英卡名那一行的**下一行**,獨立一列;徽章視覺語言與既有稀有度/
  OCG・TCG 限定徽章同一套(實色、白字、圓角)。
- 出現條件:至少一賽制上榜才有這一列;出現時 **OCG/TCG/MD 三欄固定齊列**。
- 每欄字面:上榜值寫「OCG 禁止」等(賽制名+統一三值);已發行(MD:已收錄)
  但未上榜寫「—」;未在該賽制發行/收錄一律寫「未發行」(MD 不另用「未收錄」)。
- 三值的徽章配色彼此可辨(禁止最重),「—」與「未發行」淡化為非強調樣式;
  具體色票依既有徽章體系決定。

### 搜尋軸

- 「禁限」為僅作摺疊分組的父層,其下巢狀 **OCG/TCG/MD 三個子軸**(如怪獸
  參數八軸巢狀於怪獸子類型的既有機制);位置在「OCG・TCG 限定」軸之後。
- 每個子軸只設**上榜三值**的鈕(禁止/限制/準限制),三態(包含/排除);
  「無限制」「未發行」不設鈕。
- 語意:同賽制內多選 OR、賽制間(軸間)AND、同軸包含+排除時排除優先——
  全部沿用既有軸語意,無新規則。無[[連動隱藏]]依附。
- 按鈕由 VOCAB 生成(ADR-0008),HTML 不寫死;網址 hash 的編碼走既有 FIELDS
  機制,不另設計。

### 週邊文案

- footer 資料來源行的兩處用途括號更新:Master Duel Meta(MD 稀有度・MD 禁限)、
  YGOPRODeck(Genesys 點數・OCG/TCG 禁限)。

## Testing Decisions

好測試只驗**外部行為**:餵合成輸入、斷言輸出(下載檔內容、總表欄位、索引/
VOCAB、命中清單、HTML 字串含的字面),不斷言內部結構與私有函式。

五道縫,前四道是既有縫、第五道為本功能新開(2026-08-22 使用者裁示 render
也要自動測):

1. **來源下載縫**(注入 `fetch_json`):禁限端點的分頁/欄位解析、原子替換、
   離線模式、失敗傳播。先例:card_list 的下載測試(MD 稀有度、Genesys)。
2. **卡片總表建置縫**(純函式 build):三值正規化(含 MD Limited 1/2 對應)、
   未知值建置失敗、異圖密碼對回本尊、無稀有度的 banStatus 不採計、coverage
   報告。先例:card_list 的總表建置測試(md_rarity merge)。
3. **前端索引/值域縫**(純建置):上榜卡才帶欄位、三個值域進 VOCAB、陌生值
   建置失敗、兩次建置逐位元組相同。先例:web 的 vocab/webindex 測試。
4. **接縫 3(查詢)**:node:vm 沙箱載真實前端碼、餵合成資料集,驗軸內 OR/
   軸間 AND/三態排除、與既有軸並用的 AND。先例:engine 的軸語意測試。
5. **呈現縫(新)**:同一沙箱下驗「卡片物件 → HTML 字串」——無上榜卡不長
   禁限列;上榜卡三欄齊列;字面(統一三值、「—」、「未發行」)與推導規則
   (ot/稀有度)正確。斷言字面與有無,不逐字斷言 markup。

## Out of Scope

- 禁限的**排序鍵**(結果排序不加禁限維度)。
- 禁限**歷史/生效日期/改版差異**(只呈現當前狀態,不做前後版比較)。
- OCG 以外地區榜(如 GOAT、Traditional Format)與 Genesys 的自家禁限。
- 直抓 KONAMI 官方禁限頁(維持既有第三方來源;官方頁無穩定 API)。
- Deck builder / 張數驗證等進階功能。
- MD 稀有度、Genesys 點數等既有欄位的任何行為變更。
