# 搜尋以框架述詞為單位,類別樹退成具名查詢目錄,論元結構化成片語

[[動作類別]]上線後兩週(2026-10-16〜10-31)的修正幾乎全是同一類:想多搜一個維度就得開新葉(門檻、並收、樹序)或開全軸條件(索引每句多一組葉欄、條件只能全軸套用);「找不到對應」「不知道放哪」的錯誤則集中在[[論元]]是不透明字串、類別線/動作對象/回指/區域四支程式各自用正則式重拆同一段字面。站主裁定(2026-10-31 /grill-with-docs):**搜尋單位改成[[框架述詞]]——索引每句帶[[動作框架]]清單,每框帶封閉類欄位,網站執行期對欄位評估;類別樹保留為[[具名查詢]]的目錄,葉編譯成述詞、不再互斥;框架線同時把受事者位與目的補語改成[[論元片語]],補施事者與方式欄,字面欄全部保留**。分詞器與手寫剖析不換,純 Python 零依賴與逐位元組決定性照守。同日上午定案的六項改動(任一組、目的玩家葉、置く・装備來源葉、回指回填、數量欄、條件類別)全部停下,併入這條線或等它完成後再看。

## Considered Options

- **繼續開葉與全軸條件**(上午定案的六項):每項都做得到,但每個新維度都是一片葉或一組索引欄,葉表與條件欄只會繼續長;「同一查詢裡一個節點要此卡、另一個要非此卡」這類需求表達不了。
- **只結構化論元、搜尋端不動**:下游正則式可刪,但索引仍存葉號,新維度仍要開葉;之後若再改搜尋端,索引格式要動兩次。
- **換剖析器(Sudachi/GiNZA)或 LLM 逐卡抽框架凍結成來源檔**:能一次解掉定語範圍、片語邊界等長尾;但前者破零依賴、後者要建覆核流程,都是另一個量級,站主選擇不綁在這次。
- **框架述詞+論元片語**(採用):新維度是一個欄位,不是一片葉;一套評估器同時服務具名查詢與使用者自訂;代價是索引變大、引擎與介面重寫、舊 act 網址不保證。

## Consequences

- 匯出檔從「每句的葉號」改成「每句的框架與欄位」;ADR-0017 的匯出檔入版控、原文與卡面參數雜湊擋建置、試點目錄是上游等機制不變,只有內容變。匯出檔是 `data/action_frames.json`(格式版本整數;舊檔 `data/action_categories.json`、歸葉程式與舊匯出留到規格 3 切換後刪;2026-11-01 named-queries 交件補)。
- Python 參考評估器(`.scratch/effect-tokenize/predicate.py`)是 JS 評估器的對照:述詞語意、例子夾具、目錄每個具名查詢的張數與卡集合雜湊都以它為準,規格 3 的 JS 評估器對同一份匯出框列要逐查詢相同(2026-11-01 named-queries 交件補)。
- 類別線的歸葉程式(規則表、樹序 first-match、並收、預設葉、每葉至少一框)退場;類別樹檔改為具名查詢的來源,建置期機械編譯成述詞,編不出來的葉列清單給站主。「全語料沒有命中的具名查詢不留」取代「沒有框的葉不留」。
- 條件位的 16,311 個框架進索引,「觸發事件」搜尋就是 位置=條件 的述詞,不另開第二棵樹;「含代價」勾選與[[動作對象]]全軸條件都成為述詞欄位。
- 每個新封閉類(中心詞類、修飾語類、數量類、方式類、施事者)進[[值域正典]],未知值建置失敗;中心詞與修飾語的「其他」是合法值,不擋建置;方式類的「其他」也合法(なしで/ままで/X以外で 這類落不進類的只留字面;2026-11-01 站主裁定補)。
- 舊 act 網址不保證:未知參數安靜忽略(現行行為)。沒改過的具名查詢用葉路徑寫進網址,改過的展開成欄位對。
- 索引體積先不設上限,第一版實測後回報再裁。
- 結構化是加欄不是換值:字面欄逐位元組不變是框架線的驗收條件,新欄各做一輪 LLM 抽驗。
- 分四份規格(框架線片語與新欄 / 下游改讀與匯出 / 索引與述詞評估器 / 介面與網址),超過一個 session,先走 wayfinder。
