# 效果標記表是入版控的來源檔,不是建置產物

[[效果標記表]]的判定結果會被使用者逐卡回報誤標並手工修正,而這些修正必須活過每一次重跑。前一世代把它當建置產物、修正靠外掛的 `effect_kind_overrides.json`,結果是修正與資料分離、override 檔隨規則演進而失效、且無法從資料本身看出某一行是誰判的。因此本專案改為:效果標記表是入版控的**來源檔**,一卡一物件、一欄位一行(`indent=2`)、依卡片密碼穩定排序,每個效果句帶 `source` 欄位(`official` / `rule` / `llm` / `llm_then_rule` / `manual`),重跑時只重算 `llm` 且文本雜湊未變者不重算,`manual` 與 `official` 永不覆蓋。

## Consequences

- override 檔那一層不再需要——它原本只是為了對抗「產物會被覆寫」而存在。
- 重跑不再是冪等的純函式輸出,而是「既有檔 + 新來源 → 新檔」的合併,因此建置管線必須吃既有標記表作為輸入(見 `build_tag_cards` 的 `existing` 參數)。
- 效果句需要一個穩定鍵才能讓修正對得回去:`(卡片密碼, section, index)` 搭配 `text_hash`;雜湊變動時不覆蓋而是標記 `needs_review`。
