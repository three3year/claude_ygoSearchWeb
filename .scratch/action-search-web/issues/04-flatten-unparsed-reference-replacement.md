# 04: 新路徑補齊未解析組、經引用、代替,查詢判斷改走新路徑

**What to build:** 新路徑做得出舊路徑的全部結果,`run_query` 預設改走新路徑。現有的查詢測試一條都不改、全部通過。

- 未解析組的來源照現有查詢判斷,一種都不少:無官方日文的卡、解析不出的段、解析得出但對象線的物件判不了的段(物件解析不出、引用的物件找不到、異同判不了)、解析不出的引用節點、區塊種類判不出的區塊。每一種在列裡都要有對應的欄(原文字面含哪些動作詞、原因)。
- 回傳裡每一段的原因與原文照舊,由完整的列加上卡片結構得出。
- 經引用:引用節點另成一種列(引用它的卡、被引用物件的候選卡、指定的部分、是不是泛用引用)。比對時先算直接命中,再沿這些列展開到底,走到走過的卡就停;泛用引用開關、`via`、`mark` 照舊。
- 代替:被代替段與做代替的段只在查詢含「代替」時看,`replaced_by` 照舊。
- 未結構化的段照舊不命中、不列未解析組。
- 做完後 `run_query` 預設走新路徑;舊路徑留到票 05 才刪。

- 規格:需要你決定的「Q9」;實作決策「動作索引」(引用列、解析不出的段、未解析組的來源)、「查詢判斷」;使用者故事 49;測試決策「接縫一」。
