## Comments

批次的 200 張要從 3,804 張裡怎麼抽,本票執行時決定。建議按日文句數分層(1 句 1,113、2 句 1,405、3 句 853、4 句 276、5 句以上 141),讓單句與長團都有樣本——單句整團看似不用拆,但它同樣要走一遍流程:拆句表裡一筆「1 段」的紀錄本身就是「這張卡是單效果卡」的斷言,階梯四、五要的就是這個。

有官方 `『原文』` 引用可交叉驗證的整團佔 2,150 / 3,805,抽樣時最好讓這一群佔多數——它們是唯一能自動判對錯的樣本,試點的價值大半在這裡。

### 抽樣

依整團的**日文句數**分層(0/1/2/3/4/5+,最大餘數法配額),層內再分「有沒有官方 `『原文』` 引用」,配額七成給有引用的那一群;層內等距取樣、不用亂數。實抽 200 張:有引用 139 張(69.5%),句數層 0句1 / 1句58 / 2句74 / 3句45 / 4句15 / 5句以上7。

依卡片密碼升冪切出來的第 1 批全是低號舊卡(27551、41777、62121…),判準會被那一族的寫法帶偏,所以試點不能用它。**抽樣器用完就刪掉了**:它是一次性的,正式排票要的是無遺漏地判完全部而不是代表性,留著等於在不納入測試的 CLI 薄殼裡養一段沒人跑的分配邏輯。抽出來的那 200 張本身入版控(`.scratch/tag-card/batches/split-01.json`),稽核軌跡在那裡,不在程式碼裡。

### 試點順手修掉的兩個機制缺陷

- **待拆清單沒有帶著整團的原文**(接縫層,已補測試)。批次檔原本拿[[效果標記表]]上那一行當拆句標的,但 `●` 子效果可能已經把那一行切掉一塊(批內 5 張,例:エレメント・ザウルス 92755808)——判定者照那一份拆,雜湊與覆蓋兩道驗證必然雙雙失敗。改成 `report["pending_split"]` 帶著整團的兩側原文與雜湊,批次檔與合併程序都取用同一份。
- **「拆不出來」沒有出口**。票面寫著「拆不出來的留空並記理由」,但 `merge_judgments.py` 遇到空的拆點會在關卡二被擋下來,整批不寫入。改成 `clauses` 給空陣列 + `note` 即為「這一團拆不出來」:不寫進拆句表、列進輸出,下一票會原封不動再出現一次。

### 實測成本(200 張)

- **拆句**:197 張拆得出來(拆出效果句 267 條),3 張留空——3129635 與 52140003 是繁中與日文**語序不一致**,15415552 來源沒有日文卡文。
- **判定**:寫入 120 條,另有 **159 條被回頭撿到的[[官方明示]]接手**(判定者的類型與官方一致,`source` 留 `official`,不占 ADR-0002 的判定額度)。
- **準確率(免費量測)**:那 159 條是「遮住答案判、再對官方答案」的天然遮蔽測試,**不一致 0 條**。
- **驗證失敗率 0**:三道關卡第一次跑就 0 個問題,拆句表三道驗證各 0 筆。`rule_llm_conflict` 0 筆,收斂條件三項全數成立。
- **上下文**:批次每卡 1,197 字元(補足情報不裁剪),結果檔每卡 380 字元。200 張約 24 萬字元進、7.6 萬字元出,離 1M 上下文的一半還有很大餘裕——**限制不是上下文而是逐卡判定的持續工作量**,所以每票維持 200 張。
- **規範文件補了**:§8 判準 10–15(六條)。票面只說「變成 §8 的新判準」,但打臉的地方有一半不是拆句而是**判類型**,寫進 §8 會讓判定者在錯的章節找答案,所以照內容各歸各節:§5.8(魔法・陷阱卡「這張卡本身的發動」,新節——官方對這一段從不標類型,而 200 張裡有 89 張是魔法或陷阱卡,不寫死判定者只能各判各的)、§2.1 勝利條件(連帶修掉 §1 步驟 3 把勝利條件列進無種類效果的錯誤,官方 6/6 判效果外文本)、§4 舊式代價句型 `〜する事で` 判選發。
- **判準的交叉驗證有工具了**:唯一會**製造新拆點**的判準(判準13,尾端以卡名指稱全卡效果的次數限制句獨立成段)掃過全部未拆整團——開火 58 段、23 段有 `『原文』` 引用可驗、**引用被切開 0 段**。掃描器留成 `script/tag_card/check_split_rule.py`,其餘 32 張判定票都要用它:[[拆句表]]的驗證二只驗**已經寫進表裡**的拆點,擋不住一條寫太寬的判準。反例可以拿它重現——「每個句號都是一段」開火 2,516 段、切開 **479 段**引用。

### 配號

`make_batches.py` 加了 `--start`:每票只生自己那一批,而批次是即時產生的(待判集合一票比一票小),批號因此由票自己給,檔名才不會互相蓋掉。試點的 `split-01.json` 與結果檔留在原地當稽核軌跡。

判定票 **18–50**(33 張):18–36 為「要拆+判」split-02…split-20(19 批 × 200 張 / 3,607 張卡),37–50 為「只判類型」kind-01…kind-14(14 批 × 300 張 / 4,062 張卡)。票09 的 `Blocked by` 已回填。
