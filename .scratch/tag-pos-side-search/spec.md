# Spec: 動作 Tag 的位置(代價/效果)與對象方搜尋

Status: resolved(2026-10-01 四票全數實作完成)
Date: 2026-10-01(站主 grilling 訪談定案)

## Problem Statement

使用者在搜尋介面上分不出一個動作類別命中是「代價」還是「效果」、作用在我方還是對方。資料層每個動作 tag 早已帶兩個通用槽位——位置(成本/效果)與對象方(自身/我方/對手/雙方)——但搜尋第一期把位置寫死成「只命中效果位」(裁定批1:搜「除外」不撈自家代價),對象方則完全沒參與篩選也不顯示。想找「拿除外當代價的卡」「瞄準對手的破壞」這類查詢做不到。

另外,「成本」這個槽位值名稱對使用者不直觀,站主裁定正名為「代價」。

## Solution

搜尋介面新增兩組全域鈕:**位置**(效果/代價)與**對象方**(自身/我方/對手/雙方)。條件語意是 tag 層 AND(同一個 tag 要同時滿足動作類別+位置+對象方),兩組鈕都可在未選任何動作類別時單獨使用;位置空軸不設限(效果+代價都命中,推翻裁定批1 的預設只命中效果)。命中 badge 同步升級:代價位 tag 加「(代價)」標記、對象方有填值則一併顯示。

槽位值「成本」**全面改名「代價」**(判定方式不變);LP支付類別修訂裁定票15,增設位置槽位、改走一般位置判準。

## User Stories

1. 作為玩家,我想找「把除外當代價」的卡(區域移動·終點除外 × 代價),所以需要位置鈕能與動作類別組合。
2. 作為玩家,我想找「瞄準對手的破壞」(破壞 × 對手),所以需要對象方鈕能與動作類別組合。
3. 作為玩家,我搜「除外」時希望代價位的卡也出現在預設結果裡(空軸不設限),不用先學會一個開關才找得全。
4. 作為玩家,我想還原「只看效果位」的舊語意,所以可以主動點「效果」鈕。
5. 作為玩家,我想找「任何動作是代價」的卡,所以位置鈕單獨點選(不選動作類別)也成立。
6. 作為玩家,我想找「任何動作瞄準對手」的卡,所以對象方鈕單獨點選也成立。
7. 作為玩家,我想找影響雙方的效果(對象方=雙方),所以四值都有鈕。
8. 作為玩家,我想找卡自己移動(對象方=自身)的效果,所以「自身」與「我方」分開成鈕。
9. 作為玩家,我看到一張卡命中時,想從 badge 讀懂它為什麼中——代價位命中要有「(代價)」標記、對象方有填時要顯示(如「破壞·對手」)。
10. 作為玩家,我選「代價」時希望命中發動型 LP 支付(「500LP払って発動できる」),因為支付就是付代價。
11. 作為玩家,我理解維持費/通行費這類無發動子句的支付歸效果位——想找它們時用 LP支付類別鈕本身(不加位置條件)。
12. 作為玩家,我在按鈕與 badge 上看到的是「代價」而不是「成本」,所以用詞直觀。
13. 作為玩家,我想把帶位置/對象方條件的搜尋網址分享給別人,所以兩組條件進 hash(比照區域移動起點/終點)。
14. 作為玩家,我選了對象方卻發現結果偏少時,希望介面有說明文字提示「對象方為逐步標注中的欄位,未標注的卡不會命中」,所以不會誤以為網站壞了。
15. 作為玩家,我選對象方時,沒有對象方槽位的 10 個動作類別的 tag 不命中——這是誠實語意,寧缺勿濫。
16. 作為維護者,我希望按鈕仍由值域正典生成(HTML 不寫死任何選項),所以改名只改正典一處、前端文字自動跟上(ADR-0008)。
17. 作為維護者,我希望 LP支付的 555 個 tag 由規則層重跑補判位置(ADR-0013 規則直貼),不用人工逐卡判。
18. 作為維護者,我希望改名後「索引出現 VOCAB 沒有的值即建置失敗」的守門不變,改名漏改任何一處會吵鬧地失敗而不是無聲失效。
19. 作為判定者,我希望歷史裁定紀錄的舊文不被改寫(只新增追記),所以歷史可考。
20. 作為判定者,我希望位置的判定方式一字不變(發動子句=代價、處理段/無發動子句/代替處置=效果),改的只是名字與搜尋語意。

## Implementation Decisions

- **全面改名「成本」→「代價」**:值域正典 tag_pos 的中文名改「代價」(短碼 `c` 不變、值域大小 2 不變);效果標記表來源檔中 3,831 個 tag 的值字串、規則層產出的值字串、effect_tag_guide、CONTEXT.md 的槽位詞條同步改名。歷史裁定紀錄(rulings.md 既有票文)不改寫,新增追記記錄本次裁定。
- **位置判定方式不變**:發動子句(以「〜して発動できる/発動する」收尾的第一句)裡的付出=代價;處理段、無發動子句的句子(含自我特召程序的付出)、代替處置(「代わりに〜」)=效果。
- **修訂裁定票15(LP支付)**:LP支付增設位置槽位、取消位置豁免(含值域正典的豁免集合與建置期檢查),555 個 LP支付 tag 由規則層重跑補判——照一般判準,不另寫「支付就是代價」特例:發動型支付=代價位,維持費/通行費/程序支付等無發動子句形=效果位。遮蔽測試的固定樣本/標準答案檔若含「成本」字串,機械替換同步。
- **前端兩組全域鈕**:位置(效果/代價)與對象方(自身/我方/對手/雙方),掛在動作 Tag 區塊,按鈕由值域正典生成。包含式多選(軸內 OR、軸間 AND),第一版不設排除態——比照區域移動起點/終點純包含篩選的先例。
- **條件語意為 tag 層 AND**:同一個 tag 要同時滿足已選動作類別、位置、對象方才命中;兩組鈕可單獨使用(未選動作類別時,任一 tag 滿足即命中),不做連動隱藏。
- **空軸不設限**:位置鈕都沒選=代價+效果都命中,推翻裁定批1 的「預設只命中效果」;查詢引擎與 badge 繪製裡既有的三處硬排除成本位一併移除。
- **對象方誠實語意**:選了值就只命中已填該值的 tag;留空(未標注)與沒有對象方槽位的 10 個類別不命中。現況填值率約 9%(我方 1,789/自身 1,312/對手 1,020/雙方 122、留空 32,911),接受先開、日後補標,UI 加覆蓋率說明文字。
- **badge 升級**:代價位 tag 上 badge 並加「(代價)」標記;對象方有填值時一併顯示。
- **hash 參數**:兩組條件可往返於網址,比照區域移動 `mvf`/`mvt` 的既有慣例。

## Testing Decisions

- 好測試只測外部行為:查詢引擎層「資料+條件進 → 命中集合出」、繪製層「命中 → badge 文字」,不測內部資料結構。
- **engine.test.js**(最高接縫、主戰場):空軸不設限、位置/對象方 tag 層 AND、可單獨使用、對象方留空與無槽位類別不命中、LP支付代價位命中。先例:既有區域移動起點/終點下拉的查詢語意測試。
- **render.test.js**:badge 的代價標記與對象方顯示。先例:既有 tagBadge 測試。
- **test_vocab.py**:值域正典——tag_pos 中文「代價」、位置豁免移除、LP支付槽位表含位置。
- **test_tag_line.py**:規則層——LP支付位置補判(發動子句=代價、維持費/通行費=效果)。先例:各期開貼的測試先行慣例。
- **test_webindex.py**:建置產出——LP支付 tag 帶位置短碼。
- 全部用既有接縫,不新開測試檔;主 seal 與 tag seal 跑綠為收尾門檻。

## Out of Scope

- 對象方留空的補標工程(舊卡補判式的大規模填值)——先開篩選,補標另立票。
- 位置/對象方的排除態(三態)。
- 逐類別附掛的位置選擇(本次是全域鈕)。
- 觸發時機軸、慣用名對照(蘇生/檢索)等其他搜尋語意的變動。
- 分類表 21 類與其他槽位值域的任何增刪。
