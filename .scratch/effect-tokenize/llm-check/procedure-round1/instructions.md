# 召喚手續 LLM 檢驗:子代理工作說明

你會拿到一份批次檔(`batch-<k>.md`):每張卡一節,只列**召喚條件那一句**(效果外文本;有一張是效果句)。每節有:

- `原文:` 整句日文原文。
- 約束框架列 `框架 n:[約束 限制·召喚條件] 形式 …・手續 動作 對象 來源から 目的へ;動作 …・來源 … | 子句=…`:**手續**是程式從召喚條件裡讀出的步驟(以 `;` 分,依原文順序是第 1、2… 步)。
- 召喚手續框列(手續裡的步驟,動作在白名單內的,各出一個動作框架,位置是 `[召喚手續]`):

  `框架 n:[召喚手續] 動作(極性)| 主題=… | 主語=… | 對象=… | 來源=… | 目的=… | 片語·對象=… | 片語·目的=… | 結構化來源=… | 結構化目的=… | 施事者=自分(預設)(推得) | 回填 …・推得 … | 動作對象=值(理由) | 發動位置=區域(來源) | 子句=…`

- `被白名單擋掉的步驟:第 i 步 動作、…`:手續裡動作不在白名單的步驟(不出框)。全部步驟都被擋時另有一行 `召喚手續框:(無)`。

框架序 n 是整句框架清單的序號,和同句其他框架共用一套號碼,所以會跳號;同句其他框架(效果位、條件位、素材、次數…)不列,不在本輪範圍。

你的工作:**看原文,逐步對照手續、召喚手續框與被擋的步驟,挑出錯**,寫成 `findings-<k>.json`。

## 範圍與判準(以此為準,不要用自己的直覺改判)

### 0. 哪些步驟該出框(漏出/多出)

- **白名單** 9 種動作出召喚手續框:リリース、除外、重ねる、送る(墓地へ送る)、戻す、捨てる、取り除く(X素材を取り除く)、見せる、払う(LPを払う)。
- **被擋是規格決定、不是錯**:存在(…が存在する場合)、になる/となる(合計が10000以上になる)、合わせる、異なる、P召喚可能(Ｐ召喚可能)——這些是前提,不是動作;発動(相手が…発動していた場合,做的人是對手)、選ぶ(38082437 Ｄ・テレホン,那句其實是效果文被認成召喚條件)。
- **漏出**:原文召喚條件裡有一個真的「為了召喚而做的手續動作」(解放、除外、疊放、送墓、回牌組/回手、丟棄、取除素材、給對手看、支付 LP…),卻沒有對應的召喚手續框——不論是(a)它在手續裡但動作名被讀錯、被擋掉(例:實際是 墓地へ送る,手續卻寫成 存在),或(b)手續根本沒有這一步、或手續讀錯成別的。`frame` 填 null、`step` 填手續第幾步(手續裡沒有就 null)。
- **多出**:有召喚手續框,但原文那裡不是召喚手續動作(是前提、是召喚後的效果、是對手做的、或根本沒有這個動作)。
- **不是錯**:召喚條件本身的「特殊召喚できる/召喚できる」不出框;約束框架的**手續欄**照舊保留(不改成指向召喚手續框),它的寫法本身不在本輪範圍,除非它讀錯讓召喚手續框漏出或多出。手續欄的對象字面(`自分フィールドのモンスター3体`)和召喚手續框的 `對象=`(`モンスター3体`,區域切到 `來源=`)不同是既有規則,不是錯。
- 約束框架的形式、方式、來源欄,以及框列的 `子句=` 範圍(有時會從上一個述語後面起算)不在本輪範圍,不用報。

### 1. 詞元(`[召喚手續] 動作`)

動作名是歸一後的詞元:リリースする → リリース、墓地へ送る → 送る、デッキに戻す/手札に戻す → 戻す、ゲームから除外する → 除外、X素材を取り除く → 取り除く、手札から捨てる → 捨てる、LPを払う → 払う、相手に見せる → 見せる、モンスターの上に重ねる → 重ねる。**詞元錯**:動作名與原文的動詞不符(例:原文是 除外 框卻寫 リリース)。

### 2. 結構化區域(`來源=`、`目的=`、`結構化來源=`、`結構化目的=(玩家,區域)`)

來源/目的字面各自過區域辨識成 (玩家,區域) 清單;區域七值 手牌/牌組/額外牌組/墓地/除外/場上/靈擺區,玩家 自分/相手/お互い/相對/無。對象字面前的區域定語(`自分フィールドの…`)切到來源;推得的目的(`目的=除外(推得)`)玩家一律 無。認不出的(…の上、元々の持ち主)不放。**重ねる 的目的是「…の上」**,不是區域,結構化目的空是對的。**區域切錯**:來源/目的的字面或結構化值與原文不符——區域錯、玩家錯、該切沒切、把不是這個動作的區域(例:召喚去處「自分フィールドに召喚」)當成這個動作的來源或目的。

### 3. 片語(`片語·對象=`、`片語·目的=`):中心詞與修飾語、數量

格裡以 ` | ` 分**段**,每段:`段 字面 中心詞 X(類) [玩家 P] [區域 Z] [修飾語 …] [數量 …]`。

- **切段**:依並列詞 と/か/や/及び/または 與「・」切;前一格是屬性/種族等修飾性的詞(光・闇属性、魔法使い族・闇属性モンスター、融合・S・Xモンスター、レベル4・5)不切,是並列的修飾語。
- **中心詞**:段去掉助詞、數量尾後的**最後一個名詞格**(X素材、カード名 合記一格);卡名「…」整段是中心詞。中心詞類:卡(モンスター/カード/トークン/チューナー/素材/魔法/罠 與尾字複合詞、卡名、區域詞);屬性(攻撃力/守備力/レベル/ランク/属性/種族/カード名/表示形式/コントロール…);非卡(ダメージ/LP/カウンター/数…、純數值);指示詞(それ/それら/いずれか/対象/残り…、只剩數量的段);其他(表外,落 其他 不是錯)。
- **修飾語**(`修飾語 字面(類)、…`):中心詞之前的各格依 の 與讀點切段,再依 ・/並列詞拆項逐項定類:種族(〜族)、屬性(〜属性)、字段(引號段直接接名詞「方界」モンスター;接 の 的引號段是卡名,落 其他)、卡片子類型(融合/S/X/P/L/リンク/儀式/通常/効果/チューナー… 直接接名詞;効果モンスター 這種一格的複合詞是中心詞本身)、玩家、區域、表示形式、數值(`字面(數值:欄位 比較 數字)`:レベル6以上(數值:レベル 以上 6));**其他**——定語子句、以外/他の/元々の、このカード、同じ…、上記(上記のカード 的 上記 落其他不是錯)。
- **數量**(`數量 字面(類 數字)`、取自子句的尾綴 `(取自子句)`):段尾 數字+量詞 → 定數;+まで → 上限;N以上 → 下限;全て → 全部;ずつ 併進字面(1体ずつ 定數 1);受事者字面沒數量而子句緊接 を+數量(モンスターを１体リリース)取進來並標(取自子句)。**規格決定、不是錯**:46186135、48658295「それぞれ１体ずつ、上記のカードを」的數量寫在受事者前面,沒取到(本輪不另補)。
- **中心詞錯**:切段錯、中心詞取錯格、中心詞類落錯(表內該中的落 其他)、對象字面多了不屬於它的東西或少了一截以致段/中心詞錯。
- **修飾語類錯**:修飾語類判錯、漏(中心詞之前有字卻沒有修飾語)、拆項錯、多了不該在這個受事者裡的修飾語(例:前一個子句的字面被併進來當修飾語);段的玩家/區域錯也報這型。
- **數量錯**:段尾數量漏記/錯類/錯數、不是數量的被記、取自子句接錯。

### 4. 施事者(`施事者=自分(預設)(推得)`)

召喚手續框一律 自分(規則),不看主題與主語,**不在本輪範圍**,不用報。

### 5. 動作對象(`動作對象=值(理由)`、`發動位置=區域(來源)`)

判的是這個框架動到的是不是**這張卡本身**(要召喚的這張):

- **重ねる 一律 此卡**(理由 召喚手續的疊放):被疊上去的一定是要召喚的這張,不論有沒有寫「このカードは」。
- 其他動作的受事者看 對象(沒對象而主題是此卡時看主題):
  - **此卡**:受事者指名此卡(このカード、此卡的屬性、並列含此卡)。
  - **非此卡**:確定不動到此卡。このカード以外 中;**選擇類**(帶數量:モンスター１体、カード２枚)一律非此卡;**全部類**(沒數量:自分フィールドのモンスターを全て)用**發動位置**判會不會含此卡:區域、玩家、卡種、種族、屬性、字段、子類型、數值條件全對得上 → 可能含此卡 → 皆非;任一對不上 → 非此卡。
  - **皆非**:兩邊都不中——不是卡的受事者(LP)、沒有受事者、全部類可能含此卡。
- **發動位置 = 召喚來源**:此卡在召喚前所在的區域。所屬召喚條件寫了來源(`EXデッキから特殊召喚`、`手札・墓地から特殊召喚`)照寫(寫明的召喚來源);沒寫時依卡種推:主牌組怪獸 手牌、額外牌組怪獸(融合、S、X、連結)額外牌組(推得的召喚來源)。例:「自分フィールドのモンスターを全てリリースした場合のみ特殊召喚できる」——此卡在手牌,不在場上,所以 非此卡(全部類區域對不上)。
- 理由字串是程式的理由碼,只看**值**(此卡/非此卡/皆非)對不對;值對、理由名怪不算錯。
- **動作對象錯**:值照上面的判準不對(含發動位置推錯讓值錯)。

## 錯誤類型(type 欄只能填這些字)

- `漏出`:該出召喚手續框卻沒出(含被白名單擋掉的步驟裡有真的手續動作、手續漏讀一步)。
- `多出`:出了不該有的召喚手續框。
- `詞元錯`:動作名錯。
- `區域切錯`:來源/目的字面或結構化來源/目的錯。
- `中心詞錯`:片語切段、中心詞、中心詞類錯。
- `修飾語類錯`:修飾語類錯/漏/拆錯/多了別處的字面;段的玩家/區域錯。
- `數量錯`:數量漏記/錯類/錯數/不該記。
- `動作對象錯`:此卡/非此卡/皆非的值錯。

一個框架有多個問題各寫一筆(例:對象字面吃進了前一子句,片語中心詞錯、目的也錯,報 `中心詞錯` 與 `區域切錯` 兩筆)。

## 成因(cause 欄只能填這兩個字)

- `抽取`:框架本身抽錯——步驟的錨點、論元範圍(對象/來源/目的字面)、詞元與原文不符,下游的格跟著錯;手續欄讀錯讓召喚手續框漏出或多出。
- `規則`:框架的字面欄照原文是對的,是之後的規則讓這格錯——片語定類、區域辨識、動作對象判定、白名單擋掉了真動作。

拿不準填 `抽取` 並在 reason 說明。

## 回報格式

寫到批次檔同目錄的 `findings-<k>.json`(UTF-8,k 與批次檔相同):一個 JSON 陣列,每筆

```json
{"card": 12345678, "index": "效果外文本 0", "frame": 3, "step": null, "type": "區域切錯", "cause": "抽取", "got": "目的=自分フィールド | 結構化目的=(自分,場上)", "expected": "目的空(自分フィールド 是召喚去處)", "reason": "一句話,引原文片段說明哪裡錯、應該是什麼"}
```

- `card` 卡號(整數);`index` 用「### 句」後的標籤(`效果外文本 0`、`效果外文本 0-2`、`①`…);`frame` 是「框架 n」的 n(整數),漏出填 null;`step` 是手續第幾步(整數;漏出時填,其他填 null)。
- `got` 是批次檔現在那一格的寫法(照抄),`expected` 是應該的寫法;沒有就寫空字串。
- 沒有錯就寫 `[]`。
- reason 用繁體中文,引原文照抄日文。
- 只回報有把握的錯;判準寫在上面,和判準不同的地方照判準,不要改判準。上面標明「不是錯」「是對的」「規格決定」「不在本輪範圍」的不要報。拿不準的在 reason 開頭寫「(待確認)」。
- 不要改動批次檔或其他檔案;不要寫其他檔。

完成後用一兩句回覆:看了幾張卡、各型幾筆、最常見的錯是什麼。
