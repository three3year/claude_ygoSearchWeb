# 06 — 影子預測與規則登記

**What to build:** 判定過程中歸納出的規則有地方可以落腳,而且每一條規則都被獨立驗證(見 ADR-0002)。新增一條規則後重跑,使用者能看到:規則對尚未判定的效果句寫下了影子預測(但沒有替它們決定類型);對已判定的行跑了比對,一致的升級為雙重確認、不一致的進衝突清單。

實作期間的八個決定,與票面規格有出入或補充:

1. **規則的定義是程式碼,`docs/effect_kind_rules.md` 是產出物。** 票面只說「規則清單存在」,但驗收項目同時要求覆蓋條數由建置統計並回寫——一份人要手改、機器也要回寫的檔案必然會被寫壞。因此判別條件寫成 `rules.py` 裡的 `define(...)` 呼叫(人看的敘述 + 機器跑的樣式各一份),md 每次建置整份重新產生。新增規則 = 多寫一次 `define`;合併舊規則 = 給舊條補 `merged_into` 與一筆 `merge` 變更記錄。

2. **兩趟才算得出覆蓋條數。** 門檻要在寫影子預測**之前**就知道,而覆蓋條數只能從本次全表算出來,所以規則層先跑一趟量覆蓋、再跑一趟寫預測。覆蓋條數的定義是「本次全表命中的效果句數」,測試因此得成批餵卡(8 張才過門檻),這也順便把「數字不是寫死的」測進去了。

3. **官方明示是規則層的驗證集,不進衝突清單。** 票面的「對已判定的行跑比對,不一致進衝突清單」若把 `official` 也算進去,收斂條件就會被官方的個案例外卡死。改為分成兩份:對 `official` 的一致率單獨算(門檻 99%,與 票04 必發/選發的獨立驗證同一個做法),不一致的另立 `rule_official_disagree` 清單並全數列進規則清單文件;衝突清單只收「影子預測 vs 判定產出(`llm` / `llm_then_rule` / `manual`)」。這讓每條規則在判定票開跑之前就先被 13,723 條官方明示驗證過一次,而不是等第一張判定票才知道規則寫壞了。spec 的「規則歸納」一節已補上。

4. **判別條件重疊且結論不同時不寫預測。** spec 只說這是規則變更的三種正當理由之一,沒說當下該怎麼辦。規則層自相矛盾時猜哪一條對都是錯的,因此該行不寫影子預測,改列 `rule_overlaps`(必須為 0)——這正是「該去改規則了」的訊號。

5. **規則清單自身有毛病時整層不上工。** 編號重複、變更沒記票號或理由不在三種之內、合併去向指向不存在的規則,一律讓規則層完全停擺並列進報告,而不是跳過那一條照跑。寧可沒有影子預測,也不要拿一份自己都對不起來的規則去對照判定。這一段是接縫測不到的(接縫吃的永遠是 repo 裡那一份規則清單),因此 `rules.problems` / `active` / `merged_groups` / `digest` 直接測,spec 的 Testing Decisions 已記下這個例外。

6. **收斂條件第一問比對的是規則「定義」的指紋。** 覆蓋條數會隨新卡變動,拿整份文件比會每次都說「有異動」。因此 `rules.digest()` 只吃編號、類型、範圍、判別條件、票號、合併去向與變更記錄,建置時與既有 md 裡記的指紋比對。

7. **規則消失時 `llm_then_rule` 不降回 `llm`。** 某條規則被收緊或刪掉之後,原本雙重確認的行會失去影子預測。這時不動 `source`——`llm_then_rule` 記的是「判定過,而且當時有規則附和」這件歷史事實,降級只會把資訊洗掉,也違反 `llm` 系來源「判定一次就算數」的界線。這一行不會靜靜消失:逐行差異清單會列出它的影子預測由某類型變成 `—`。

8. **「規則變更後逐行差異」比對的是既有標記表裡的影子預測。** 票面要求規則變更觸發全表重跑並逐行列出差異,但重跑本來就是全表的,差異需要一個基準——既有標記表那一欄 `rule_predicted` 記的正是上一版規則的意見。因此每次重跑都逐行比對 `rule_predicted` 的前後值,列進 `rule_prediction_changed`。改一條規則後重跑,這份清單就是這次改動的完整影響範圍;沒改規則時它必為 0 筆(實測如此)。

### 本票歸納的 9 條規則

規則層不能是空的——空的規則層沒辦法證明機制會動,票08 之後也沒有可以增修的基準。本票從[[官方明示]]的 13,723 條效果句歸納出 9 條規則,判別條件全部取自 `docs/effect_kind_guide.md` 已寫下的句型線索,再以整份官方明示驗證:

| 規則 | 類型 | 覆蓋 | 對官方明示 |
|---|---|---|---|
| R1 發動子句「〜た場合に…発動」(排除「だった場合」) | 誘發效果(1速) | 2,716 | 2,318/2,318 = 100% |
| R2 發動子句以「リバース：」起首 | 誘發效果(1速) | 86 | 71/71 = 100% |
| R3 發動子句「(エンド\|スタンバイ)フェイズに…発動」 | 誘發效果(1速) | 419 | 319/319 = 100% |
| R4 發動子句「自分メインフェイズに…発動」 | 啟動效果 | 515 | 358/359 = 99.7% |
| R5 發動子句「自分・相手ターンに」(排除「存在する限り」) | 誘發即時效果(2速) | 239 | 231/231 = 100% |
| R6 「手札から特殊召喚できる」無発動無事件 | 無種類效果 | 289 | 265/265 = 100% |
| R7 單句「(フィールド\|モンスターゾーン)…存在する限り」無発動無事件 | 永續效果 | 626 | 534/535 = 99.8% |
| R8 「効果を受けない」無発動無事件、排除素材/召喚限定 | 永續效果 | 90 | 68/68 = 100% |
| R9 「対象に…ならない」無発動無事件、排除素材/儀式限定 | 永續效果 | 67 | 42/42 = 100% |

R5 的排除條件是量出來的:「〜存在する限り、自分・相手ターンに自分は「魔弾」魔法・罠カードを手札から発動できる」這一族(9 條)官方判永續效果——它賦予的是**他卡**的發動權,自己不發動。R7 排除「フェイズ」「事ができる」同理:舊式卡文把觸發時點寫成「自分のスタンバイフェイズ毎に」而不帶「発動」二字,只擋「発動」會漏掉。
