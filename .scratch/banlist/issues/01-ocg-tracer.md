# 01 — OCG 禁限直通彈(來源→總表→索引→徽章列)

**What to build:** 查卡的人在卡片畫面上、日/英卡名那一行的下方,看到 OCG 的禁限
徽章:上了 OCG 榜的卡顯示「OCG 禁止/限制/準限制」,上榜但該欄無限制的情境
(本票僅 OCG 一欄,故列的出現條件=OCG 上榜);未在 OCG 發行的卡該欄寫
「未發行」。資料來自 ygoprodeck 的 OCG 禁限端點,跟著一鍵更新流程自動刷新。

**Blocked by:** None — can start immediately。

**Status:** done

規格:`.scratch/banlist/spec.md`。本票是追蹤彈,打穿全部層並立起五道縫的測試
骨架(其中呈現縫是新開的);TCG/MD 之後沿同一條管道併入。

- [x] 一鍵更新流程多下載一份 OCG 禁限來源檔(原子替換、`--offline` 沿用既有檔、
      失敗不毀既有檔),[[資料更新時間]]照舊一次執行記一個
- [x] [[卡片總表]]每張卡有 OCG 禁限欄位,值域統一三值(禁止/限制/準限制),
      只在上榜時有值;來源出現三值以外的字串即建置失敗
- [x] 來源以[[卡片密碼]]對齊,異圖密碼對回本尊;對不上總表的筆數進建置報告
      (不視為失敗);只上 GOAT 等其他榜的資料忽略
- [x] 更新流程重跑時禁限隨來源無條件刷新(上榜/降級/除名都反映),不依賴
      卡文變動
- [x] [[前端索引]]只有上榜卡帶禁限欄位;[[值域正典]]新增 OCG 禁限值域並隨
      VOCAB 輸出;索引出現 VOCAB 沒有的值即建置失敗;兩次建置逐位元組相同
- [x] 卡片畫面在卡名行下方長出禁限徽章列(僅上榜卡),徽章視覺語言與既有
      稀有度/限定徽章同一套;OCG 欄的「未發行」由 `ot` 推導
- [x] 五道縫各有測試:下載(注入 fetch)、總表建置(純函式)、索引/值域
      (純建置)、接縫 3 不受影響(既有測試全綠)、呈現縫(沙箱驗卡片物件
      → HTML 字串:無上榜不長列、字面正確)
