# Spec: 約束框架(Constraint Frame)——限制、時機、素材

Status: ready-for-agent
Date: 2026-10-09

上游是效果文分詞線的動作框架(票 04〜11)。該線票 11 的站主質性驗收暫停,等本規格上線後,動作框架與約束框架一起驗收。

## Problem Statement

站主在拆解頁翻卡驗收動作框架時,發現卡片「能怎麼用、什麼時候用、怎麼出場」的規則讀不出來,或被讀錯:

1. **完全沒有框架**:發動句裡的「１ターンに１度、」「自分メインフェイズに」沒有述語,整段被略過;「この効果はこのカードが特殊召喚したターンには発動できない」「この効果は相手ターンでも発動できる」被當成速度註記整句丟掉;素材行「「アマゾネス女王」＋「アマゾネス」モンスター」與降臨句沒有述語,效果外文本的覆蓋率因此只有 78.87%。
2. **被當成卡片的動作**:「このカード名の②の効果は１ターンに１度しか使用できない」出了「できる/效果/否定」;誓約「この効果を発動するターン、自分は機械族モンスターしか特殊召喚できない」出了「特殊召喚/效果/否定」;召喚條件「〜を除外した場合のみ特殊召喚できる」出了「特殊召喚/效果/可能」。將來推導動作類別時,這些會讓「特殊召喚」混進根本不是卡片在做的事。

規模粗估(試點層 24,599 句,依字面正規式計數):

| 句型 | 例 | 句數 |
|---|---|---|
| 發動句內次數 | ①：１ターンに１度、…発動できる | 約 1,460 |

| 卡片發動次數 | このカード名のカードは１ターンに１枚しか発動できない | 約 881 |
| 事件回合禁用 | この効果はこのカードが特殊召喚したターンには発動できない | 約 76 |
| 誓約 | このカードの効果を発動するターン、自分は…しか特殊召喚できない | 約 149 |
| 召喚條件 | このカードは通常召喚できない。…を除外した場合のみ特殊召喚できる | 約 297 |

## Solution

新增一種與動作框架並列的框架——**約束框架**。它不靠述語錨點生出,由句型認出,所以沒有述語的段落也有框架。約束框架分三類:

- **限制**:子類為次數、事件回合禁用、誓約、召喚條件。
- **時機**:效果在哪個回合或階段窗口能發動。
- **素材**:素材行與降臨句。

被認成約束的句子或子句不再另出動作框架。拆解頁把兩種框架放在同一張表、依原文順序排列,以類別欄區分;覆蓋率改為「有任一種框架」的句數比例。

站主翻任一張卡,就能一眼讀出這個效果一回合能用幾次、什麼時候能發動、發動那回合自己受什麼約束、這張卡怎麼出場、要什麼素材,而且這些不會再混進「卡片做了什麼」的動作框架裡。

## User Stories

1. 身為站主,我想看到「①：１ターンに１度、…発動できる」出一個限制·次數框架,以便知道這個效果一回合只能用一次。
2. 身為站主,我想看到「このカード名の①②の効果はそれぞれ１ターンに１度しか使用できない」出一個限制·次數框架,並記下它管的是①與②、次數各自計算,以便知道這張卡哪些效果有卡名次數限制。
3. 身為站主,我想看到「このカード名の①②の効果は１ターンに１度、いずれか１つしか使用できない」記成①②共用一次,以便和「それぞれ」分開。
4. 身為站主,我想讓前言段的次數註記框架留在前言段,以便拆解頁上原文與框架左右對得上。
5. 身為站主,我想看到「このカード名のカードは１ターンに１枚しか発動できない」出限制·次數框架,對象是這張卡的發動,以便魔陷卡的卡名發動次數也讀得出來。
6. 身為站主,我想看到「（同一チェーン上では１度まで）」與「デュエル中に１度しか使用できない」也出限制·次數框架,並記期間是同一連鎖或決鬥,以便和每回合一次分開。
7. 身為站主,我想看到「この効果はこのカードが特殊召喚したターンには発動できない」出限制·事件回合禁用框架,並記下界定回合的事件,以便知道哪個回合這個效果不能用。
8. 身為站主,我想看到誓約「この効果を発動するターン、自分は機械族モンスターしか特殊召喚できない」出限制·誓約框架,記下被約束的動作與允許範圍,以便知道用這個效果要付出的回合約束。
9. 身為站主,我想讓誓約句不再出「特殊召喚/效果/否定」動作框架,以便推導動作類別時「特殊召喚」不被誓約污染。
10. 身為站主,我想看到誓約寫在發動句括弧裡時也被認出,以便「（この効果を発動するターン、自分は…しか特殊召喚できない）」不漏。
11. 身為站主,我想看到「このカードは通常召喚できない」出限制·召喚條件框架,以便知道這張卡不能通常召喚。
12. 身為站主,我想看到「自分の墓地の「SPYRAL」カード３枚を除外した場合のみ特殊召喚できる」出限制·召喚條件框架,召喚手續「除外 墓地の「SPYRAL」カード３枚」記在框架內,以便找得到「除外墓地卡來自己特召」的卡。
13. 身為站主,我想讓召喚條件句不再出「特殊召喚/效果/可能」與手續的動作框架,以便召喚條件不被當成卡片做的動作。
14. 身為站主,我想看到「このカードは融合召喚でのみＥＸデッキから特殊召喚できる」出限制·召喚條件框架並記召喚方式,以便知道唯一的出場方式。
15. 身為站主,我想看到「「終焉龍 カオス・エンペラー」は１ターンに１度、…除外した場合のみ…特殊召喚できる」出兩個框架——召喚條件與次數,以便一個框架只管一件事。
16. 身為站主,我想看到「「FA－ホープ・レイ・ランサー」は１ターンに１度、…X召喚する事もできる」這種召喚手續的次數也出限制·次數框架,以便特殊召喚方式的次數讀得出來。
17. 身為站主,我想看到「①：自分メインフェイズに発動できる」出時機框架,記下窗口是自己的主要階段,以便知道效果什麼時候能用。
18. 身為站主,我想看到「自分・相手のメインフェイズに発動できる」記成雙方的主要階段,以便和只限自己的分開。
19. 身為站主,我想看到「相手ターンに発動できる」與「この効果は相手ターンでも発動できる」記成不同的時機——前者只限對手回合,後者是在原本窗口之外再加對手回合,以便分辨限定與放寬。
20. 身為站主,我想看到「自分・相手のバトルフェイズ開始時に発動できる」「自分スタンバイフェイズに発動する」這類階段時點也出時機框架,以便階段觸發的效果也看得到窗口。
21. 身為站主,我想讓「〜した場合に発動できる」這類觸發事件照舊是條件位置的動作框架,以便時機只管回合與階段窗口。
22. 身為站主,我想讓原文沒寫窗口的啟動效果不補時機框架,以便框架只反映原文。
23. 身為站主,我想讓「●相手ターン：」這類選項標籤不出時機框架,以便標籤照舊記在選項上。
24. 身為站主,我想看到「①：１ターンに１度、自分メインフェイズに発動できる」同時出次數與時機兩個框架,以便兩種約束都讀得出來。
25. 身為站主,我想看到 P 區「①：１ターンに１度、…を対象として発動した効果を無効にできる」出限制·次數框架,以便沒寫「発動できる」但句首寫了次數的效果也算使用次數。
26. 身為站主,我想看到代破「②：１ターンに１度、…破壊される場合、代わりに…取り除く事ができる」也出限制·次數框架,以便句首次數的判準一致。
27. 身為站主,我想看到括弧註記「このカードを裏側守備表示にする（１ターンに１度のみ）」出限制·次數框架,以便沒寫「発動」的起動效果也讀得出次數。
28. 身為站主,我想讓「…１ターンに１度だけ戦闘では破壊されない」的次數記在破壊動作框架自己的次數欄,而不是約束框架,以便效果內容的次數和使用次數分開。
29. 身為站主,我想讓「通常召喚に加えて１度だけ、自分メインフェイズに…召喚できる」的次數與窗口記在召喚動作框架的欄位上,以便追加召喚的內容完整、又不被當成發動時機。
30. 身為站主,我想讓「もう１度だけ続けて攻撃できる」的次數記在攻擊動作框架的次數欄,以便追加攻擊的次數讀得出來。
31. 身為站主,我想看到素材行「「アマゾネス女王」＋「アマゾネス」モンスター」出一個素材框架,內含有序的素材清單,以便一眼看完這張卡的素材需求。
32. 身為站主,我想看到素材清單每項記數量(「双天」モンスター×２ 記 2;モンスター１体以上 記 1 以上),以便數量要求不丟。
33. 身為站主,我想讓素材框架的召喚法由卡片子類型帶入(融合/同調/超量/連結),以便素材行本身沒寫召喚法也知道是哪種素材。
34. 身為站主,我想看到降臨句「「光の黄金櫃」により降臨。」出素材框架,召喚法為儀式、清單是那張儀式魔法,以便儀式怪獸的出場需求和其他額外怪獸同一處讀。
35. 身為站主,我想看到拆解頁把約束框架與動作框架排在同一張表、依原文順序,並以類別欄與底色區分,以便從頭讀到尾就是處理順序。
36. 身為站主,我想滑過約束框架那一列時,原文對應的字段被標出來,以便核對框架抓的是哪一段。
37. 身為站主,我想看到覆蓋率改為「有任一種框架的句數比例」,效果句與效果外分開,以便看到素材行補上後效果外覆蓋率的變化。
38. 身為站主,我想看到「框架覆蓋與盲區」分頁多一組約束框架類別與子類的分佈,以便知道各類約束各有多少。
39. 身為站主,我想讓抽不到任何框架的句子清單照舊列出,以便約束框架上線後的剩餘盲區看得到。
40. 身為站主,我想讓整條分詞鏈決定性重跑後產物逐位元組可重現,以便前後比對有意義。

## Implementation Decisions

### 框架形狀

- 框架清單裡兩種框架並存,每個框架多一個**種類**欄:動作或約束。動作框架其餘欄位不變(動作、對象、來源、目的、位置、極性、句序、詞序列範圍、子句字面)。
- 約束框架共有欄位:種類、類別(限制/時機/素材)、子類(只有限制有:次數/事件回合禁用/誓約/召喚條件)、句序、詞序列範圍、子句字面,以及各類的專屬欄位(見下)。極性只在有意義的類別填。
- 框架依原文位置排序(詞序列範圍起點),兩種框架混排;順序欄照舊由框架主程式編號。

### 限制

- **次數**:期間(回合/決鬥/同一連鎖)、次數值、對象(哪幾個效果:①②、この効果、このカード名のカード、某召喚方式)、共用方式(それぞれ/いずれか１つ/不適用)。
- **事件回合禁用**:界定回合的事件(例:特殊召喚したターン)、被禁止的動作(発動)。
- **誓約**:被約束的動作(特殊召喚、召喚・特殊召喚…)、形式(只能/不能)、範圍(機械族モンスター、効果モンスター…)。
- **召喚條件**:形式(不能通常召喚/不能特殊召喚/只能以某方式特殊召喚)、方式(融合召喚、「X」の効果)、手續(動作與對象,如 除外 墓地の「SPYRAL」カード３枚)。
- 一個框架只管一件事:召喚條件帶次數時出召喚條件與次數兩個框架;次數的對象就是那個召喚方式。

### 時機

- 欄位:誰的回合(自分/相手/雙方)、窗口(ターン或階段名,含開始時/終了時這類階段時點)、型態(限定或追加:「〜に発動できる」是限定,「〜でも発動できる」是追加)、極性。
- 來源只有兩處:發動句(以 発動できる/発動する 收尾)內的回合或階段窗口,與以「この効果は」為主題的時機註記句。
- 以事件界定的回合不是時機,歸限制·事件回合禁用。觸發事件「〜した場合」照舊是條件位置的動作框架。
- 只記原文寫出的窗口,不依效果類型補隱含窗口。選項標籤不出時機框架。

### 素材

- 一行素材行或一句降臨句出一個素材框架。
- 欄位:召喚法、素材清單。清單每項是素材字面(保留卡名、卡名群組、種族、屬性、等級等原詞)與數量(定值或下限)。
- 召喚法由卡片總表的卡片子類型帶入(融合/同調/超量/連結/儀式);降臨句召喚法為儀式,清單是那張儀式魔法。

### 取代規則

- 被認成約束的句子或子句不出動作框架:使用次數註記、卡片發動次數註記、事件回合禁用註記、誓約、召喚條件(含手續)、時機註記。
- 發動句內的「１ターンに１度、」與窗口本來就不出動作框架,只是加上約束框架;發動句其餘的代價、條件、效果框架不受影響。
- 既有的「この効果は…」整句不出框架的規則,改為出時機或事件回合禁用框架。

### 次數的歸屬

判準是字面,不看效果類型:

- **限制·次數**:句首「…度、」(不論是否發動句,含 P 區「…無効にできる」、代破「…代わりに…事ができる」、場地魔法「…事ができる」);括弧註記「（同一チェーン上では１度まで）」「（１ターンに１度のみ）」;「…の効果は/カードは…しか使用できない/発動できない」註記;召喚手續的次數。
- **動作框架的欄位**:句中「１度だけ」「もう１度だけ」。動作框架新增兩個可選欄位:**次數**與**窗口**,記這類效果內容的次數與同句的階段窗口(追加召喚的「自分メインフェイズに」)。

### 掛載與對象效果

- 約束框架原文寫在哪就掛在哪一句效果句:前言段的「このカード名の①②の効果は…」留在前言段,以對象欄記①②。
- 推導層要知道「②有沒有次數限制」時,依對象欄查回;本規格不把框架複製到各效果。

### 管線與拆解頁

- 接縫沿用「一句原文(帶同卡同段上文)→ 框架清單」,輸入多一個可選的卡片子類型;框架主程式逐句從卡片總表帶入。
- 覆蓋率統計(框架主程式、報表、拆解頁三處共用的同一個函式)改為:有任一種框架即算覆蓋;另回傳約束框架的類別與子類分佈。
- 拆解頁:同一張表依原文順序列兩種框架,新增類別欄(動作框架顯示位置值,約束框架顯示 類別·子類),約束框架列以底色區分;專屬欄位併成一欄「內容」顯示。滑過一列標出原文字段的行為照舊。「框架覆蓋與盲區」分頁加約束框架分佈。
- 分詞鏈照舊決定性重跑後發布到既有檢視 artifact。

## Testing Decisions

- **好測試的標準**:只斷言接縫輸出的框架(種類、類別、子類、專屬欄位、動作框架的動作/論元/位置/極性/次數/窗口),不測規則內部;用真的分詞器與詞典。每個句型一條回歸例子,修規則前先補一條會失敗的例子。
- **受測模組**:框架抽取一個模組,經同一接縫。取代規則在同一個斷言裡驗——例如誓約句的輸出只有限制·誓約框架、沒有特殊召喚動作框架。
- **既有回歸例子**:63 條照跑;受取代規則影響的(「効果は…できない」述語 できる 那條、この効果は 註記不出框架那幾條)改期望值,不刪。
- **新增例子**:至少涵蓋使用者故事 1〜34 的每個句型各一條,含邊界——句首「１ターンに１度、」的代破與 P 區、句中「１度だけ」、「相手ターンに」與「相手ターンでも」、召喚條件加次數、降臨句、「〜した場合に発動できる」仍是條件動作框架。
- **素材例子**:經接縫帶入卡片子類型(融合、同調、超量、連結、儀式各一條);不帶子類型時召喚法留空,不報錯。
- **全語料**:分詞鏈決定性重跑,比對取代前後的框架數與覆蓋率;拆解頁與覆蓋率不另設接縫,靠重跑與站主翻頁。
- **前例**:動作框架的行為測試檔(票 05〜10 的回歸例子)就是同一接縫的前例。

## Out of Scope

- 依效果類型補隱含時機(例:啟動效果補自己主要階段)。
- 選項標籤「●自分ターン：/●相手ターン：」的時機框架。
- 動作類別的歸組與搜尋介面:約束框架只是推導基底,不上網站搜尋。
- 舊式卡文與試點層以外的卡;中文側卡文。
- 儀式魔法卡上的素材條件(「レベルの合計が…になるように」):那是魔法卡的效果處理,照舊是動作框架。
- 把前言段的次數框架複製到各編號效果。

## 需要你決定的

### 約束框架要不要做 LLM 抽驗?

決定(2026-10-09):(c)比照動作框架三輪——第一輪抽驗、依錯誤類型修規則後同批複檢、新種子抽驗(票 07〜09)。

動作框架經過三輪 LLM 子代理抽驗(每輪 300 張)才交件。約束框架句型比動作框架規整、多為固定字面,但取代規則會讓既有動作框架消失,漏認或誤認都會直接少框架。

- (a)抽一輪小樣本(建議):只抽有約束框架或素材行的卡 100 張,交子代理看原文與框架挑錯,依錯誤類型修規則一次;成本約票 09 的三分之一。
- (b)不抽:回歸例子加全語料重跑後直接併入票 11 的質性驗收;最快,但錯誤只能靠站主翻頁發現。
- (c)比照動作框架三輪:最穩,工作量與票 09〜10 相當。
