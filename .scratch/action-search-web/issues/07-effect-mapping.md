# 07: 效果對應

Status: resolved

**What to build:** 動作索引的每一段都對回前端索引的一個效果句。之後「要落在同一個效果」的判斷與標出命中的效果(票 16)都靠它。

- 建置多兩份輸入:效果標記表(提供每個效果句的日文原文,前端索引裡沒有日文)與前端索引(提供效果句的序號)。
- 對法依序:區塊有①②③編號時,對到同一個來源(主文或靈擺效果)裡同編號的效果句;沒有編號時,看段的原文位置落在哪個效果句的日文原文裡;都對不上就留空。
- 內嵌效果裡的段算在它所在的區塊上;引用列算在引用節點所在的效果上。
- 效果句的序號要和前端索引實際的序號一致;對不上時(效果句數不符)建置失敗。
- 建置報告列出留空的段數與卡號。
- 任何一份輸入變了,動作索引要跟著重建。

- 規格:需要你決定的「Q25」;實作決策「效果對應」、「動作索引」最後一條;使用者故事 53;測試決策「接縫二」。
- 統計:有編號的區塊裡的段佔 73.6%(規格〔區塊〕),其餘 26.4% 要靠原文位置。

### 實作(2026-11-23)

- 新模組 `script/action_structure/clause_map.py`(`ClauseMap`):段或引用節點的原文位置 → 前端索引的效果句序號(= 前端索引 `tx` 的位置 = 效果標記表裡這張卡的第幾句;`script/web/webindex.py` 照效果標記表的順序寫 `tx`)。對法依序:
  1. 編號:頂層區塊有①②③時,找同來源(`card_text` → `main`、`pen_effect` → `pendulum`)裡編號相同的效果句。同編號有好幾句(①、①-●1、①-●2 這種 ● 子效果拆開的)時,看段的位置落在哪一句;都沒落到就取編號剛好是 ① 的那句。
  2. 位置:沒有編號,或編號找不到效果句時,看段的起點落在哪個效果句的日文原文裡。效果句的日文依序在來源原文裡找(忽略空白;先從上一句結尾往後找,找不到再從頭找),找不到的那句不參與。
  3. 都對不上就留空(null)。
- 原文位置在攤平時算(`action_rows`,解讀卡片結構只在這裡):`Row.place`、`Reference.place` = (來源, 頂層區塊的編號, 在來源原文裡的起點);內嵌效果的區塊 span 本來就是來源的位置,所以內嵌效果裡的段直接用頂層區塊的編號(算在它所在的區塊上)。來源原文由區塊與略過文本照 span 拼回(`ActionIndex.texts`)。全庫驗過:拼回的原文和官方 DB 文本逐字相同,沒蓋到的只有空白。引用節點的位置要知道它直屬的區塊,`effect_reference` 多一個 `iter_reference_sites`(`iter_references` 改成用它)。
- 產物格式只**往後加**,先前的讀法照舊(票 08 平行中):卡那一行多第 6 格「效果」(與段同序的清單,序號或 null);引用列多第 5 格(引用節點所在的效果句)。`decode_action_index` 讀回時,段與引用列各多一個 `clause`。
- `build_action_index(..., tag_cards=效果標記表)`:多一份輸入(關鍵字參數,沒給時每張卡都沒有效果句,段的效果全留空,所以票 08 不帶它的呼叫照樣能跑)。建置前先比每張卡的效果句數:前端索引 `tx` 的句數 ≠ 效果標記表的句數就建置失敗、不寫檔,問題寫出卡號與兩邊句數。
- CLI 多 `--tags`(預設 `data/tag_cards.json`),印它的 digest;報告多兩行:「效果對應 段 N:靠編號 …、靠位置 …、留空 …;引用列 …(留空 …)」與「留空的卡 N 張:卡號…」(全列,不截斷)。
