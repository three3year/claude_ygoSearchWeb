# Spec: 細分項放最後一列、具名查詢自己寫的欄鎖住

Status: ready-for-agent
Date: 2026-11-03

站主回報兩件事:目錄裡「破壊」這類有子項的列一點就加標籤,本來只想展開;點細分項(如 破壊@相手フィールド)加的標籤,抽屜裡還是一大堆灰鈕,因為細分條件可以從抽屜點掉,隱藏名單只好照整個動作列。2026-11-03 /grill-with-docs 訪談定案,下面各題都已決定,正文依決定寫。上游規格:`.scratch/predicate-ui/spec.md`(目錄導覽、網址)、`.scratch/drawer-values/spec.md`(抽屜選項;本規格改它「隱藏名單只看動作」一條)。

- (c)不改網址,對不上就不鎖:規則最簡單。代價:鎖住的標籤另加了其他欄,重整後變回不鎖。

決定(2026-11-03):(a)不鎖,看當初從哪一列點的。

- (b)自動變鎖住。代價:剛加的值馬上拿不掉。

### 上一題與重整的衝突

決定(2026-11-03):(a)接受。從詞元節點加、欄位剛好等於某個具名查詢的標籤,重整後照那個具名查詢鎖。

- (b)重整後一律不鎖。代價:直接點細分項的標籤重整後也變回一堆灰鈕。

決定(2026-11-03):(b)鎖。鎖的範圍統一成「具名查詢自己寫的欄,詞元、極性以外」。

- (b)鎖(建議):規則不分詞元節點、條件葉;特殊否定組合改用一般詞元標籤加極性否定。

### 測試接縫就這兩個嗎?

決定(2026-11-03):是。條件模型(既有)與目錄導覽樹(既有);鎖住那一行的畫面不做自動測試,交件票在真 Chrome 桌面與手機寬各走一輪。

## Problem Statement

站主點目錄裡的「破壊」想看底下的細分,結果直接加了一張標籤;要展開得點列左邊的小三角,事前看不出來。

站主點細分項(破壊@相手フィールド)加了標籤後,打開抽屜還是一大堆灰鈕:那些值是「破壊 有、但在相手フィールド的破壊 沒有」的值。抽屜隱藏名單只看動作,因為細分條件本身可以在抽屜裡點掉,點掉後那些值就有結果。結果細分項的標籤抽屜和整個動作一樣長,大半按不下去。耐性/限制 的詞元節點(破壊(耐性)、発動(限制))同樣如此:否定形可以改,所以只在肯定框出現的值都列成灰鈕。

## Solution

1. **目錄樹**:有子項的詞元節點(25 個)點列只展開,和大類、中類一樣。節點自己以同名列在子的最後一列,− 一起移過去;父列照舊標張數。大類 召喚 底下的詞元節點 召喚 也移到最後。「已用」只標在那一列。
2. **鎖住的欄**:從具名查詢產生的標籤,具名查詢自己寫的欄(詞元、極性以外)鎖住:條件葉的來源、目的、所在、受事者中心詞、目的中心詞,耐性/限制詞元節點的否定形。鎖住的欄在抽屜只留一行,列出鎖住的值,樣式同按不掉的鈕,滑鼠停上去說明「由 X 決定」;不能加值也不能減值。
3. **隱藏名單**:鎖住的標籤,其他欄只列「詞元+鎖住的欄」在三個位置、三種極性下出現過的值;沒有鎖住欄的標籤照舊只看詞元。灰色、亮著、位置與極性最後一顆的規則不變。
4. **要擴大**:破壊 在相手フィールド或墓地、発動 的一般否定這類,改用詞元那一列加的標籤自己加值。
5. **鎖跟著來源**:只有從會鎖的具名查詢點出來的標籤鎖;從詞元那一列加、自己改成和某個細分項一樣的,不鎖。
6. **網址**:格式不改。讀網址時欄位剛好等於某個具名查詢(不看位置)就是它的標籤、照它鎖;對不上就不鎖。

驗收:真 Chrome 桌面與手機寬各走一輪;全語料上鎖住的標籤可按的鈕加上去都有結果、鎖住的值按了標籤不變。

## User Stories

1. 作為使用者,我要點「破壊」這列只展開,這樣想看細分時不會誤加條件。
2. 作為使用者,我要有子項的列和大類、中類同一種點法,這樣不必記哪些列點了會加標籤。
3. 作為使用者,我要「破壊」本身排在它底下最後一列,這樣找得到不分細分的那一個。
4. 作為使用者,我要最後一列和標籤同名,這樣樹上看到的字就是條件列上的字。
5. 作為使用者,我要排除(−)跟著最後一列,這樣排除整個動作的地方和包含的地方一樣。
6. 作為使用者,我要大類 召喚 底下的 召喚 也在最後,這樣「可選的那一個在最下面」沒有例外。
7. 作為使用者,我要父列照舊標張數,這樣收合時也看得到這個動作多少張。
8. 作為使用者,我要「已用」標在我點的那一列,這樣和大類、中類同一套。
9. 作為使用者,我要在過濾框打詞元名字時父列自動展開、最後一列看得到,這樣過濾後直接點得到。
10. 作為使用者,我要點細分項加的標籤,細分條件在抽屜裡改不了,這樣標籤名字永遠對得上它的條件。
11. 作為使用者,我要細分項標籤的抽屜不列被細分條件擋掉的值,這樣抽屜短、灰鈕少。
12. 作為使用者,我要鎖住的條件在抽屜裡留一行看得到,這樣知道這張標籤的條件全貌。
13. 作為使用者,我要鎖住的那一行看得出按不掉、滑鼠停上去說明由哪個具名查詢決定,這樣不會以為壞了。
14. 作為使用者,我要鎖住的區域欄沒有玩家、區域選單,這樣不會想去加。
15. 作為使用者,我要鎖住的中心詞欄沒有輸入框與候選,這樣不會想去打字。
16. 作為使用者,我要 破壊(耐性) 這類標籤的否定形也鎖住,這樣只在肯定框出現的值不列。
17. 作為使用者,我要鎖住的標籤其他欄仍照目前條件灰掉,這樣按得下去的都有結果。
18. 作為使用者,我要鎖住的標籤其他欄仍可加值、減值、還原,這樣還能在細分內再縮小。
19. 作為使用者,我要鎖住的標籤包含與排除都一樣鎖,這樣切換包含、排除不改抽屜。
20. 作為使用者,我要從詞元那一列加的標籤完全不鎖,這樣要自組條件時有地方下手。
21. 作為使用者,我要從詞元那一列加、改成和細分項一樣的標籤不會突然鎖住,這樣我剛加的值拿得掉。
22. 作為使用者,我要直接點細分項加的標籤,重整或貼網址後仍鎖住,這樣分享出去看到的抽屜一樣乾淨。
23. 作為使用者,我接受鎖住的標籤另加了其他欄時,重整後變回不鎖;條件不變,只是抽屜變長。
24. 作為使用者,我接受從詞元那一列加、欄位剛好等於細分項的標籤,重整後變鎖住;要解開就重新點詞元那一列。
25. 作為使用者,我要舊網址照樣讀得進來,查到的卡不變。
26. 作為使用者,我要鎖住的標籤只改了位置時仍算同一個具名查詢,這樣改位置不會解鎖。
27. 作為使用者,我要 耐性/限制 標籤的極性欄只列 否定,這樣不會看到灰掉的肯定、可能。

## Implementation Decisions

**目錄導覽樹(Acat)**
- 有子項的詞元節點(子是具名查詢的列):節點本身變純導覽——沒有葉路徑、點了只展開、沒有 −;張數照舊用那一列的張數(灰字規則照舊)。
- 那一列的具名查詢另成一個同名子節點,排在該節點所有子的最後;葉路徑仍是原本那一列的路徑,所以網址的路徑、`tagAt` 不變。
- 大類 召喚 底下的詞元節點 召喚(現行已是子節點,鍵另編)改排在大類所有子的最後。
- 「已用」照葉路徑標,父節點沒有葉路徑,自然不標。
- 過濾規則不變:最後一列與父節點同名,打父節點的名字一定比到最後一列,祖先跟著展開。

**條件模型(Cond)**
- 一張標籤的**鎖住的欄** = 它的來源(origin)那一列的述詞中,詞元、極性以外的欄;沒有來源或來源列沒有這種欄時,沒有鎖住的欄。鎖住的欄的值就是來源列述詞的值。
- 鎖跟著來源:從目錄點列(`tagAt`)來源就是那一列;改欄位不改來源,所以從詞元節點加的標籤改成和細分項一樣也不鎖;還原回來源列不影響鎖。
- 讀網址(`fromPairs`)維持現行:欄位等於某個具名查詢(比對不看位置)才有來源,有來源就照那一列鎖;網址格式不變。網址只寫路徑的情況照舊走 `tagAt`。
- `addValue`、`removeValue`、`toggleValue` 對鎖住的欄回傳原標籤(不變)。
- 抽屜選項:鎖住的欄回一個標明鎖住的欄選項,只帶鎖住的值(選值欄的每個值狀態為鎖住;區域欄與中心詞欄只帶已加入的項,不帶玩家、區域選單與候選),並帶來源名字供說明文字用。
- 隱藏名單:其他欄的「出現過」改用 詞元 + 鎖住的欄 去問引擎(不帶位置、極性,即三個位置、三種極性都算);沒有鎖住欄時等於現行只看詞元。灰色判定照舊用標籤目前的述詞。
- 位置、極性「最後一顆按不掉」規則不變;耐性/限制 標籤的極性欄因隱藏名單只剩 否定,自然是按不掉的那一顆。
- 包含、排除同一份選項(鎖住的欄不看 ex)。

**抽屜畫面(Strip)**
- 鎖住的欄畫一行:欄名 + 鎖住的值,樣式沿用按不掉的鈕(on locked),不可按;說明文字「由 X 決定」,X 是來源具名查詢的名字。
- 區域、中心詞欄鎖住時不畫玩家選單、區域選單、輸入框與候選,已加入的項不帶 ×。

**文件**
- GLOSSARY 已在訪談中更新:動作類別第三版段與軸內 OR 例外段寫明帶子的詞元節點只展開、自己列在子的最後;具名查詢條新增「鎖住的欄」。
- drawer-values 規格的「隱藏名單只看動作」由本規格改寫;那份規格不回頭改,本規格 Further Notes 記一行。

## Testing Decisions

- 好的測試只看外部行為:給標籤看抽屜選項與改欄位的回傳,給目錄看導覽樹的節點、順序與葉路徑;不測內部資料結構與 DOM。
- **條件模型接縫**(既有):`Cond.drawerOptions(標籤)`、`addValue`/`removeValue`/`toggleValue`、`tagAt`、`fromPairs`。手寫小框表的例子:條件葉標籤鎖住區域欄,只列鎖住的項、改不動;其他欄只列詞元+鎖住欄出現過的值(詞元有、鎖住欄下沒有的值不列;鎖住欄下有、目前位置沒有的值仍灰);否定形鎖住後極性欄只剩否定;詞元節點標籤不鎖;從詞元節點改成等於條件葉不鎖;`fromPairs` 欄位等於條件葉時鎖、另加一欄時不鎖、只差位置時仍鎖;包含、排除同一份。全語料核對:162 張會鎖的標籤上,抽屜可按的鈕加上去都有卡、鎖住的值按了標籤不變。先例:drawer-values 的 drawer-options、drawer-regions、head-options 三個測試檔。
- **目錄導覽樹接縫**(既有):帶子的詞元節點沒有葉路徑、最後一個子同名且帶原葉路徑;大類 召喚 的詞元節點 召喚 是最後一個子;沒有子的詞元節點不變;過濾父節點名字時父節點展開。先例:conditions.test.js 裡的 Acat 例子。
- **真瀏覽器**:交件票更新 drawer-values 的 `drawer_browser.js` 與 `press_stats.js`(或在本功能 tools 另寫),桌面與手機寬各走一輪:點 破壊 只展開、最後一列加標籤;破壊@相手フィールド、特殊召喚←墓地、破壊(耐性) 的抽屜鎖住那一行與可按的鈕;貼網址重開仍鎖;console 無錯。

## Out of Scope

- 網址寫來源記號(見[重整頁面或貼網址後還鎖不鎖](#重整頁面或貼網址後還鎖不鎖?))。
- 大類、中類收合時標「已用」。
- 鎖住欄以外的灰鈕再減少(剩下的灰是被預設位置或極性擋掉的,drawer-values 已決定那樣顯示)。
- 目錄、具名查詢、命名規則、建置期檢查的任何改動;引擎與參考評估器不改。
