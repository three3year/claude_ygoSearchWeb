# footer 與資料更新時間

Status: ready-for-agent

2026-08-21 訪談定案(訪談逐條裁示見「Implementation Decisions」)。

## Problem Statement

訪客在站上看不出卡片資料有多新:唯一的時間線索是頂部資訊列的「建置於
2026-08-17T19:41:03+0800」,一來是 ISO 原始字串難讀,二來語意根本不對——
建置時間是[[前端索引]]產出的時刻,離線重建也會前進,不代表卡片資料的新舊。
同時整個頁面沒有任何來源聲明:效果類型的判定依據、中文卡文與卡圖的出處、
日英卡名與 MD 稀有度的來源都沒有交代,也沒有版權免責,訪客可能誤認本站
與官方有關。

## Solution

頁尾新增三行純文字聲明區(footer):[[資料更新時間]]一行、來源集中一行
(括號標各來源對應的資料,效果類型的依據站 Yu-Gi-Oh! Neuron 也在其中)、
KONAMI 免責一行(2026-08-21 實看後多次改版定案;字級 10px、上下 padding
4px)。內容不足一屏(還沒搜尋)時 footer 貼齊視窗底。資料更新時間定義為**最近一次成功下載來源檔的時間**,由
更新流程記錄、建置時寫進 META、前端格式化為 `2026-08-17 19:41 (UTC+8)`
顯示。頂部資訊列的「建置於…」下架,只留卡數與效果句數。

## User Stories

1. As a 訪客, I want 頁尾看到資料更新時間, so that 我知道查到的卡片資料有多新。
2. As a 訪客, I want 時間顯示成「2026-08-17 19:41 (UTC+8)」而不是 ISO 原始字串,
   so that 不必自行解讀 `T` 與 `+0800` 是什麼意思。
3. As a 訪客, I want 在資料來源看到效果類型的依據站(Yu-Gi-Oh! Neuron), so that
   我知道這個進階欄位的依據從哪來。
4. As a 訪客, I want 看到中文卡片資料與卡圖來源於查牌網, so that 我知道卡文與
   卡圖的出處。
5. As a 訪客, I want 看到日文/英文卡名資料來源於 ygopro-database, so that 我知道
   跨語言卡名搜尋的資料從哪來。
6. As a 訪客, I want 看到 Master Duel 稀有度與 Genesys 點數的來源, so that 我知道
   這兩個欄位的出處。
7. As a 訪客, I want 看到「遊戲王」為 KONAMI 著作權與商標的免責聲明, so that
   我不會把本站誤認為官方網站。
8. As a 手機訪客, I want footer 的來源段自動換行, so that 窄螢幕不會被撐出
   橫向捲軸。
9. As a 訪客, I want 資料更新時間未知時整行消失而不是顯示錯誤時間, so that
   我看到的時間永遠是真的。
10. As a 訪客, I want 頂部資訊列只剩卡數與效果句數, so that 標題列簡潔、
    不再出現與資料新舊無關的建置時間。
11. As a 維護者, I want 更新流程下載成功後自動記下時間, so that 不必手動維護
    任何時間欄位。
12. As a 維護者, I want `--offline` 重跑不改動已記的時間, so that 資料更新時間
    誠實反映「下載」而不是「重跑」。
13. As a 維護者, I want 一次下載執行只記一個時間(五個來源不分開), so that
    footer 一行講完、不列五個時間。
14. As a 維護者, I want 建置時間(`built_at`)仍寫進 META, so that 追查索引
    是何時、由哪份來源產出時有據可查。
15. As a 維護者, I want 時間記錄不存在時建置照常通過(META 欄位缺席、不是
    建置失敗), so that clean checkout 或從未跑過更新流程的機器也能建置。
16. As a 維護者, I want 同一份輸入兩次建置逐位元組相同的性質保持, so that
    [[前端索引]]在版控裡的 diff 仍然可讀。
17. As a 維護者, I want 前端格式化在欄位形狀非預期時退回原樣字串, so that
    看到的是原值而不是 `NaN` 或 `Invalid Date`。
18. As a 維護者, I want 全部新測試不連網、不讀時鐘, so that 測試可重複且離線可跑。

## Implementation Decisions

- **資料更新時間 = 來源檔下載時間**,不是建置時間;兩者的分工已入 CONTEXT.md
  詞條[[資料更新時間]]。
- **更新流程(下載殼)**:五個來源(中/日/英 cdb、MD 稀有度、Genesys)全部
  下載成功後寫一筆下載時間記錄,存於來源檔目錄(本機檔、不入版控——來源檔
  目錄本來就是 gitignored,建置只在有來源檔的機器上跑,讀得到)。下載失敗
  或 `--offline` 不動既有記錄。「現在時刻」由呼叫端注入,寫檔函式不讀時鐘。
- **建置薄殼**:讀時間記錄,與 `built_at`、來源檔雜湊一樣以參數傳入建置管線
  純函式;純函式不讀時鐘不讀檔,決定性不變。META 新增資料更新時間欄位;
  記錄不存在時欄位不存在(不是空字串)。
- **前端**:時間格式化做成純函式,`2026-08-17T19:41:03+0800` →
  `2026-08-17 19:41 (UTC+8)`;顯示固定 UTC+8,偏移只認 `+0800`,其他任何
  形狀(含別的偏移)原樣返回。footer 三行(字級 10px、上下 padding 4px):
  第一行「資料更新:…」整行動態,META 無該欄位時整行 hidden;第二行資料
  來源(效果類型的依據站 Yu-Gi-Oh! Neuron 併入其中);第三行免責。內容不足
  一屏時 footer 貼齊視窗底(body 直向 flex、版面區撐滿剩餘高度)。頂部
  資訊列移除「建置於…」。冒號用全形「：」——與站上
  既有 UI 文案(「例：」等)同一套標點(2026-08-21 審查後定案)。
- **footer 純文字、不加外部連結**;文案定稿如下(第二行時間為範例,實值來自
  META):

  ```
  資料更新：2026-08-17 19:41 (UTC+8)
  資料來源：查牌網（中文卡文・卡圖）・ygopro-database（日英卡名）・Master Duel Meta（MD 稀有度）・YGOPRODeck（Genesys 點數）・Yu-Gi-Oh! Neuron（效果類型）
  「遊戲王」為 KONAMI 之著作權與商標,本站為非官方查詢工具
  ```

- **零建置協定(ADR-0007)不變**:footer 由既有前端模組組裝,不引入任何
  新依賴或建置步驟。

## Testing Decisions

- 好測試只驗外部行為:檔案裡寫了什麼、META 出現/缺席哪個欄位、格式化函式
  的輸入輸出——不綁內部實作細節。
- 三條既有縫,零新縫:
  1. **下載殼縫**(prior art:來源下載殼測試):注入假 fetch 與暫存目錄,
     驗「全部下載成功才寫時間記錄、單一來源失敗不寫、offline 不動既有記錄」;
     時刻注入,不讀時鐘。
  2. **建置管線純函式縫**(prior art:webindex 測試):傳入資料更新時間 →
     META 有該欄位且序列化裡看得到;不傳 → 欄位不存在;同輸入兩次序列化
     逐位元組相同。
  3. **前端接縫 3 harness**(prior art:engine 測試 + 沙箱載入器):DRIVER
     加一個格式化鉤子,驗 `+0800` ISO 字串 → `YYYY-MM-DD HH:mm (UTC+8)`、
     壞輸入(空值、非字串、缺 offset)原樣返回。
- footer 的 DOM 組裝是薄殼,不測——與現行頂部資訊列同一待遇。

## Out of Scope

- 逐來源分開記時間(裁示:一次執行一個時間)。
- footer 加外部連結(裁示:純文字)。
- 建置時間上畫面(留在 META 供維護者查)。
- 官方 Q&A 快取的抓取時間——更新流程對 Q&A 只對帳不自動爬,資料更新時間
  只涵蓋五個下載來源。
- 訪客時區換算(固定顯示 UTC+8)與多語 footer。

## Further Notes

- 時間記錄目前不存在,**首次上線時 footer 不會有時間行**;跑過一次更新流程
  後出現。這是預期行為(第 9、15 條 user story),不是缺陷。
- 效果類型的措辭沿革:訪談原定「效果類型依官方 QA 判定」(判定責任在本站,
  官方沒有發佈過這個欄位,不寫「由官方 QA 提供」);2026-08-21 實看後改併入
  資料來源行,記為「Yu-Gi-Oh! Neuron(效果類型)」——Yu-Gi-Oh! Neuron 是官方
  資料庫(db.yugioh-card.com)的站名,效果類型的判定依據是該站的 Q&A。
