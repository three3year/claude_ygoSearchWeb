# 13 — 軸摺疊機制與逐軸已選數

**What to build:** 側欄的 17 個參數[[軸]]各自變成可摺疊區塊、**預設全部收起**:開站
初見只剩卡片密碼/卡名/效果文三欄、搜尋/清除鈕與一排軸標題列,不必捲過兩百多顆按鈕。
點標題列展開/收起,各軸獨立、可同時多開(非手風琴式)。

[[摺疊]]是瀏覽狀態:收起**保留**條件生效,標題列顯示該軸的已選條件數(如「種族 (2)」),
讓收起的條件保持可見——「看不見的條件解釋不了零結果」這條原則由 badge 接手,而
[[連動隱藏]](大類取消→子類組清空)照舊清空,兩機制並存。逐軸已選數抽成 Query 純規則
(`critCount` 的逐軸版),DOM 只照答案寫數字。

本票完成後子類組仍由既有連動出現,只是以預設收起狀態出現;自動展開在票 14。

## Comments

2026-08-17 實作完成(與票12、14 同一輪)。生成的每個區塊(11 個三態軸 + 6 個範圍)
都長出摺疊標題列(`headHtml`:軸名 + 已選數),body 預設 hidden;開合狀態只有一份
說法(`aria-expanded`),與窄螢幕側欄摺疊鈕同一條規則。**摺疊(setAxisOpen,收起
保留條件)與連動隱藏(showAxis,藏掉清空)是兩個函式**,對應 CONTEXT.md 的兩個詞。

逐軸已選數抽成純函式 `Query.axisCounts(q)`,鍵是畫面上的區塊(三態軸用值域名、
範圍用欄位名),badge 四個觸發點:tri 點擊、range input、清除、網址還原。
**驗收文字修訂**:原「跨側子類合併計數」與三段各有標題列的 UI 矛盾,改為
「共用一個軸物件、各段數自己那一側」——spec 的 Testing Decisions 同步修訂。

一個順序陷阱記在 clear() 的註解裡:收合要放在 syncSubs/syncOptional **之後**,
否則必發/選發軸因連動從隱藏轉回可見時會被自動展開,清除就不是回到初始狀態了。
接縫 3 測試 +4 條。`read()` 不看摺疊狀態(收起的鈕仍在 DOM 裡),「收起保留生效」
由結構成立,DOM 視覺走 spec 的人工驗收清單。
