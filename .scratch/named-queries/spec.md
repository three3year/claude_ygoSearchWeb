## 需要你決定的

### 具名查詢的來源檔是什麼形狀?

現在 `category_tree.json` 的葉用葉條件寫(來源/目的/所在/×玩家/關鍵詞/目的關鍵詞,詞元節點帶極性類),建置期歸葉程式讀它。第三版起每個節點是一個框架述詞;試跑證明 233 葉全部編得出來。問題是目錄檔以後用哪套字彙寫。

決定(2026-11-01):(a)一次改寫成述詞字彙:編譯器跑一次把葉條件改寫成述詞欄位,之後建置期只檢查。與「舊匯出檔過渡」疊加:改寫結果寫到新目錄檔,舊樹檔凍結、只給過渡期的舊歸葉程式讀,規格 3 刪舊樹檔(to-tickets 時定)。

- (a)**一次改寫成述詞字彙**(建議):編譯器只跑一次,把每片葉的條件機械改寫成述詞欄位(詞元、極性、否定形、來源/目的/所在的 (玩家, 區域) 清單、受事者中心詞、目的中心詞)寫回目錄檔,預設葉 `{}` 刪掉、極性類節點改成「否定形 ∈ {受身, 不成不受}」或「否定形 = 不可能」;之後站主直接用述詞字彙寫目錄,建置期只做檢查(值域、完整性、「不留」),沒有第二套字彙。代價:目錄檔 diff 一次全變(340 行);以後新維度(施事者、方式類、動作對象)就是述詞多一個欄,不用再開葉條件。
- (b)**沿用葉條件、建置期每次編譯**:目錄檔不動,編譯規則(耐性 = 否定形 ∈ {受身, 不成不受}、關鍵詞 → 中心詞)留在程式裡;代價:兩套字彙並存,要加施事者、方式這類維度時葉條件還得擴,規格 4「改過的具名查詢展開成欄位對」要再做一次葉條件 → 欄位的對照。
- (c)**另開一個目錄檔、舊樹檔留著**:兩份都入版控;代價:同一棵樹兩份來源,改名要改兩處。

### 「全語料沒有命中的具名查詢不留」算哪些位置?

ADR-0018 把條件位框架也納進搜尋、位置是述詞的一個欄位;具名查詢本身不限位置。試跑:只算效果位時 取り除く@お互いのフィールド 命中 0 張(它只在代價位有 10 句),算三個位置就沒有空的。

決定(2026-11-01):(a)三個位置合計至少一張。

- (a)**三個位置合計至少一張**(建議):和「具名查詢不限位置、位置由使用者的述詞定」一致;一個只在代價位或條件位出現的具名查詢仍是合法的目錄項,介面預設只看效果位時它顯示 0 張是規格 4 的顯示問題。
- (b)只算效果位:與現行介面預設一致;代價:取り除く@お互いのフィールド 這類要刪,以後開條件位專用的具名查詢(觸發事件)也過不了檢查。
- (c)效果位加代價位:延續第二版「效果位或代價位至少一框」;代價:條件位專用的具名查詢同樣過不了。

### 關鍵詞改成中心詞後怎麼比?

舊關鍵詞是子字串(含 した/する/され 尾不算);第四版的中心詞是最後一個名詞格,封閉值域複合詞(効果モンスター、永続罠カード)整格是中心詞。對全語料 49 片關鍵詞類葉試算三種比法(效果位張數):子字串與尾綴只差兩葉——破壊:モンスター 609 → 605(中心詞 モンスターカード 4 張)、にする:ドロー/数 18 → 16(中心詞 数値 2 張);相等差 14 葉(置く:カウンター 149 → 30、にする→守備表示 189 → 69、にする→族 35 → 0、無効にする:召喚 18 → 0 等)。地圖把比對方式排在規格 3,但編譯具名查詢現在就要用一種。

決定(2026-11-01):(a)尾綴;規格 3 的評估器實作同一條。

- (a)**尾綴**(建議):中心詞以關鍵詞結尾才中——モンスター 中 効果モンスター/融合モンスター、召喚 中 特殊召喚、族 中 戦士族,不中 モンスターカード/数値;只差 6 張,全是「子字串碰巧命中」;述詞欄「受事者中心詞」的語意就是尾綴,使用者自建述詞照用,規格 3 評估器實作同一條。
- (b)子字串(現行):張數全同;代價:攻撃 會中 攻撃力 這類碰巧命中,述詞語意不乾淨。
- (c)相等:語意最乾淨;代價:14 葉張數大變,目錄要改寫成列舉(モンスター 要列 効果モンスター、融合モンスター…八個值)。

### 回指要改讀論元片語嗎?

票面範圍寫 anaphora.py 改讀論元片語;但規格 1 票 01 把片語結構化放在框架抽取的最後一步(回指之後),回指現在讀不到片語。回指用正則式比候選的限定語與中心詞(32 處正則),和片語的修飾語/中心詞/數量是同一件事。

決定(2026-11-01):(a)拆兩段、片語結構化搬到回指之前、回指改讀片語;回指欄變的逐卡說明後重新凍結基準。

- (a)**拆兩段、回指改讀**(建議):片語結構化(段/中心詞/修飾語/數量/玩家/區域/指示詞)搬到回指之前——它只讀既有欄與切區域前的字面,不讀回指;結構化區域、施事者、方式、否定形、回指回填留在回指之後(它們讀回指)。回指的候選比對改讀片語,正則式刪掉。代價:回指欄是既有鍵,結果可能變——全語料逐框比對、變的逐卡說明,確認後重新凍結基準;片語本身不變(它不讀回指)。
- (b)回指不動:保留它的正則式,只改動作對象、類別線;代價:四支程式裡還有一支自己拆字面,ADR-0018 的問題陳述少解一支;下次改回指規則時兩套中心詞判法還是會分岔。

### 舊匯出檔與歸葉程式怎麼過渡?

匯出檔內容要從「每句的葉」換成「每句的框架與欄位」,但索引建置(規格 3)與介面(規格 4)還讀舊檔;地圖 Notes 說不先動搜尋端。

決定(2026-11-01):(a)新檔 `data/action_frames.json` 並存,舊檔、歸葉程式與舊匯出留到規格 3 切換後刪。

- (a)**新檔名並存,舊的留到規格 3 切換後刪**(建議):本規格新增 `data/action_frames.json`(每句的框架與欄位、具名查詢目錄、卡面雜湊),舊的 `data/action_categories.json`、歸葉程式與舊匯出照常產出、索引建置不動;規格 3 把索引切到新檔後,刪舊檔、歸葉程式、舊匯出與它們的測試(規格 3 的票)。代價:過渡期分詞鏈多跑兩步、兩份匯出檔並存;類別線退場分兩次完成。
- (b)同檔名直接換內容,索引建置最小改動只驗雜湊、不讀葉:網站的動作類別軸在規格 3 之前停擺;違反「不先動搜尋端」。

### 匯出檔要不要格式版本號?

現行匯出檔沒有版本號,靠「說明」字串與原文/卡面雜湊擋過時;過時是內容層的,格式層(鍵名、欄位語意)改了只靠索引建置讀不到鍵才發現。

決定(2026-11-01):(a)加整數格式版本。

- (a)**加整數格式版本**(建議):頂層一個整數,欄位語意變就加一;索引建置(規格 3)比對不符即建置失敗,Python 參考評估器也讀它。代價:多一個要同步的數字。
- (b)不加:沿用現行;代價:格式改了而匯出檔沒重生時,失效是安靜的(鍵讀不到當作沒值)。

### 開葉門檻要不要留?

第二版的類別樹草案用「≥10 框才開葉」當門檻(與「沒有框的葉不留」並列);第三版只剩「全語料沒有命中的具名查詢不留」,具名查詢不互斥、不影響別的查詢。

決定(2026-11-01):(a)退場,建置期只檢查至少命中一張。

- (a)**退場**(建議):建置期唯一的門檻是至少命中一張(位置口徑見上一題);一個具名查詢值不值得開是站主的編輯判斷,拆解頁的目錄總覽列出三個位置的張數供判斷。
- (b)保留 ≥10 框當建置期檢查:代價:取り除く@お互いのフィールド(10 句)、破壊@お互いのフィールド(6 張)這類現有具名查詢要刪,或門檻要另設例外。

### 拆解頁、類別樹草案、檢驗摘要三個鏡像各怎麼辦?

決定(2026-11-01):(a)拆解頁留、類別總覽改成具名查詢總覽;草案退場、鏡像留作歷史;檢驗摘要留。

- (a)**拆解頁留、類別總覽分頁改成具名查詢總覽;草案退場;檢驗摘要留**(建議):拆解頁的「類別總覽」(已歸/未歸/不適用儀表板、每葉框架清單)改讀每框命中的具名查詢——每個具名查詢三個位置的框數/卡數、展開看框架,沒有「未歸」概念,動作對象照舊顯示;類別樹草案(`category_draft.py`、tree-draft.md)的用途是在歸葉模型下決定開不開葉(未歸聚合、所在分佈擬葉名),第三版沒有這些概念,停止重生、鏡像網址留作歷史;檢驗摘要照常加本規格的小節。代價:草案的「所在分佈擬葉名」這類找新具名查詢的視角沒有替代品,要的話以後從拆解頁總覽加。
- (b)草案也改寫成「目錄草案」(每個具名查詢的張數與例句):多一份和拆解頁總覽重疊的鏡像。

### 具名查詢命中要不要一輪 LLM 抽驗?

地圖約束「新欄各做一輪 LLM 抽驗」。本規格沒有新欄:動作對象是改讀、驗收是全語料結果不變;具名查詢的命中語意變了(不互斥、預設葉取消、所在讀取自來源),變動的葉與張數試跑已逐葉歸因(31 葉不同、97 葉預設取消,原因三種)。

決定(2026-11-01):(a)命中變動的框做一輪(100 卡 4 批加複檢,存 `llm-check/queries-round1`);動作對象結果不變就不抽。

- (a)**命中變動的框做一輪**(建議):依「命中集合與舊歸葉不同」分層抽 100 卡 4 批加複檢(慣例),錯誤類型沿用類別線的(漏收/誤收/位置),存 `llm-check/queries-round1`;動作對象改讀後全語料結果不變就不抽,有變的逐卡說明。代價:一輪的工。
- (b)不抽,只靠試跑逐葉歸因:省一輪;代價:試跑歸因的是「為什麼和以前不同」,不是「新的命中對不對」。

### 玩家「相對」與「無」在述詞裡怎麼用?

結構化區域的玩家值域是 自分/相手/お互い/相對/無;第二版的葉不能宣告 相對 與 無。

決定(2026-11-01):(a)留在值域、述詞可選、具名查詢不宣告、編譯不折值。

- (a)**留在值域、述詞可選、具名查詢不宣告**(建議):目錄裡的區域條件只寫 自分/相手/お互い 或不寫玩家(不寫=不看玩家);使用者自建述詞可以選 相對(持ち主の墓地)或 無(沒寫玩家);編譯不折值。代價:介面(規格 4)要解釋這兩個值。
- (b)編譯與匯出時把 相對 折成 無:少一個值;代價:持ち主の 這條資訊丟掉,規格 1 記它是白記。

### 詞元節點的述詞含不含否定框架?

試跑把詞元節點編成「詞元=X 且 極性類=肯定」(可能視同肯定),否定框架只在 詞元(耐性)/詞元(限制) 節點;一般否定(送らず、戻さず,600 框)兩邊都不在。

決定(2026-11-01):(a)詞元節點 = 詞元=X 且 極性 ∈ {肯定, 可能}。

- (a)**詞元節點 = 詞元=X 且 極性 ∈ {肯定, 可能}**(建議):張數與試跑一致(101 個詞元節點全部不變),一般否定只能由使用者自建述詞(否定形=一般)查到;耐性/限制節點照舊是否定形的兩個值集合。
- (b)詞元節點含全部極性:「破壊」會連 破壊されない 一起收;代價:101 個詞元節點張數全變,「做什麼」和「不被怎樣」混在一起。

### 測試接縫就這四個嗎?

決定(2026-11-01):(a)沿用框架抽取、目錄、匯出三個既有接縫,新增參考評估器一個。

- (a)**沿用三個既有接縫,新增參考評估器一個**(建議):框架抽取(一句原文 → 框架清單,回指改讀在此斷言)、目錄(一句原文 → 每個動作框架命中的具名查詢名清單,取代歸葉的 classify)、匯出((效果句與框架、命中、目錄、卡面)→ 匯出文件與問題清單)、參考評估器((述詞, 匯出的框列)→ 命中與否;規格 3 的 JS 評估器用同一組例子)。動作對象照舊在匯出接縫斷言(匯出的框列帶動作對象欄)。
- (b)只在匯出接縫測:接縫最少;代價:回指與目錄的例子要包整條鏈才能斷言,一條例子壞了看不出是哪一層。

## Problem Statement

規格 1 把框架的論元結構化成片語、結構化區域、施事者、方式、否定形,但下游四支程式沒改:動作對象(patient.py,25 處正則)、回指(anaphora.py,32 處)、類別線(categories.py:head_nouns、keyword_in、polarity_class、place_literal)各自仍從字面猜中心詞、數量、區域、玩家,同一段字面四套判法;類別線的歸葉(規則表、樹序 first-match、並收、預設葉、每葉至少一框)把一個框架硬貼到一片葉,想多搜一個維度就得開葉;匯出檔只給每句的葉號,索引與介面拿不到框架的欄位,規格 3 的述詞評估器沒有東西可評估。站主要的是:類別樹變成具名查詢的目錄、每個節點就是一個述詞、框架可同時命中好幾個;匯出檔給每句的框架與欄位;下游改讀片語、正則式刪掉;動作對象的判定結果不變。

## Solution

1. **具名查詢目錄**:類別樹檔改成目錄——每個葉與詞元節點是一個述詞(同欄多值 OR、欄間 AND、單一框架上成立),大類與中類只是導覽;預設葉取消,詞元節點自己就是「詞元=X」;具名查詢不互斥。建置期檢查目錄(值域、名字唯一、詞元是正規詞元、至少命中一張),編不出來或過不了的列清單。
2. **參考評估器**:純 Python 的述詞評估器,讀匯出的框列算命中;目錄每個具名查詢的全語料張數(三個位置)與卡集合雜湊寫進匯出檔,規格 3 的 JS 評估器要對得上。
3. **下游改讀**:動作對象改讀片語(數量類、中心詞類、修飾語類、區域、指示詞旗標)、結構化區域,正則式刪掉,全語料判定結果不變或逐卡說明;回指改讀片語(片語結構化搬到回指之前);類別線的歸葉程式退場。
4. **匯出**:每句標記句帶它的動作框架,每框帶述詞會問的欄位(詞元、位置、極性、態、否定形、來源/目的/所在的結構化值、施事者、方式類、受事者與目的的中心詞/中心詞類/數量類/修飾語類、動作對象),三個位置都匯;沿用原文雜湊與卡面雜湊;加格式版本。舊匯出檔與歸葉程式留到規格 3 切換後刪。
5. **鏡像**:拆解頁的類別總覽改成具名查詢總覽;類別樹草案退場;檢驗摘要加本規格小節;具名查詢命中做一輪 LLM 抽驗。

驗收:動作對象全語料結果逐框相同(或逐卡說明);回指欄全語料逐框相同(或逐卡說明,確認後重新凍結);目錄全部具名查詢編得出、至少命中一張;具名查詢張數與試跑逐葉相同(差異逐葉說明);匯出決定性、入版控、雜湊擋建置;舊匯出檔逐位元組不變;全套測試通過。

## Implementation Decisions

**總則**

- 本規格在整合分支 `frame-args-v4`(規格 1 已交件)上做;框架線模組(片語、結構化區域、施事者、方式、否定形、封閉表)不改值,只有片語結構化的執行位置依[需要你決定的](#需要你決定的)搬到回指之前。
- 一個意思一個地方:玩家詞、區域詞、量詞、中心詞類、封閉值域的表只有框架線那一份;下游改讀封閉表與片語欄,不再有第二份正則式或字面表。
- 字彙:述詞欄位名、值、目錄鍵名、匯出鍵名用 GLOSSARY 的詞;匯出的鍵沿用 frames.json 已有的拼法(框架已有的鍵照抄),新鍵依封閉表模組的常數名。玩家一律 自分/相手/お互い/相對/無(舊類別檔的 雙方 不再出現)。
- 處理順序:分詞 → 框架抽取(既有步驟 → 片語結構化 → 回指 → 結構化區域/施事者/方式/否定形/回指回填)→ 目錄(載入、檢查、命中)→ 匯出。過渡期舊的 類別 → 舊匯出 兩步照跑(見[需要你決定的](#需要你決定的))。

**具名查詢目錄**

- 目錄檔是現在的類別樹檔改寫(依[需要你決定的](#需要你決定的)的 (a):一次性機械改寫;改寫工具就是票 02 的編譯器,改寫完退場)。節點三種:大類(名、可選中類清單、子)、中類(名,只在大類清單宣告)、具名查詢(述詞、可選子、可選宣告的大類/中類)。詞元節點是帶子的具名查詢;葉是不帶子的具名查詢。
- 述詞的欄:詞元(單值,必填)、極性(值清單;省略=肯定與可能)、否定形(值清單)、來源/目的/所在(各一清單,每項 (玩家或不限, 區域七值);任一項命中即中——同欄多值 OR)、受事者中心詞(字串清單,尾綴比對,任一段任一值中)、目的中心詞(同)。本規格先開這幾欄(試跑用到的),施事者、方式類、動作對象、數量類、修飾語類、中心詞類、態、位置的欄本規格不在目錄裡用,但參考評估器全部支援(規格 3 的使用者述詞要用)。
- 命名:節點名由述詞機械組出,寫法沿用第二版(詞元;←來源、→目的、:來源→目的、@所在;玩家前綴連寫 自分/相手/お互いの;:中心詞(多個以 / 並列);→目的中心詞;否定形集合等於耐性集合寫 (耐性)、等於 {不可能} 寫 (限制))。組不出名字的述詞(用了本規格沒給命名規則的欄)建置失敗、列清單;本規格不給命名規則的欄,以後要進目錄時先補命名規則。
- 檢查(違反即建置失敗、列全部違反處):名字全目錄唯一;每個大類至少一個具名查詢;宣告的大類/中類存在、中類不與同大類的詞元節點同名;詞元是框架抽取產得出的正規詞元(沿用既有判準);每個值在值域;節點名不含網址路徑分隔符;每個具名查詢在全語料至少命中一張(位置口徑依[需要你決定的](#需要你決定的))。歸葉時代的「同詞元的葉不被前面較寬的葉蓋掉」「目的與目的關鍵詞不疊在一葉」隨不互斥一起退場。
- 命中:每個動作框架 → 命中的具名查詢名清單(目錄序),三個位置都算;大類/中類的命中是底下的聯集,由樹推得、不另存。這是取代 frame_categories.json 的中間產物,給拆解頁總覽與 LLM 抽驗讀。

**參考評估器**

- 一個純 Python 函式:(述詞, 匯出的框列)→ 命中與否。語意:欄間 AND、同欄多值 OR、全部在同一框上;區域欄比 (玩家, 區域) 清單任一項(述詞沒寫玩家就不看玩家);中心詞比尾綴;其餘欄相等。讀的是**匯出的框列**(不是 frames.json 的框架),和規格 3 的 JS 評估器同一份輸入。
- 目錄張數:每個具名查詢三個位置各一個卡數,與卡集合的雜湊(sha1 前 16 碼,卡片密碼排序後連寫),寫進匯出檔的目錄;規格 3 的評估器對全語料重算要逐查詢相同。
- 評估器的例子(述詞 × 框列 → 真假)寫成一張 JSON 夾具入版控,規格 3 的 node 測試讀同一張。

**動作對象改讀**

- 受事者取法不變(依態:他動取對象、自動/受身取主語再主題、對象空而主題是此卡時取主題),判定規則不變,只換讀取來源:選擇類 ← 受事者片語任一段有數量且數量類不是 全部(取自子句的數量已在片語裡,子句字面比對刪掉),或回指欄的數量;中心詞類 ← 片語的中心詞類(卡/屬性/非卡/指示詞/玩家/位置/表示形式/其他)加一張小表把 屬性 類裡跟主人走的事件類(効果/発動/攻撃/召喚)分出來;全部類的區域 ← 結構化所在/來源與段的玩家/區域;全部類比對的卡種 ← 中心詞字面尾,種族/屬性/字段/卡片子類型/數值 ← 修飾語類(數值帶欄位/比較/數字),其他類修飾語視為比不了;か/と 的替代項 ← 段;指示詞 ← 段的指示詞旗標(已是語意判定);此卡/此卡以外/此卡的附屬卡/この効果 這幾條字面規則可留字面比對,但要改成比段(最後一段中心詞是 カード 且段字面以 このカード 結尾、任一段指示詞為真等)。
- patient.py 的正則式全部刪除;改讀後不另有字面表。
- 驗收:改讀前先凍結全語料每框的(判定值, 理由),改讀後逐框比,判定值差異 0;有差異時逐卡列出原文、前後值與理由,每條判定「改讀後更對」才留下、否則修規則,清單進票 Comments 與檢驗摘要的偏離清單。理由碼可變(讀法變了理由名跟著變),但要對得出對照表。

**回指改讀**

- 片語結構化搬到回指之前:框架抽取的既有步驟(主題延續、回填、列舉、推得、正規化)→ 片語結構化 → 回指解析 → 結構化區域、施事者、方式、否定形、回指回填。片語不讀回指,所以片語欄逐位元組不變;結構化區域等讀回指的照舊在後面。
- 回指的候選比對(限定語、中心詞、單複數、數量、玩家、區域)改讀回指字面與候選欄的片語段;指示詞判定改讀段的指示詞旗標;找法(対象/欄位/字面/事件的順序、範圍、選項)不變。anaphora.py 的正則式刪除,留不住的(事件名詞尾這類回指特有的)改成封閉表。
- 驗收:回指欄是既有鍵,全語料逐框比對(沿用剝鍵基準的工具,比的是整個回指欄);差異逐卡列出、每條判定更對才留下;確認後重新凍結基準(依建置產物文件的做法),票 Comments 寫數字。

**類別線退場**

- 歸葉程式退場:規則表、樹序 first-match、並收、預設葉、每葉至少一框、極性類對照、來源當所在、平假名邊界中心詞、子字串關鍵詞,連同框架類別檔與卡層彙總檔。留下的模組只做目錄載入、檢查、命名、命中與參考評估器。
- 過渡期(依[需要你決定的](#需要你決定的)的 (a)):舊歸葉程式與舊匯出照常跑、舊檔不變,它們的測試照過;規格 3 切換索引後一起刪。本規格新加的目錄模組不 import 舊歸葉程式。
- places.py 不是下游:它是框架線的區域辨識,留著;類別線與動作對象不再呼叫它去解字面,改讀結構化值。

**匯出**

- 新檔(名字依[需要你決定的](#需要你決定的)):頂層 說明、版本(整數)、目錄、卡面、句。目錄:每個節點一列(名、路徑、述詞或空、三個位置的張數、卡集合雜湊),目錄序。卡面:同現行。句:每句標記句一列(卡片密碼、段落、index、原文雜湊)加框列清單(依原文順序;框架對標記句的規則同現行:只有一段全屬那句、帶選項 n 屬 index-●n、沒有選項屬領起句;對不到即匯出失敗)。
- 框列的欄:詞元、位置、極性、態、否定形、來源/目的/所在的結構化值((玩家, 區域) 清單;含轉欄與回指回填寫進的,記號不匯)、施事者、方式類、表示形式值、受事者片語與目的片語各一個段清單(每段:中心詞、中心詞類、數量類、修飾語類集合)、動作對象(此卡/非此卡,皆非不帶)。全部可選鍵、只在有值時帶;字面(子句、受事者整段、修飾語字面、數量字面)不匯——拆解頁讀 frames.json,網站顯示是規格 4 的事,要字面時從這裡加欄。受事者片語取 對象→主語→主題 第一個有值的欄(與舊關鍵詞同),動作對象的受事者取法(依態)只影響它自己那一欄。
- 一句一行、決定性、入版控;原文雜湊與卡面雜湊算法同現行;統計(動作對象的框數與理由)照帶,建置報告照登。

**建置鏈與鏡像**

- 重跑鏈:分詞 → 框架 → 目錄 → 匯出(過渡期後接舊的 類別 → 舊匯出);任一步失敗停下。建置產物文件的表加新檔與重生指令。
- 拆解頁:類別總覽分頁改讀命中清單(每個具名查詢三個位置的框數/卡數、展開看框架;大類/中類是聯集),已歸/未歸/不適用儀表板拿掉;卡片拆解分頁每框列命中的具名查詢名與動作對象;照原網址重新發布。
- 類別樹草案停止重生,鏡像網址留作歷史;檢驗摘要加「具名查詢目錄」一節(改寫前後逐葉張數、不留清單、LLM 一輪結果、偏離);批次檔(LLM 抽驗)的類別線改讀命中清單分層。
- GLOSSARY:動作類別第三版段補目錄檔形狀、不留的位置口徑、詞元節點的極性、命名規則;具名查詢條補中心詞尾綴比對與「編不出來列清單」;動作對象條補「改讀片語,判定不變」;框架述詞條補參考評估器與匯出檔是它的輸入。ADR-0018 Consequences 補匯出檔名與「Python 參考評估器是 JS 評估器的對照」一句;ADR-0017 不改。

**給規格 3 的對照(交件時寫進 handoff)**

- 索引編碼讀匯出檔的框列,欄位與值域就是上面那張表;具名查詢目錄(名、路徑、述詞、張數、雜湊)進 VOCAB 的類別部分。
- JS 評估器的語意與例子夾具:參考評估器那一節;全語料逐查詢張數與雜湊要相同。

## Testing Decisions

- 接縫依[需要你決定的](#需要你決定的)的裁定(建議四個):框架抽取、目錄、匯出、參考評估器。好的測試只看接縫輸出的欄位(回指欄、命中的具名查詢名清單、匯出框列的欄、評估結果),不斷言正則式、候選、樹怎麼存、編譯中間態。
- 框架抽取:回指改讀的每個句型一條例子(限定語相符/不符、單複數、數量在子句、玩家與區域、指示詞是修飾語不回指),修規則前先補會失敗的例子;片語欄不變由剝鍵基準的全語料測試守。先例:`test_frames.py`、`test_v4.py`。
- 目錄:一句原文 → 每個動作框架命中的具名查詢名清單;真目錄的例子一個句型一條(不互斥:相手フィールドのモンスターを破壊 命中 破壊:モンスター、破壊@相手フィールド、破壊@フィールド;所在取自來源:手札・墓地から選ぶ 命中 選ぶ@墓地;否定形:破壊されない 命中 破壊(耐性));機制(同欄多值、欄間 AND、尾綴、不看玩家)以測試小目錄驗,經同一接縫的目錄參數。目錄檢查(名字撞、表外值、不是正規詞元、沒命中)各一條。全語料「每個具名查詢至少命中一張」寫成測試,缺輸入時 skipTest 並印原因。先例:`test_categories.py`(154 條,整批依新語意改寫,不保留歸葉的預期)。
- 匯出:合成幾張卡的標記句經真的組裝、框架抽取、目錄,斷言匯出框列的欄(含動作對象)、目錄列的張數與雜湊、原文/卡面雜湊、問題清單;決定性(同輸入兩次逐位元組相同)。先例:`test_export.py`(120 條;舊匯出的測試在過渡期保留,規格 3 刪)。
- 參考評估器:述詞 × 框列的夾具一張(每個欄一組正反例、同欄多值、不看玩家、尾綴不中前綴),Python 測試讀它;規格 3 的 node 測試讀同一張。
- 動作對象:凍結全語料判定(值, 理由)後逐框比對寫成測試(基準檔缺時 skipTest);既有的動作對象行為例子全部照過(它們在匯出接縫)。
- 全語料兩件事寫成測試:剝鍵基準(片語與既有欄)差異 0——回指欄刻意改了時重新凍結;舊匯出檔逐位元組不變(過渡期)。
- 全套:effect-tokenize 全套、node 測試、script/* 五套;三步鏈後 data/ 只有新檔的差異。
