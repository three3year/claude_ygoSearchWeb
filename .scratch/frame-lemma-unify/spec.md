# Spec: 動作詞元統一——態歸一、縮寫歸一、補語不併、態欄

Status: ready-for-agent
Date: 2026-10-27

上游是框架第三版論元(`.scratch/frame-args-v3/`,2026-10-19 票 09 交件)與類別樹票 06 的裁定關卡(`.scratch/action-categories/issues/06-tree-draft-and-ruling-gate.md`,2026-10-27 resolved)。票 06 草案的「同一動作兩個詞元」一節列了 12 組同一個動作被框架抽取記成不同詞元的情形,站主裁定「現在就回框架線統一」、哪幾組統一與統一成哪個詞元在框架線的票決定。本規格是 2026-10-27 /grill-with-docs 的定案;CONTEXT.md 已於 grill 時新增「動作詞元」「態」兩個詞條,ADR-0016 與本規格同時寫。

## 需要你決定的

### 其他折疊的 N になる/となる 詞元也照 なる→する 歸一嗎?

決定(2026-10-27):(a)照同一條規則歸一——全部折疊的 N になる → N にする(態 自動)、N となる → N とする(態 自動);不留例外清單。

grill 點名的是 倍/半分/同じ になる 與裸 になる。同一條「なる 是 する 的自動態」的規則套到全部折疊詞元時,還有這些會改名:対象になる 140、攻撃対象になる 11、直接攻撃になる 11、素材になる 9、無効になる 8、効果になる 5、同じ効果になる 1、チューナーになる 1、攻撃可能になる 1、S素材になる 1,與 となる 系的 素材となる 18、効果となる 1、合計分となる 1,合計約 210 框。

- (a)照同一條規則歸一(建議):対象になる → 対象にする(態 自動)、直接攻撃になる → 直接攻撃にする(態 自動)、素材となる → 素材とする(態 自動)。規則一句話說得完,不留例外清單。代價:効果にする、チューナーにする 這幾個名字原文沒有這種寫法(各 1〜5 框),拆解頁讀起來生硬。
- (b)只動 grill 點名的組:倍/半分/同じ/裸 になる 與 無効化。代價:同一條規則有例外清單,対象になる 與 対象にする 仍是兩個詞元、類別線得並排。

### 態差異的八組要不要統一成一個詞元?

決定(2026-10-27):統一到他動形,框架加「態」欄。

- (a)不統一,維持各自詞元,類別線用中類並排。
- (b)統一到他動形,框架加「態」欄(他動/自動/受身)。
- (c)只統一 無効化→無効にする。

### 數值升降組統一成哪個詞元?

決定(2026-10-27):アップ/ダウン(上げる/上がる→アップ、下げる/下がる→ダウン);アップ/ダウン 本身不分自他,態由受事者的助詞判。

- (a)アップ/ダウン:卡文主流寫法、類別樹現有葉名不動;「統一到他動形」在這組是例外。
- (b)上げる/下げる:照他動形原則;アップ 1,038 框改名、葉名全改。

### 「態」欄填在哪些框架上?

決定(2026-10-27):三值一欄(他動/自動/受身);受身接現有的被動旗標、全語料;自動/他動只在被統一的詞元上填,其餘框架空。

- (a)三值一欄;受身全語料、自/他只在統一組。
- (b)三值一欄,全部動作框架都填(詞典逐詞登記自他)。
- (c)受身照舊用被動旗標,另加自/他二值的態欄。

### 縮寫與全名統一成哪一邊?

決定(2026-10-27):縮寫 A召喚、L召喚、L素材,與既有 S召喚/X召喚/P召喚 同一體例。

- (a)縮寫。
- (b)全名 アドバンス召喚、リンク召喚、リンク素材。

### 值黏在詞元上的那組怎麼統一?

決定(2026-10-27):種族/屬性/数値 不併入詞元,值留目的欄。

- (a)不併入,詞元記 になる/にする,值留目的欄。
- (b)併成屬性類名 属性になる/種族になる。
- (c)不動。

### 「不併入」的判準劃到哪裡?

決定(2026-10-27):補語是封閉值域字面或屬性名詞收尾時都不併(含 レベルになる、守備力になる、カード名になる、エンドフェイズになる),狀態/角色詞照舊併。

- (a)封閉值域字面與屬性名詞收尾的補語都不併。
- (b)只改已定的四類:種族/屬性/表示形式/数値。

### 表示形式要不要一致化?

決定(2026-10-27):也不併,詞元 にする、目的 裏側守備表示(票 06 已裁的表示形式三葉交類別線跟進改讀目的欄)。

- (a)維持併入。
- (b)也不併。

### 直接攻撃 要不要自成詞元?

決定(2026-10-27):自成詞元;直接攻撃できる/できない 改記 直接攻撃。

- (a)自成詞元。
- (b)維持 攻撃,直接 當修飾。

### 前面有 攻撃 的 宣言 一律記 攻撃宣言?

決定(2026-10-27):一律記 攻撃宣言,不分述語形;宣言 只剩真的宣言(カード名を宣言する)。

- (a)一律記 攻撃宣言。
- (b)不動。

### 「S召喚を行う」要不要統一成該召喚詞元?

決定(2026-10-27):不動,留在 處理程序 › 行う:召喚。

- (a)對象是「〜召喚」時詞元記該召喚。
- (b)不動。

- (b)本規格連類別樹一起改。

- (a)差異清單加回歸例子,不跑 LLM 檢驗。
- (b)受影響的卡另跑一輪 LLM 檢驗。

決定(2026-10-27):立 ADR-0016「動作詞元正規化到他動形、態另成框架欄位」,與本規格同時寫。

## Problem Statement

站主在類別樹草案看到同一個動作被框架抽取記成不同的詞元,類別樹只能把它們放在同一大類底下並排,總覽頁讀起來一件事分兩處、門檻也被分散(攻撃宣言(限制) 只有 2 框開不了葉,另外 21 框記在 宣言 底下)。草案列出 12 組:

1. **態不同的同一動作**:他動/自動(戻す 1,231/戻る 111、上げる 103/上がる 34、下げる 71/下がる 11)、なる/する(倍になる 88/倍にする 10、半分になる 82/半分にする 42、同じになる 75/同じにする 21、になる 303/にする 113)、能動/受身(無効にする 750/無効化 384——無効化 全是 無効化される)。
2. **縮寫與全名**:アドバンス召喚 57/A召喚 29、リンク召喚 39/L召喚 94、リンク素材にする・とする 67/L素材にする・とする 56;分詞殘片 そのX素材とする・にする 18。
3. **值黏在詞元上**:N に なる/する 的補語併入詞元的規則把種族/屬性值(闇属性になる 7、ドラゴン族になる 4…十幾個 1〜7 框的詞元)、属性になる 21、数値になる 25、表示形式(裏側守備表示にする 110 等五個)、レベルになる 16 也併了,開不了葉、也沒有一個「變成什麼」的欄位可讀。
4. **動作名切錯**:「攻撃宣言できない」記成 宣言(21 框;動作框架已知未修第 8 項),「直接攻撃できる/できない」記成 攻撃(94/34 框)。
5. **行う:召喚**(S召喚を行う 記成 行う):站主裁定不動。

框架現在把態記在詞元裡(受事者在自動句是主語、他動句是對象),沒有一個欄位說「這是誰動手」。

## Solution

框架線把**動作詞元**正規化,並加一欄**態**:

1. **態歸一**:同一個動作的他動/自動/受身是同一個詞元,以他動形為名,差別記在新欄「態」(他動/自動/受身)。數值升降以卡文主流的 アップ/ダウン 為名。
2. **寫法歸一**:縮寫與全名、分詞殘片是同一個詞元,以現行官方縮寫為名。
3. **補語不併**:N に/と なる/する 的補語是封閉值域字面或屬性名詞收尾時不併入詞元,整段留在目的欄;狀態/角色詞照舊併。
4. **動作名完整**:攻撃+宣言 一律是 攻撃宣言;直接攻撃 自成詞元。
5. 態欄的受身接現有的被動旗標(全語料),自動/他動只在被統一的詞元上填;其餘框架空。

拆解頁同一張表多一格「態」;詞元欄是正規形,原文字面仍在子句欄。類別樹只做讓既有測試綠的最小改名,其餘跟進寫成清單交類別線另開票。

## User Stories

1. 作為站主,我要「このカードは墓地に戻る」與「このカードを墓地に戻す」的詞元都是 戻す、態分別是 自動 與 他動,這樣總覽頁一個節點收齊「回到」。
2. 作為站主,我要「攻撃力は３００アップする」的詞元是 アップ、態 自動,「攻撃力を３００アップする」是 アップ、態 他動,「レベルを１つ上げる」是 アップ、態 他動,「レベルが１つ上がる」是 アップ、態 自動,這樣升降只有 アップ/ダウン 兩個詞元。
3. 作為站主,我要「攻撃力は倍になる」的詞元是 倍にする、態 自動,「攻撃力を倍にする」是 倍にする、態 他動,半分、同じ 同理,這樣倍化/減半/相同各一個詞元。
4. 作為站主,我要「受ける戦闘ダメージは０になる」的詞元是 にする、態 自動,「相手のLPを１００にする」是 にする、態 他動,這樣數值改變只有一個詞元,誰變由態說。
5. 作為站主,我要「そのモンスターの効果は無効化される」的詞元是 無効にする、態 受身,「効果は無効化されない」是 無効にする、極性 否定、態 受身,這樣無效只有一個詞元、耐性仍由被動否定判得出。
6. 作為站主,我要「このカードを…として扱いアドバンス召喚できる」「リンク召喚した場合」「リンク素材にできない」的詞元是 A召喚、L召喚、L素材にする,這樣與 S召喚/X召喚/P召喚/X素材とする 同一體例。
7. 作為站主,我要「そのX素材とする」的詞元是 X素材とする,その 不黏在詞元上,這樣分詞殘片不再製造詞元。
8. 作為站主,我要「ターン終了時まで宣言した属性になる」的詞元是 にする、態 自動、目的 宣言した属性,「このカードは闇属性になる」是 にする、目的 闇属性,這樣「變成什麼」在目的欄讀得到。
9. 作為站主,我要「モンスターを裏側守備表示にする」的詞元是 にする、態 他動、目的 裏側守備表示,「守備表示になる」是 にする、態 自動、目的 守備表示,這樣表示形式與屬性同一種讀法。
10. 作為站主,我要「合計した数値になる」「同じレベルになる」「元々の守備力になる」「エンドフェイズになる」的詞元都是 にする、補語整段留目的欄,這樣「值」與「屬性」一律在欄位、不在詞元。
11. 作為站主,我要「〜を対象とする」「効果を無効にする」「融合素材とする」「攻撃対象にする」「リリースにする」照舊併入詞元,這樣狀態/角色詞的詞元不變、既有的葉不動。
12. 作為站主,我要「攻撃力を０にする」的目的仍是 ０、詞元 にする,這樣數字留目的欄的既有做法與不併判準是同一條原則。
13. 作為站主,我要「攻撃宣言できない」「攻撃宣言できず」「攻撃宣言した」「攻撃宣言時」的詞元都是 攻撃宣言,「カード名を宣言する」仍是 宣言,這樣攻撃宣言(限制) 的框數收齊、真的宣言不被吃掉。
14. 作為站主,我要「相手プレイヤーに直接攻撃できる」的詞元是 直接攻撃、極性 可能,「直接攻撃できない」是 直接攻撃、極性 否定,「攻撃できる」仍是 攻撃,這樣「能直接攻擊」與「能攻擊」分得開。
15. 作為站主,我要「S召喚を行う」照舊是 行う、對象 S召喚,這樣本規格不動 行う。
16. 作為站主,我要「このカードは破壊されない」的態是 受身(接現有的被動旗標),「カードを破壊する」的態是空,這樣空代表「沒判」、不是他動。
17. 作為站主,我要態不改變受事者落在哪一欄——自動與受身的受事者仍在主語/主題、他動的仍在對象,這樣第三版論元的讀法不變。
18. 作為站主,我要 アップ/ダウン 的受事者既不是 を 也不是 は/が 時態留空,這樣判不出的不亂填。
19. 作為站主,我要拆解頁的框架表多一格「態」、詞元欄顯示正規形、子句欄仍是原文,這樣看到 にする 時往右一格就知道原文是 になる 還是 にする。
20. 作為站主,我要全語料重跑前後的差異逐框列出、每組詞元的框數對得上本規格的計數、沒有本規格以外的框架變動,這樣我知道沒有別處被波及。
21. 作為站主,我要每一組統一、每一種不併、每一種態的判法都有回歸例子,這樣之後改詞典或改規則不會把它們改回去。
22. 作為站主,我要受影響的卡再做一輪 LLM 挑錯,錯誤類型分得出「詞元錯」「態錯」「補語錯欄」,這樣統一與不併的規則有第三方看過。
23. 作為站主,我要類別線的既有 29 條測試在最小改名後照常通過、類別總覽的已歸/未歸/不適用差異逐項說得出原因,這樣類別線在它自己的票開工前不是紅的。
24. 作為站主,我要交件時附一份「類別線要改的事」清單並追記在票 06,這樣我知道類別線的票要裁什麼。

26. 作為推導層的作者,我要詞元對照與不併判準各是框架線的一份封閉表,這樣類別線與檢驗腳本讀同一份、不各自猜。

## Implementation Decisions

**詞元對照表(框架線的封閉表,原詞元 → 正規詞元、態)**

- 態歸一:戻る→戻す(自動);上げる→アップ(他動)、上がる→アップ(自動);下げる→ダウン(他動)、下がる→ダウン(自動);倍になる→倍にする(自動)、半分になる→半分にする(自動)、同じになる→同じにする(自動);になる→にする(自動);無効化(される)→無効にする(受身)。其他折疊的 N になる/となる 依[需要你決定的](#需要你決定的)。
- 寫法歸一:アドバンス召喚→A召喚;リンク召喚→L召喚;リンク素材にする/とする→L素材にする/とする;そのX素材とする/にする→X素材とする/にする(指示詞 その/この 一律不併入補語)。召喚法鏈與「・」並列(アドバンス召喚・特殊召喚した)各框架照樣對照。
- 動作名完整:攻撃+宣言 不分述語形(できない/できず/する/した/時)一律 攻撃宣言;直接+攻撃(できる/できない/する)一律 直接攻撃。
- 原詞元保留在框架的子句字面裡,不另加「原詞元」欄。

**態欄**

- 動作框架新欄「態」,值域 他動/自動/受身;取代現有的被動旗標(旗標的 True 即 受身)。約束框架不動。
- 受身:全語料,判法沿用述語錨點的被動判定;被統一組的受身形(戻される、無効にされる、アップされる)也是 受身。
- 自動/他動:只在對照表的統一組填。詞對(戻る/戻す、上がる/上げる、になる/にする…)由原詞元決定;アップ/ダウン 由受事者的助詞決定——對象欄有值(を)是他動,受事者在主語/主題(は/が)是自動,兩者都沒有時空。
- 其餘框架態是空;空是「沒判」。
- 拆解頁與 LLM 檢驗批次檔的框架表多「態」一格。

**補語不併判準(N に/と なる/する)**

- 補語**最後一個詞**是封閉值域字面(種族、屬性、表示形式、階段名、區域名、卡片子類型、傷害種類…)或屬性名詞(現有屬性主語清單:レベル、ランク、攻撃力、守備力、種族、属性、カード名、数、数値、Pスケール、リンクマーカー、合計…;本規格加 合計値、合計分)時,**整段補語不併**:詞元是 にする/とする(になる/となる 經態歸一也是 にする/とする,態 自動),補語原文字面進目的欄,與「補語是數字留目的欄」同一機制。
- 補語是狀態/角色詞(対象、無効、素材、融合素材、X素材、S素材、L素材、倍、半分、同じ、直接攻撃、攻撃対象、リリース、必要、代わり、効果、チューナー)照舊併。
- 現有的補語不吸收清單(全て、以上、以下、同名…)不變。

**拆解頁**

- 框架表的詞元欄顯示正規詞元,加「態」格;其餘欄位與淡色規則不變。照原網址重新發布。

**類別線的最小調整(只到讓既有測試綠、樹完整性檢查過)**

- 樹裡的詞元字串改成正規詞元(アドバンス召喚→A召喚、リンク召喚→L召喚、上げる/上がる/下げる/下がる 的葉併入 アップ/ダウン 節點、L素材、倍/半分/同じ/裸 になる 的葉併入 にする 形節點);無効化 節點與 無効化(耐性) 節點併入 無効にする 與 無効にする(耐性)(耐性由被動否定判,改讀態=受身);消失的詞元節點刪除。葉的條件、中類、大類都不動。
- 類別線讀被動旗標的地方改讀 態=受身。
- 既有 29 條類別歸組測試的預期值隨詞元改名同步;不加新例子。
- 全語料重跑後比對已歸/未歸/不適用與每葉計數,差異逐項說明(表示形式三葉、属性になる 葉、攻撃宣言(限制)、直接攻撃 等會變成未歸或框數變動,是預期的、交類別線處理)。

**交給類別線的清單(交件時附在票 06 追記,類別線另開票裁)**

- 詞元節點正式合併/改名後,葉的重看:統一後過門檻的新葉(攻撃宣言(限制) 23 框、直接攻撃 可能 94/否定 34、戻す 自動 的葉…)。
- 關鍵詞條件要不要加讀目的欄:表示形式三葉、規則改寫 › 属性になる、數值 › 数値になる 的框架現在詞元是 にする、值在目的欄。
- 態要不要當葉條件(無効にする 的受身=舊 無効化、戻す 的自動=舊 戻る 要不要分葉)。
- 已歸/未歸計數的重新基準。

## Testing Decisions

- **接縫兩個,都沿用既有**(2026-10-27 站主確認):(1)框架抽取「一句效果句 → 框架清單」,斷言框架的(詞元、態、目的、對象/主語/主題、極性、位置),是本規格的主接縫;(2)類別歸組「一句效果句 → 每個框架的類別紀錄」,只用來確認最小改名後既有 29 條照常通過,不加新例子。不測對照表怎麼存、不測樹怎麼存。
- **好的測試**是句型層的回歸例子:一句原文、預期的詞元與態。修對照表或判準前先補一條會失敗的例子。
- **第一批例子**(框架抽取):戻る/戻す 兩態;アップ 的 を/は 兩態與判不出留空;上げる/上がる→アップ、下げる/下がる→ダウン;倍/半分/同じ になる→にする 形(態 自動);裸 になる→にする;無効化される→無効にする(受身)、無効化されない 極性否定;アドバンス召喚→A召喚、リンク召喚→L召喚、リンク素材にする→L素材にする;そのX素材とする→X素材とする;攻撃宣言できない/できず/した/時→攻撃宣言、カード名を宣言する 仍 宣言;直接攻撃できる/できない→直接攻撃、攻撃できる 仍 攻撃;闇属性になる、宣言した属性になる、裏側守備表示にする、守備表示になる、合計した数値になる、同じレベルになる、エンドフェイズになる 不併、補語進目的欄;対象とする、無効にする、融合素材とする、攻撃対象にする 照舊併;攻撃力を０にする 的目的仍是數字;破壊する 態空、破壊されない 態 受身;S召喚を行う 仍 行う。
- **全語料**:分詞鏈決定性重跑;與修前框架檔逐框比對,差異只落在本規格的幾型,每組的框數對得上 Further Notes 的計數;類別線重跑的已歸/未歸/不適用差異逐項說明。
- **前例**:test_frames(158 條,票 09 後)、test_categories(29 條)同一接縫、真的分詞器;測試檔放模組旁、沿用專案的 unittest。

## Out of Scope

- 類別樹的正式跟進(節點合併後的葉重看、關鍵詞讀目的欄、態當葉條件、門檻重算):交類別線另開票。
- 行う 的對象是召喚時折成該召喚(站主裁定不動)。
- 全部動作框架的自動/他動(詞典登記自他屬性)。
- 量條件的結構化、觸發事件軸、約束框架、搜尋介面與前端索引、試點層以外的語料。
- 直接攻撃になる/にする 這類狀態變化詞元要不要與 直接攻撃 合併(它們是「攻擊變成直接攻擊」,不是「直接攻擊」這個動作)。
