# 03 — 位置篩選前端落地

**What to build:** 使用者在搜尋介面的動作 Tag 區塊看到一組由值域正典生成的全域位置鈕(效果/代價),可以:(a) 什麼都不選——代價+效果都命中(空軸不設限,推翻裁定批1 的「預設只命中效果」,查詢引擎與 badge 繪製裡既有的三處成本位硬排除移除);(b) 與動作類別組合——tag 層 AND,同一個 tag 要同時滿足類別+位置(例:區域移動·終點除外 × 代價=「拿除外當代價」的卡);(c) 單獨使用——不選類別只點「代價」=找任何動作是代價的卡;(d) 條件進 hash 可分享(比照區域移動起點/終點慣例)。命中 badge 對代價位 tag 加「(代價)」標記,使用者讀得懂命中理由。發動型 LP 支付在選「代價」時命中。CONTEXT.md 槽位詞條的「搜尋第一期只命中效果」措辭同步更新,rulings 追記裁定批1 預設語意推翻。

**Blocked by:** 01 — 改名(鈕與 badge 顯示「代價」);02 — LP支付位置補判(LP支付的代價位命中依賴其資料)。
