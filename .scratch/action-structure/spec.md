# 動作搜尋:卡片結構(第一里程碑)

Status: ready-for-agent

## 需要你決定的

### 魔法、陷阱卡的①②③效果歸哪一種區塊?

決定(2026-11-07):(a)「怪獸效果」改名「編號效果」,魔陷與怪獸共用。

討論定的區塊種類是素材、召喚條件、卡片發動、靈擺效果、怪獸效果(①②③)。魔法、陷阱卡的編號效果(例:永續魔法的②)沒有對應的種類。

- (a)「怪獸效果」改名「編號效果」(建議):魔法、陷阱、怪獸的編號效果同一種;要分辨時看卡片大類。種類表不必為魔陷再開一格。
- (b)另開「魔陷效果」:和怪獸效果分開,但兩者的抽取規則完全相同,只差名字。

### 邊界補丁記什麼、雜湊算哪份文本?

決定(2026-11-07):(a)只記日文,雜湊只算官方日文。

參照實作是拆句表:記中日成對的原文子字串,雜湊是整團繁中加日文一起算。邊界補丁只管日文的區塊邊界,不做中文對位(中文標亮已延後)。

- (a)只記日文(建議):每筆是官方日文的切點(各區塊的原文子字串),雜湊只算官方日文。與拆句表不同:不記中文,中文卡文改動不會讓補丁失效。
- (b)照拆句表記中日成對:雜湊含中文。中文對位要等「結構轉中文」時才用得到,現在多記一份,中文一勘誤補丁就失效、要重判。

### 抽取用哪一份日文?

決定(2026-11-07):官方 DB 文本(補足情報所在的 `faq_info.json` 的 `card_text`,靈擺效果在 `pen_effect`),不用 `ja-JP.cdb`。

### 區塊要不要直接沿用效果句?

決定(2026-11-07):不沿用。區塊照本規格的規則自己切,不等於效果句。

### 舊式無編號卡的區塊邊界怎麼定?

決定(2026-11-07):規則切,多來源當驗收;沒有共識的由站主判,判完寫進邊界補丁來源檔。見[區塊切分](#區塊切分)。

### ● 列舉算一個區塊還是拆開?

決定(2026-11-07):一律留在區塊內,當段樹的分歧。

### 沒有官方日文的卡怎麼辦?

決定(2026-11-07):不納入抽取,歸[未解析](#查詢判斷),原因標「無官方日文」。由結構產生文本是之後的事,且只對反向檢查能完整還原的卡做。

### 抽取可以用哪些依賴?

決定(2026-11-07):只用 Python 標準庫;真的需要時建置期允許裝斷詞器,屆時另寫 ADR(現行零安裝原則在 ADR-0007)。

### 第一版用不用 LLM?

決定(2026-11-07):只用規則。長尾交給 LLM 補欄延到看過覆蓋報告之後再決定。

### 反向檢查怎樣算通過?

決定(2026-11-07):嚴格。由結構套句型模板產生的日文,正規化後與該段原文全等。

### 查詢可以只給條件、不指定卡嗎?

決定(2026-11-07):可以。只給條件時,判法是「卡片總表裡存在一張實卡,同時滿足查詢條件與物件條件」,化成指定卡的判法,只寫一套。

### 泛用卡怎麼處理?

決定(2026-11-07):泛用物件是條件式裡除大類、位置、控制方外沒有任何條件的物件。結果分特定、泛用、全部三組,可只查泛用;介面怎麼呈現之後再定。

### 解析不出的段怎麼呈現?

決定(2026-11-07):不靜默略過。字面含查詢動作詞、但結構不完整的段,另列「未解析」一組並附張數。

### 字段怎麼判定?

決定(2026-11-07):用 setcode。新建字段表(日文名、中文名、setcode),以上游 ja-JP `strings.conf` 起頭,不用 worktree `04-archetype-table` 的草稿。

### 不認得的「」名稱怎麼辦?

決定(2026-11-07):列進建置報告,該條件標未解析,建置照常通過。

### 前提裡的位置要不要寫進物件目前位置?

決定(2026-11-07):要。

### 條件式要不要加遊戲狀態原子?

決定(2026-11-07):要(回合方、階段、傷害步驟等)。

### 卡名包含和字段要不要分開?

決定(2026-11-07):分開。「「X」と名のついた」是字段;「カード名に「X」を含む」是卡名包含。

### 第一個里程碑包含什麼?

決定(2026-11-07):抽取、反向檢查、覆蓋報告、Python 版查詢判斷;不做前端。

### 標準卡怎麼寫才不會被結構重構弄壞?

決定(2026-11-07):寫成查詢層斷言(該命中、不該命中的查詢)加反向檢查通過,不存整份結構快照。

### 第一個里程碑什麼時候算完成?

決定(2026-11-07):10 張標準卡全過,並產出全庫覆蓋報告;不設數字門檻,站主看報告決定下一步。

### 測試接縫開哪幾個?

決定(2026-11-07):查詢判斷、反向檢查、區塊邊界三個。見[測試決策](#測試決策)。

### 開關預設與【子】項目?

決定(2026-11-07):條件段、推得的終點兩個開關預設全關。子代理從難例找到的加值項全部採用(從/到下放到對象線、物件表整卡共用、內嵌效果、前提可引用段、極性等)。

## 問題陳述

站主想用「動作」找卡:找「怪獸從牌組特殊召喚」的卡,或「黑魔導 → 墓地」——所有可能把黑魔導送進墓地的卡,包括從牌組把等級 5 以上怪獸送墓、破壞場上的怪獸、捨棄手牌等。

現在的網站只能比對卡文字串。字串比對分不出機制:「捨てる」和「墓地へ送る」、「時」和「場合」、取對象和選擇,在搜尋上都必須分開;同一個機制的被動、語序、舊式寫法又必須視為同一件事。main 上先前的做法(效果 tag、分詞、動作框架)把判定存成無法重算的字串或 LLM 結論,結構一改就整批作廢,站主判定太複雜而撤除。

## 解決方案

從官方日文卡文用規則抽出每張卡的卡片結構:卡片屬性、物件、名稱、區塊,區塊內是由段組成的段樹。每段記下一個動作的動作詞、對象、從哪裡到哪裡、誰做、極性、時機與前提。查詢是一組條件,一段同時滿足全部條件,這張卡就命中。

結構全由規則從原文重算,原文字面保留,每格可以留空或標「解析不出」。抽取的客觀驗收是反向檢查:結構套句型模板產生日文,要和原文全等。

這個里程碑只把結構做穩:抽取、反向檢查、覆蓋報告與 Python 版查詢判斷。前端、查詢輸入方式、中文標亮都在之後。

## 實作決策

### 來源與正規化

- 抽取的唯一文本是官方 DB 文本:每張卡以卡片密碼對 `faq_info` 的 `password`;主文取 `card_text`,靈擺效果取 `pen_effect`。`ja-JP.cdb` 不參與抽取。
- 沒有官方文本的卡整張標未解析,原因「無官方日文」。
- 官方文本的英數多為半形,`name_ja` 為全形:名稱比對前雙方做全半形折疊;結構裡保留原文字面。
- 中文卡名對應走卡片總表的 `name_zh` / `name_ja`(同一張卡的兩欄),不靠翻譯。

### 卡片結構的形狀

- **卡片**:卡片屬性表、物件表、名稱表、區塊列表。
  - **卡片屬性表**:每種屬性(卡名、字段、屬性、種族…)一張表,每列帶位置條件。例:滅びの黒魔術師 的卡名表是「滅びの黒魔術師:任何位置」與「ブラック・マジシャン:只在場上、墓地」。「ルール上〜としても扱う」的位置條件是任何位置。這是物件0(這張卡自己)的來源。
  - **物件表**:整張卡共用一張,不是每個區塊一份。
  - **名稱表**:名稱{id、字串、來源(「」引用或宣言)}。條件比的是名稱。
  - **區塊**:種類為素材、召喚條件、卡片發動、靈擺效果、編號效果(魔陷與怪獸的①②③共用);每個區塊有自己的段樹。
- 「1ターンに1度」這類次數限制不記。

### 物件

- 來源:新建;子集(物件X、條件、全部或選、選者、是否隨機);剩餘(X − Y);聯集。
- 剩餘:子集是「全部」時,剩餘 = 原條件且非(子集條件);子集是「選」時,剩餘不扣條件。
- 條件:條件式(見下節)。
- 初始位置:區域集合,分我方、對手。
- 區域:手牌、牌組(含牌組頂、牌組底)、額外牌組、場上(怪獸區、魔陷區、P 區、場地區、EX 怪獸區)、墓地、除外、掛在某物件下的素材;表側、裏側是狀態。
- 數量:1體、2枚まで…;可寫算式(合計、計數、×N、最低);單位可為「種類」。
- 物件種類除了卡,還有玩家、計數器、格位、宣言值。

### 條件式

- 且、或、非。
- 屬性 比較 值(等級 ≥ 5、種族 = 魔法使い族);屬性 比較 引用(等級 = 物件1.階級)。
- 卡名 ∋ 名稱或引用;卡名 ∈ 範圍(No.101～No.107)。
- 卡名包含(字串):比卡名表的子字串,帶位置條件,不看 setcode。
- 記載(名稱):卡文含「名稱」,含括號精確比對;查詢時直接掃全卡文,不建表。
- 字段(名稱):依字段表把名稱換成 setcode 後比卡的 setcode。「「X」と名のついた」是字段的舊式寫法。
- 存在(…)。
- 遊戲狀態:回合方(我方、對手)、階段、傷害步驟等;只出現在前提,不屬於物件。
- 曾被特殊召喚、召喚方式、持ち主、裝備或連結關係、可為物件Y的素材。
- **判斷卡 X 能否當某物件**:代入 X 的參數;遇到引用時,在被引用物件的候選卡裡找得到一組讓全部條件成立即可;卡名與屬性帶位置條件時,取做這個動作時物件所在位置(該對象線的「從」)。
- **泛用物件**:條件式裡除大類(卡、怪獸、魔法、陷阱)、位置、控制方外沒有任何條件。

### 段

| 格 | 內容 |
|---|---|
| 類別 | 條件、代價、效果、被代替、召喚手續、限制、修飾 |
| 動作詞 | 一個以上;多個為「且」 |
| 對象線 | 每條:物件、取對象標記、角色(施事、受事、被召喚、素材)、從、到 |
| 誰 | 我方、對手、任一方、雙方各自;或「物件.控制者/持ち主」 |
| 受方 | 例:誰受傷害 |
| 原因 | 戰鬥、效果(含誰的);作為X素材 |
| 從/到 | 區域,標來源:明寫、繼承、推得;到可帶表示形式 |
| 極性 | 做、不能、不會、可以、只能、必須 |
| 期間 | 持續、本回合、該戰鬥、到X為止 |
| 時機 | 立即、延遲(エンドフェイズ…)、每次X |
| 觸發形 | 時、場合、際(僅條件段) |
| 前提 | 條件式;可引用「段X已執行」「本回合發生過(段)」 |
| 被改的屬性 | 攻、守、等級… |
| 數量 | 例:支付 1000LP(此時段可無物件) |
| 可選 | 照日文判斷,不照中文 |
| 代替誰 | 指向被代替的段 |
| 原文範圍、原述語字面、態 | 保留字面,日後合併或拆動作詞只改對照表 |
| 穩定 id | 引用用,不用序號 |

- 動作詞:機制相同、寫法不同收成同一詞(被動也收);機制不同分開。S、X、L、融合召喚是特殊召喚的下位,查「特殊召喚」要含它們。
- 同義表收舊式用語;舊式「選択して」是取對象,不收成「選擇」。

### 段樹

- 序列由段、分歧、內嵌效果組成;序列帶連接:同時(し、)或先後(その後)。
- 分歧:方式(選1、各自可以、依前提)、選者、分支列表(每支有前提與內容)。● 列舉一律是分歧,不切區塊。
- 內嵌效果:綁定(自己 = 物件Y、我方 = 玩家P)與內容(一個區塊)。用於「以下の効果を得る」、改寫「自分」的效果、「」となる。
- 「重複到停為止」不結構化,只寫第一輪,標「未結構化」。

### 自動規則

- **位置**:
  - 照順序處理;處理完一段,把「到」寫回物件目前位置。
  - 「從」沒寫:先用物件目前位置(繼承),仍沒有才查推得表。
  - 前提「X が Y に存在する」(含「〜存在する状態で」)把 X 在該區塊的目前位置設成 Y。
  - 分歧時每支各一份位置;分歧走完,位置取各支聯集。
  - 條件段會更新位置;被代替段不更新;延遲段更新並帶標籤;極性非「做」的段不更新、不推得。
- **取對象標記**(標在對象線,不標在物件):
  - 同一次效果處理裡對著對象做的,標。
  - 延遲段不標;從條件段指回來的(そのモンスター)不標。
  - 序列中段出現條件段時,之後的段算延遲(リビングデッドの呼び声)。
- **推得表**:破壞未寫從 → 場上、到 → 墓地;解放 場上 → 墓地;捨棄 手牌 → 墓地。已知誤差:靈擺被破壞會去額外牌組。
- 前提裡關於物件的條件,併進該物件的條件(クリアクリボー)。
- 性質變更後,後續段讀改後的屬性;要追蹤的不只位置。

### 區塊切分

- 新式卡:依①②③、前言的官方換行、素材行、召喚條件句切;靈擺效果取 `pen_effect`。
- 舊式無編號卡:
  - 素材行、召喚條件句各自切出,其餘在句號處依開頭決定切不切。
  - 不切的續句開頭(候選):選択した〜、この効果は〜、このターン〜、その後〜、デッキから〜、そのモンスター/そのカード〜、この効果を発動するターン〜、「X」のこの効果は〜、ターン終了時まで〜、括號補註。
  - 要切的開頭(候選):また、、このカードが〜、〜時、、このカードは〜。
  - 判不了的(自分〜、相手〜、〜場合、、この効果で〜):照共識集調規則;仍不行的列給站主判。
  - 硬約束:補足情報的『』引用跨句號時,不得切斷。
  - 區塊種類由句型判;判不出歸編號效果,該段標未解析。
- **邊界補丁**:站主判過的舊卡邊界存成來源檔,規則先讀補丁。
  - 同拆句表:來源檔而非產物(ADR-0003)、一卡一筆、帶卡文雜湊、卡文變動整筆失效。
  - 與拆句表不同:只記官方日文的區塊切點(各區塊的原文子字串),不記中文;雜湊只算官方日文,中文勘誤不讓補丁失效。

### 字段表

- 以上游 mycard ygopro-database 的 ja-JP `strings.conf`(`!setname`)為日文名 → setcode 的起點。
- 中文名:從同一 setcode 底下的卡在繁中卡文裡的「」引用配對;配不到的列進報告。
- 上游缺漏或錯誤由本站補丁表覆蓋;補丁是來源檔。
- 字段表是建置產物,隨上游與補丁重算。

### 查詢判斷

- 查詢是一組條件:動作詞、從/到、對象(指定卡,或條件)、取對象、段類別範圍、兩個開關(條件段、推得終點,預設都關)。
- 一段命中須同時滿足:
  - 查詢的動作詞都在段內。
  - 從/到逐條對象線對得上;推得值只在開關開時算。
  - 查詢卡代入對象物件後條件式成立;只給條件時,卡片總表裡存在一張實卡同時滿足查詢條件與物件條件。
  - 段類別在範圍內:條件段看開關;被代替段只在查詢含「代替」時看,可經「代替誰」找到做代替的段。
  - 查詢含取對象時,只算有標取對象的線。
  - 極性預設只算「做」。
- 一張卡任一分支、任一段命中即命中。
- 結果分三組:特定、泛用(只靠泛用物件命中)、全部;另列未解析組(字面含查詢動作詞但結構不完整的段,含原因)。
- 介面:Python 純函式,輸入全庫結構與查詢,輸出命中的卡、命中段與分組。前端版本不在本里程碑。

### 反向檢查

- 結構 → 句型模板 → 日文,正規化後(空白、全半形)與該段原文範圍全等才算通過。
- 模板依句型撰寫;沒有模板的句型記「無模板」,算不通過、列進報告。

### 產物與建置

- 結構是建置產物:一卡一行 JSON、入版控;同一份輸入兩次建置逐位元組相同(時間與來源雜湊由 CLI 薄殼給進純函式,比照前端索引)。
- 只用 Python 標準庫;真的需要斷詞器時,先寫 ADR 再裝(建置期依賴)。
- 報告三份:覆蓋報告、反向檢查報告、區塊邊界比對報告;都附卡號,依原因分類。

## 測試決策

- 好的測試只驗外部行為:輸入官方卡文與卡片參數,看查詢結果或報告;不驗結構內部的格與形狀。
- **接縫一,查詢判斷**:輸入卡文與參數、輸出命中卡與命中段。標準卡的斷言全部測在這裡:每張標準卡記「該命中的查詢」與「不該命中的查詢」。字段表、同義表、位置推得、條件式都經由這個接縫測。
- **接縫二,反向檢查**:對全庫跑、產報告;句型模板另有少量固定測試。每張標準卡須通過反向檢查。
- **接縫三,區塊邊界**:舊卡的切法對三方共識集(拆句表、cdb 的①、英文三者效果數與邊界一致的卡)比對;不一致列進報告。這是唯一往下切的接縫,因為邊界有現成的大型驗收集,而接縫一測不出錯在哪個邊界。
- 標準卡 10 張:特異点の悪魔 32484853、大皇帝ペンギン 6836211、盗賊の七つ道具 3819470、The Fallen & The Virtuous 30271097、森羅の神芽 スプラウト 10753491、滅びの黒魔術師 59400890、深紅の剣士/バスター 50604072、神風的龍盟 7917970、偉魔祆現 327051、競鬥-交叉次元 56889。全部照官方 DB 文本重新核對(先前手寫依據的是 cdb 或中文);斷言由站主核可。
- 白き森のリゼット 61980241 是討論時試寫的例子,可加入斷言(命中「白き森 怪獸 牌組 → 手牌」、命中「墓地 → 手牌」、不命中「莉賽特 → 除外」)。
- 前例:Python 側各模組的標準庫 `unittest` 測試;純函式加 CLI 薄殼的做法見前端索引建置;前端查詢引擎 `runQuery(db, q)` 是同樣的純函式接縫。

## 不做的事

- 前端、查詢輸入方式、結果介面、三組結果怎麼切換。
- 在中文卡文上標亮命中段;等做「結構轉中文」時處理。
- 和既有效果類型篩選結合。
- 長尾交給 LLM 補欄。
- 以結構產生卡文取代官方顯示文字;將來若產生,只對反向檢查能完整還原的卡做,並標「本站生成」。
- 沒有官方日文的卡的抽取。
- 「1ターンに1度」等次數限制。
- 重複到停為止的完整結構。
