### 召喚手續、限制、修飾這三種段沒寫誰時怎麼算?

決定(2026-11-23):(a)召喚手續段的主動句算我方;限制段、修飾段算不限定。

Q3 只定了兩種:效果段、代價段的主動句算我方;條件段與被動句是不限定。召喚手續、限制、修飾這三種段類別當時沒講到。你試過的原型是 (a) 的做法。

- (a)召喚手續段的主動句算我方;限制段、修飾段算不限定(建議):召喚手續是持有這張卡的人去做的動作,和效果段同理;限制與修飾講的是卡本身的性質,沒有誰在做。
- (b)召喚手續段、限制段的主動句都算我方;修飾段算不限定:誰選我方、極性選限制時,「このカードは通常召喚できない」會直接命中。
- (c)三種都算不限定:篩誰時要打開「含不限定的」才查得到。

### 段類別的三個勾選全部取消時怎麼辦?

決定(2026-11-23):(a)至少要勾一個,只剩一個勾著時不能取消。

現有的查詢判斷在段類別是空的時候會退回預設(效果、代價、召喚手續),和畫面上「一個都沒勾」對不起來。

- (a)至少要勾一個:只剩一個勾著時不能取消(建議)。
- (b)可以全部取消:這時動作條件不生效,區塊裡顯示提示。

### 段類別「限制」在玩家介面要不要跟著「效果」一起算?

決定(2026-11-23):(a)跟著效果一起算。

段類別 限制 是召喚條件區塊裡極性不是「做」的段,例如「このカードは通常召喚できない」。Q14 的選項文字寫的是「召喚手續跟著效果一起算;限制、被代替、修飾留在進階模式」。你試過的原型卻把 限制 也跟著效果一起算。兩者不一致,要選一個。

限制段沒寫誰時怎麼算是另一題,見上面第一題。

- (a)跟著效果一起算(建議):玩家介面勾「效果」、極性選「限制」就查得到「不能通常召喚」這類卡,和召喚手續的處理一致。
- (b)留在進階模式:照 Q14 的選項文字。代價是這一輪的玩家介面查不到召喚條件區塊裡的限制。

### Q0 動作搜尋放上網站時,查詢邏輯放在哪裡?

決定(2026-11-16):(e)建置時由 Python 把卡片結構攤平成動作索引,網站只比對列;物件的候選卡預先算好、壓縮存。否決的做法與理由寫在 ADR-0013。

- (a1)只留 Python,本機開查詢伺服器:上線的站和雙擊開啟的站都用不到。
- (a2)只留 Python,預先算好所有查詢結果:組合數算不完;各欄分開算再取交集會錯。
- (b)用 JavaScript 把查詢整份移植:查詢有兩份,50 MB〔大小〕的結構也送不進瀏覽器。
- (c)先補規則到某個門檻再做搜尋:期間站上沒有動作搜尋,新形狀照樣會出現。
- (d)先凍結結構形狀再做搜尋:已知有新形狀要加,每次都要解凍。
- (e)攤平成索引,網站只比對。

## 問題陳述

動作搜尋現在只有 Python 的查詢判斷,沒有命令列也沒有網頁,玩家用不到,站主要驗證也得寫程式。

查詢能篩的只有動作詞、從、到、被動作的卡和幾個開關。卡片結構裡已經記了誰做的、落在誰身上、因為什麼,卻沒有對應的查詢欄,所以「對手抽牌時」「被戰鬥破壞時」「不會被對手的效果破壞」這類問題問不出來。

查卡網站是靜態網站,要能雙擊開啟、也要能放在 GitHub Pages(ADR-0007),不能在瀏覽器裡跑 Python,也載不動 50 MB 的卡片結構〔大小〕。

卡片結構的覆蓋還在提高:段解析出的比例是 66%〔覆蓋〕,之後每一輪規則回合都會出現新形狀。站主的要求是搜尋做好之後,不要因為規則補了新形狀就得一直改搜尋。

網站目前把每個查詢條件都寫進網址。當初是為了上一頁能回到前一次查詢,但網址變得很長很亂;動作條件再加進去會更長。

## 解決方案

建置時由 Python 把卡片結構攤平成動作索引:每條對象線一列,每一欄都是已經解讀完的值,物件的條件式換成候選卡。規則之後補了新形狀,只改攤平這一步。

查詢判斷改成讀攤平出來的列,並加上誰、受方、原因三個篩選欄、不限定開關,以及「被動作的是這張卡自己」。

查卡網站的側欄多一個「動作搜尋」區塊,和現有的卡片條件一起用。玩家選動作、從哪裡到哪裡、誰做的、被動作的是哪種卡,得到一份和一般搜尋長得一樣的清單,命中的效果會標出來。目前判斷不了的卡只在清單下方顯示一行張數。動作索引是另一個檔,第一次打開這個區塊時才載入。

網址不再帶查詢條件;上一頁、下一頁、重新整理照常回到對應的查詢。

## 使用者故事

以下「查」指在查卡網站的玩家介面操作;沒寫的選項就是預設(段類別勾效果與代價、極性「會做」、不限定開關關)。卡名後面引的是官方日文卡文。

1. 身為玩家,我要在側欄的「動作搜尋」區塊選一個動作(例如 破壞)後按搜尋,得到卡文裡有這個動作的卡,這樣不必自己猜關鍵字。
2. 身為玩家,我要動作條件和側欄其他條件取且(種族選龍族、動作選破壞、極性選抗性),這樣查得到有破壞抗性的龍族卡片。
3. 身為玩家,我要效果類型選「誘發即時效果(2速)」、動作選破壞時,只得到那個誘發即時效果本身會破壞的卡,而不是卡上另有一個破壞效果的卡,這樣動作條件和效果類型講的是同一個效果。
4. 身為玩家,我要效果文關鍵字、必發/選發和動作條件一起用時同樣落在同一個效果,這樣三種句層條件的行為一致。
5. 身為玩家,我要對不回網站上任何一個效果的段在第 3、4 條的情況下當作符合,這樣資料對不上時寧可多列也不漏。
6. 身為玩家,我要選「從 墓地」和動作「特殊召喚」,得到從墓地特殊召喚的卡;區域可以再指定是我方的還是對手的,這樣「從對手墓地特殊召喚」問得出來。
7. 身為玩家,我要選「到」某個區域,這樣「送去墓地」「加入手牌」「回到牌組」分得開。
8. 身為玩家,我要一次選兩個以上的動作時,只命中同一段裡全部都有的卡,這樣組合動作查得準。
9. 身為玩家,我要動作詞的選項把常用的直接列出來、其餘收在「更多」,這樣不必在一長串裡找。
10. 身為玩家,我要預設只查效果和代價,勾「觸發條件」後才查到 ヴェルズ・ナイトメア「相手がモンスターを特殊召喚した時」這種條件段,這樣「效果去做」和「發生時觸發」不混在一起。
11. 身為玩家,我要召喚手續(「EXデッキから特殊召喚できる」這類召喚方式)跟著「效果」一起算,這樣不必多懂一個類別。
12. 身為玩家,我要極性選「抗性」、動作選破壞時命中 神縛りの塚「効果では破壊されない」,預設的「會做」不命中它,這樣抗性和會去破壞的卡分得開。
13. 身為玩家,我要極性選「限制」時查到「不能」「只能」的句子(例如「攻撃できない」),召喚條件裡的「このカードは通常召喚できない」也在內,這樣限制類的效果查得到。
14. 身為玩家,我要預設的「會做」包含「このカードは直接攻撃できる」這種永續許可,這樣不必弄懂「可以」和「做」的差別。
15. 身為玩家,我要誰選「我方」、動作選抽牌時,命中沒寫主語的「デッキから１枚ドローする」這類效果,也命中 マグナム・ザ・リリーバー「自分は１枚ドローする」,這樣省略主語的卡不會查不到。
16. 身為玩家,我要誰選「對手」、動作選特殊召喚、勾觸發條件時命中 ヴェルズ・ナイトメア「相手がモンスターを特殊召喚した時」,這樣對手行動時的誘發查得到。
17. 身為玩家,我要誰選「對手」、動作選返回、勾觸發條件時,預設不命中 ホーリーナイツ・オルビタエル「…モンスターが手札に戻った場合」這種沒寫誰的條件段,把「含不限定的」打開後才命中,這樣我能自己決定要不要把「誰都算」的卡列進來。
18. 身為玩家,我要沒寫誰的被動句(EMスカイ・ピューピル「そのモンスターの効果は無効化される」)在篩誰時同樣只在「含不限定的」打開後命中,這樣不限定的規則只有一套。
19. 身為玩家,我要卡文寫「お互いに」、雙方各自做的效果(例如雙方各抽牌),誰選我方或對手時都命中,這樣寫得比我問的寬的卡算數。
20. 身為玩家,我要受方選「對手」、動作選傷害時命中 毒サソリの罠「相手に３００ダメージを与える」、不命中 溶岩魔神ラヴァ・ゴーレム「自分は１０００ダメージを受ける」,受方選「我方」時相反,這樣打對手和打自己分得開。
21. 身為玩家,我要原因選「戰鬥」、動作選破壞、勾觸發條件時命中 ミラクル・フリッパー「戦闘によって破壊された場合」與 アンクリボー「戦闘・効果で破壊され墓地へ送られた場合」,這樣寫「戰鬥或效果」的卡兩邊都查得到。
22. 身為玩家,我要同一個查詢不命中 リミット・リバース「そのモンスターとこのカードを破壊する」,這樣效果去破壞別人的句子不因為原因而混進來。
23. 身為玩家,我要同一個查詢預設不命中 ラヴァル・ランスロッド「このカードが破壊され墓地へ送られた時」,把「含不限定的」打開後才命中,這樣沒寫原因的被動句和沒寫誰的用同一個開關。
24. 身為玩家,我要動作選破壞、勾觸發條件、原因選「效果」時命中 蛇神降臨「戦闘以外で破壊された時」,原因改選「戰鬥」時不命中,這樣「戰鬥以外」歸在效果這一邊。
25. 身為玩家,我要原因選「效果」並指定是對手的、極性選抗性、動作選破壞時,命中 黒魔導強化「相手の効果では破壊されない」,也命中沒寫是誰的效果的 神縛りの塚「効果では破壊されない」,這樣不會被任何效果破壞的卡也算不會被對手的效果破壞。
26. 身為玩家,我要原因的選項不出現「戰鬥或效果」「戰鬥以外」,其餘原因(作為素材、召喚方式等)寫什麼就比什麼,這樣選項只有我會問的那幾種。
27. 身為玩家,我要「含不限定的」預設是關的,而且誰和原因共用這一個開關,這樣預設的結果只有寫明符合的卡。

## 實作決策

### 動作索引

- 動作索引在建置期由卡片結構攤平產出。解讀卡片結構的程式只有攤平這一處;查詢判斷與網站都只比對攤平出來的列。
- 列的單位是對象線:每條對象線一列;沒有線的段以段為一列。同一段的列互相認得(同一個段序號)。
- 攤平出來的列是完整的:查詢判斷現有的每個查詢欄、回傳的每個欄位都要從列得出來。網站的檔是這些列的序列化。
- 下表是玩家介面比對會用到的欄,網站的檔這一輪至少要有這些。表來自原型(分支 `prototype/action-player-ui`),欄的編碼方式由實作者定,欄的意思照表。
- 完整的列另外還有下表沒列的欄:段的識別(回傳命中段、取回原文用)、區塊種類、被改的屬性、代替的連結、取對象、受方的物件(現有規則「受方是被取對象的物件的段也算」要用)、物件是不是泛用物件、物件判不了的原因。這些欄這一輪寫不寫進網站的檔,由實作者依體積決定;下一輪進階模式會用到,同樣受 8 MB 的門檻管。

| 欄 | 內容 |
|---|---|
| 卡 | 這一列屬於哪張卡 |
| 段序號 | 同一段的列共用;用來判斷多個動作詞是否在同一段 |
| 效果 | 這一段對回前端索引的哪個效果句;對不回時留空 |
| 段類別、極性 | 照卡片結構 |
| 動作詞 | 段的動作詞,上位詞已經展開 |
| 誰 | 寫明的值、算我方、或不限定,三種分得開 |
| 受方 | 受方是玩家時記哪一方;受方是卡時不記 |
| 原因 | 原因的種類與哪一方;沒寫時分得出是被動句(不限定)還是主動句 |
| 做動作的線 | 這條線是做動作的一方而不是被動作的卡 |
| 從、到 | 區域與哪一方,子區域已算在上位區域內;推得的值要分得出來(玩家介面不算推得的值) |
| 被動作的卡 | 沒有物件、此卡、候選卡集合、判不了、代不進去,五種分得開 |
| 原文字面的動作詞 | 整段原文字面含哪些動作詞(經同義表);被動作的卡判不了時,用它決定這張卡要不要進未解析組 |

- 物件的條件式在建置時對卡片總表求值,存成候選卡集合。候選卡以對象線為單位算:同一個物件在不同線上、位置條件不同時,候選卡可以不同。內容相同的集合共用一份。小的集合存卡的清單,大的集合存位元集。
- 引用其他效果的節點另成一種列:引用它的卡、被引用物件的候選卡、指定的部分、是不是泛用引用、所在的效果。比對時先算每張卡直接命中的段,再沿這些列展開到底,走到走過的卡就停。解析不出的引用節點也有列,帶原文字面的動作詞,不展開。
- 解析不出的段另成一種列:卡、段類別、極性、原文字面含哪些動作詞(經同義表)、原因。無官方日文的卡另列一份清單。
- 未解析組的來源照現有查詢判斷,一種都不少:無官方日文的卡、解析不出的段、解析得出但對象線的物件判不了的段(物件解析不出、引用的物件找不到、異同判不了)、解析不出的引用節點、區塊種類判不出的區塊。每一種在列裡都要有對應的欄。回傳裡每一段的原因與原文,由完整的列加上卡片結構得出;網站的檔這一輪不帶原因與原文。
- 索引另帶三份表:動作詞、區域、原因值各自的清單與列數(介面的選項由它生成,比照 ADR-0008);字段與它的成員卡(「給條件」選字段時用,成員照卡片屬性表);卡的順序(對到前端索引的卡)。
- 未結構化的段、被代替段的處理照現有查詢判斷的規則,這一輪不改。
- 產物是獨立的一個 `.js` 檔,掛一個全域變數(ADR-0007),和前端索引分開,入版控。排版讓版控的差異讀得出來(比照前端索引的一卡一行)。同樣的輸入兩次產出逐位元組相同。
- 索引的建置吃四份輸入:卡片結構、卡片總表、效果標記表、前端索引。效果標記表提供每個效果句的日文原文(前端索引裡沒有日文),前端索引提供效果句的序號與卡的順序,兩者都是效果對應要用的。任何一份變了,動作索引要跟著重建;對不上時(卡不存在、效果句數不符)建置失敗。

### 比對規則

以下是這一輪新增的規則;沒提到的照現有查詢判斷。

- **誰**。查詢給我方或對手。段寫明了誰:寫的值和查詢相同,或寫的是同時含兩方的值(雙方各自),命中。段沒寫誰:效果段、代價段、召喚手續段的主動句算我方;其餘(條件段、被動句、限制段、修飾段)是不限定,不限定開關開才命中。
- **受方**。查詢給我方或對手,只比受方是玩家的段。受方是卡的段、沒有受方的段,在查詢給了受方時不命中。
- **原因**。查詢給原因的種類,可以再給是哪一方的。
  - 種類:寫的和查的相同命中;寫「戰鬥或效果」時查戰鬥、查效果都命中;寫「戰鬥以外」時查效果命中、查戰鬥不命中。其餘種類(作為素材、召喚方式、方法、規則)寫什麼比什麼。
  - 哪一方:查詢給了方,段的原因沒寫方時命中(寫得比查詢寬),寫了方就要相同或同時含兩方。
  - 沒寫原因:被動句是不限定,不限定開關開才命中;主動句不命中。
- **不限定開關**。預設關,誰與原因共用。只管「整欄沒寫」;寫得比查詢寬的不歸它管,一律命中。
- **這張卡自己**。查詢指定被動作的是此卡時,只命中物件是此卡的對象線。物件是一個條件式、而這張卡剛好滿足的,不算。和指定卡、給條件三者擇一。
- **給條件**。查詢側可用的條件種類照現有查詢判斷。網站的玩家介面只開放六種:大類、屬性、種族、等級、字段、卡名包含;判法是「滿足查詢條件的卡」與「這條線的候選卡」有交集。
- 誰、受方、原因是段的欄,比的是段;從、到、被動作的卡、取對象是線的欄,比的是線。一個查詢的全部條件要落在同一段,線的條件要落在同一條線,和現有規則相同。
- 未解析組照現有規則;段類別、極性的篩選對它照樣生效,誰、受方、原因的篩選對它不生效(解析不出的段沒有這些欄可比)。

### 查詢判斷

- `run_query` 的呼叫方式與回傳的形狀不變。內部改成兩步:攤平成列、比對列。
- 查詢多五個鍵:誰、受方、原因(種類與方)、不限定開關、這張卡自己。鍵名英文、值用 `GLOSSARY.md` 的詞,比照現有的鍵。沒給這些鍵時行為與現在相同。
- Python 的預設值不變(段類別 效果、代價、召喚手續;極性只算「做」;各開關關)。玩家介面的預設是網站那一層的事,見[玩家介面](#玩家介面)。
- 舊的讀法在重構期間留著當標準答案。刪除的條件:現有查詢測試全部通過新的路徑,而且在全庫上用一批查詢比過新舊兩條路徑、結果逐張相同。比對用的查詢清單與結果記在票的 Comments。之後舊的讀法刪掉,不留開關。

### 效果對應

- 每一段要對回前端索引的一個效果句,同一效果的判斷與標出命中的效果都靠它。
- 對法依序:區塊有①②③編號時,對到同一個來源(主文或靈擺效果)裡同編號的效果句;沒有編號時,看段的原文位置落在哪個效果句的日文原文裡;都對不上就留空。
- 有編號的區塊裡的段佔 73.6%〔區塊〕,其餘要靠原文位置。
- 內嵌效果裡的段算在它所在的區塊上。經引用的命中算在引用節點所在的效果上。
- 留空的段在「要同一個效果」的判斷裡當作符合,但不標出命中的效果。
- 建置報告列出留空的段數與卡號。做這一步的票回報比例,站主看過後決定要不要再補對法。

### 前端查詢引擎

- 現有引擎的輸入多一組動作條件、多一份動作索引;輸出照舊是命中的卡與每張卡命中的效果句,另加無法確認的卡(介面只顯示張數)。
- 沒有動作條件時,引擎不碰動作索引,結果與現在相同。
- 有動作條件時:卡要同時滿足卡片條件與動作條件。現有的句層條件(效果文、效果類型、必發/選發)和動作條件要落在同一個效果句;動作命中的段沒有對回效果時當作符合。
- 命中的卡是特定、泛用、經引用三組的聯集,不分組、不帶標記。泛用引用開關固定關。
- 無法確認的卡:未解析組裡同時滿足卡片條件的卡。句層條件對它不做同一效果的判斷。
- 排序照現有規則,動作搜尋不加排序鍵。
- 比對邏輯在 Python 和網站各有一份,都只比對列,不解讀卡片結構。兩份的一致由[測試決策](#測試決策)的檢查守住。

### 玩家介面

- 位置:側欄裡的一個可摺疊區塊「動作搜尋」,預設收起。
- 動作索引在兩種時候載入,載過就不再載:第一次展開這個區塊;或從瀏覽紀錄還原的查詢帶著動作條件(這時區塊可能是收起的)。其餘時候不載入。
- 欄位:動作(可多選)、從(區域與哪一方)、到(區域與哪一方)、被動作的卡(不指定、這張卡自己、指定一張卡、給條件)、誰、受方、原因(種類與哪一方)、段類別三個勾選、極性三選一、「含不限定的」。
- 選項由動作索引帶的表生成,HTML 不手抄。動作詞依列數排,前面一批直接顯示,其餘收在「更多」。原因的選項不列「戰鬥或效果」「戰鬥以外」。「給條件」的大類、屬性、種族按鈕由值域正典生成。
- 介面到查詢的對應如下。

| 介面 | 查詢 |
|---|---|
| 勾「效果」 | 段類別 效果、召喚手續、限制 |
| 勾「代價」 | 段類別 代價 |
| 勾「觸發條件」 | 段類別加上 條件(現有的條件段開關只在查詢沒給段類別時才有作用,所以這裡要直接把 條件 放進段類別範圍) |
| 極性「會做」 | 做、可以、必須 |
| 極性「限制」 | 不能、只能 |
| 極性「抗性」 | 不會 |
| 「含不限定的」 | 不限定開關 |

- 三個勾選至少要勾一個:只剩一個勾著時不能取消。
- 不露出、用固定值的:取對象(不限)、推得終點(關)、泛用引用(關)、代替(不看)、區塊種類(全部)、被改的屬性(不篩)、只查泛用(關)。
- 區塊裡要有文字說明「這裡篩的是被動作的卡,不是有這個效果的卡」。
- 結果畫面沿用現有的清單、分頁、排序與每頁筆數。命中的效果用現有標出命中效果句的方式加底色;動作條件不標到字。清單下方一行「另有 N 張無法確認」,不能點,N 是 0 時不顯示。
- 索引載入中按搜尋:顯示載入中,載完自動查。載入失敗:在區塊裡顯示說明,動作條件不生效,其他條件照常。
- 「清除條件」清掉動作條件。窄螢幕沿用現有側欄的摺疊;摺疊鈕的生效條件數把動作條件算進去。
- 這一輪沒有進階模式的入口。

### 網址與瀏覽紀錄

- 查詢狀態(卡片條件、動作條件、排序)不再寫進網址。每次搜尋在瀏覽紀錄新增一筆,狀態存在那一筆裡;上一頁、下一頁、重新整理時從那一筆還原條件並重查。
- 還原的查詢帶動作條件時,先載入動作索引再查。
- 存在瀏覽紀錄裡的狀態可能是舊版網站寫的:認不得的欄位或值忽略,其餘照常還原,不讓頁面壞掉。
- 網址帶著舊格式的參數時:不解讀,顯示首頁,並把網址上的參數清掉。
- 把條件寫成網址、從網址讀回條件的程式與它的測試一併移除,包括修復被轉傳弄壞的連結那一段。
- ADR-0010 的後果裡有一條講舊網址的處理;這一輪之後舊網址一律不解讀,那一條不再適用。ADR-0010 本身不改。

### 建置與門檻

- 動作索引有自己的建置入口,比照前端索引的建置:讀輸入、產出檔案、印報告;另有只驗證不寫檔的模式。
- 體積門檻:產物檔超過 8 MB 時建置失敗。門檻是一個設定值,測試可以用小的值驗「擋得住」。
- 時間門檻:卡片結構建置加動作索引建置,在站主的機器上不超過 2 分鐘。建置報告印出各階段花的時間。
- 候選卡的計算要加速:先把卡片總表按屬性、種族、等級、字段等建好索引,多數條件式不必逐張掃。
- 第一張做索引的票要回報體積與時間。任何一個門檻過不了就停下來,在票的 Comments 寫明數字,由站主決定。
- 建置報告:列數、各種列的數量、候選卡集合的數量與大小、產物體積、各階段時間、對不回效果的段。

## 測試決策

- 好的測試只驗外部行為:輸入官方卡文、卡片參數與查詢,看結果;或輸入查詢條件與合成資料,看命中的卡與效果。不驗列的編碼、不斷言 DOM 結構與 CSS class。
- **接縫一,查詢判斷(既有)**:`run_query`。[比對規則](#比對規則)全部在這裡驗,[使用者故事](#使用者故事)15 到 28、47 的規則從這個接縫驗(故事寫的是介面操作,測試用對應的查詢鍵)。現有的查詢測試不改、全部通過(故事 49)。
- **接縫二,動作索引建置(新增)**:輸入卡片結構、卡片總表、效果標記表、前端索引,輸出動作索引與報告。驗查詢判斷看不到的事:
  - 每一段對回哪個效果句(有編號、沒編號靠位置、對不回留空並進報告)
  - 候選卡集合還原出來是同一批卡
  - 超過體積門檻時建置失敗
  - 同樣的輸入兩次產出相同
  - 前端索引與卡片結構對不上時建置失敗
  - 故事 50、52、53 從這個接縫驗
- **接縫三,前端查詢引擎(既有)**:node 沙箱載入 `web/` 底下真實的前端檔,餵合成的卡片資料與一份小的動作索引。驗:沒有動作條件時結果不變(故事 36)、和卡片條件取且(故事 2)、同一個效果(故事 3、4、5)、清單收三組(故事 32、33)、命中的效果句(故事 34)、無法確認的張數(故事 35)、介面選項到查詢的對應(故事 10 到 14)、從瀏覽紀錄還原時認不得的欄位被忽略。
- **兩邊答案一致**:一組 Python 測試,用測試內建出來的卡片結構攤平成索引,同一批查詢分別交給 `run_query` 和 node 沙箱裡的前端引擎,命中的卡號與無法確認的卡號必須相同(故事 48)。查詢要涵蓋每個玩家介面的欄位;故事 6、7、8、29、30 的比對行為(從、到、多個動作詞同一段、指定一張卡、給條件)從這組測試驗。這組測試需要機器上有 node。
- 標準卡:規則票由實作者從下表挑卡寫斷言,在票的 Comments 列「待站主核可」。候選卡卡在票外的寫法時另挑替代卡,比照里程碑三的做法。

|---|---|
| 誰,寫明 | マグナム・ザ・リリーバー、ヴェルズ・ナイトメア |
| 誰,主動句沒寫 | パラレル・テレポート |
| 誰,不限定 | ホーリーナイツ・オルビタエル、EMスカイ・ピューピル |

## 不做的事

- 進階模式:分組與標記、未解析組的明細、日文原文與命中的段、六個原始極性、取對象、推得終點、泛用引用、代替、區塊種類、被改的屬性、只查泛用。下一輪。
- 規則回合的工作:里程碑三補票延後的三條規則、重複範圍與「」內容的解析、長尾寫法的補法。這一輪不動抽取規則,卡片結構的內容不變。
- 「只要不取對象」的查法。
- 受方是卡的比對。
- 物件是條件式、而這張卡剛好滿足時算進「這張卡自己」。
- 分享連結、「複製這次搜尋的連結」按鈕、舊連結的還原。
- 動作條件標到字。
- 查詢比遊戲狀態(回合方、階段):照舊只記不比。
- 結果依特定、泛用、經引用排序。
- 動作索引以外的資料瘦身(前端索引的大小不動)。

## 補充說明
