# 動作詞元統一 LLM 檢驗:子代理工作說明

你會拿到一份批次檔(`batch-<k>.md`):每張卡一節、每句效果句一段,列出**原文**與程式抽出的**框架**。動作框架一列長這樣:

`框架 n:[位置] 動作(極性・態=…)| 主題=… | 主語=… | 對象=… | 來源=… | 所在=… | 目的=… | 內容 | 子句=…`

態沒有值時不列「・態=」;主題/主語/所在沒有值時不列;格後的「(回填)」表示值是規則從前面的述語接過來的,「(推得)」表示值是規則依動作補的、原文沒寫。約束框架(`[約束 …]`)不是本輪範圍。

你的工作:**看原文,挑出動作框架的錯**,重點是本輪新規則(動作詞元的正規化、態、補語留目的欄),寫成 `findings-<k>.json`。

## 新規則的判準(以此為準,不要用自己的直覺改判)

「動作」欄是**正規化後的動作詞元**,不是原文字面——原文寫法在子句欄。正規化規則如下:

1. **態歸一**:同一個動作的他動/自動/受身是同一個詞元、以他動形為名,差別記在「態」:
   - 戻る → 戻す(態 自動);戻す 本身 他動;戻される 受身。
   - なる → する:「N に/と なる」的詞元是「N に/と する」、態 自動;「N に/と する」本身 他動(倍になる → 倍にする 自動、対象にならない → 対象にする 自動 否定、素材となって → 素材とする 自動、裸的「０になる」→ にする 自動、「相手のLPを１００にする」→ にする 他動)。原文沒有「効果にする」「チューナーにする」這種寫法是規格接受的代價,不是錯。
   - 無効化される → 無効にする(態 受身);無効にする 他動。
   - 數值升降以 アップ/ダウン 為名:上げる → アップ 他動、上がる → アップ 自動、下げる → ダウン 他動、下がる → ダウン 自動。アップ/ダウン 原文本身不分自他:**對象欄有原文 を 的值 → 他動;受事者在主語/主題(は/が)→ 自動;兩者都沒有 → 態空**。
2. **受身**:被動句(〜される、〜されない、送られた、選ばれた…)的態一律是 受身,不論詞元。
3. **其餘框架態是空**:不在上面幾組的詞元(破壊、送る、特殊召喚、選ぶ…)主動句的態空著是對的——空是「沒判」,不是錯。
4. **寫法歸一**:アドバンス召喚 → A召喚、リンク召喚 → L召喚、リンク素材にする/とする → L素材にする/とする;「そのX素材とする/にする」的 その 不併入詞元(→ X素材とする/にする)。
5. **動作名完整**:攻撃+宣言 不論述語形(できない/できず/した/する/時)一律 攻撃宣言;宣言 只剩真的宣言(カード名を宣言する)。直接+攻撃(できる/できない)一律 直接攻撃;攻撃できる 仍是 攻撃。「直接攻撃になる/にする」是另一個狀態變化詞元(直接攻撃にする)。
6. **補語不併**:「N に/と なる/する」的補語**最後一個詞**是封閉值域的字面(種族 ドラゴン族…、屬性 闇属性…、表示形式 裏側守備表示…、階段名 エンドフェイズ…、區域名、卡片子類型、傷害種類)或屬性名詞(レベル、ランク、攻撃力、守備力、種族、属性、カード名、数、数値、Pスケール、リンクマーカー、合計、合計値、合計分…)時,**整段補語不併入詞元**:詞元是 にする/とする,補語原文字面在**目的**欄(闇属性になる → にする 自動、目的=闇属性;このカードを裏側守備表示にする → にする 他動、目的=裏側守備表示、對象=このカード;宣言した属性になる → 目的=宣言した属性)。補語是狀態/角色詞(対象、無効、素材、融合素材、X素材、倍、半分、同じ、直接攻撃、攻撃対象、リリース、必要、代わり、効果、チューナー)時照舊併進詞元。補語是數字時(攻撃力を０にする)詞元 にする、數字在目的,這是既有做法。「エンドフェイズになる」記 にする+目的 エンドフェイズ 是規格接受的已知偏離。
7. **態不改變受事者落在哪一欄**:自動與受身的受事者在主語/主題、他動的在對象(このカードは手札に戻る → 主題=このカード、對象空;このカードを手札に戻す → 對象=このカード)。
8. 「S召喚を行う」照舊記 行う,不是錯。

## 錯誤類型(type 欄只能填這些字)

本輪新增(請優先檢查):
- `詞元錯`:動作欄不是上面規則該給的正規詞元(該歸一沒歸一、歸錯詞元、該併的狀態詞沒併、不該併的值/屬性被併進詞元、攻撃宣言/直接攻撃 沒收齊或收錯)。
- `態錯`:態的值不對(該 受身 沒記、自動/他動 反了、アップ/ダウン 的助詞判錯、不在統一組卻填了自/他)。
- `補語錯欄`:不併的補語沒進目的、進錯欄、目的字面多吃或少吃了(吃進述語的期間「ターン終了時まで」、吃進句子的對象…)。

既有類型(新規則以外看到明確的錯也可回報):`漏抽動作`、`論元抽錯`、`位置判錯`、`極性判錯`、`多抽(不是動作)`。

## 回報格式

寫 `findings-<k>.json`(UTF-8,k 與批次檔相同):一個 JSON 陣列,每筆
`{"card": 卡號(整數), "index": "①"/"②"/"效果外文本 0"…(句的標籤,照批次檔「### 句」後的寫法), "frame": 框架序(整數)或 null, "type": 上列之一, "reason": "一句話,引原文片段說明哪裡錯、應該是什麼"}`。

- 沒有錯就寫 `[]`。一個框架有多個問題各寫一筆。
- reason 用繁體中文,引原文照抄日文。
- 只回報有把握的錯;判準寫在上面,和判準不同的地方照判準,不要改判準。拿不準的在 reason 開頭寫「(待確認)」。
- 不要改動批次檔或其他檔案。
