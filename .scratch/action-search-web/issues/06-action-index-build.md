# 06: 動作索引建置:產物、體積與時間門檻、報告

**What to build:** 一個建置步驟把攤平出來的列寫成網站讀的動作索引檔,並擋住體積超標。這是規格指定的檢查點:體積或時間過不了門檻就停在這張票。

- 建置入口比照前端索引的建置:讀輸入、產出檔案、印報告;另有只驗證不寫檔的模式。
- 產物是獨立的一個 `.js` 檔,掛一個全域變數(ADR-0007),和前端索引分開,入版控。排版讓版控的差異讀得出來。同樣的輸入兩次產出逐位元組相同。
- 內容:玩家介面比對用得到的欄(見規格的欄位表)、候選卡集合(內容相同的共用一份;小的存卡的清單、大的存位元集)、引用列、解析不出的段的列、無官方日文的卡的清單、動作詞/區域/原因值各自的清單與列數、字段與它的成員卡、卡的順序(對到前端索引的卡)。
- 完整的列裡玩家介面用不到的欄,這一輪寫不寫由實作者依體積決定,在 Comments 說明。
- 體積門檻:產物檔超過 8 MB 時建置失敗。門檻是設定值,測試用小的值驗「擋得住」。
- 時間門檻:卡片結構建置加動作索引建置,在站主的機器上不超過 2 分鐘。報告印出各階段花的時間。
- 報告:列數、各種列的數量、候選卡集合的數量與大小、產物體積、各階段時間。
- 之後的票會再加欄(誰、受方、原因、效果對應);門檻每次建置都驗。
- 產物在票分支不 commit,見 `docs/agents/implement-spec.md`。

- 規格:需要你決定的「Q0」「Q10」「Q12」「Q13」;實作決策「動作索引」「建置與門檻」;使用者故事 50–53;測試決策「接縫二」。
- 參考:原型的索引 4.64 MB(規格〔原型〕),格式在分支 `prototype/action-player-ui`;原型沒有引用列與字段成員表。

- 第五份輸入字段表(`data/archetypes.json`):字段的中文名與 setcode 要從它來;成員照卡片屬性表裡位置條件不設限的 setcode 列算(與 Python「給條件 字段」同一判法),沒有成員的字段(6 個)不寫。效果標記表留給票 07(效果對應才用到)。

- 排版:每個鍵一行;候選卡集合一個一行、卡一張一行(行首是卡號)。集合的鍵是內容雜湊(base36,全庫 7 字元),別的集合增減不會改到它的鍵,版控差異只落在改到的卡與集合。值的清單照字串排序。集合存清單或位元集,取短的(全庫清單 11,529 個、位元集 382 個)。

### 寫進索引的欄

- 規格欄位表裡這一輪已有的欄:卡、段序號(同一段的線放在同一個段裡)、段類別、極性、動作詞(上位詞已展開)、做動作的線、從、到(區域含上位區域、方、推得另標)、被動作的卡(沒有物件/候選卡集合)、未解析的來源(段類別、極性、字面動作詞、原因有無的旗標)、引用列、無官方日文的卡、動作詞/區域的清單與列數、字段成員、卡的順序。
- 還沒有的欄由後面的票加:效果(07)、誰(10)、受方、原因與原因值清單(11)、被動作的卡分出此卡/判不了/代不進去(12;現在此卡是只含自己的集合,判不了、代不進去是空集合,與 `row_match` 現行判法相同)。
- 玩家介面用不到、這一輪**有寫**的欄(體積有餘裕,下一輪進階模式要用):段 id(417 KB)、區塊種類(每卡一個清單,每段指到它的區塊)、被改的屬性(149 KB)、取對象(線的旗標一位元)、泛用物件(0/1)、是不是做代替的段、未解析的來源的區塊種類判不出/代入卡時判不了旗標、引用列的指定的部分(`parts`,只列不是整張的 468 筆)。
- **沒寫**的:代替的連結(被代替段 → 做代替的段)、物件判不了的原因與原文(網站這一輪不帶原因與原文,規格如此)、字面不含任何動作詞的未解析來源(7,516 筆;帶動作詞的查詢才看未解析組,字面要含全部查詢動作詞,這些永遠進不去)。
