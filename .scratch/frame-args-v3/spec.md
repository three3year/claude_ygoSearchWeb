Status: ready-for-agent

## 需要你決定的

### 哪些動作算「移動類」(區域記來源),其餘記所在?

決定(2026-10-17):(b)只算區域移動與召喚;素材類的區域記所在。

受事者片語裡的區域,移動類動作記成來源、其餘記成所在(grill 已定)。清單是框架線的一份封閉表。草案:區域移動與召喚兩個大類的成員——加える、ドロー、送る、捨てる、リリース、除外、戻す、戻る、置く、セット、装備、移動、特殊召喚與各召喚法(召喚、通常召喚、アドバンス召喚、A召喚、融合召喚、儀式召喚、S召喚、X召喚、リンク召喚、P召喚)。有疑問的是素材類:融合素材とする、S素材とする、X素材とする、重ねる、素材とする、リンク素材にする 都會把卡從手札/場上移去墓地或疊放,「自分の手札・フィールドのモンスターを融合素材とする」的 手札・フィールド 讀成來源是合理的。

- (a)區域移動、召喚、素材類都算(建議):融合素材的「從哪裡拿素材」分得出來;代價是素材類框架(約 1,150 框)的區域改記來源,類別線的素材大類以後要依來源切葉時才用得上。取り除く(取除 X 素材)不算,它的 から 是 X 素材,不是區域。
- (b)只算區域移動與召喚:素材類的區域記所在;代價是融合素材的區域在「所在」,和 特殊召喚 的「來源」讀法不同。

### 装備 要不要補推得目的 フィールド?

決定(2026-10-17):(a)装備 不補。

推得值對照表(grill 已定範圍「目的固定的動作都補,另補 捨てる、ドロー 的隱含來源」):除外→目的 除外;捨てる→目的 墓地、來源 手札;ドロー→目的 手札、來源 デッキ;特殊召喚與各召喚法→目的 フィールド;セット→目的 フィールド;加える→目的 手札。装備 有疑問:「そのモンスターに装備する」的 に 是被裝備的怪獸,不是區域,目的欄在 装備 上本來就不是地點(381 框有 272 框目的寫的是怪獸)。

- (a)装備 不補(建議):目的欄在 装備 上維持「被裝備的對象」這個讀法;代價是目的空著的 109 框看不出卡最後在場上。
- (b)補 フィールド:代價是同一個欄在 装備 上有時是怪獸、有時是區域。

## Problem Statement

站主在類別樹草案裡看到兩件事,框架讀不出來:

1. **「墓地のこのカードを除外する」的區域在錯的欄**。框架記成 對象=墓地のこのカード、來源=空、目的=空,可是站主讀這句是「對象=此卡、來源=墓地、目的=除外」。對象欄開頭帶區域、來源空著的動作框架有 8,323 個(対象とする 3,460、除外 1,024、選ぶ 569、破壊 495、リリース 439、捨てる 316、送る 314、戻す 309…)。類別線為此在分類層加了「來源空著時讀對象欄開頭的區域」的補丁(影響 4,699 框),但拆解頁上的框架照舊,補丁也只在分類層看得到。目的同理:除外、捨てる、ドロー、特殊召喚 的去處由動作本身決定,原文不寫,框架的目的欄就空著(除外 2,511 框有 2,507 框目的空)。
2. **「誰變成多少」讀不出來**。になる(416 框)與 にする(113 框)被歸在「數值」大類,但抽樣裡「守備力が０になり」是數值、「受ける効果ダメージは０になる」「相手のLPを１００にする」是 LP・ダメージ、「通常のドローは２枚になる」是規則改寫。になる 的對象欄 416 框有 414 框是空的——變的是什麼寫在主語(〜が/〜は)裡,框架切了 が/は 片語卻沒收下來(第一版「主體不收」)。アップ 的對象欄 1,038 框有 972 框是空的,同樣看不出是攻擊力還是守備力。

## Solution

框架多四種資訊,都從既有的接縫(一句效果句 → 框架清單)流出,拆解頁同一張表看得到:

1. **主題與主語**:「は」前的片語記主題(說的是誰,主動句裡常是執行者),「が」前的片語記主語(說的是什麼在變)。主題在同一句內延續到後面沒有自己主題的子句,延續的值標成回填;主語不延續。被動句的受事者留在主題/主語,不搬進對象。
2. **來源與所在**:受事者片語裡的區域切出來——主動句的受事者是對象,被動句的是主語(沒有時是主題)。移動類動作記來源,其餘記所在(卡在那裡、沒有被移走)。區域在片語中間也切;並列的受事者各帶區域時取聯集,和「手札・デッキから」一樣是多區域。
3. **推得值**:目的(與 捨てる、ドロー 的來源)由動作本身唯一決定、原文沒寫時,框架補上並標推得,拆解頁淡色。
4. **回填轉欄**:上游的區域交給下游時,依下游動作決定放來源還是所在。

類別線接上新欄位的最小調整:拿掉「對象欄當來源」的補丁,改讀框架的來源與所在。類別樹本身的改動(になる 依主語分大類、アップ 依攻擊力/守備力切葉…)留給票 06 重起草案。

## Implementation Decisions

**資料格式(動作框架的新欄位,全部可選;約束框架不動)**

- `主題`、`主語`:字串,值是 は/が 片語的原文字面(切掉區域後的剩餘)。
- `所在`:字串,和 `來源` 同一種寫法(區域字面,可帶玩家前綴,多區域以「・」並列)。
- `推得`:字串清單,值域「目的」「來源」;沒有推得時不帶此欄。
- `回填`:值域擴成「對象」「來源」「所在」「主題」。
- `被動`:真值,只在被動時帶。述語錨點本來就判了被動,這裡只是讓它流出到框架上。
- 拆解頁框架表多主題、主語、所在三格;推得與回填的格淡色,滑過說明是哪一種。批次檔同樣標示。

**區域辨識下移到框架線**

- 「一段字面是不是區域、是哪個區域、帶哪個玩家」的辨識現在在類別線(地點字面 → 玩家+區域清單)。本線把它搬到框架線,類別線改用同一份;行為不變,類別線的既有測試照舊通過。
- 框架裡的來源/所在仍存原文字面(自分の墓地、相手フィールド),映成區域七值仍是類別線的事。

**主題與主語**

- 子句內依格助詞切片語時,は 片語收成主題、が 片語收成主語;同一子句有多個時取離述語最近的。後綴型(には/では/とは)照既有規則併入前一格,不算主題。
- 主題延續:子句沒有主題時,沿用同一句內前一個主題,直到句號、新的主題、或一個自己帶 が/は 的條件子句(〜場合/〜時/〜限り 收尾)。延續的值記進 `回填`(主題)。主語不延續。
- 定語裡的 が(カード名が記されたモンスター)照既有的定語範圍規則屬於名詞片語,不出主語。
- 「この効果は」「このカードの効果は」這類速度/時機註記的主題,沿用既有判斷,不當成動作的主題。

**受事者的區域切分**

- 受事者:主動句是對象;被動句是主語,沒有主語時是主題。主動句的主題(執行者)不切。
- 片語裡第一段「(玩家の)區域の」切出:開頭或中間都切;剩餘字面去掉這一段,其餘不動。整個片語就是區域(手札、相手のEXデッキ)時,區域記進來源/所在、受事者欄維持原文(這種寫法的受事者就是那個區域本身)。
- 並列的受事者(〜と〜、〜か〜)各帶區域時,區域取聯集、依字面順序以「・」並列;受事者欄的每段都去掉自己的區域。
- 放哪一欄:動作在移動類清單(見[需要你決定的](#需要你決定的))裡記來源,否則記所在。原文已經有 から 來源時不切(21 框)。
- 「除外されている自分のモンスター」「EXデッキの表側表示の…」這類用狀態或定語寫的區域,依區域辨識認得出就切,認不出就不動。

**推得值**

- 一張「動作 → 推得的目的/來源」對照表,和移動類清單一樣是框架線的封閉表(內容見[需要你決定的](#需要你決定的))。
- 只補原文沒寫的格;原文有字面時用原文、不標推得。推得的值是區域字面(除外、墓地、手札、デッキ、フィールド)。
- 否定框架(〜を除外できない、破壊されない)也補:欄位說的是「這個動作的去處」,極性另記。

**回填**

- 沿用第二版的兩種來源(か 群組、選ぶ鏈)與停止條件。區域轉欄:上游的來源或所在交給下游時,依下游動作是不是移動類決定放進來源還是所在;下游原文自己有來源或所在時不填。
- 處理順序:先切區域與收主題/主語,再推得,最後回填;回填接到的區域若下游又有推得的同欄,以回填為準(上游原文的字優先於規則補的字)。

**類別線的最小調整**

- 拿掉「來源空著時讀對象欄開頭的區域」補丁,改讀框架的來源;來源空著時讀所在(破壊、対象とする 的玩家從這裡取)。
- 不改類別樹、不改葉;全語料重跑後比對已歸/未歸/不適用與每葉計數,差異逐項說明。

**檢驗**

- 比照第二版:受影響卡依型分層(區域切分、並列多區域、推得、主題延續、主語、被動受事者、回填轉欄)、固定種子抽 100 張、切 4 批交 4 個子代理看原文與框架挑錯;錯誤類型在既有之外加「區域切錯/漏切」「推得錯」「主題/主語錯」「延續錯」;依類型修規則後同批複檢一次。存檔沿用 `llm-check/`。

**文件與頁面**

- CONTEXT.md:論元詞條的主題/主語、來源/所在、推得值三段在 grill 時已寫;交件時核對與程式一致,並更新動作類別詞條「來源/目的映到區域」那句(來源可能來自切分)。

- 接縫兩個,都沿用現有:(1)框架抽取「一句效果句原文(含 ● 項、帶同卡同段上文、可選效果外/卡片子類型)→ 框架清單」,本規格所有新欄位都在這裡斷言;(2)類別歸組「一句效果句 → 每個框架的類別紀錄」,只驗最小調整後既有葉仍歸得到。拆解頁顯示與 LLM 抽驗不另設單元測試。
- 好的測試只看輸出框架:動作框架看(動作、位置、極性)加上本規格的欄位(主題、主語、對象、來源、所在、目的、推得、回填、被動)。不斷言子句切分或中間狀態。
- 每個句型一條回歸例子,修規則前先補一條會失敗的例子;每條規則都配反例:原文有 から 時不切、主動句執行者主題不切、主語不延續到下一子句、條件子句自己的 が 擋住主題延續、リリース/破壊 不推得、原文有目的時不標推得、定語裡的 が 不出主語、下游原文有來源時回填不蓋。
- 先例:`test_frames.py`(動作框架,94 條)、`test_categories.py`(類別歸組,28 條)、`test_constraints.py`、`test_assemble.py`。
- 全語料重跑後與修前比對:差異只能落在本規格的幾型(對象欄帶區域約 8,300 框、推得約 1 萬框、主題/主語、回填轉欄);其他記錄逐一說明或視為缺陷。分詞鏈決定性重跑相同。
