# 13: 被動作的卡:給條件

**What to build:** 「被動作的卡」多第三種選法:給條件。玩家可以查「能特殊召喚龍族的卡」,不必指定某一張。

- 介面開放六種條件:大類、屬性、種族、等級、字段、卡名包含。大類、屬性、種族的按鈕由值域正典生成;字段的選項由動作索引帶的字段成員表生成。
- 判法:「滿足查詢條件的卡」與「這條線的候選卡」有交集就命中。網站自己從前端索引與字段成員表算出滿足條件的卡。
- Python 這邊用現有的「只給條件」查詢,不加新的條件種類。
- 條件一項都沒填時等於不指定。
- 物件判不了的線的處理同票 12。

- 規格:需要你決定的「Q19」;實作決策「比對規則」的給條件、「動作索引」的字段成員表、「玩家介面」;使用者故事 30、31;測試決策「兩邊答案一致」。
- 參考:原型有大類、屬性、種族、等級、卡名包含五種,沒有字段。

**做了什麼**
- 網站 `web/js/action.js`:動作條件的 `target` 多第三種形狀 `{ condition: 給條件 }`,給條件的正規形是 `{ cat, attr, race, lvMin, lvMax, set, name }`(填了的才寫;大類、屬性、種族是值域正典的短碼,等級是 0 以上的整數,字段是 setcode,卡名包含是去頭尾空白的字串);認不得的值忽略,一項都沒有時整個 target 是 null,等於不指定。`count` 照舊算一條。
- 列查詢:`rowQuery` 換成 Python 的只給條件查詢(`condition` 鍵,Python 不加新的條件種類):大類 `{op: 大類, value: 怪獸|魔法|陷阱}`、屬性與種族 `屬性比較 =`(值是官方日文字面,照 `attribute_words` 的 ATTRIBUTE_JA、RACE_JA)、等級 `屬性比較 ≥ / ≤`、字段 `{op: 字段, setcodes: [setcode]}`、卡名包含 `{op: 卡名包含, text}`;一項是原子本身,多項是「且」。
- 判法:`objectTest` 給條件時先算滿足條件的卡(位元集),線的候選卡集合與它有交集就命中;同一個集合在一次查詢裡只比一次,位元集的集合逐位元組比、不展開。滿足條件的卡由前端索引的卡(`c`、`at`、`r`、`lv`、`s`、名字)與動作索引的字段成員表算出,判法照 `eval_condition`:超量、連結怪獸沒有等級;卡名包含把全形英數折成半形。為此 `Action.prepare(raw, db)` 多收前端索引的卡(面板傳 `Util.DB`,沙箱傳 `CARD_DATA`)。
- 無法確認:`Action.unsure` 本來就看 `rq.condition`,給條件時用「代入卡時判不了」的旗標(同指定卡、同 Python)。
- 新函式 `Action.conditionOptions()`:大類、屬性、種族的選項由 `window.VOCAB` 生成(宣告序);`Action.archetypeSuggest(index, 字, 上限)`:字段成員表裡中文名含輸入字的字段,名字短的排前面,最多 12 個。

**實作者自己定的小事(請站主知悉;第 1 條需要你決定)**
