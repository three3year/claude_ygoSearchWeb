# Spec: 文本改寫表機制與試點批(text-rewrite)

Status: ready-for-agent

2026-08-23 盤問定案(/grill-with-docs)。上游 feature:text-format(規範文件、三級分類報表,已全票收工);本 feature 啟動其 spec 預留的「未來管線」。

## Problem Statement

[[文本格式規範]](`docs/text_format_guide.md`)與三級分類報表已就緒:3,805 段[[舊式卡文]]的改寫佇列分好群、每群對應好 §4 的舊→新句型規則。但改寫成果**沒有進站通道**——今天就算改寫好一批文本,也只能躺在草稿裡,網站的正式卡文、搜尋、效果判定管線全都看不到。spec 裡定位過的「文本改寫表」尚未實作,一張卡都還沒被實際改寫過。

同時,一次改寫 3,805 段風險太高:規範或流程有問題時返工成本巨大,需要先以小批試點驗證「機制+改寫+審查」全線。

## Solution

兩件事,依序完成即收工:

1. **文本改寫表進站機制**(仿[[卡文勘誤表]]的並列第二條線,勘誤=修誤譯、改寫=格式現代化):來源檔 → 建置期整卡全文替換(舊全文校驗、吵鬧失敗)→ 三級分類新增「本站已改寫」級 → 前端「顯示原文」全文切換。
2. **試點批改寫**:報表「反轉標籤(§4.3)× 怪獸」群 49 段,以官方日文卡文為基底依規範改寫,產單一 markdown 審查檔供站主逐卡審,放行後寫入改寫表進站。

## User Stories

1. 作為站主,我想要一份「文本改寫表」來源檔,讓審核過的改寫文本有正式落點,而不是散在草稿裡。
2. 作為站主,我想要改寫表在建置卡片總表時套用、新全文成為本站正式卡文(搜尋與顯示都用它),讓改寫成果真正上站。
3. 作為站主,我想要改寫表每筆帶「舊全文」校驗欄,上游來源更新導致對不上時建置吵鬧失敗,讓改寫永遠不會默默套錯卡。
4. 作為站主,我想要同一張卡同時出現在勘誤表與改寫表時建置失敗,讓「勘誤=內容、改寫=形式」的分工不被偷渡混淆。
5. 作為站主,我想要改寫卡的舊譯誤譯直接寫對在新全文、於該筆 reason 註明,讓改寫批不必為誤譯另開勘誤票。
6. 作為站主,我想要既有勘誤卡日後被改寫時,勘誤筆遷出勘誤表併入改寫筆,讓兩表互斥規則長期成立。
7. 作為網站使用者,我想要被本站改寫的卡有「顯示原文」按鈕、按了整段切換成查牌網舊譯全文,讓我知道這張卡被改寫過、也查得到舊寫法。
8. 作為網站使用者,我想要改寫卡的原文視圖是純文字全文、不帶逐字刪改標註,讓整段重寫的對照可讀(逐字標註留給勘誤卡)。
9. 作為站主,我想要三級分類器認得改寫表、把本站改寫的卡獨立成「本站已改寫」級,讓它們不再誤歸「官方已改寫」、優先稽核佇列不被污染。
10. 作為站主,我想要報表把「本站已改寫」獨立成區,讓改寫工程的進度直接可視化。
11. 作為站主,我想要試點批選「反轉標籤(§4.3)× 怪獸」49 段(單一條目純群、零誤報化石句型),讓第一批以最明確的對應規則驗證全線流程。
12. 作為站主,我想要改寫以 faq_info 官方日文卡文為基底、依規範 §4.3→§3.18 譯寫,再對照查牌網舊譯互查語意缺漏,讓新文本忠於官方原文又不漏舊譯已覆蓋的語意。
13. 作為站主,我想要改寫遇到裁定判斷點(取對象與否、區域指涉、強制/任意)時查得到官方佐證才改句面、查不到就保守照日文原句型照譯並標記待查,讓改寫不把猜測寫進正式卡文。
14. 作為站主,我想要 49 段成果整理成單一 markdown 審查檔(每卡:日文原文/查牌網舊譯/新文本三欄+依據條目+判斷點註記),讓我逐卡審核、批註,審查紀錄落檔可回溯。
15. 作為站主,我想要審查放行後才寫入改寫表、且依慣例只在我明說 commit 才提交,讓正式卡文的變更永遠經過人審。
16. 作為站主,我想要改寫進站後該卡新①段自動依圈號切句、新句進效果判定既有佇列重判,讓[[效果標記表]]用同一套管線接手,不另起爐灶。
17. 作為站主,我想要改寫表納入既有[[資料更新時間]]與建置回報慣例(套用筆數列印),讓它與其他來源檔同等待遇、可觀測。
18. 作為未來的改寫 agent,我想要機制與試點批驗證過的工作流(佇列→改寫→審查檔→進站)可原樣重複,讓後續批次純填表、不再盤問架構。
19. 作為網站使用者,我(間接)想要舊卡文逐批現代化成可判讀的新格式,讓我不查裁定也能讀懂舊卡——本 feature 是第一塊真貨。

## Implementation Decisions

### 改寫表來源檔

- 與勘誤表並列的第二份自持來源檔(`data/` 直下,比照 `text_errata.json`),JSON 陣列,一筆一卡:`id`(卡片密碼)、`old`(改寫前 desc 全文,校驗用)、`new`(改寫後 desc 全文)、`refs`(依據的規範條目,如 `["§4.3"]`)、`reason`(含誤譯一併修正的註明)、`ticket`。
- **整卡 desc 全文替換**,不是子字串:改寫動整段結構(圈號、分行、句序),靈擺混合卡(有①段+無①段並存,全庫 3 張)也以一筆整卡覆蓋。

### 建置期套用

- 卡片總表建置的套用層新增改寫套用純函式,與勘誤套用同層:`old` 與現行 desc 全文不相等即整批列舉後吵鬧失敗(比照勘誤表 ADR-0011 的失敗哲學)。
- **兩表互斥**:同一 `id` 同時在勘誤表與改寫表 → 建置失敗。套用順序上改寫卡不經勘誤(互斥保證無交集)。
- 套用後的新全文是本站正式卡文,搜尋與顯示都用它;建置回報列印套用筆數(比照「卡文勘誤: 套用 N 筆」)。

### 三級分類與報表

- 分類器增加「該卡已被本站改寫」輸入,新增第五級「**本站已改寫**」:改寫卡不再落入「官方已改寫」(首發日在 9 期界日前+desc 帶①的誤歸),優先稽核佇列不混。
- 報表把「本站已改寫」獨立成區(進度可視化);既有等式(舊文本段=tagcard `pending_split`)在改寫進站後兩側同步縮減,迴歸測試維持。

### 前端原文對照

- 沿用勘誤卡「顯示原文」按鈕與切換交互;改寫卡的原文視圖為**舊全文純文字**,不做逐字刪改標註(整段重寫下逐字標註是滿版噪音)。建置期把舊全文帶進[[前端索引]]的該卡欄位,與勘誤卡的 diff 段落表欄位區分。

### 內容工作流(試點批)

- 佇列:報表「反轉標籤(§4.3)× 怪獸」群 49 段。
- 基底:faq_info 官方日文卡文;依[[文本格式規範]] §4.3→§3.18 改寫(「反轉：」化石標籤 → 「①：此卡反轉的場合，…發動/可以發動。」),成品回 §3 逐條檢查;卡名與術語沿用庫內既有譯名(§3.19)。
- 互查:新文本對照查牌網舊譯逐卡檢語意缺漏。
- 裁定判斷點(§4.5 取對象與否、§4.8 區域指涉、反轉句強制/任意):**查得到官方佐證(含庫內官方 Q&A 快取)才改句面;查不到保守照日文原句型照譯**,審查檔標記待查,不硬猜。
- 審查:單一 markdown 審查檔落在 feature 目錄,每卡一節:日文原文/查牌網舊譯/新文本三欄+依據條目+判斷點註記。站主逐卡審、放行後寫入改寫表;只在站主明說 commit 才提交。

### 下游銜接

- 改寫進站後,該卡 desc 帶①,tagcard 管線自動依圈號切句;新句無判定 → 自然進既有判定批次佇列重判。掛在舊整團雜湊上的既有效果判定退場,接受效果標記短暫空窗直到重判完成。不建遷移邏輯。

### 詞彙與文件配套

- `CONTEXT.md` 新增詞條「文本改寫表」(text-format spec 當時明文不建,因屬未來 feature;本 feature 即該未來,現在建),與[[卡文勘誤表]]、[[文本格式規範]]互相區隔連結。
- `docs/text_format_guide.md` 第 5 章「文本改寫表(未來機制)」的「尚未實作」定位語隨實作更新。

## Testing Decisions

- 只測外部行為,不測內部構造。三條接縫全沿既有:
  1. **建置套用純函式**(主接縫):合成卡片記錄+合成改寫表,斷言替換結果、`old` 不匹配的吵鬧失敗(整批列舉)、兩表同卡互斥失敗。Prior art:勘誤套用測試與 `test_sync_errata` 的合成記錄慣例。
  2. **分類器**:已改寫輸入 → 「本站已改寫」級;界日前後+已改寫的組合邊界。直接擴充既有分類器測試。
  3. **前端索引建置**:改寫卡的原文欄位存在、內容為舊全文、與勘誤卡 diff 欄位不混。沿用既有 web 測試面(Python+node)。
- 審查檔產生器與報表調整是薄殼,不立測試(repo 既有慣例)。
- 與管線一致性:改寫進站後,分類器舊文本段數與 tagcard `pending_split` 的等式仍須成立(兩側同把尺)。

## Out of Scope

- 試點批以外任何群的改寫(後續批次另開票)。
- 效果類型判定的執行(重判走 tag_card 既有佇列,屬該線日常工作)。
- 勘誤表既有 2 張卡的遷移(它們不在試點群;遷移規則已定,待其所在群改寫時執行)。
- 前端除「顯示原文」沿用擴充外的任何變更;發售日照舊不進[[前端索引]]。
- 官方效果 Errata(效果內容修訂)議題。

## Further Notes

- 試點群大小以報表 2026-08-23 版為準(反轉標籤(§4.3)× 怪獸,49 段/49 張);資料更新後重跑報表若群成員變動,以開工當下重跑結果為準。
- 反轉句強制/任意的佐證來源:官方已改寫佇列裡帶①的反轉卡是最近似的官方句型參照(日文「発動する/できる」語尾),屬「查得到」的一種。
- 審查檔中站主批註的處理:逐卡放行/退回/改判,退回卡修正後同檔更新再審;全數放行才進改寫表。
