# 動作搜尋 人工驗收清單

這份清單把規格列為「不自動測、由站主人工驗收」的項目寫成步驟:版面與文字、手機版、動作索引第一次載入的時機與載入中的顯示、上一頁/下一頁/重新整理、舊連結、區域與哪一方怎麼選、卡名的建議清單、條件怎麼給。對應使用者故事 1、9、31、37–46,以及 6、7、29、30 的操作方式。步驟由票 01、08–16 的 Comments 彙整、去重。

每一步寫「做什麼」與「要看到什麼」。張數是 2026-11-23 用整合分支 `action-search-web` 版控裡的 `web/data.js` 與 `web/action-data.js`,在 node 沙箱裡載入真實前端檔量的,出處見[數字出處](#數字出處);真實瀏覽器裡的張數應該相同。

## 開法(兩種各走一遍)

全部步驟走兩遍:一遍雙擊開啟,一遍經本機伺服器開啟。

- **雙擊開啟**:在檔案總管雙擊 `web/index.html`(網址列是 `file:///…/web/index.html`)。
- **經伺服器開啟**:在 repo 根跑 `python -m http.server 8765 --directory web`,瀏覽器開 `http://localhost:8765/`。
- 開著開發者工具(F12)的 Console 與 Network 兩頁。全程 Console 不該出現紅字。

## 載入時機

1. 開頁,只在「卡名」填「青眼」按搜尋:Network 沒有 `action-data.js`;結果和改版前一樣。
2. 點側欄「效果文」下面的「動作搜尋」展開:Network 出現 `action-data.js`;區塊裡短暫顯示「動作索引載入中…」,接著出現動作詞按鈕。
3. 重新整理頁面(區塊回到收起),展開區塊後立刻點「破壞」按搜尋(或在載完前按搜尋):結果區先顯示「動作索引載入中… 載完會自動出結果」,載完自動出 2,200 張,不必再按一次。
4. 收起再展開區塊:Network 不再下載 `action-data.js`。
5. 載入失敗的樣子:把 `web/action-data.js` 暫時改名,重新整理、展開區塊:區塊裡有載入失敗的說明;卡名「青眼」照常能搜。看完把檔名改回來。

## 版面與文字

1. 展開「動作搜尋」:由上而下是說明「找卡文裡有這個動作的卡;和其他條件同時成立才算」、動作、從哪裡、到哪裡、被動作的卡、這個動作是、極性、誰做的、落在誰身上、因為什麼、「含不限定的」。看文字與擺法是否順眼。
2. 動作詞:直接列出 14 個(特殊召喚、破壞、送墓、除外、加入手牌、性質變更、通常召喚、召喚、返回、解放、攻擊、傷害、捨棄、發動);按「更多」後共 45 個。先選一個「更多」裡的詞再收起「更多」:已選的詞照樣顯示。
3. 「被動作的卡」底下有一行「這裡篩的是被動作的卡,不是有這個效果的卡」,看得出它和側欄上方的種族等條件篩的是不同的卡(故事 31)。
4. 「含不限定的」滑鼠移上去有提示,說明它放寬的是沒寫誰、沒寫原因的段。
5. 原因的種類選項只有戰鬥、效果、作為素材、召喚方式、方法、規則,沒有「戰鬥或效果」「戰鬥以外」。

1. 選好動作、從、到、被動作的卡(給條件填幾項)、勾選、極性、誰、受方、原因、「含不限定的」,按「清除條件」:全部回到預設(動作沒選、區域不限、不指定、勾效果與代價、會做、不限、「含不限定的」沒勾);再點「給條件」時各項是空的。
2. 手機寬度(或開發者工具的裝置模擬):動作搜尋區塊跟著側欄一起摺疊;選了動作詞與被動作的卡時,摺疊鈕寫「篩選條件・N 項」,N 把動作條件算進去(每個欄位一項,「含不限定的」不算)。
