# 01 — 所在條件與葉名 @、拿掉「來源空著時讀所在」橋接

**What to build:** 類別樹的葉多一個條件欄「所在」(區域七值),葉名寫「詞元@區域」(破壊@フィールド、選ぶ@手札、見せる@EXデッキ)。來源條件只比框架的來源、所在條件只比框架的所在,歸組模組裡「來源字面空著時讀所在」的橋接拿掉。站主在框架類別檔看到「相手フィールドのカードを破壊する」歸 破壊@フィールド(本票先不分玩家)、「墓地のこのカードを除外する」仍歸 除外←墓地、「フィールドのモンスターを対象にする」歸 対象にする@フィールド;除外←フィールド 這類來源葉不再被所在框架誤中。

**Blocked by:** None — can start immediately

**Status:** resolved

- [x] 樹來源檔的葉認「所在」鍵(值在區域七值);葉名組法:區域段依序只會有 ←來源/→目的/:來源→目的/@所在 其一或來源+目的的組合;完整性檢查認所在(值不在七值報錯;「後面的葉被前面的葉整個蓋住」的判斷涵蓋所在)。
- [x] 規則表:來源與所在各自映成(玩家, 區域清單)、各比自己那一欄;複合所在(手札・フィールド)逐區域各匹配一葉、依字面順序去重;推得的來源/目的照舊參與匹配。橋接拿掉後,源自所在的玩家不再寫進來源玩家欄(來源玩家欄只記來源字面的玩家)。
- [x] 現有樹裡靠橋接才歸到的葉(破壊 的區域、戻す:フィールド→手札 這類)改寫成所在或維持來源,以全語料前後比對逐項說明差異;已歸/未歸/不適用數與每葉計數前後記在票 Comments。
- [x] 回歸例子(類別歸組接縫):破壊@フィールド 歸得到;所在框架不匹配同詞元的來源葉;複合所在帶兩葉;除外←墓地(來源來自受事者切分)不變;來源與所在都空的框架落預設葉。
