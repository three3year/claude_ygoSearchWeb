# Spec: 介面與網址——條件列、目錄導覽、抽屜,切換到述詞搜尋並刪掉舊軸

Status: needs-info
Date: 2026-11-02

框架述詞搜尋線(`.scratch/frame-predicate-search/map.md`)四份規格的最後一份,對應地圖票「寫規格 4:介面與網址」。形狀由 GLOSSARY.md(框架述詞、具名查詢)、ADR-0018 與站主核可的原型 D 版裁定,本規格只抄;原型沒定的細節依地圖 Notes 在[需要你決定的](#需要你決定的)一次問完。上游是規格 3(`.scratch/predicate-index/`),查詢與結果形狀、VOCAB 新部分、要刪清單見 predicate-index 票 05 Comments「給規格 4 的對照」。正文依各題的建議寫,裁定不同再改。

## 需要你決定的

### OR 區在哪裡算?

原型是介面每張 OR 標籤各跑一次引擎再聯集,正式引擎只有 AND。實測每多一張 OR 標籤就多跑一次:OR 5 張加 AND 條件,node 中位 49.2 ms(瀏覽器約快 2〜3 倍,見 [Further Notes](<#Further Notes>))。

- (a)**進引擎**(建議):`Engine.runQuery` 接 `q.or = [條件片段…]`,聯集、命中句、命中框都由引擎合併。測試走既有接縫,全語料對照不受影響。代價:引擎多一層分支與述詞編號規則。
- (b)**留在介面**:引擎不動,介面照原型聯集。代價:合併邏輯(句、框、述詞序號換算)落在沒有現成接縫的介面層,要另開測試入口。

### 網址怎麼寫標籤與 AND、OR 區?

左側條件的參數(`cat`、`atk`、`text`…)不動。ADR-0018 已定:沒改過的具名查詢寫葉路徑,改過的展開成欄位對。例子見[網址](#網址)。

- (a)**可讀的欄位對**(建議):`act` 是 AND 區、`actOr` 是 OR 區的動作標籤,`or` 列出放在 OR 區的左側條件;展開形如 `詞元:破壊;動作對象:非此卡`,同欄多值用 `~` 接。代價:要有一套分隔符規則。
- (b)**JSON 再 base64**:不用定分隔符。代價:網址讀不出內容,手改不了,也更長。

### 條件一變就重查,瀏覽器的上一頁退到哪?

現行每按一次搜尋留一筆歷史。沒有搜尋鈕之後要另外定。

- (a)**離散操作留一筆,打字不留**(建議):加減標籤、換區、抽屜改值、點左側鈕各留一筆;打字與數字範圍只改寫目前這一筆。上一頁退回上一個操作。代價:打字過程退不回去。
- (b)**每次重查都留一筆**:最單純。代價:打一個詞就多好幾筆,上一頁要按很多次。
- (c)**都不留**:只改寫目前這一筆。代價:上一頁直接離開網站。

### 效果位 0 張的具名查詢,點了之後位置帶什麼?

原型定了灰字標「條件 3396」,但點下去仍帶效果位,結果是 0 張。全目錄只有兩個:`対象とする`(條件 3,396)、`取り除く@お互いのフィールド`(代價 10)。

- (a)**帶有張數的那個位置**(建議):`対象とする` 點了就是條件位,馬上有結果。代價:多一條規則,網址要寫展開形。
- (b)**一律帶效果位**:規則單純,與原型相同。代價:這兩個查詢點了都是 0 張,要自己開抽屜改位置。

### 刪歸葉程式後,仍 import 它的舊工具怎麼辦?

`compile_dry_run.py`、`project.py`、`compare_dry_run.py`、`rewrite_tree.py` 都 import `categories`,結果檔在建置產物表上算可重生。`llm_check.py` 也 import,但它還要用。

- (a)**四支轉成歷史,`llm_check.py` 改寫**(建議):四支工具與結果檔留在原處、檔頭註明已不能重跑(要跑請切到切換前的 commit),從建置產物表拿掉;`llm_check.py` 的歸組與 `tree.md` 改讀目錄與 `frame_queries.json`。代價:這四支從此不能在新版重跑。
- (b)**全部改寫到新程式**:都能繼續跑。代價:它們比對的是舊樹與新目錄,舊樹一刪就沒有比對對象,改寫沒有實際用途。

### 切換前要不要先發布一次重建過的 data.js?

本地分支的 data.js 已帶規格 2 的動作對象結果(754 張),你已裁定接受;這份還沒併進 main。

- (a)**不另發布,跟切換一起上**(建議):少發布一次。代價:切換前站上的動作對象篩選維持舊結果。
- (b)**先發布一次**:站上先跟上規格 2。代價:多發布一次,data.js 多帶約 262 KB gz 暫時沒人用的框架資料。

### 測試接縫就這四個嗎?

- (a)**四個**(建議):`Engine.runQuery`(既有,加 OR)、`Hash`(既有,加標籤)、`View.cardHtml`(既有,改句尾標籤)、條件模型(新,標籤 ↔ 引擎查詢、短句文字,不碰 DOM);互動另由交件票在真瀏覽器跑一輪。代價:DOM 互動(拖曳、抽屜)沒有自動測試。
- (b)**再加瀏覽器自動測試**:互動也有回歸保護。代價:專案要多一個 Playwright 依賴,打破目前零 npm 依賴的測試方式。

## Problem Statement

分詞鏈、匯出檔、索引、評估器都已換成框架述詞,但站上還是舊的動作類別軸:只能勾節點、全軸套用含代價與動作對象,「一個述詞要此卡、另一個要非此卡」「只查條件位」「破壊 且 中心詞 モンスター」都表達不了。條件散在側欄深處,要按搜尋才看得到結果,也不能表達「墓地或除外」這類 OR。舊欄、舊匯出檔、歸葉程式也還留著,data.js 比必要的大,分詞鏈多跑兩步。

## Solution

1. **條件列**:結果上方用標籤列出這次查詢的全部條件,分 AND、OR 兩區。AND 區全部成立,再加 OR 區任一成立。查詢由標籤組成,條件一變就重查,桌面沒有搜尋鈕。
2. **產生標籤**:一律從左邊產生。側欄的動作類別改成具名查詢目錄,點列是包含、點 − 是排除,點大類、中類只展開;其他左側條件同一類併成一個標籤。沒有空白卡。
3. **改標籤**:點動作標籤開右側抽屜(手機是底部面板)改欄位,不改詞元;要「A 或 B」就放兩張標籤到 OR 區。點左側條件的標籤跳到左邊那一項。
4. **結果**:句尾標籤只標命中的述詞。沒有條件時句尾沒有標籤,現行「每句列出全部葉」隨舊欄消失,要看一句的完整拆解到拆解頁。
5. **網址**:標籤與兩區都寫進網址,貼出去開得起來;未知參數安靜忽略。
6. **切換**:舊欄、舊匯出檔、歸葉程式、舊軸 UI 與相關測試同一波刪掉。

驗收:標籤、抽屜、兩區、網址在真瀏覽器桌面與手機寬各走一輪;目錄 237 個具名查詢經網址、條件模型、引擎的效果位張數與 `VOCAB.catalog` 相同;舊東西刪完全套測試通過;同輸入建置兩次 data.js 逐位元組相同。

## User Stories

1. 作為使用者,我要在結果上方看到這次查詢的全部條件,這樣不用回側欄找哪裡還勾著。
2. 作為使用者,我要條件一變結果就更新,這樣能邊調邊看,不必按搜尋。
3. 作為使用者,我要打字與輸入數字時稍等一下才重查,這樣打字不卡。
4. 作為使用者,我要從側欄目錄點一個具名查詢就多一張標籤,這樣不必從頭組條件。
5. 作為使用者,我要點一列旁的 − 產生排除標籤,顯示成「沒有 X」,這樣能排除做某件事的卡。
6. 作為使用者,我要點大類、中類只展開不產生標籤,這樣導覽不會誤加條件。
7. 作為使用者,我要目錄每列看到效果位張數,這樣點之前就知道大概多少。
8. 作為使用者,我要效果位 0 張的列灰字標出有張數的位置,點了帶那個位置,這樣不會點出空結果。
9. 作為使用者,我要在目錄上方打字過濾節點,這樣不用一層層展開。
10. 作為使用者,我要點動作標籤開抽屜改欄位,點某個字就捲到那一欄,點抽屜外關閉。
11. 作為使用者,我要抽屜列出常用欄與進階欄,值都是網站列出來讓我選的,中心詞可以自己打。
12. 作為使用者,我要抽屜不能改詞元,這樣標籤的主要動作不會被悄悄換掉。
13. 作為使用者,我要標籤讀成短句,預設值(效果位、肯定+可能)不寫,這樣一眼看得完。
14. 作為使用者,我要滑鼠移到標籤上看到具名查詢名或「改自 X」,這樣知道它從哪來。
15. 作為使用者,我要抽屜裡看到這張標籤單獨的張數與還原鈕,改壞了能回到原本的具名查詢。
16. 作為使用者,我要在同一個查詢裡一張標籤要此卡、另一張要非此卡,這樣能查含代價與動作對象全軸做不到的組合。
17. 作為使用者,我要把位置改成條件,這樣「觸發事件」就是一張標籤。
18. 作為使用者,我要把標籤拖到 OR 區(手機按 ⇄),這樣能查「從墓地或從除外特殊召喚」。
19. 作為使用者,我要左側條件也能換區,這樣能查「ATK 2000 以上或光屬性」。
20. 作為使用者,我要同一類左側條件併成一個標籤、標籤內維持 OR,這樣和現行軸內語意一致。
21. 作為使用者,我要點左側條件的標籤跳到左邊那一項,× 直接清掉。
22. 作為使用者,我要清除條件鈕在兩區上方,這樣一鍵重來。
23. 作為使用者,我要只有一個 OR 區、規則簡單;已知「(墓地或除外)且(破壊或ドロー)」表達不了。

## Implementation Decisions

**總則**

- 新整合分支 `predicate-ui`,基於 `predicate-index`。原型分支 `prototype/predicate-card` 只作參考、不併回;版面與互動以它的 D 版、句尾 a 為準。
- 述詞語意不改,仍以參考評估器為準;目錄內容、框架線、索引編碼不改。
- 模組:`engine.js` 加 OR、刪舊軸;`hash.js` 加標籤與區;`acat.js` 改讀目錄;`query.js` 只留側欄條件與目錄;新模組「條件模型」;新模組「條件列」(標籤與抽屜的 DOM);`render.js` 改句尾標籤;`main.js` 改成重查流程。

**引擎的 OR**

- 查詢多一個欄 `q.or = [條件片段…]`,片段的形狀就是查詢本身的子集(左側條件的鍵、`preds`)。空或沒有就不是條件。
- 語意:每個片段與主查詢合併成一個分支;卡命中任一分支就中。結果依資料順序,`rows` 取各分支聯集後排序,`hits[k]` 合併去重,`marks` 合併去重。任一分支的 `rows` 是 `null` 時,以其他分支有句的結果為準;全都是 `null` 才是 `null`。
- 述詞序號是整個查詢的編號:先主查詢的 `preds.inc`,再依片段順序接各片段的 `preds.inc`。介面用它對回標籤。
- 排除標籤放 OR 區就是一個分支,語意是「這個分支要卡上沒有 X」。
- 刪舊軸時一併拿掉 `q.act` 分支與 `act` mark;`pred` mark 在 render 不顯示徽章文字。

**條件模型(新模組,純函式,不碰 DOM)**

- 狀態:動作標籤 `{ex, pred, origin}` 兩區各一串,加上放在 OR 區的左側條件鍵集合;左側條件本身仍由側欄讀寫。
- 目錄列 → 標籤:述詞複製一份,帶 `位置` 預設。位置預設是效果;效果位 0 張時帶有張數的位置(代價、條件依序取第一個)。
- 標籤與左側條件 → 引擎查詢(含 `q.or`)。側欄條件依同一類併成標籤,選了子類型就不另列大類、子類型標籤帶著大類,規則同原型。
- 認具名查詢:比對時不看 `位置`;其餘欄相同就是那個具名查詢,所以改回原樣會認回去。
- 短句:排除寫「沒有」,效果位與肯定+可能不寫,其餘欄依固定順序加連接字;區域用日文,對照表放在條件模型一處,測試守它涵蓋值域每個區域。
- 位置全關視同三個位置都看,明寫三個值。述詞沒有 `詞元` 不成標籤。
- 欄位清單與分組(常用、進階)是條件模型的常數,對應 16 欄;值從 `VOCAB.frame.domains` 來,玩家選單列出 相對、無 與不限玩家,不另外包裝。詞元不在抽屜。中心詞自由輸入,候選是中心詞表前 300 個。

**目錄導覽(`acat.js`)**

- 改讀 `VOCAB.catalog`,用路徑建樹。目錄不是完整的樹:缺的路徑補純導覽節點;大類 `召喚` 與詞元節點 `召喚` 同路徑時,詞元節點掛在大類底下。
- 每列顯示效果位張數;效果位 0 張時灰字標有張數的位置。大類、中類的張數沿用目錄列。初始全部收合。過濾框比對節點名,比對時展開祖先。
- 已在條件列的具名查詢該列標示「已用」。

**條件列與抽屜**

- 位置在結果上方;清除條件在兩區上方,是桌面唯一的清除鈕;沒有條件時兩區顯示提示字,結果區顯示「從左邊選條件,結果會立刻出現」。
- 桌面拖曳換區,標籤游標 `move`、× 維持手指;手機按 ⇄。新標籤預設進 AND。
- 抽屜:頭是短句與包含/排除切換,接著單張張數、「改自 X」與還原鈕、刪除鈕;欄位依條件模型分組。點抽屜外關閉。手機是底部面板。
- 重查:離散操作立刻,打字與數字範圍延遲 150 ms。重查時回第 1 頁,不捲動。Enter 立刻重查;手機同時收起側欄。
- 手機:條件列固定在頂端,超過上限列內捲動;「看結果(N 張)」收起側欄。
- 搜尋鈕、側欄清除鈕在桌面拿掉;舊軸的含代價、動作對象、過濾框隨舊軸 UI 刪除。

**句尾標籤(`render.js`)**

- 命中句的句尾列命中的述詞,每個述詞一個,文字是短句;沒有包含述詞的命中句不列。
- 位置前綴取命中框的位置,效果不寫,其餘寫 `代價:`、`條件:`。框的位置由引擎提供查詢函式,`render.js` 不讀框元組。
- 框所在句不是這一句時,標籤加 `↑領起句` 與說明提示。
- 述詞序號 → 短句的對照由條件模型依同一份查詢組出,傳給呈現層。

### 網址

- 參數:`act`(AND 區動作標籤)、`actOr`(OR 區動作標籤)、`or`(在 OR 區的左側條件鍵,逗號分隔,例如 `sub:m,atk,text`)。左側條件的既有參數不變。
- 標籤之間用 `,`;排除在開頭加 `-`。
- 沒改過:`encodeURIComponent(葉路徑)`。這個形式表示目錄述詞加 位置=效果。
- 改過(含位置不是效果):欄位對。`欄:值~值;欄:值`,例如 `詞元:破壊;位置:代價~效果;動作對象:非此卡`。沒寫 `位置` 是效果;沒寫 `極性` 是不限。
- 區域項寫 `玩家.區域`,不看玩家只寫 `區域`,例如 `來源:自分.墓地~除外`。
- 轉義:欄名與值逐個 `encodeURIComponent`,再把 `~` 補編成 `%7E`;所以字面的 `: ; , ~ › |` 都不會和分隔符撞。分隔符選 `~` 不選 `|`,因為 `|` 不是合法網址字元,聊天軟體會改編。
- 寫出的欄序固定(條件模型的欄位順序),值依值域順序,所以 `canon` 穩定。
- 解析:有字面 `:` 就是欄位對,否則是路徑。找不到的路徑、不認得的欄、值域外的值都安靜忽略;詞元不在詞元表也忽略;沒有詞元的標籤整張忽略。不認得的欄不會送進引擎。
- 不寫來源:改過的標籤重新載入後沒有「改自 X」與還原鈕,除非欄位又等於某個具名查詢。
- `PARAM_NAMES` 加 `actOr`、`or`,拿掉 `actCost`、`actPat`;舊網址的這兩個參數安靜忽略。
- 歷史:離散操作留一筆,打字與數字範圍改寫目前這一筆。
