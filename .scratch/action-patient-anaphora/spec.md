# Spec: 回指——動作對象找出「その」實際指的目標

Status: ready-for-agent
Date: 2026-10-30

上游是動作對象線(`.scratch/action-patient/`,票 01〜06 已交件):現行判定把受事者位的指示詞一律當選擇類,算非此卡。站主裁定「その 應該能找到到底是哪個目標」,本規格是 2026-10-30 /grill-with-docs 的定案,取代動作對象規格 Further Notes「指示詞當選擇類」那一條。GLOSSARY.md 已新增「回指」詞條,並在「動作對象」詞條補上指示詞規則。

## 需要你決定的

### 找到目標後怎麼判?

決定(2026-10-30):(a)沿用目標的判定。

- (a)沿用目標的判定(建議):帶數量是非此卡,含此卡是此卡,無數量的群體走全部類比對。「非此卡」更接近確定不動到此卡,張數會少一些。
- (b)只分是不是此卡:目標字面含此卡才判此卡,其餘都非此卡。改動最小,但「自分のモンスターが戦闘を行う…そのモンスター」這種可能就是此卡的仍算非此卡。

### 找不到目標時怎麼判?

決定(2026-10-30):(a)維持非此卡。

- (a)維持非此卡(建議):回指此卡實測極少,這批幾乎都判對;極少數實際指此卡的會判錯。
- (b)改判皆非:寧可漏不要錯,但「破壞+非此卡」這類查詢少掉約 270 框,其中大多本來是對的。

### その発動、その効果、その攻撃 怎麼判?

決定(2026-10-30):(a)事件主人字面是此卡才算此卡。

- (a)主人是此卡才算此卡(建議):このカードの攻撃宣言時…その攻撃 是此卡;相手が効果を発動した時…その発動、このカードが攻撃対象に選択された時…その攻撃 是非此卡。
- (b)沒寫玩家的事件也比對:語意最嚴,但約數百框「その発動を無効」會離開非此卡,而卡文實際很少無效自己。
- (c)全部照舊非此卡:沒有改動,但 このカードの攻撃宣言時…その攻撃 繼續判錯。

### 解析放在哪裡?

決定(2026-10-30):(b)框架抽取加回指欄位。

- (a)只放動作對象判定(建議):frames.json 不變、不必 LLM 檢驗、幾秒重跑完;其他功能用不到解析結果。
- (b)框架抽取加欄位:其他功能也能用;框架線要改、要加檢驗線,並修改動作對象規格 Out of Scope 的範圍。

### 欄位與詞條叫什麼?

決定(2026-10-30):(a)回指,「前項」列為避免用語。

- (a)回指(建議):分詞線的「回指用法」指 以下の効果,詞條要分清。
- (b)所指:沒有既有他義,但 GLOSSARY 已有「以下の」所指。
- (c)前項:和「列舉前項」撞名。

### 找目標的範圍有多大?

決定(2026-10-30):(a)欄位優先、子句字面備援。

- (a)欄位優先、子句字面備援(建議):最接近站主要求;字面備援較易誤認,靠檢驗抓。
- (b)只看框架欄位:誤認少,但約 270 框還是不知道指誰。

### 指示詞只是修飾語時算不算回指?

決定(2026-10-30):(a)不算,受事者照自己的字面判。

- (a)不承接,照自己判(建議):そのモンスターよりランクが２つ高いXモンスター１体 帶數量是非此卡;沒有數量的走全部類比對。語意正確,非此卡會少一些。
- (b)不承接,一律非此卡:張數不變,但自己符合條件的此卡會判錯。

### 交付順序?

決定(2026-10-30):(a)先欄位與檢驗,再接判定。

- (a)先欄位與檢驗,再接判定(建議):第一階段搜尋結果不變,站主先看回指對不對。
- (b)一次到底、最後檢驗:較快,但錯誤會先進搜尋結果。
- (c)不跑 LLM 檢驗:省成本,但字面備援的誤認較難發現。

### ● 選項與跨句怎麼處理?

決定(2026-10-30):(a)編號效果內,● 隔離。

- (a)編號效果內,● 隔離(建議):和發動位置的範圍一致。實測 対象とする→指示詞 跨句號 3,462 框、同句號 16 框,不能限同句號。
- (b)也找同卡上文:範圍最大,但該類只有十多框、誤認風險高。

### 回指欄存什麼?

決定(2026-10-30):(a)字面+區域+玩家。

- (a)字面+區域+玩家(建議):和回填同體例,測試接縫讀得到,拆解頁一眼能看。
- (b)存框架索引:資料不重複,但難讀,框架序也會因約束框架混排而變。

### 対象の 怎麼處理?

決定(2026-10-30):(a)與 その 同等,目標固定取 対象とする 框架。

- (a)同等,目標取 対象とする(建議):規則一致,也避開最近名詞的誤認。
- (b)一律非此卡:較簡單,但 このカードまたは…を対象として 這類判錯。

### 目標含此卡時怎麼判?

決定(2026-10-30):(a)只判此卡,與雪花蓮的裁定一致。

- (a)只判此卡(建議):「その２体の内の１体」「このカードまたは…１体」雖不一定選到此卡,因為可能動到,也算此卡。
- (b)確定才判此卡:較精確,但其中一體或替代項在兩種模式都查不到。

### 單數指示詞能指 このカード 嗎?

決定(2026-10-30):(a)不回指,跳過繼續往前找。

- (a)不回指(建議):原型「目標是此卡」439 框抽樣幾乎全是誤認;極少數真的用 その 指此卡的卡會漏。
- (b)正常當候選:規則一致,但這批大多會誤判此卡。

### 候選多個時選哪個?

決定(2026-10-30):(a)限定語優先,再取最近。

- (a)限定語優先、再最近(建議):較準,實作多一層比對。
- (b)只看中心詞取最近:簡單,但語序不同時 その相手モンスター 會指錯。

### 事件對象的玩家看哪裡?

決定(2026-10-30):(a)也看事件主語。

- (a)看事件主語(建議):相手がモンスターを特殊召喚した時…そのモンスター 判非此卡;回指欄多存事件主語。
- (b)只看字面:欄位簡單,但對手事件的效果會整批離開非此卡。

### 哪些框架帶回指?

決定(2026-10-30):(a)卡、屬性、效果類,含條件位。

- (a)卡、屬性、效果類,含條件位(建議):欄位定義不分位置;動作對象仍只看效果位與代價位。
- (b)只效果位與代價位:少驗幾框,但欄位意義依位置而異。
- (c)所有指示詞:連 その数、その戦闘ダメージ 也解析,候選規則要大增。

## Problem Statement

牌手用「動作對象」把動作類別限縮到此卡或非此卡時,所有 そのモンスター、そのカード、その発動 都被直接算成非此卡,因為判定不知道它們指誰。這有三種錯:

- 「自分のモンスターが戦闘を行う時…そのモンスターの攻撃力」的那隻可能就是此卡,卻出現在「非此卡」,而「非此卡」的定義是確定不動到此卡。
- 「手札のこのカードと手札のモンスター１体を相手に見せて…その２体を特殊召喚」確實會動到此卡,「此卡」卻查不到。
- 「このカードの攻撃宣言時…その攻撃を無効」的攻擊是此卡的,也被算到別張。

站主自己讀拆解頁時,也看不出一個 その 被當成指誰,所以無從檢查。

## Solution

框架抽取替受事者位的指示詞多記一個**回指**:它實際指的目標的字面、區域、玩家,目標是事件對象時也記事件的主語。拆解頁多一欄顯示。

站主看過回指、LLM 檢驗通過後,動作對象判定改讀回指,沿用目標的判定。「此卡/非此卡」切換的介面、網址與查詢語意都不變,只有部分句子的此卡葉、非此卡葉改變。

回指此卡的實例很少,主要的變化是「非此卡」變得更準:可能動到此卡的句子離開「非此卡」。

## Implementation Decisions

**第一階段:框架抽取加回指欄**

- 新增可選欄位「回指」,值是字面、區域、玩家(區域、玩家從目標框架的所在與來源帶),目標是事件對象時另有事件主語;值是上游字面,不是框架序號,接縫 `frames.extract` 讀得到。找不到就省略。
- 解析是框架建立流程裡獨立的一步,排在主題延續、回填、列舉之後,因此讀得到回填後的值。不併進回填:回填處理對象空著的框架且遇句號就停,回指處理已有指示詞的框架且跨句號。回填來的對象是指示詞時也解析。
- 不把回指欄名放進「被回填的欄」清單,該清單有固定的顯示對照。
- 帶回指的條件:受事者位(依態,他動取對象,自動/受身取主語或主題),字面是指示詞開頭,中心詞是卡、屬性或效果類。不分位置。
- 修飾語:指示詞後面接比較或述語,受事者的中心詞是另一張卡(〜より、〜と同じ、〜と異なる、〜以下の…を持つ、〜が記された)時不帶回指。
- 找目標的順序:
  1. 対象の、この効果の対象 → 同編號效果的 対象とする 框架。
  2. 效果類 → 最近的 発動、攻撃、攻撃宣言 等事件框架。主人依序取主語、主題、子句字面的「Xの」。
  3. 其餘 → 往前找框架的對象、主語、主題,中心詞要對得上;單數指示詞跳過字面只是 このカード 的值,並列含此卡的不跳過。
  4. 都沒有 → 往前找子句字面裡中心詞對得上的片語。
- 候選多個時先比限定語(相手、自分、融合、攻撃…)與中心詞,都對得上取最近的。
- 目標本身是指示詞時解到底。
- 範圍是整個編號效果,● 選項隔離:只看共同部分與自己這個選項。
- 拆解頁:框架列尾端追加回指欄(追加、不插入),檢視頁加表頭與說明,重新產生資料,照原網址發布。
- 分類、匯出、索引不讀這個欄位,第一階段的 `data/action_categories.json` 與 `web/data.js` 除建置時間外不變。

**LLM 檢驗線(第一階段的關卡)**

- 新開一條 `llm_check` 線:回指欄進批次檔的欄位清單,錯誤類型加指錯、該指未指、不該指。
- 依回指來源分層:対象の、一般欄位、字面備援、效果類、並列含此卡、修飾語、留空。約 60〜100 張、3〜4 批,固定種子,由 general-purpose 子代理判讀;改用多代理工作流程編排要先取得站主同意。
- 每類錯誤先補會失敗的回歸例子再修規則。第一輪後依錯誤率決定要不要第二輪;彙整進檢驗摘要並發布鏡像。

**第二階段:動作對象讀回指**(站主看過回指後才開始)

- 判定順序:受事者字面指名此卡的規則仍優先(そのカードとこのカード 仍是並列含此卡)。之後受事者是指示詞的走回指。
- 帶回指時,對目標字面跑既有的判定規則:
  - 帶數量 → 非此卡(選擇類)。
  - このカード以外、他の → 非此卡。
  - 並列含此卡、包含此卡(含 その２体の内の１体、このカードまたは…１体)→ 此卡。
  - 無數量的群體 → 全部類比對:區域與玩家用回指欄(含事件主語),發動位置用受事者那個框架當時的位置,卡面比對照舊。
- 屬性跟著目標判(そのモンスターの攻撃力 → 目標)。

## Testing Decisions

- 好的測試只斷言接縫的外部行為:日文例句進,回指欄或此卡葉、非此卡葉出。不測解析函式的內部。
- **框架抽取接縫(第一階段)**:沿用 `test_frames.py` 的寫法(真分詞器與詞典,經 `extract`),直接取回指欄斷言,不改 `brief`。每條裁定至少一個例句:
  - 跨句號、対象の、回填來的對象、連鎖指示詞。
  - ● 隔離:●1 不指 ●2、共同條件兩邊都能指。
  - 單數跳過 このカード;並列含此卡不跳過。
  - 限定語挑選;字面備援;留空。
  - 修飾語不帶;不是卡不帶;屬性、效果類帶;條件位帶。
  - 事件主語;効果類主人取自子句字面(相手モンスターの攻撃宣言時)。
- **分詞鏈匯出接縫(第二階段)**:沿用 `test_export.py` 的寫法(合成標記句與卡面,經真抽取與類別樹),斷言此卡葉、非此卡葉:
  - 選擇類目標維持非此卡;此卡以外;その２体、その２体の内の１体 只在此卡。
  - 全部類:事件主語是相手 → 非此卡;可能含此卡 → 皆非;種族對不上 → 非此卡;此卡移動之後看目的。
  - 效果類主人是此卡、主人是別張、被針對。
  - 留空 → 非此卡;修飾語帶數量與不帶數量;字面指名此卡優先。
  - 決定性重跑逐位元組相同。
- **真資料**:
  - 第一階段以檢驗線與拆解頁抽驗為準。
  - 第二階段對第一階段的匯出逐框比對,差異只能出現在指示詞框架;差異抽樣記在票裡。
  - 真 Chromium 重量票 06 的四組搜尋。
- 索引與查詢引擎的欄位、語意不變,不加測試,既有測試要繼續通過。
- 人工驗收:站主在拆解頁抽看回指;第二階段完成後在本機搜「破壊+非此卡」「アップ:攻撃力+非此卡」「特殊召喚←手札+此卡」。

## Out of Scope

- 選擇類可能選到自己:「フィールドのモンスター１体を対象として…そのモンスター」照 story 17 仍是非此卡。
- 跨編號效果、同卡上文的回指。
- 不是卡的指示詞(その数、その戦闘ダメージ)。
- 指示詞以外的省略受事者(回填線已處理的以外)。
- 其他功能使用回指欄。
- 動作對象懸著的四項:他の、受身的破壊/リリース、靈擺段落預設、この効果,照現行判法。
- 介面、查詢語意、索引欄位。
- push 到 GitHub Pages(等站主開口)。
