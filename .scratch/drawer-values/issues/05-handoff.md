### 耗時(真 Chrome,10 次中位;機器未隔離)

「點鈕到畫完」是對一顆可按的鈕同步 `click()`,含重查、條件列、抽屜、結果區;「抽屜選項」是 `Cond.drawerOptions(標籤)` 本身。

| 標籤 | 桌面 點鈕到畫完 / 抽屜選項 | 手機 |
|---|---|---|
| 破壊(點 位置=代價) | 32.7 / 2.0 ms | 34.8 / 1.9 ms |
| 特殊召喚(位置=條件) | 41.3 / 4.0 ms | 44.5 / 9.0 ms |
| 破壊(耐性)(位置=條件) | 45.3 / 3.0 ms | 31.3 / 1.8 ms |
| 特殊召喚←墓地(位置=條件) | 45.1 / 4.2 ms | 34.7 / 3.8 ms |

都在按鍵預算內。同一套第一次跑時和 python 測試同時跑,點鈕到畫完 38〜90 ms、抽屜選項 2〜7 ms,上表是機器閒時重跑的數字(結果檔也是這一輪)。票 02 量的特殊召喚抽屜選項 8〜10 ms,這次 4〜9 ms,沒拆原因。

### 看到的、照規格

- **破壊(耐性) 的來源欄整欄可見、全部玩家灰**:詞元 破壊 有來源的框(手札、場上),但在否定極性、受身或不成不受的框上沒有;隱藏只看詞元,所以欄留著、全灰(規格判定段)。
- **破壊(耐性) 關掉 否定形=受身 是 0 張**:剩 不成不受 單獨沒有命中。規格「亮著的鈕都能關,關掉可能變 0 張」(決定 b)。
