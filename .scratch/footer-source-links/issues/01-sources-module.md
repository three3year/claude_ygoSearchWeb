# 01: 來源模組（先整理，行為不變）

**What to build:** 外部站的網址集中到一個新的前端來源模組，之後的頁尾連結（票 02）與現有的卡片連結都從這裡取網址。這張票做完，訪客看不出任何差別：卡名照樣連到查牌網單卡頁，縮圖與異圖輪播照樣顯示，網址逐字跟改動前相同。規格見 `.scratch/footer-source-links/spec.md` 的 Implementation Decisions 前三條與「來源清單」表。

對照參照實作：同 ark-keyword 把網址集中在獨立的來源模組（`core/sources.ts`），而且也收結果卡連到的外部站（規格 Q13、Q15、Q16）。與 ark 不同的是建置腳本不共用：本站建置是 Python，ark 的建置腳本從同一份來源模組衍生下載位置。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 新增前端來源模組，照零建置協定（ADR-0007）寫成掛在全域的 IIFE，在呈現模組之前載入。script 標籤寫成 `<script src="…">`，`src` 是第一個屬性。
- [ ] 模組公開頁尾來源清單，五項依現行頁尾順序，連結文字、站名、網址與規格「來源清單」表逐字相符。
- [ ] 模組公開單卡頁網址函式：輸入卡片密碼，輸出查牌網首頁網址加 `?code=<卡片密碼>`。查牌網首頁網址在模組內只定義一次，清單與這個函式共用。
- [ ] 模組公開卡圖網址函式：輸入卡片密碼，輸出卡圖網址，與現行逐字相同。
- [ ] 呈現模組拿掉卡圖與查牌網兩個網址常數，卡名連結、卡片縮圖、異圖輪播三處改呼叫來源模組。
- [ ] index.html 說明載入順序的註解已更新，列入來源模組。
- [ ] 既有前端測試全過：`node --test script/web/engine.test.js script/web/render.test.js`。
- [ ] 在 headless 瀏覽器實際開頁面：搜一張有異圖的卡，確認卡名連結的 href、縮圖的 src、切換異圖後的 src，都跟改動前（main）逐字相同。
