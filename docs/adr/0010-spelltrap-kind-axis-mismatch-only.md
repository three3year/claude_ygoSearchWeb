# 效果類型軸的魔陷十值只收卡片種類不一致的卡

[[效果類型]]軸的十個[[魔陷卡效果]]值,判準是運作身分(ADR-0004):裝備魔法卡自己的效果句當然判「裝備魔法卡效果」。按鈕照字面收的話,選「裝備魔法卡效果」回傳的是全部裝備魔法卡加上少數異類卡——前者用[[卡片子類型]]軸一顆鈕就查得到,真正只有這個軸答得出的是後者(怪獸「當作裝備魔法卡」之類)。因此十值按鈕的成員重定義為:**帶該值效果句、且自身[[卡片種類]]與該值不一致**的卡;三態含排除態都用此定義。想找「所有裝備魔法卡」的人用子類型軸,兩軸分工不重疊。

一致的對應:前九值 ↔ 同名[[卡片種類]];**靈擺魔法卡效果的一致對象是靈擺怪獸**——靈擺怪獸的靈擺效果句一律判它(ADR-0005),照字面比對(怪獸卡≠靈擺魔法卡)會讓這顆鈕變回「全部有靈擺效果的靈擺怪獸」,與排除理所當然的初衷相悖。

排除一致卡後全庫無卡的值,**建置期就不生成按鈕**(與衍生物的 `filterable` 同一個精神,卡數來自建置期 census),前端零推導照舊。側欄的「魔陷卡效果」群組標題隨語意改名為「跨類型魔陷效果」。

## Considered Options

- **保留字面語意、另開「只看不一致」開關或新軸**:現有按鈕與子類型軸的功能重疊照舊,側欄多一層複雜度,而「照字面的裝備魔法卡效果」這個問題其實沒有使用者。
- **改現有軸語意**(採用):一顆鈕一個不重疊的問題;代價是初見者可能意外「選裝備魔法卡效果查不到裝備魔法卡」,由群組標題與本 ADR 承接。

## Consequences

- 排除態亦用新定義:排除「裝備魔法卡效果」擋的是不一致卡的該類效果句;裝備魔法卡自身的效果句不在成員裡,不受這顆鈕影響。
- 舊網址帶魔陷十值條件的,結果集少掉一致卡;被建置期拿掉的值出現在網址時視同未知碼忽略。
- 怪獸側六類、命中 badge 文案([[效果句]]自己的 `k` 值名)、[[必發/選發]]的承載關係全部不變。
