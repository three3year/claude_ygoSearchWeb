# 動作詞元正規化到他動形,態另成框架欄位

[[動作框架]]的動作原本直接記述語的 lemma,同一個動作因此依態分成兩三個詞元(戻す/戻る、倍にする/倍になる、無効にする/無効化される),類別樹票 06 的草案只能把它們在同一大類底下並排,門檻也被分散(攻撃宣言(限制) 只有 2 框開不了葉)。站主裁定(2026-10-27):**[[動作詞元]]是正規形,他動/自動/受身是同一個詞元、以他動形為名,差別記在新欄[[態]]**(他動/自動/受身);受身全語料都記(接原本的被動旗標),自動/他動只在被統一的詞元上記,其餘框架空。數值升降是明示的例外:以卡文主流的 アップ/ダウン 為名,態由受事者的助詞判。同一次裁定一併把縮寫與全名(A召喚/アドバンス召喚)歸一到官方縮寫,並把 N に なる/する 的補語是封閉值域或屬性名詞收尾時改成不併入詞元、整段留目的欄(闇属性になる → にする+目的 闇属性)。

## Considered Options

- **不統一,詞元維持,類別線用中類並排**:態是真資訊、不動框架;但總覽頁同一動作仍是兩個節點,門檻分散,每個中類都要手工把同一動作的葉收在一起。
- **只併受身(無効化→無効にする)**:改動最小;但「受身併、自他不併」說不出理由,規則不一致。
- **統一到他動形、態另成欄**(採用):總覽一個詞元節點、葉名短、門檻合算;代價是「ダメージは０になる」記成 にする(態 自動)與原文字面不同,拆解頁要靠態欄讀回來,類別線的規則表與葉名要跟著改一次。

## Consequences

- 詞元不再等於原文述語的字面;原文在框架的子句欄,詞元是對照表的輸出。對照表與不併判準是框架線的封閉表,類別線與檢驗腳本讀同一份。
- 態欄的空值是「沒判」,不是他動;要把自動/他動擴到全語料得先在分詞詞典登記自他屬性,另開線。
- 類別線靠態欄分辨舊的 無効化(受身)與 無効にする(他動)、戻る(自動)與 戻す(他動);態要不要當葉條件由類別線決定。
