# 派子代理的模型

主會話派子代理(Agent 工具)時,`model` 參數照下面的判準由上往下選,第一條符合就停;implement-spec 本身沒有模型選項,每次派工都要選。本檔只寫本專案的判準與例子;全域 skill(`review-mirror` 等)的子代理照 `~/.claude/docs/subagent-models.md`。

**判準**:

1. 工作的對錯能由既有的自動守門判定(全語料基準差異 0、md5 不變、digest ok、接縫測試),而且不寫新邏輯,只搬現有程式、跑現成工具、重發既有產物 → `sonnet`。
2. 工作的對錯能由同樣的守門判定,而且做法規格已寫死(照形狀寫、統計、發布)→ `opus`。
3. 其餘一律不傳 `model`(跟主會話同模型)——包括拿不準的。

`sonnet` 子代理守門不過或遇到衝突就停手回報,主會話改派 `opus` 接手。

合併:能 `git merge --ff-only` 的主會話自己做(實作者回報前已自合整合分支,多半是這種);有衝突才派 `opus`,在該票的工作樹內合、重建產物、全綠後回報。

例子(只是例子,不是清單;對不上判準就不傳):

| `sonnet` | `opus` | 不傳 `model` |
|---|---|---|
| 步驟重排、全套重跑驗收、鏡像與拆解頁重發、無衝突的合併 | 探索筆記、基準/驗收工具、匯出序列化、評估器、目錄機械改寫、張數統計、拆解頁/報告、交件文件、有衝突的合併、Standards 審查 | 改判定規則、逐卡判「改讀後更對」、刪正則式改讀結構化欄且要零行為改變、讀日文原文挑錯(LLM 抽驗的審閱者)、Spec 審查、code review 修正、裁定落地 |

依據:2026-11-01 named-queries 共 17 個子代理約 5M token,`sonnet` 與 `opus` 欄那類約 2.5M 用主會話的模型沒有必要。`sonnet` 欄是照該批票面內容分出來的,還沒實跑驗證過。
