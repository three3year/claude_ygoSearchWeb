# 05 — 卡片參數軸

**What to build:** 使用者能用「暗屬性、龍族、等級 8 以上、攻擊力 2500 以上、但不要融合」
這種條件找卡。這是條件最多的一軸,也是 ADR-0008 的「按鈕由[[值域正典]]生成」第一次真正
發揮作用的地方——HTML 只留空殼容器,種族有幾個、[[卡片子類型]]有幾種,全部由
`window.VOCAB` 決定。

分類類條件是**三態鈕**:點一下=包含,再點=排除,再點=取消。同一軸多選是 OR,不同軸之間
是 AND,同一軸同時被包含與排除時**排除優先**。

順帶把 MD 稀有度、Genesys 點數、OCG・TCG 三個欄位做成可搜條件——它們在 oldProject 只能
顯示不能搜。

**Blocked by:** 02 — 完整卡片呈現、03 — 搜尋骨架與卡名軸

## Comments

2026-08-14 實作完成(與票04 同一輪)。`query.js` 多一張欄位表與側欄生成,`engine.js` 多
三個判定函式(三態、範圍、`?`),`index.html` 多一個空殼容器 `#critParams`。接縫 3 測試
多 16 條。

**一張欄位表(`FIELDS`)同時餵給按鈕生成、`read()` 與 `clear()`,順序就是側欄的排列。**
分成三份的話,加一軸要記得改三個地方,而漏改的那一處會安靜地不生效——這與 ADR-0008 要擋
的失效模式是同一個形狀,只是換了個地方發生。

**[[卡片子類型]]是一個軸的三段,不是三個軸。** 三個軸的話「融合怪獸或速攻魔法」會變成軸間
AND、永遠零筆。短碼跨側重複(cdb 位元 0x80 在怪獸側是儀式怪獸、在魔法側是儀式魔法),
所以條件帶大類前綴 `m:ritual` / `s:ritual`——不帶的話「選儀式」會把儀式魔法一起撈進來。

**「按鈕由正典生成」的可測形狀是 `Query.axes()`。** 接縫 3 的沙箱沒有真的 DOM,而 DOM 那
一層只是照這份清單擺按鈕;清單由 `window.VOCAB` 導出(連軸標題都是 `VOCAB[dom].zh`,HTML
連軸叫什麼名字都不知道)。測試餵一份多一個種族的 VOCAB 進第二個沙箱,斷言按鈕多一顆。
真實索引冒煙對帳過:大類 3、怪獸子類型 15(+[[衍生物]]不做鈕)、魔法 6、陷阱 3、屬性 7、
種族 26、連結標記 8、MD 稀有度 4、OCG・TCG 3,九軸全部等於 VOCAB 的成員數。

**排除優先是「排除掃完才算數」而不是「排除寫在前面」。** 命中包含就提早回傳的話,排在後面
的排除條件會被跳過,排除優先就只在寫法順序上成立。測試因此把同一組條件的兩種書寫順序
都斷言一次。看得出差別的是多值的軸(子類型):同一張卡可以同時中包含與排除。

**「沒有這個參數」不是 0,也不是 `?`。** 三者在索引裡是三種不同的形狀,範圍條件因此對
「缺欄位」與「負哨兵值」都不命中。三個受益者:罠モンスター(索引裡根本沒有種族/屬性/
等級/攻守——搜「岩石族」得 274 張,一張陷阱都沒有)、連結怪獸的守備(沒有 `df` 這個鍵,
所以不算 `?`)、攻守 `?`(83 / 54 張,不被 `攻擊力 0～0` 撈到)。靈擺刻度 0 反過來是真的
值(28 張),測試守著這一條。

**MD 未實裝的 416 張不是值域成員,所以沒有按鈕。** 要找它們的路徑是四種稀有度全排除
(「有稀有度的都不要」= 沒有這個欄位的那一批),實測 416 張,與 spec 的基線相符。

**條件變多之後「搜尋」釘在側欄頂端。** 側欄自己會捲(卡片參數一長串),調完種族按鈕還要
捲回最上面才按得到,那是每一次搜尋都要付一遍的代價。
