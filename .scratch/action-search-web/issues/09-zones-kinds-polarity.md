# 09: 從、到、段類別勾選、極性三選一

**What to build:** 動作搜尋區塊多四組選項:從哪裡、到哪裡、段類別、極性。這四組在 Python 的查詢判斷裡都已經有,這張票是把它們接到網站上。

- 從、到:各選一個區域,可以再指定是我方的還是對手的。區域的選項由索引的表生成。子區域算在上位區域內;推得的值不算。條件要落在同一條對象線上。
- 段類別三個勾選:效果、代價、觸發條件,預設勾效果和代價。至少要勾一個,只剩一個勾著時不能取消。
- 極性三選一:會做、限制、抗性,預設「會做」。
- 介面到查詢的對應:

| 介面 | 查詢 |
|---|---|
| 勾「效果」 | 段類別 效果、召喚手續、限制 |
| 勾「代價」 | 段類別 代價 |
| 勾「觸發條件」 | 段類別加上 條件(現有的條件段開關只在查詢沒給段類別時才有作用,所以要直接放進段類別範圍) |
| 極性「會做」 | 做、可以、必須 |
| 極性「限制」 | 不能、只能 |
| 極性「抗性」 | 不會 |

- 這些選項跟著查詢狀態存進瀏覽紀錄,「清除條件」會還原成預設。

- 規格:需要你決定的「Q14」「Q15」與前三題裡的「段類別的三個勾選全部取消時怎麼辦?」「段類別「限制」在玩家介面要不要跟著「效果」一起算?」;實作決策「玩家介面」;使用者故事 6、7、10–14;測試決策「接縫三」「兩邊答案一致」。
- 參考:原型的擺法。與原型不同:原型可以把三個勾選全部取消,這裡不行。

### 實作者(as/09)

**做了什麼**
- `web/js/action.js`(`Action`):
  - 動作條件多四個欄位:`from`、`to`(`{ zone }` 或 `{ zone, side }`,方只認我方、對手)、`kinds`(勾選 `eff`/`cost`/`cond`)、`pol`(`do`/`limit`/`resist`)。正規形不寫預設值(勾效果與代價、極性「會做」),所以沒動過這兩組時存進瀏覽紀錄的 `act` 和票 08 一樣。認不得的值忽略:區域不是字串就整欄不算、方認不得就不限、段類別裡認不得的那個拿掉,全部拿掉就是預設。
  - `count`:正規形裡一個欄位算一條(動作詞選幾個仍是一條;從、到、段類別、極性不是預設時各算一條)。
  - `rowQuery`:照 spec 對應表換成 `run_query` 的鍵。勾效果 → 效果、召喚手續、限制;代價 → 代價;觸發條件 → 條件,**另加 `include_condition: true`**(見下面「請站主知悉」第 1 點)。極性:會做 → 做、可以、必須;限制 → 不能、只能;抗性 → 不會。從、到 → `from_zones`/`to_zones` `[{ zone, side }]`(沒指定方時 `side: null`,只比區域)。沒動過的欄位不寫鍵,預設的列查詢與票 08 逐字相同。
  - `prepare` 多讀線(段的第 7 格:做動作的一方、從、到、物件在不在)與區域、方的值表;`match` 多一段線的判斷 `lineTest`:從、到要落在同一條線上,做動作的一方那條線、物件表裡找不到的線不算,推得的從、到不算(照 `row_match._line_matches`,推得終點開關固定關)。之後加線的條件(被動作的卡)的票加在 `lineTest` 裡。段類別同 Python:列查詢沒開條件段開關時拿掉 條件。
  - `zoneOptions(index)`:區域選項由索引的區域表生成,依列數排(同列數照索引的順序)。`toggleKind(kinds, kind)`:勾選點一下之後的勾選,只剩一個勾著時不能取消。
- `web/js/action-panel.js`:動作詞下面依序是「從哪裡」「到哪裡」(各兩個下拉:區域〔不限 + 索引的區域〕、方〔不限哪一方/我方/對手〕)、「這個動作是」(效果、代價、觸發條件三個勾選;只剩一個勾著時那一個停用)、「極性」(會做、限制、抗性三選一,下面一行說明「限制:不能、只能;抗性:不會被…」)。擺法照原型;與原型不同的只有勾選不能全部取消(票上寫明)。`read`/`write`/`clear` 帶這四組;「清除條件」把它們還原成預設;還原帶這些欄位的紀錄時區塊展開。標題列的數字改成 `Action.count`(票 08 是選了幾個動作詞;現在選了從、沒選動作詞也看得到有條件)。

**請站主知悉(實作者自己定的或發現的)**
1. 票上與 spec 寫「現有的條件段開關只在查詢沒給段類別時才有作用」,實際的 `row_match._normalise` 是:開關關著時,查詢給的段類別裡的 條件 也會被拿掉(開關是閘門)。所以勾「觸發條件」換成的列查詢是段類別加上 條件,**同時**開條件段開關;前端的比對照同一條規則。結果與票上要的相同,只是對應表那一格多一個鍵。
2. 從、到的方照 Python 現行判法**逐字比**:查「對手的墓地」只命中寫明對手的線,寫「任一方」(「自分または相手の墓地から」)、「雙方各自」的不算。spec 的 Q17「寫的範圍比查詢寬也算」寫的是誰與原因,沒講區域的方。全庫上「從對手墓地特殊召喚」29 張;若「任一方」也算,多 10 張(39 張;「雙方各自」0 張)。要不要讓區域的方也照 Q17 涵蓋,請站主決定(要的話 Python 與前端兩邊一起改,另開票)。
3. 只改段類別或極性、沒選動作詞也算動作條件(例如只選「抗性」:有任何「不會」段的卡,全庫 810 張)。只勾「觸發條件」不選動作詞會得到幾乎所有有效果的卡;這是組合本身的意思,沒有另外擋。
4. 方的下拉只有我方、對手(票上的「可以再指定是我方的還是對手的」);索引裡的其他方(任一方、持有者、自身、雙方各自)不列。
