## Comments

實作:`tagcard.py` 新增「重跑合併」一節(`_index_existing` / `_merge_clause` / `_apply_late_attestation` / `_report_orphans`),掛在主迴圈 `_dedupe_indexes` 之後、統計之前;`test_tagcard.py` 新增 7 個測試類別共 26 個測試(全檔 87 → 113 個);CLI 薄殼預設把輸出檔讀回來當 `existing`,`--ignore-existing` 才從零重建。

實作期間的四個決定,與票面規格有出入或補充:

1. **`needs_review` 是資料欄位,不只是報告項目。** 票面寫「標記為待複查並列進報告」,但旗標若只活在報告裡,下一次重跑就再也不知道這一行還沒被人看過(重跑後既有行的雜湊已等於新雜湊,變動的證據消失)。因此新增第 13 個效果句欄位 `needs_review`(布林,置於 `source` 之後),跨重跑存活到使用者把它改回 `false` 為止。報告每次列出所有 `needs_review` 為真的行,並標明本次是否為新變動(`hash_changed`)。spec 的欄位表與 ADR-0001 已補上這一欄。

2. **`source: "rule"` 的行照常重算,不在保留之列。** 票面的「雜湊相同時沿用既有行的全部判定」若照字面實作,規則層就永遠凍結在第一次建置的結果,Story 49「規則變更後全表重跑並逐行列出差異」不可能成立,票06 的規則層演進也推不到資料上。界線改為看**這一行裡有沒有一次性的成果**:`manual` / `official` / `llm` / `llm_then_rule` 永不覆蓋,`rule` 是當前規則層對當前文本的純函式輸出、沒有成果可保留,照常重算並把「重算後與既有不同」列進報告。ADR-0001 的措辭已同步。

3. **官方對官方以最新來源為準。** 既有行是 `official`、本次也判出 `official` 時採用本次的值,不同則列進報告的「官方改了自己的裁定」。Story 29 的「官方明示永不被重跑覆蓋」講的是不被**後來的規則或判定**推翻,而補足情報更新後的新官方值與舊值同權威,凍結舊值只會讓標記表與來源資料脫節。實測全表 0 筆。

4. **人工修正與官方一致時保留 `manual`,不升為 `official`。** `manual` 是「使用者看過這一行」的證據,升級會把這個資訊洗掉。不一致時同樣只列進衝突清單、絕不改動。另補一份「既有判定對不到任何一行」清單——拆句法變動會讓某一行整個消失、判定跟著蒸發,這是票面沒列但與「不靜靜覆蓋使用者的修正」同一件事的漏洞。

升為 `official` 的行整組改吃本次的官方+規則結果(類型既已確認一致),但**本次算不出來的欄位不把既有的值洗成 null**——規則層抓不到發動子句時 `optional` 會是 `null`,若無條件覆蓋就會把票08 判定出來的必發/選發吃掉。`tags` 完全不由官方決定,任何情況都沿用既有值。
