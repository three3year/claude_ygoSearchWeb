# 網站搜尋讀分詞鏈匯出的類別檔,分詞程式仍留在試點目錄

[[動作類別]]要上網站搜尋(2026-10-30 /grill-with-docs 定案),但分詞→框架→類別的程式與產物都在 `.scratch/effect-tokenize/`(試點目錄,產物不入版控),類別樹還在一輪一輪修。站主裁定:**分詞鏈多匯出一份「每句標記句的葉(分效果位/代價位)、原文雜湊與類別樹」寫進 `data/` 入版控,網站索引建置只讀這份檔;分詞程式先不搬出試點目錄**。上線功能因此依賴試點程式的產出,但不依賴它的執行——網站建置不呼叫分詞鏈。

## Considered Options

- **索引建置直接呼叫分詞鏈**:一個指令從原文建到索引;但網站建置綁上試點程式,建置變慢,試點目錄的任何改動都會直接打到線上。
- **先把分詞鏈搬到 `script/`**:結構乾淨;但類別還在改,現在搬等於邊搬邊改,是一整條線的工作,會把「先看到搜尋樣子再修類別」的順序倒過來。
- **匯出檔入版控、試點程式不搬**(採用):網站建置照舊只讀 `data/`;代價是類別規則一改要兩步(重跑分詞鏈更新匯出檔,再重建索引),而且匯出檔可能過時。

## Consequences

- 匯出檔每句記原文雜湊;索引建置發現雜湊與 `data/tag_cards.json` 對不上就建置失敗(不靜默沿用過時類別),匯出檔裡的葉不在類別樹裡也失敗([[值域正典]])。
- [[差值更新]]流程多一步「重跑分詞鏈」,否則新卡或勘誤會擋住建置。
- 類別定版後再另開線把分詞鏈搬出試點目錄;搬之前,`.scratch/effect-tokenize/` 是網站資料的上游,不能當草稿隨手刪改。
