## 問題陳述

站主用動作搜尋時,指定從、到的「哪一方」常常查不到該有的卡:

- 卡文寫「自分または相手の墓地から」(任一方)、「お互いに」(雙方各自)的,查「對手的墓地」不命中;Q17 定了誰與原因寫得比查詢寬也算,從、到的方卻還是逐字比。
- 很多寫法根本不寫方:「墓地へ送る」「除外する」「フィールドのカードを破壊する」「持ち主の手札に戻す」。現在指定方時一律不命中,所以「送墓 到對手的墓地」「除外 到對手的除外」「返回 到對手的手牌」都是 0 張。
- 「卡名包含」在網站上比中日英名與別名,在 Python 上只比日文名:打中文「黑魔導」網站有 1,259 張、Python 0 張,兩邊答案不一致,Python 驗不到中文的結果。

## 解決方案

- 區域的方照 Q17 涵蓋:查詢指定我方或對手時,寫任一方、雙方各自、持有者的區域都命中。卡文沒寫方、但照遊戲規則推得出方的,建置時把方寫進卡片結構:從的區域沒寫方、但物件寫了「自分の」「相手の」的照物件寫的;其餘場上沒寫方是任一方;墓地與除外照持有者(此卡是我方,其他卡是持有者);「自身の」照段的誰。Python 與網站讀同一份結構與索引,判法同一條。
- 卡名包含兩邊都先把打的字換成一組卡片編號:中文名、日文名、英文名、別名任一個含這段字的卡,加上「〜として扱う」當作的卡名對到的卡;被動作的卡在這組裡就命中。支援 `%` 萬用字元、全形當半形、大小寫不分。Python 的玩家查詢與網站做法相同,兩邊答案永遠一致。卡文裡的「カード名に「X」を含む」照舊只比日文。
- 介面不變:沒有新按鈕、新選項;玩家只會看到查得到的卡變多。

## 實作決策

### 規則推得的方(卡片結構)

- 卡片結構建置在段與對象線抽完之後,對每條對象線的從、到的每個區域補方。「沒寫方」指區域條目沒有方,不看來源;已經有方的(不論來源是明寫、預設或沒有來源的繼承)不動,自身除外。依序套用:
  - 從的區域沒寫方、物件的條件式寫了控制方(「自分の墓地の」「相手の表側表示モンスター」;物件是子集或剩餘時往上找它的來源物件)→ 照寫的方(我方、對手、任一方)。到的區域不用這條:物件的控制方說的是它出發時的位置,不是去處。
  - 場上系區域(場上、怪獸區、魔陷區、P區、場地區、EX怪獸區、主要怪獸區)沒寫方 → 任一方。
  - 墓地、除外沒寫方 → 物件是此卡的是我方;其他物件是持有者。
  - 方是自身 → 換成這一段的誰,解法同查詢判斷算誰的那一套:我方、對手照填;主動句沒寫誰算我方的,填我方;動作回指解回它指的那一段的誰;解出來是雙方各自、不限定或判不了 → 任一方。
- 補上或換掉的方,來源記「規則」:`SIDE_SOURCES` 加這個值。抽取時方的值域不變(`SIDES` 仍含自身);建置完成的結構裡不再有自身。
- 其他區域(手牌、牌組、額外牌組、牌組頂、牌組底、素材)沒寫方的照舊不補。
- 前提、條件式的位置原子、卡片屬性表的位置條件不補,只補對象線的從、到。
- 反向檢查:來源是規則的方不寫回字面(與預設、None 同樣處理)。有字面 `text` 時照字面寫回;驗證字面與區域一致的那一步,來源是規則的條目只比區域、不比方與來源(「自身の手札から」的字面解出自身,結構裡已換成段的誰;「フィールドの」解出沒有方,結構裡是任一方)。
- 覆蓋報告與既有統計照常產出;若有報告列方的分布,加上「規則」一欄。

### 比對規則(Python 與網站同一條)

- 查詢的從、到給了方(我方或對手)時,區域的方是查詢的方、任一方、雙方各自或持有者,就算該區域命中。沒給方時照舊只比區域。
- 這條規則不歸不限定開關管(同 Q17)。推得開關照舊決定推得的區域算不算。
- Python 改的是查詢判斷比區域的那一處;網站改的是前端查詢引擎比區域碼的那一處(區域碼是區域 × 方的格數 + 方,改成接受同一區域、四種方的碼)。

### 卡名包含換成卡片編號

- 查詢側的卡名包含(`condition` 裡的 `卡名包含` 原子)先換成一組卡片編號,再判「被動作的卡在這組裡」;判法照既有給條件:滿足條件的卡與這條線的候選卡有交集就命中。
- 一張卡的名字有:中文名、日文名、英文名、別名(中文卡文「※ 別名」抽出的譯名,與前端索引的同一個抽法),以及它「〜として扱う」當作的每張卡的這四種名字;當作的卡名對不到卡的,用日文字面。當作的卡名取卡片屬性表 `name` 的第二列起,不看位置條件。
- 當作的卡名對到卡的比法:先比日文卡名原字,再比全半形折疊、去空白後的字。
- 比對:打的字先去頭尾空白(同網站 `condOf` 現在的做法),打的字與名字都再做網站現在的折疊(全形英數與全形空白當半形、小寫);打的字以 `%` 切成幾段,去掉空段,各段依序出現在名字裡就算(同主搜尋卡名框的萬用字元)。去頭尾空白後沒有非空的段時等於沒給卡名包含。
- 卡文裡的「カード名に「X」を含む」(卡片結構條件式的 `卡名包含` 原子,判候選卡用)照舊只比日文卡名,含位置條件;只有查詢側換成卡片編號。實作上查詢側與卡文側要分得開,例如查詢進入比對前先把原子換成編號集合。
- Python 的 `run_query` 讀得到別名:沿用前端索引建置的別名抽法(同一個函式,不另寫一份)。
- 動作索引加一節「當作的卡名」:每張有當作卡名的卡 → 對到的卡號清單,與對不到卡的日文字面清單。網站用它和前端索引的四種名字算出同一組卡號。節名照既有命名慣例,解碼端與 Python 的 `decode_action_index` 一起加。
- 網站的 `fitsCondition` 卡名包含那一支改成上面的比法(四種名字 + 當作的卡名 + `%`);一次查詢裡同一段字只算一次卡號集合。

## 測試決策

- 好的測試只看外部行為:給卡文或查詢,看結構裡的方、查詢命中的卡號;不看中間的資料結構。
- **卡片結構建置**(既有的建置單元測試):每條規則各有正反例——從的區域照物件寫的控制方(「自分の墓地の」記我方,到的區域不用控制方);場上沒寫方記任一方、來源規則;此卡送墓記我方、其他物件送墓記持有者;「墓地から」沒寫方仍是預設我方;自身照誰(我方、對手、主動句沒寫誰算我方、動作回指解回「ドローしたプレイヤー」那一段、雙方各自 → 任一方);已經有方的(我方、對手、任一方、雙方各自、持有者,含沒有來源的繼承)不被改;手牌、牌組沒寫方的不補。全庫反向檢查照樣通過(含「フィールドの」「自身の」有字面的條目)。
- **Python 的 `run_query`**(既有查詢測試,`script/action_structure` 的 `test_*.py`):指定我方、對手時任一方、雙方各自、持有者命中;此卡的墓地查對手不命中;沒指定方結果不變;推得開關照舊。卡名包含:中文、日文、英文、別名、當作的卡名(含對到卡後用中文名比)、`%`、全形、大小寫、頭尾空白、只有空白或 `%`;卡文側的「カード名に「X」を含む」判候選卡照舊只比日文(既有測試一條不改、全部通過)。
- **兩邊答案一致**(`test_web_parity.py`,既有):條件組加上指定方的從、到(墓地、除外、場上、手牌各我方與對手),以及卡名包含的中文、英文、別名、當作的卡名、`%`、全形;網站命中的卡號 = `run_query` 的全部 ∪ 經引用,無法確認的卡號 = 未解析,逐張相同。
- 前端接縫三(`node --test`)不另加測試:介面沒變,比對由上一條驗。既有測試全部通過;前端測試夾具的動作索引要補「當作的卡名」一節。
- 全庫統計:重跑 action-search-web 的常用查詢(中文「黑魔導」那條改為預期相同)與本規格的 `side_coverage.py`,數字寫進收尾摘要。
- 先例:action-search-web 票 09(從、到)、票 13(給條件、兩邊答案一致的 `ConditionParityTest`)。

## 不做的事

- 持有者的方細分(例如從「相手フィールドの」或物件的控制方推去處的持有者是對手):到的區域先照持有者兩邊都命中,站主用過再看。
- 前提、條件式位置原子、卡片屬性表位置條件的方。
- 當作的卡名的位置條件。
- 平假名、片假名不分;語言切換鈕。
- 卡文裡「カード名に「X」を含む」的判法。
- 經引用的 `via` 樹縮小(action-search-web 收尾摘要第四題,另議)。
- 介面的任何改動。

## 補充

- 數字是在查詢時模擬新規則量的預估,實作後以重建的結構重量為準;自身在模擬裡一律當兩邊,全庫 67 個區域條目;物件寫的控制方在模擬裡只認我方、對手(任一方照其餘規則,結果相同)。
- action-search-web 的人工驗收還沒做;它已併進 main,本規格接在上面做。
- 稽核時補的兩點(grilling 沒有逐題問,照「卡文沒寫方才套規則」的前提補):從的區域沒寫方、但物件寫了「自分の」「相手の」的,照物件寫的方,不套持有者;自身的誰用查詢判斷同一套解法(主動句沒寫誰算我方、動作回指解回去)。
