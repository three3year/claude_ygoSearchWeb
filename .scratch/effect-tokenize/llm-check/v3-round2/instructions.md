# 第三版論元 LLM 檢驗(同批複檢):子代理工作說明

你會拿到一份批次檔(`batch-<k>.md`):每張卡一節、每句效果句一段,列出**原文**與程式抽出的**框架**。動作框架一列長這樣:

`框架 n:[位置] 動作(極性・被動)| 主題=… | 主語=… | 對象=… | 來源=… | 所在=… | 目的=… | 內容 | 子句=…`

主題/主語/所在沒有值時不列;格後的「(回填)」表示值是規則從前面的述語接過來的,「(推得)」表示值是規則依動作補的、原文沒寫。約束框架(`[約束 …]`)不是本輪範圍。

你的工作:**看原文,挑出動作框架的錯**,重點是本輪新規則(主題/主語、來源/所在、推得、回填轉欄),寫成 `findings-<k>.json`。

## 新欄位的判準(以此為準,不要用自己的直覺改判)

1. **主題/主語**:「は」前的片語記主題、「が」前的片語記主語,同一子句有多個時取離述語最近的。には/では/とは/にも 的 は/も 是後綴,不算主題。定語裡的 が(「X」のカード名が記されたモンスター、自分が受けるダメージ)屬名詞片語,不出主語。被動句的受事者(このカードは破壊されない、このカードが墓地へ送られた場合)留在主題/主語,對象欄空著是對的。屬性 が 在名詞片語裡(攻撃力か守備力が２０００のモンスター、属性が…と同じモンスター)併進對象、不出主語。沒成框架的條件子句(自分のLPが相手より少ない場合、…)的 が 屬那個子句,後面的述語不帶這個主語。附加子句「〜が…を素材として L召喚された場合」「〜が…を発動するためにリリースされた場合」的主語屬後面的述語(L召喚/リリース),標(回填),附加子句的框架不帶。
2. **主題延續**:子句沒有自己的主題時,沿用同一句(句號、● 之內)前一個主題,標(回填)。到句號、新的主題、或一個自己帶 が/は 的條件子句(〜場合/〜時/〜限り)為止。主語**不延續**。條件子句裡主題寫在自己主語之前(このカードは、相手モンスターが攻撃した場合、攻撃できない)時,主題屬主句:條件框架沒有主題、主句的主題=このカード(回填)。主題是「Xの攻撃力/守備力/効果/レベル」(不含 カード名)時,延續給下一子句的是 X(装備モンスターの攻撃力は…アップし、…破壊されない 的 破壊 主題=装備モンスター)。
3. **來源/所在(受事者的區域)**:受事者——主動句是對象,被動句是主語(沒有時是主題)——片語裡的區域(墓地の、相手フィールドの、自分の手札・墓地の、除外されている自分の、デッキの一番上の…)切出來:
   - 戻る 是移動類的自動詞:移動的卡是主語(沒有時主題),照被動句的取法切區域。
   - 動作是**移動類**(加える、ドロー、送る、捨てる、リリース、除外、戻す、戻る、置く、セット、装備、移動、特殊召喚與各召喚法)→ 記**來源**;其餘動作(破壊、対象とする、選ぶ、アップ、無効にする、融合素材とする…)→ 記**所在**。素材類(融合素材とする 等)記所在是規格決定,不是錯。
   - 區域在片語開頭或中間都切(対象のモンスター以外の自分フィールドの表側表示モンスター → 對象=対象のモンスター以外の表側表示モンスター、區域=自分フィールド);受事者欄只少掉那一段,其餘字面不變。
   - 並列的受事者各帶區域時取聯集,以「・」並列(自分の墓地のモンスター１体と相手フィールドの…モンスター１体 → 自分の墓地・相手フィールド)。
   - 整個受事者就是區域(手札を１枚捨てる、相手のEXデッキを確認する)或片語以區域收尾(このカード以外の手札)時,區域記進來源/所在、受事者欄維持原文。
   - 原文已經用 から 寫了來源時不切。主動句的主題(執行者)不切。片語是數量(…の数×100ダメージ)時不切。定語子句裡的區域(…自分の墓地の通常モンスターと同じとなる相手フィールドのモンスター)不是受事者的。
4. **推得**:原文沒寫、由動作唯一決定的格補上並標(推得)——除外→目的 除外;捨てる→目的 墓地、來源 手札;ドロー→目的 手札、來源 デッキ;特殊召喚與各召喚法、セット→目的 フィールド;加える→目的 手札。原文有字面時用原文、不標推得。装備、リリース、破壊 不補。否定框架、條件位置的框架也補。去處被其他效果改寫(破壊される代わりに除外する)不在推得的範圍。
5. **回填轉欄**:「〜を(融合)素材として除外し/墓地へ送り/戻し/リリースし」的 除外 等接過素材的對象與區域(標回填)。「〜を選んで/選び」之後缺對象的述語、か 並列的成員,接過上游的對象與區域(標回填);上游的區域交給下游時,下游是移動類就放來源、否則放所在(墓地のモンスター１体を選んで特殊召喚する → 特殊召喚 來源=墓地(回填))。下游原文自己有來源或所在時不填;回填來的區域蓋過推得的同欄。延續的主題落在沒有主語的被動框架時,主題的區域照第 3 條切,主題與所在都標回填。

## 錯誤類型(type 欄只能填這些字)

本輪新增(請優先檢查):
- `區域切錯/漏切`:受事者片語裡的區域該切沒切、切錯段、切成來源/所在放錯欄(移動類卻記所在等)、對象剩餘字面不對、聯集漏了或多了。
- `推得錯`:該補沒補、不該補卻補了、補的值不對、原文有字面卻標推得。
- `主題/主語錯`:子句內的主題/主語收錯(收到定語裡的 が、收錯片語、漏收)、被動受事者被搬進對象。
- `延續錯`:主題延續該接沒接、不該接卻接了(跨句、越過新主題/條件子句)、接錯值。
- `回填錯`:回填的對象/區域接錯、該接沒接、轉欄放錯(來源/所在)。

既有類型(新規則以外看到明確的錯也可回報):`漏抽動作`、`論元抽錯`、`位置判錯`、`極性判錯`、`多抽(不是動作)`。

## 回報格式

寫 `findings-<k>.json`(UTF-8,k 與批次檔相同):一個 JSON 陣列,每筆
`{"card": 卡號(整數), "index": "①"/"②"/"效果外文本 0"…(句的標籤,照批次檔「### 句」後的寫法), "frame": 框架序(整數)或 null, "type": 上列之一, "reason": "一句話,引原文片段說明哪裡錯、應該是什麼"}`。

- 沒有錯就寫 `[]`。一個框架有多個問題各寫一筆。
- reason 用繁體中文,引原文照抄日文。
- 只回報有把握的錯;判準寫在上面,和判準不同的地方照判準,不要改判準。拿不準的在 reason 開頭寫「(待確認)」。
- 不要改動批次檔或其他檔案。
