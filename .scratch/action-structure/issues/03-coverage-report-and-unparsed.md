### 2026-11-07 票 03 實作(as/03)

**覆蓋報告**:`script/action_structure/coverage_report.py`(純函式 `build_coverage` / `render_coverage`)+ 薄殼 `build_report.py`,另開一支不動 `build_structure.py`(避開票 02);讀的是產物 `data/action_structure.json`(走 `load_structures`)與 `data/cards.json`,不需 `data/sources/`。輸出 `.scratch/action-structure/report/coverage.md`(入版控、不寫時間、排序固定;時間與雜湊只印 stdout)。產物張數與總表張數不符 → exit 1、不寫檔。報告節:總覽(卡片總表 14,207 = 有結構 14,187 + 無官方日文 20)、卡片層無官方日文、區塊(依種類;解析不出依原因附卡號)、段(依類別;依原因附卡號)、段的各格(有值/留空/解析不出;對象線從/到依來源)、物件(依來源;依原因附卡號)、不認得的「」名稱。卡號一行一個、列全部不截斷(約 39k 行、500KB,與 `.scratch/text-format/report.md` 同量級)。

**未解析組**:`run_query` 結果多 `groups["未解析"]`(卡號列表,張數 = 長度)與 `unparsed`(每張 `{"id", "reason", "segments": [{"segment", "reason", "text"}]}`)。進組規則:無官方日文的卡任何查詢都列(`reason` = 無官方日文、`segments` 空);段整段字面含每一個查詢動作詞(經同義表 `PREDICATE_STEMS` 換成述語字面)、且(段標解析不出,或對象線引用的物件標解析不出,或所在區塊因種類判不出被 `block_kinds` 篩掉)而沒命中的段列進去;段類別與極性篩選對未解析組同樣生效;任一段命中的卡只在命中組。**實作決定,請站主留意**:比的是整段字面、不是只比原述語字面——子句切錯時(「このカードが特殊召喚に成功した時、…めくる事ができる」切出的述語是「２枚までめくる事ができる」)原述語字面也是錯的,多列總比漏列好。全庫實跑:查「特殊召喚」命中 1,097 張、未解析 5,378 張;查「捨棄」命中 103、未解析 883;每次查詢約 0.1 秒。

**測試**(`test_action_query.py` 7、`test_coverage_report.py` 11):字面含「特殊召喚」但述語語尾抽不出的段 → 未解析組、不進命中組;查「破壞」時同一段不列;物件修飾抽不出時指定卡代入不命中 → 未解析組附物件原因;只給動作詞時該段命中、不重複列;無官方日文任何查詢都在未解析組;60 張無官方日文的卡號全部出現在報告(不截斷);CLI 兩次寫出逐位元組相同、產物張數不符 exit 1。
