# 效果 Tag 線(分類表)執行規格

Status: ready-for-agent

> 前導研究:`.scratch/effect-tag-research/`(attention-principles.md 與兩份分群快照)。
> 訪談定案:2026-09-20 grill-with-docs 兩輪 + to-spec 接縫確認。

## Problem Statement

牌手在本站只能用卡名、卡片參數、效果文關鍵字、效果類型(kind)、必發/選發搜卡。想找「把怪獸從墓地弄到場上的卡」「從牌組把卡加入手牌的卡」「調整攻擊力的卡」「造成效果傷害的卡」時,只能猜官方卡文的寫法拼關鍵字——同一用途有幾十種寫法,關鍵字搜不全也搜不準。效果標記表的 `tags` 欄位自規劃以來一直是空陣列,「分類表」(CONTEXT.md 詞條)始終未開工。

## Solution

給每條效果句貼上兩維標註,讓搜尋直接以「效果做什麼」與「什麼時候發動」為條件:

1. **動作維**:每句 0..N 個結構化 tag 物件(類別 + 槽位;槽位含「成本/效果」位置區分)。例:「將此卡除外,攻擊力上升1000」→ `[{類別:區域移動, 起點:場上, 終點:除外, 對象:自身, 位置:成本}, {類別:攻守調整, 項目:攻擊, 方向:上升, 位置:效果}]`。
2. **時機維**:誘發系句子多一個「觸發時機」句層軸(單值),仿必發/選發只長在承載類型上。

體系**全部一次定稿**(草案由 agent 從分群素材產出、站主逐類裁定,定稿後凍結;新卡增量只選 tag、不重跑分群),貼標**分期進行**(按分群大小由大到小),首期範圍限**新式卡文效果句 19,342 條**;規則層對高確信句型**直接寫入**(source=rule)、LLM 逐票判長尾;搜尋側同期上**最小 UI**(動作類別三態鈕 + 區域槽位起點/終點下拉)。

## User Stories

1. As a 牌手, I want 用「區域移動:墓地→場上」搜出所有蘇生系效果, so that 不用猜「特殊召喚」在各種卡文裡的寫法。
2. As a 牌手, I want 用「區域移動:牌組→手牌」搜出所有檢索效果, so that 組牌時能窮舉某主題的檢索件。
3. As a 牌手, I want 搜「攻守調整」並區分上升/下降, so that 找戰鬥輔助或弱化手段。
4. As a 牌手, I want 搜「效果傷害」, so that 組燒血軸時能全面比較。
5. As a 牌手, I want 搜「生命回復」, so that 找回復軸的組件。
6. As a 牌手, I want 排除「位置=成本」的命中, so that 搜「除外」時不會撈到一堆把自家卡除外當代價的卡。
7. As a 牌手, I want 動作 tag 與效果類型(kind)、必發/選發在**同一句**上組合(句層耦合), so that 「2速的蘇生」這種條件不會被跨句誤配。
8. As a 牌手, I want 動作 tag 條件是三態鈕(包含/排除), so that 與現有側欄操作習慣一致。
9. As a 牌手, I want 區域移動的起點/終點各有一個下拉可選, so that 「墓地→場」「牌組→手牌」這類組合不用學新語法。
10. As a 牌手, I want 搜尋條件照樣進 `#hash`, so that 查詢結果可以分享連結。
11. As a 牌手, I want 命中句在結果裡有標記(badge/上色), so that 一眼看到是哪一句、哪個 tag 命中。
12. As a 牌手, I want 搜「無效(發動/效果)」「行動限制」「耐性」等妨害向類別, so that 建構後手/坑位時能系統性瀏覽。
13. As a 牌手, I want 已貼標範圍明確標示(第一期僅新式卡), so that 理解為什麼某張舊卡搜不到,而不是以為資料錯了。
14. As a 站主, I want 從既有分群素材拿到完整體系草案並逐類裁定, so that 定稿權威在我、且不必從零發明分類。
15. As a 站主, I want 體系定稿後凍結、之後只有裁定能改, so that 不重演翻新線「通則反覆追加、回頭重核」的止損劇本。
16. As a 站主, I want 規則直貼的每條規則先過遮蔽測試門檻才敘用, so that 直貼權限不會把錯標大量寫進資料。
17. As a 站主, I want 每期貼標結束跑 seal 報告全綠才進版, so that 分期推進有明確的驗收線。
18. As a 站主, I want 改判流程(rejudge)對 tag 一樣可用, so that 發現錯標時能走既有票務修正。
19. As a 站主, I want 新卡入庫時自動出 tag 判定票(規則先貼、殘句進票), so that 增量維護不需要重跑任何分群。
20. As a 站主, I want 舊卡補判時以 faq 官方現行日文為判準, so that 與 kind 線同一權威精神、不受舊句型干擾。
21. As a 判定者(LLM), I want 批次檔自帶體系定稿、結果格式與範例, so that 只讀規範與批次檔就能作答。
22. As a 建置鏈, I want tag 與時機值域進值域正典、索引出現正典外值即建置失敗, so that 錯貼在建置期就擋下。

## Implementation Decisions

- **兩維 schema**:動作 tag = 效果句上的結構化物件陣列(類別 + 槽位;槽位值域逐類定義,含通用槽位「位置:成本/效果」);觸發時機 = 句層單值軸,以值域正典 carriers 機制限定只長在誘發系承載類型上。兩軸分開儲存、查詢時自由組合。
- **體系一次定稿、貼標分期**:草案(動作類別 + 槽位 + 時機值域)由 agent 從 48 群 embedding 分群與 30 群人工分群整理;站主逐類裁定(裁定票);定稿即凍結,追加類別需新裁定。貼標期次按分群大小由大到小。
- **範圍**:第一線只貼新式卡文(有①編號段之卡)的效果句,排除效果外文本;純通常怪獸無效果句、天然不涉及。舊文卡效果句(5,115 條)於體系穩定後另期補判,判準用 faq 補足情報的官方現行日文。
- **權威層級(偏離 ADR-0002,需新 ADR)**:tag 無官方明示可用,層級為「站主裁定 > 規則直貼(source=rule,敘用前過遮蔽測試門檻)> LLM 逐票判定(source=llm)」。規則直貼是成本考量下的刻意偏離:kind 規則僅影子預測,tag 規則對高確信句型直接寫入;錯貼風險由遮蔽測試 + 抽驗 + rejudge 流程對沖。
- **判定票工具**:沿用判定票骨架另開 tag 系列——出票(新系列,入選條件為「kind 已定且 tags 未貼、屬當期類別」,批次檔攜帶體系定稿與新 RESULT_FORMAT)、收票(新 merge,沿用三道關卡語意:集合一致性、對得回效果句、改判旗標對帳;無拆句路由)、封存(新 seal 門檻:體系定稿 digest 無異動、已貼期次零空缺、規則遮蔽 recall 達標、冪等 fixpoint、tags 值全在正典)。
- **值域正典**:新增動作類別值域、逐類槽位值域、觸發時機值域(多值/句層/carriers);正典自檢與索引側驗證沿用既有機制。
- **前端(零建置紀律不變,ADR-0007)**:索引匯出句層 tag 短碼(陣列的陣列,形狀新設計)與時機短碼;查詢引擎句層條件新增 tag 軸與時機軸(沿 ADR-0010/現有句層耦合語意);側欄由值域正典自動長出類別三態鈕,區域移動另給起點/終點下拉;hash schema 隨正典自動衍生;結果頁命中標記新增 tag 類型。
- **embedding 僅為定稿素材**:分群、venv、模型皆不入建置鏈;repo 零新增依賴。
- **定稿素材優化(採前導研究 §6.3 建議)**:裁定前以更強模型(BGE-M3 或 multilingual-e5-large)重跑新式子集分群——輸入日文原文、排除效果外文本(均已驗證);長尾用途以**兩層分群**(粗分群 → 大群內二次分群)提高解析度;更新草案的分群證據與檢視網頁後才開裁定批 1。
- **文件配套**:tag 判定規範仿效果類型判別規範的形狀(值域逐項定義 → 正交軸 → 歷史易錯 → 禁用句型 → 逃生口);CONTEXT.md 更新「分類表」「效果 Tag」詞條並新增「動作類別」「槽位」「觸發時機」;新 ADR 記錄規則直貼決策。

## Testing Decisions

- 只測外部行為,不測實作細節。四個現成接縫、零新接縫:
  1. **值域正典**:新值域進 `problems()` 十種檢查;prior art:`script/web/test_vocab.py`。
  2. **資料管線**:tag 出票/收票走管線與 merge 關卡的行為測試(少一筆多一筆指名道姓、tags 保留不隨 kind 改判消失);prior art:`script/tag_card/` 既有測試群。
  3. **規則層**:遮蔽測試框架逐類 recall(規則敘用門檻);prior art:`masked.py` / `run_masked_test.py`。
  4. **前端**:`Engine.runQuery` 單點驗證 tag/時機篩選(句層耦合、三態排除優先、marks);prior art:`script/web/engine.test.js` 與 `frontend_harness.js`。
- 每條直貼規則上線前:遮蔽測試通過 + 首批人工抽驗(混合方案的門檻數字由裁定票定案)。

## Out of Scope

- 舊文卡 5,115 條效果句的貼標(另期,體系穩定後)。
- 完整搜尋語意:句內 AND/卡內 AND 切換、槽位全組合查詢 UI(第一期只有類別鈕 + 區域起點/終點下拉)。
- embedding 語意相似搜尋(「找效果相似的卡」)——另案功能,與本線互補。
- 觸發時機軸的貼標期次排程(體系與 schema 本期定,貼標期次於票券排定)。
- 味道文字、效果外文本的任何標註(前者無效果句、後者已有 role 三形態)。
