## 需要你決定的

### 段的條件在哪裡解析、匯出成什麼形狀?

決定(2026-11-05):(a)建置期用 Python 把每段解析成段的條件匯出,JS 只做相等、位元與數值比較。與動作對象不同:動作對象在建置期拿卡面直接比(`_segment_blocker`),這裡比對移到前端;段的解析仍只有 Python 一份,兩邊共用。

現在匯出的段只有中心詞、中心詞類、數量類、修飾語類集合,沒有值。比對要在前端做:卡 14,207 × 不重複框 16,781,建置期預算命中表太大。

- (a)建置期用 Python 把每段解析成**段的條件**:卡種碼、子類型碼、種族碼、屬性碼(與 data.js 卡面的 `c`/`s`/`r`/`at` 同一套碼)、數值 [欄位, 比較, 數字或區間]、字段與卡名展開成卡片密碼清單的索引、此卡旗標、比不了的原因;JS 只做相等、位元與數值比較(建議)。data.js gzip +84 KB(+4.0%);日文剖析、省略補全、融合素材特例都只有 Python 一份。
- (b)匯出日文字面,JS 剖析。gzip +87 KB,體積差不多;代價:Python 與 JS 各一份剖析,要逐條對拍。
- (c)建置期預算卡 × 框的命中表。代價:約 2.4 億格,不可行。

### 回指目標存目標的段,還是先行框的索引?

決定(2026-11-05):(a)存目標的段,帶段的條件。同動作對象:目標字面切段的讀法同 `patient.segments_of`。

受事者第一段是指示詞的框 5,616,解出目標 5,001(89%);目的片語是指示詞的 423 框。

- (a)存目標的段(同受事者的段,帶段的條件)(建議):data.js gzip +39 KB(+1.9%);回指以字面備援解出的 416 框也帶得到,讀法同 `patient.segments_of`。
- (b)存先行框的索引:gzip +8 KB。代價:437 筆(8.7%)指不到匯出的框列;另約 500 筆指得到但先行框的受事者不是目標(回指鏈 253、目標字面被改寫 247,多是 無効にする 指的 発動),前端要沿鏈走、處理跨標記句。

### 字段怎麼判?

決定(2026-11-05):(a)卡名包含 + 對照表(另比的卡名子字串、補進的密碼、排除的密碼,各附理由);草稿機械產生、站主逐條核可,建置期失配就失敗。同動作對象的「卡名包含」(`_segment_blocker` 的 quoted 比 NFKC 包含),多一張對照表。

票 01 Q17 定了「卡名包含,另加人工對照表補對不到的 38 種」。實測(對照組用 cards.json 的 setcode,EDOPro 社群資料,不是官方):語料出現的字段字串 595 種、5,892 框;卡名對到 0 張 37 種(扣掉 3 種抽取錯,要補的 34 種);誤中(卡名包含但 setcode 不屬)545 卡次、61 種,大宗是 D、N 這種單字母與 カオス、魔術師;漏中(setcode 屬但卡名不含)977 卡次、157 種,大宗是漢字卡名配片假名讀音(グラディアル→剣闘獣 51、サラマングレイト→転生炎獣 42)。

- (a)卡名包含 + 對照表,對照表每個字段三欄:另比的卡名子字串、補進的卡片密碼、排除的卡片密碼,每筆附理由(建議)。同動作對象的「卡名包含」,多一張表。草稿由 setcode 差集(0 張、誤中、漏中三份)與卡文「このカード名はルール上「X」カードとしても扱う」(146 張、164 組)機械產生,站主逐條核可(審核關卡);建置期失配就失敗(另比的子字串對到 0 張、密碼不存在、排除的卡其實不含該字串)。代價:草稿約 250 種要核。
- (b)直接用 setcode 判字段。代價:EDOPro 規則與 OCG 有落差(例:融合 碼收 フュージョン 卡名),要另一層 OCG 校正;改了 Q17 的決定。
- (c)照 Q17 字面,只補 0 張的 34 種。代價:誤中 545、漏中 977 卡次留著。

### 中心詞是卡名時,比全名相等還是包含?

決定(2026-11-05):(a)中心詞「X」NFKC 後全名相等;修飾語「X」才是字段、比包含。與動作對象不同:`_segment_blocker` 把中心詞「X」也放進 quoted 比包含;共用模組後動作對象也改成全名相等,屬[現行比對器](#現行比對器的兩個錯要不要一起修?)逐框確認的變動之一。

與動作對象不同:`_segment_blocker` 把中心詞「X」也當字段比包含。中心詞是卡名的 685 種、1,337 框;其中 81 種用包含會對到不只一張(375 框),例:「ブラック・マジシャン」1体 會順帶中 ブラック・マジシャン・ガール 等 12 張、「融合」中 66 張。

- (a)中心詞是卡名:NFKC 後全名相等;修飾語「X」(「X」モンスター)才是字段、比包含(建議)。卡文「「X」1体」說的是那張卡,「「X」モンスター」說的是字段。
- (b)照現行,一律包含。代價:上面 375 框誤中。

### 現行比對器的兩個錯要不要一起修?

決定(2026-11-05):(a)抽出段的條件解析模組,動作對象與針對卡片共用,兩個錯一起修;動作對象判定的變動逐框確認後 patient 尺重凍。與現行不同:`_numeric_block` 把區間的兩個數當列舉(沒有比較詞時 `value not in numbers`)、`_compare_face` 只取中心詞類是卡的段。共用模組後動作對象另有三處跟著變,一併逐框確認:[卡名全名相等](#中心詞是卡名時,比全名相等還是包含?)、[魔法・罠 卡種候選](#卡種並列)、[未知比較詞](#未知比較詞怎麼辦?);其餘判法同現行。

實測發現 `_segment_blocker` 兩個錯,動作對象的全部類判定也受影響:

- 數值區間當成列舉:レベル3～5、ランク8～10 這類 6 筆與「レベル4以下と8以上」1 筆,レベル4 會被レベル3～5 擋下。
- 屬性段沒併進卡段:「ドラゴン族・光属性・レベル7モンスター」切成屬性段與卡段,`_compare_face` 只取卡段,種族與屬性被丟掉(41 框;黑魔導因此誤中)。

選項:

- (a)抽出一個**段的條件**解析模組,動作對象與針對卡片共用,兩個錯一起修;動作對象判定的變動逐框確認後 patient 尺重凍(建議)。同一段只有一份判法。
- (b)只在針對卡片修,動作對象不動。代價:同一段兩套判法、結果不一致。
- (c)都不修。代價:針對卡片帶著這兩個錯上線。

### 哪些條件標「部分條件未比對」?

決定(2026-11-05):(a)只有卡面參數比不了的標,另加回指解不出或經事件回指的;狀態與事件條件不標、不算有寫條件;只看命中的那段。與動作對象不同:`_segment_blocker` 把定語子句、表示形式這類 其他 類修飾語一律算比不了(皆非的理由 全部類比不了),動作對象這邊不改——模組把「卡面參數比不了」與「狀態條件」分開記,動作對象兩類都算比不了、針對卡片只算前一類。

Q16 列了 このカード以外、同じ種族、元々の、合計。實測受事者段(寬口徑,一段可多個原因)比不了的分兩類:

- 卡面參數比不了:以外/他 1,965、同じ/同名/異なる 587、中心詞 X素材 424、融合素材 131、元々の 108、合計 31、多欄數值 28、子類型對不到 13。
- 不是卡面參數:定語子句 2,786(この効果で特殊召喚した 707、除外されている 179…)、表示形式 1,689、このカード 當修飾語 723、關係與位置詞(素材、装備、リンク先)510、指示詞修飾 253。

選項:

- (a)只有卡面參數比不了的標「部分條件未比對」,另加回指解不出或經事件回指(その効果)的;狀態與事件條件不標、也不算「有寫條件」(建議)。任何卡都可能處在那個狀態,它們不回答「能不能作用到這張卡」。只看命中的那段,不看其他段。
- (b)兩類都標。代價:預設模式約三分之一的命中句帶標,標記失去意義。

### 卡種並列(魔法・罠カード)怎麼辦?

決定(2026-11-05):(a)段的條件解析時認成卡種候選(魔法或罠),片語不動。與動作對象不同:現行把它算比不了;共用模組後動作對象也認成卡種候選(受事者 55 段所在的框可能從 皆非 變 非此卡/此卡),屬[現行比對器](#現行比對器的兩個錯要不要一起修?)逐框確認的變動之一。

「魔法・罠カード」被片語切成 其他 類修飾語加中心詞,算成比不了;受事者 55 段、回指目標 180 段。

- (a)段的條件解析時認成卡種候選(魔法或罠),片語不動(建議):既有修飾語類欄不變。
- (b)修片語抽取。代價:既有修飾語類欄變,剝鍵基準要重凍。
- (c)不修,算比不了。

### 「効果モンスター」單獨算不算「有寫條件」?

決定(2026-11-05):(a)子類型 効果 不算有寫條件,和卡種一樣;仍會擋。比 GLOSSARY「卡種不算」多一項,GLOSSARY 跟著補。動作對象不數條件、擋法不變,無關。

GLOSSARY 定子類型算條件、卡種不算。原型照這樣算,效果怪獸的「只看有寫條件的」命中被灌大:天霆號アーゼウス 命中段第一名是「効果モンスター1体」79 框、「相手フィールドの効果モンスター1体」52 框。

- (a)子類型「効果」不算有寫條件,和卡種一樣;仍會擋(通常怪獸不中 効果モンスター)(建議)。
- (b)照 GLOSSARY,算。代價:「只看有寫條件的」對效果怪獸找不出專門支援。

### 目的片語讀哪些段?

決定(2026-11-05):(a)去掉區域段、とする/なる/同じにする 的目的不算;方位詞(上、下)取它的主人再解回指。與動作對象不同:動作對象不比目的片語的段,目的只當區域用(`_all_class` 的 goal_zones 只取玩家)。

Q28 定了受事者或目的片語任一段滿足就算。原型發現兩種段會讓每張卡都空泛地過:

- 本身是區域的段(墓地、手札、自分フィールド:中心詞類標成卡)。
- とする/なる/同じにする 的目的(陷阱怪獸的「通常モンスター(…)」被當成條件)。

- (a)去掉區域段、とする/なる/同じにする 的目的不算;方位詞(上、下)取它的主人再解回指(建議)。
- (b)前兩項照 (a),方位詞不補,重ねる 這 80 框的目的算比不了。

與動作對象不同:動作對象把召喚手續的 重ねる 一律判此卡(summon-procedure 定案)。

### 目錄選擇窗怎麼算張數?

### 網址與鎖怎麼記?

決定(2026-11-05):(a)網址欄 `針對卡片`、`針對模式` 排在欄序最後,預設模式不寫;認具名查詢時跳過這兩欄,帶了卡片的標籤寫欄位對。同 位置 欄在 `predKey` 的做法;舊網址逐位元組不變。

網址現在只寫欄位對,標籤等於某具名查詢時只寫葉路徑;鎖靠「標籤認得出原具名查詢」(`predKey`)。帶入卡片後 `predKey` 把新欄也算進去,就認不回原列,重開網址鎖與註記都不見。

- (a)寫 `針對卡片:46986414`;模式另一欄 `針對模式:只看有寫條件`,預設模式不寫;兩欄排在欄序最後。認具名查詢時跳過這兩欄(同 位置),帶了卡片的標籤寫欄位對、不寫葉路徑(建議)。舊網址逐位元組不變。
- (b)帶入卡片就是新標籤,不再認原列。代價:鎖與註記在重開網址後消失。

## Problem Statement

站主想知道「黑魔導能被哪些效果從場上除外」。現在搜尋只能比受事者的中心詞字面:寫「ブラック・マジシャン」的效果查得到,寫「レベル６以上の魔法使い族・闇属性モンスター」的(滅びの黒魔術師的召喚手續、大多數支援卡)查不到,因為匯出檔只帶修飾語的類(有種族、有數值),沒有值,也沒有指示詞(そのモンスター)指的目標。反過來「哪些效果專門支援黑魔導」也找不出來。

## Solution

1. 框架述詞新增一欄**針對卡片**:給一張卡,只留受事者或目的片語任一段寫出的條件(卡種、子類型、種族、屬性、數值、字段、卡名)那張卡都滿足的框。片語是指示詞時讀回指目標的段;是 このカード 時只有挑的正是框所屬的卡才中。
2. 兩種模式:預設「不違反寫出的條件」;「只看有寫條件的」= 命中的那段至少寫出一個條件(卡種與子類型 効果 不算)且全部滿足。
3. 比不了的卡面條件(以外、同じ種族、元々の、合計、多欄數值、X素材、回指解不出)不擋,命中句尾標「部分條件未比對」。狀態與事件條件(表示形式、除外されている、この効果で特殊召喚した)不比、不標。
4. 建置期把每段解析成段的條件匯出;回指目標存目標的段;目的片語也解回指(只記目標、不回填區域)。字段用卡名包含加站主核可的對照表,卡名中心詞比全名。
5. 兩個入口:抽屜的針對卡片欄(打中文卡名自動完成,網址記卡片密碼);結果卡片上的鈕開目錄選擇窗,只列帶入這張卡後仍有命中的列、附張數,預設「只看有寫條件的」,挑一列就產生那列的標籤並帶入這張卡。
6. 比對規則抽驗 5 張卡各 20 對上、20 擋下;目的片語回指抽 100 框;各兩輪。

驗收:加「除外」標籤、位置按亮召喚手續、針對卡片選黑魔導,滅びの黒魔術師在結果裡;結果卡片的鈕在黑魔導上開窗,「除外」列有張數;既有欄位剝新鍵後不變,舊網址不變。

## User Stories

1. 作為使用者,我要給一張卡就查出受事者條件它都滿足的動作,這樣「黑魔導能被哪些效果除外」查得到,不必知道卡文怎麼描述它。
2. 作為使用者,我要種族、屬性、等級/階級/連結、攻守、子類型、卡種、字段、卡名都拿來比,這樣「等級6以上的魔法使族」這種寫法也對得上黑魔導。
3. 作為使用者,我要預設模式只擋「寫了而不符」的,這樣沒寫條件的「場上のモンスター１体」也列出來,我看得到所有能作用到這張卡的效果。
4. 作為使用者,我要切到「只看有寫條件的」,這樣找得出專門支援這張卡(或它的種族、字段)的效果。
5. 作為使用者,我要「効果モンスター」「モンスター」這種泛稱不算有寫條件,這樣「只看有寫條件的」不會被泛用效果灌滿。
6. 作為使用者,我要受事者是「そのモンスター」時讀它指的那隻的條件,這樣「対象とした…そのモンスターを破壊」這類兩段寫法也比得到。
7. 作為使用者,我要裝備、疊放的目的片語(「そのモンスターに装備」「対象のモンスターの上に重ねて」)也比,這樣「能裝備到黑魔導」的魔法查得到。
8. 作為使用者,我要「このカード」只有我挑的正是那張卡才中,這樣挑黑魔導時不會中每張卡的自己特招。
9. 作為使用者,我要比不了的卡面條件(このカード以外、同じ種族、元々の、合計)不擋、命中句標「部分條件未比對」,這樣我知道哪幾句需要自己讀原文確認。
10. 作為使用者,我要表示形式、「この効果で特殊召喚した」這類狀態條件不擋也不標,這樣標記只出現在真的沒比到卡面參數的句子上。
11. 作為使用者,我要字段照官方「卡名包含」判,另有站主核可的對照表補讀音不同(海晶乙女=マリンセス)與誤中(單字母 D),這樣字段支援卡找得齊又不亂中。
12. 作為使用者,我要卡文寫「「ブラック・マジシャン」1体」時只中名字正好是它的卡,這樣挑黑魔導女孩時不會中只認黑魔導的效果。
13. 作為使用者,我要等級範圍(レベル3～5)照區間比,這樣等級4的卡不會被擋下。
14. 作為使用者,我要「魔法・罠カード」照卡種比,這樣挑一張魔法卡時這類效果算比得了。
15. 作為使用者,我要在抽屜的針對卡片欄打中文卡名、從自動完成挑,這樣不必記卡片密碼。
16. 作為使用者,我要在結果卡片上按一個鈕,看到帶入這張卡後還有命中的目錄列和張數,這樣不必猜要從哪一類動作開始找。
17. 作為使用者,我要選擇窗預設「只看有寫條件的」,這樣第一眼看到的是專門支援這張卡的動作。
18. 作為使用者,我要選擇窗在手機上也一下就算完,這樣不必等好幾秒。
19. 作為使用者,我要從選擇窗挑一列就產生那列的標籤並帶入這張卡,這樣標籤仍有詞元、仍是我熟悉的具名查詢。
20. 作為使用者,我要帶入卡片後標籤仍鎖在原來那列,這樣鎖住的欄與註記照舊。
21. 作為使用者,我要網址記卡片密碼與模式,這樣「針對黑魔導」的查詢分享出去打開一樣。
22. 作為使用者,我要舊網址照樣讀得進來、查到的卡不變,這樣分享出去的連結不會壞。
23. 作為使用者,我要針對卡片在四個位置都能用,這樣召喚手續「除外等級6以上的魔法使族」也對得上黑魔導。
24. 作為使用者,我要排除述詞也能帶針對卡片,這樣能找「沒有任何效果能除外黑魔導」以外的卡。
25. 作為站主,我要既有欄位剝掉新鍵後逐位元組不變,這樣這次只加不改,以前的驗收都還算數。
26. 作為站主,我要動作對象與針對卡片共用同一份段的條件判法,這樣兩邊不會對同一段判出不同結果。
27. 作為站主,我要比對器的數值區間與屬性段兩個錯修掉、動作對象的變動逐框確認,這樣修正是看過的。
28. 作為站主,我要字段對照表是審核關卡、建置期失配就失敗,這樣上游資料改了會吵出來。
29. 作為站主,我要參考評估器與 JS 評估器在針對卡片上對得上,這樣兩邊的語意只有一份。
30. 作為站主,我要比對規則抽驗 5 張卡各 20 對上、20 擋下,目的片語回指抽 100 框,這樣錯有多少是量出來的。
31. 作為站主,我要匯出檔的格式版本加一、網站建置檢查新版本,這樣舊建置讀到新檔會明確失敗。
32. 作為站主,我要 data.js 的體積增加有數字,這樣知道手機載入的代價。

## Implementation Decisions

**段的條件(建置期,新模組)**
- 一個模組把論元片語的一段解析成段的條件:卡種、子類型、種族、屬性、數值、字段、卡名、此卡旗標、比不了的原因清單、有寫條件數。動作對象的全部類判定與針對卡片都讀它;`_segment_blocker` 改成在它之上判,行為只改[現行比對器](#現行比對器的兩個錯要不要一起修?)列的變動(兩個錯、卡名全名相等、魔法・罠 卡種候選、未知比較詞)。
- 判法(同動作對象,除註明者):
  - 卡種由中心詞字面尾判(先補省略、去尾 カード;チューナー 當怪獸加 チューナー 子類型)。
  - 子類型來自中心詞前綴與子類型修飾語;魔法/罠的 通常 = 沒有子類型位元;沒卡種只有子類型時比不了。子類型「効果」照擋、不算有寫條件(與動作對象不同,動作對象不數條件)。
  - 融合素材(子類型修飾語後接 素材)整段比不了。
  - 種族、屬性任一符合。屬性段的種族與屬性併進後面的卡段(與現行不同,修正)。
  - 數值欄位限 レベル、ランク、リンク、攻撃力、守備力;區間(３～５)照區間比,列舉(７・８)任一符合,以上/以下/未満比第一個數(區間是修正);攻守是 ? 不擋;多欄或並列欄位比不了;未知比較詞比不了(與現行不同:現行靜靜放行,資料裡目前沒有;見[未知比較詞](#未知比較詞怎麼辦?))。
  - 字段:修飾語「X」;卡名包含加對照表,建置期展開成卡片密碼清單。卡名:中心詞「X」,NFKC 全名相等(與動作對象不同)。
  - 卡種並列(魔法・罠)認成卡種候選。
  - 區域、玩家修飾語不比。同 `_segment_blocker`(它也跳過這兩類);動作對象另在 `_all_class` 拿區域對發動位置,針對卡片不做,照 GLOSSARY 的條件清單(不含區域)。
  - 選擇類(帶數量)照樣比卡面(與動作對象不同:動作對象選擇類直接判非此卡、不比卡面;針對卡片照 Problem Statement 的例子——滅びの黒魔術師的受事者帶數量 1体——非比不可)。
  - このカード:此卡旗標;只有挑的卡是框所屬的卡才過,算有寫條件。このカード以外/他の、同じ/同名/異なる、元々の、合計、X素材、此卡的附屬卡:比不了。
  - 狀態與事件條件(定語子句、表示形式、關係與位置詞、指示詞修飾):不比、不算比不了、不算有寫條件。
- 段的讀取:受事者片語(屬性受事者 このモンスターの攻撃力 取主人的段)、目的片語(去掉區域段;とする/なる/同じにする 的目的不算)、回指目標的段;任一段過就算。只看有寫模式:過的那段有寫條件數 ≥ 1。「部分條件未比對」只看命中的那段。
- 召喚手續的 重ねる 照常比(與動作對象不同)。

**回指線**
- 目的片語的指示詞也解回指,沿用受事者的解法;方位詞(上、下)取主人再解。只記目標,不回填區域;存成新鍵,不動既有回指欄。
- 經事件的回指(その効果、その発動)、解不出的,算比不了。

**匯出檔**
- 段多帶段的條件;受事者與目的的回指目標存成目標的段(同一形狀)。
- 字段與卡名的卡片密碼清單匯成一張表,段只帶索引。
- 格式版本 3 → 4,網站建置的版本檢查跟著改。目錄、統計不變(針對卡片不是目錄列)。

**字段對照表**
- 入版控的手寫來源檔,每個字段:另比的卡名子字串、補進的卡片密碼、排除的卡片密碼,各附理由。建置期套用;另比的子字串對到 0 張、密碼不存在、排除的卡其實不含該字串時建置失敗。
- 草稿由 setcode 差集與卡文「ルール上「X」カードとしても扱う」機械產生,是審核關卡,站主逐條核可後才進建置。

**參考評估器**
- 新增兩欄:針對卡片(值:卡片密碼)、針對模式(不違反 / 只看有寫條件)。評估要框所屬卡的密碼與卡面表(同 data.js 的卡面欄),回傳命中與「部分條件未比對」旗標。語意只有這一份,JS 對拍它。

**網站建置與前端**
- 評估器:框欄多一欄針對卡片;命中表區分命中與命中但部分條件未比對,命中帶旗標;句尾多一個「部分條件未比對」標記。
- 條件模型:新欄種類「卡片」,值驗證是存在的卡片密碼;顯示中文卡名;模式一欄,預設不違反。認具名查詢時跳過針對卡片與模式(同 位置);帶了卡片的標籤寫欄位對。網址欄 `針對卡片`、`針對模式`,排在欄序最後,預設模式不寫。
- 抽屜:針對卡片欄打中文卡名自動完成(全庫,邊打邊只放前幾十筆候選),旁邊模式切換。
- 結果卡片:卡頭一個鈕,開目錄選擇窗:目標卡逐框表算一次,詞元索引掃各列的框、框→卡反查張數,只列張數 > 0 的列,預設只看有寫條件的,窗內可切模式;挑一列 → 產生那列的標籤、帶入這張卡、加到 AND 區。
- 卡面:屬性、種族在載入時編成位元,與段的條件同一套碼。

**LLM 抽驗**
- 比對規則線:5 張抽驗卡(黑魔導 46986414、スカーライト 80666118、ホープ・ザ・ライトニング 56832966、閃刀姫－カガリ 63288573、瞬間融合 17236839),每張「只看有寫條件的」命中抽 20、擋下抽 20,分層(字段、子類型、數值、追回指、目的片語);批次檔列原文、命中段、段的條件、判定與比不了的原因。錯誤類型:誤中、誤擋、該標未比對沒標、不該標標了、解析錯(碼、數值、字段)、回指目標錯。
- 目的片語回指線:抽 100 框,看目標對不對。
- 各兩輪:第一輪找的錯在抽驗票修,同一批複檢。

**文件**
- GLOSSARY「針對卡片」條補:狀態條件不比不標、効果 不算有寫條件、卡名中心詞比全名、字段對照表、目的片語範圍;「回指」條補方位詞取主人;「論元片語」條補段的條件。

## Testing Decisions

- 好的測試只看外部行為:給一句卡文看出的框與段的條件,給述詞、框列與卡面看命中與旗標,給標籤看網址;不測解析的中間步驟。
- **分詞鏈接縫**(既有):一句卡文 → 框架清單。例子:目的片語回指(装備 的「そのモンスターに」、重ねる 的「対象のモンスターの上」)解到目標;既有回指欄不變。先例:anaphora 的既有單元測試。
- **段的條件**:透過匯出接縫(一句卡文 → 匯出框列)看段的條件:等級區間、屬性段併進卡段、魔法・罠 卡種候選、卡名全名 vs 字段包含、比不了的原因、狀態條件不算。動作對象的兩個修正透過既有的動作對象測試。先例:test_05_export_frames、動作對象規則測試。
- **全語料守門**(既有):匯出檔剝新鍵後與現行逐句相同;剝鍵比對、回指尺 0 差異不重凍;patient 尺只有[現行比對器](#現行比對器的兩個錯要不要一起修?)列的變動(兩個錯、卡名全名、魔法・罠、未知比較詞),逐框確認後重凍。
