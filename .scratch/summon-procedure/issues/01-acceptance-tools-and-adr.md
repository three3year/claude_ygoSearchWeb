# 01: 驗收工具剝框重編,寫 ADR 0019

**What to build:** 召喚手續框出框之前,先讓守門分得出「新加的框」和「既有的框」。剝鍵比對、下游基準(動作對象、回指)、匯出檔比對在比之前都先剝掉位置是召喚手續的框,框序照剩下的重編;匯出檔另剝掉召喚手續框列與目錄列、統計裡新增的召喚手續那一格。現在全語料還沒有召喚手續框,所以三道守門照舊 0 差異,digest 不重凍。同時寫 ADR 0019「召喚手續另出動作框架」。見規格「既有欄位逐位元組不變怎麼驗?」與「要不要寫 ADR?」的決定。工作在新整合分支 `summon-procedure`(基於 `main`)上開始。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 剝框重編是一個共用的接縫(給一筆框架紀錄 → 剝掉召喚手續框、框序重編後的紀錄),剝鍵比對與下游基準都經它;單元測試:手寫一句含召喚手續框的紀錄,剝完的框與框序等於不含它的版本
- [ ] 匯出檔比對:剝掉召喚手續框列、目錄列與統計的召喚手續格後,與現行 `data/action_frames.json` 逐句相同(不看版本號);有單元測試
- [ ] 現行語料上:剝鍵 digest ok、差異 0;回指、動作對象逐框差異 0;匯出比對 0 差異;都沒有重凍
- [ ] ADR 0019 寫明:為什麼不把約束框架直接進索引、為什麼要白名單、為什麼約束框架的手續欄保留不改、同一段卡文有兩種框架表示的取捨;docs/adr 的索引(若有)跟著加
- [ ] effect-tokenize 全套通過;機械 lint 通過
