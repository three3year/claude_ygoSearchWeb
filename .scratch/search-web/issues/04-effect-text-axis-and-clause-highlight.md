# 04 — 效果文關鍵字與句層命中標亮

**What to build:** 效果文框可用,而且命中的是**哪一個效果**看得見——命中的[[效果句]]整行
標亮、關鍵字本身在行內上色、行首掛 badge。逐句比對是這個站與一般查卡站的分水嶺:
「墓地%手牌」只在同一個效果裡同時出現才算命中,而不是散落在兩個無關的效果。

同時實作**排除素材行**:效果文關鍵字不掃 `role = 素材指定` 的 2,358 行。搜「融合」時,
574 張融合怪獸的素材寫法會把真正的答案淹掉。[[效果標記表]]逐句判過 `role`,所以這件事
做得準,而一般查卡站做不到。這是固定規則,不提供開關。

已知副作用(spec 已記):在效果文框搜「青眼白龍」不會撈到把它寫在素材行的融合怪獸,
但卡名框搜得到本尊。

**Blocked by:** 03 — 搜尋骨架與卡名軸

**Status:** resolved

- [x] 效果文框逐[[效果句]]獨立比對,一句之內同時滿足才算命中
- [x] `%` 萬用字元同卡名框
- [x] **不掃 `role = 素材指定` 的行**;召喚條件、使用次數限制與其餘[[效果外文本]]照樣掃
- [x] 命中的[[效果句]]整行標亮,關鍵字本身在行內上色
- [x] 命中行行首掛 badge 標示命中原因
- [x] 未命中的效果句維持原樣(標亮只落在真正命中的那幾行)
- [x] 接縫 3 測試:關鍵字只出現在素材指定行 → 不命中;只出現在召喚條件或使用次數限制行
      → 命中;命中效果句索引指向正確的那一句

## Comments

2026-08-14 實作完成(與票05 同一輪)。`engine.js` 多一段句層判定,`render.js` 的卡文那一段
改成吃「命中的效果句索引」。接縫 3 測試多 8 條。

**句層條件與卡層條件在引擎裡是兩種東西。** 卡名、密碼、卡片參數是卡層:整張卡通過或不通過。
效果文關鍵字是句層:逐[[效果句]]獨立比對,一張卡只要存在一個效果句滿足就命中,那一句進
`rows`。這個分界不是實作方便,是 spec 的分水嶺語意——一般查卡站對整段卡文比對,分不出
「同一個效果做了兩件事」與「兩件事散落在兩個無關的效果」。合成資料集裡的 `20107`(同句)
與 `20108`(異句)就是這一組對照:整段比對的話兩張都會中。

**`rows` 的內容決定標亮,呈現層不自己再判一次命中。** 「哪一行亮」與「哪一行算命中」是
同一件事,兩處各判一次必然漂開。同理,行內上色的位置取自引擎導出的 `likeRanges`——與
決定命中的是同一次走訪,所以不會出現「這一行被標亮了但沒有一個字上色」。`likeMatch` 因此
改寫成 `likeRanges(...).length === parts.length`,比對只剩一份走法。

**命中原因由 `marks` 回報,而不是逐行記一次。** 每一個 row 都滿足**全部**句層條件(那正是
句層耦合的定義),所以命中原因對整批 rows 是同一組,`runQuery` 回傳一次就夠。票06 加效果
類型與必發/選發時往 `marks` 加一種,badge 自動變成「效果文・誘發即時效果(2速)」。

**`role = 素材指定` 的行連掃都不掃,不是掃了再扣分。** 實測效果文搜「融合」得 803 張
(574 張融合怪獸的素材寫法全部不在其中),搜「「青眼白龍」」得 31 張。已知副作用照 spec
接受:效果文框搜「青眼白龍」撈不到把它寫在素材行的融合怪獸,卡名框搜得到本尊。

**沒有效果句的 689 張純通常怪獸不被效果文條件命中。** 故事文不是效果,`d` 欄位不進句層
比對——搜效果文搜不到黑魔導是對的,那張卡沒有效果。

**`body()` 改寫成 `lineHtml(text, ranges)`,● 換行、原文換行與關鍵字上色在同一次走訪裡
決定。** 先切成「命中段/非命中段」再各自處理的話,段界上的 ● 會看不到它前面那個字,而那
正是「開頭的 ● 不重複換行」要看的東西。改寫後與舊實作逐字元對帳過全部 14,207 張
(沒有句層條件時輸出必須完全相同,0 筆差異)。
